# 04. 웹툰 콘텐츠 가이드

## 1. 웹툰의 역할

웹툰은 별도의 재미 콘텐츠가 아니라
**어려운 기술 개념을 직관적으로 이해시키기 위한 선택적 학습 장치**다.

모든 용어를 웹툰화하지 않는다.

---

## 2. 톤

유머 비율:

**약 30~50%**

원칙:

> **개념을 웃기게 왜곡하지 않는다. 개념이 사용되는 상황을 웃긴다.**

사전 본문은 정확하고 진지하게 유지한다.

---

## 3. 우선 웹툰화할 개념

다음 특성을 가진 용어를 우선한다.

### A. 혼동 해소형

두 개념을 자주 혼동하는 경우.

예:

- Shell vs Terminal
- Docker Image vs Container
- Git vs GitHub
- Volume vs Bind Mount
- Class vs Object

### B. 추상 개념 시각화형

눈에 보이지 않는 동작을 그림으로 표현하면 이해가 쉬운 경우.

예:

- Port Mapping
- File Permission
- Branch / Merge
- MAC Operation
- Time Complexity

### C. 직관에 반하는 개념

처음 접했을 때 예상과 다른 결과가 나오는 경우.

예:

- Floating Point / Epsilon
- Persistence
- UTF-8 / Encoding
- PID 1
- Force Push

---

## 4. 권장 4컷 구조

### 1컷 — 문제 상황

학습자가 실제로 겪을 만한 상황.

### 2컷 — 오해 또는 과장

초보자가 흔히 하는 착각을 유머로 확대한다.

### 3컷 — 개념 등장

핵심 기술 개념이 문제를 설명한다.

### 4컷 — 기억에 남는 결론

웃긴 결과 또는 반전과 함께 핵심 차이를 남긴다.

---

## 5. 정확한 설명 연결

웹툰은 단독으로 끝내지 않는다.

웹툰 다음에 다음 요소를 제공한다.

> **그래서 진짜 뜻은?**

그리고 정확한 기술 설명을 짧게 정리한다.

선택적인 마무리 카피:

> **웃었으면 됐고, 이제 진짜 뜻을 봅시다.**

---

## 6. 제작 데이터

각 웹툰에는 다음 메타데이터를 관리한다.

```yaml
term_id: docker-image
title: "이미지와 컨테이너는 같은 게 아니다"
humor_level: 40
concept_goal: "이미지는 실행 전 템플릿이고 컨테이너는 실행 인스턴스라는 차이 이해"
misconception: "이미지와 컨테이너를 같은 대상으로 생각함"
format: 4-panel
status: candidate
```

---

## 7. 품질 원칙

- 웹툰을 보고 잘못된 기술 개념을 기억하게 만들지 않는다.
- 캐릭터의 대사는 쉬워도 기술 설명은 정확해야 한다.
- 비유가 적용되지 않는 부분은 명시한다.
- 억지로 웃기기 위해 핵심 개념을 희생하지 않는다.
- 웹툰만 보고 끝내도 최소한 핵심 차이는 기억할 수 있어야 한다.
