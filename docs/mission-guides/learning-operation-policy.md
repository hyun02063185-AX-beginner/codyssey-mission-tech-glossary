# 미션 스토리·개념지도 학습 운영 정책 및 교육 철학

> **버전:** v1.0 · 2026-10-22
> **적용:** 기술용어사전의 미션 스토리·개념지도·용어사전·분야 기술지도·학습가이드 및 대면 강의 운영
> **상태:** Owner가 대화에서 정한 교육 설계·운영 방향. **코디세이 운영기관의 공식 출석·교육·평가 규정은 아니다.**
>
> **신규 미션 필독:** [`workflow.md`](workflow.md). 미션 스토리를 기획할 때, 콘텐츠를 독립 검토할 때, 웹으로 통합할 때 이 정책을 다시 확인한다.

## 1. 목적과 핵심 철학

입문자는 익숙하지 않은 용어의 정의를 읽는 것뿐 아니라 그 기술이 **왜 필요하고, 어디에서 작동하며, 서로 어떤 관계를 맺는지** 이해하는 데 어려움을 겪는다. 미션 수행 시간이 제한되어 있으므로 모든 관련 지식을 첫 단계에서 외우도록 요구하지 않는다.

교육 목표는 **강사의 안내로 미션의 핵심 흐름을 이해하고, 개념지도로 기술 간 관계를 파악하며, 실제 미션을 수행한 뒤 스스로 설명하고 더 넓은 지식으로 연결하는 것**이다.

- **입문의 부담은 낮추고, 이해의 깊이는 높인다.**
- **학습에 필요한 집중력을 낮춘다고 주장하지 않는다.** 이해에 기여하지 않는 인지부하를 줄여 중요한 내용에 주의를 집중하도록 한다.
- 그림은 정확한 설명을 대체하지 않는다. 구조·흐름·관계의 시각화와 정의·예외·코드·검증을 상호 보완한다.
- 입문 시 명시적인 안내를 제공하고, 이해가 쌓일수록 학습자가 스스로 탐색·구현·판단하도록 도움을 줄인다.
- 학습 완료는 '자료를 봄'이 아니라 **자신의 언어로 설명하고 적용·검증할 수 있음**으로 확인한다.

## 2. 대면 강의 필수 운영 원칙

**우리 교육 모델에서는 미션 시작 시 강사 주도 대면 강의를 필수 초기 학습 단계로 운영한다.** 초보자에게 학습 출발점과 자료 사용법을 안정적으로 제공하기 위한 **운영 선택**이며, 대면 강의가 언제나 다른 교육 방식보다 우월하다는 연구 결과로 표현하지 않는다.

강사는 미션의 답을 대신 수행하거나 용어사전 전체를 강독하지 않는다. **대면 강의는 학습자에게 미션의 목표, 스토리와 개념지도를 이해하고 활용하는 방법, 실습의 출발점을 전하는 시간**이다.

대면 강의에는 다음이 포함되어야 한다.

1. 미션의 핵심 질문·시간·실제 완료 조건과 학습 범위를 공유한다.
2. 꼭 필요한 선수개념만 먼저 소개한다.
3. **미션 스토리**를 따라 문제·동작·요청과 응답 등의 의미 있는 흐름을 설명한다.
4. **미션 개념지도**에서 핵심 노드·관계·차이를 선택하여 시연하고 지도 읽는 법을 가르친다.
5. 용어사전·분야 기술지도·학습가이드를 **언제 찾아보고 어떻게 돌아오는지** 직접 보여준다.
6. 짧은 질문·말로 설명하기 또는 따라 하기 활동으로 독립 실습에 들어갈 준비가 되었는지 확인한다.

강의 시간, 세부 배분, 수준별 그룹 운영, 대면 참여가 어려운 경우의 보완 방식은 시범 운영 후 확정한다.

## 3. 다섯 가지 학습 콘텐츠의 역할 구분

| 자산 | 학습 질문 | 설계 경계 |
| --- | --- | --- |
| **미션 스토리** | *이 미션에서 무엇이 왜 일어나고, 어떤 순서로 작동하는가?* | 하나의 미션·문제·흐름에 집중. 강의 자료이자 복습 자료. 실제로 인과관계가 아닌 개념을 억지로 순서로 연결하지 않는다. |
| **미션 개념지도** | *그 흐름에 등장한 기술은 서로 어떤 관계인가?* | 미션과 관련된 개념을 선별해 **좁은 맥락에서 관계를 밀도 있게** 설명. 노드 선택·관계 강조·비교·설명. 모든 연결을 한 번에 강하게 보여주지 않는다. |
| **용어사전** | *한 기술의 정확한 뜻과 원리는 무엇이며, 다른 지식과 어떻게 연결되는가?* | 미션 범위를 벗어나 정의·작동·예외·선수학습·학문·관련 미션과 **의미 있는 연결을 폭넓게** 제공. 링크 수 최대화가 목적이 아니다. |
| **분야별 기술지도** | *전체 기술 분야에서 어디에 위치하는가?* | 미션 개념지도보다 넓은 기술 체계를 조망하며 인터랙션 원칙을 공유한다. |
| **미션 학습가이드** | *실제로 어떻게 해 보고 확인할 것인가?* | 작업·코드·명령어·검증·오류 해결을 안내한다. 스토리·지도·용어 정의 전체를 중복 작성하지 않는다. |

**학습 왕복 경로:** 미션 스토리 장면 → 해당 개념지도 노드·관계 → 상세 용어사전·분야 기술지도 → 원래 미션 맥락 복귀. 링크나 화면이 아직 구현되지 않았다면 명시적으로 **미구현**으로 기록하고 작동하는 것처럼 표시하지 않는다.

## 4. 전체 학습 운영 흐름

| 단계 | 주도 | 목적·행동 | 완료 신호 |
| --- | --- | --- | --- |
| **0. 준비** | 강사 | 미션 요구·시간·사전지식·도달 목표 파악 | 범위와 핵심 질문 확정 |
| **1. 필수 대면 강의** | 강사+학습자 | 필수 개념, 스토리 설명, 개념지도 시연, 도구 사용법, 짧은 이해 확인 | 스스로 미션을 시작할 준비 |
| **2. 안내된 첫 실습** | 강사→학습자 | 대표 작업 시연 후 따라 하기, 실행 결과 확인 | 개념과 실제 실행 연결 |
| **3. 자기주도 미션 수행** | 학습자 | 직접 구현·오류 해결, 필요 시 지도·사전·가이드 재탐색, 도움 요청 | 결과물·검증 근거 |
| **4. 지식 확장** | 학습자 | 지도 관계 재검토, 정확한 정의 학습, 관련 기술·분야로 확장 | 미션 밖 관계 이해 |
| **5. 이해·완료 확인** | 학습자+강사/평가자 | 공식 미션 요구 충족과 핵심 기술 역할·차이·오류 원인 설명을 각각 확인 | 미션 결과와 보완 지식 구분 |

실습 중에는 이전 단계로 자유롭게 왕복한다. 위의 대면 강의 필수 원칙은 **우리 교육 운영 모델**에 적용하며, 외부 기관의 미션 통과 요건과 혼동하지 않는다.

## 5. 학습 UI·시각자료 설계 원칙

1. **각 Scene에 하나의 명확한 학습 질문과 기대 이해를 둔다.**
2. **흐름과 관계를 구별한다.** 요청·응답 순서와 포함·역할·선행·대응·연관은 동일하지 않다. 설정·규칙을 물리적 경유 장치처럼 묘사하지 않는다.
3. **선택적으로 밀도 높게 보여준다.** 미션과 직접 연결된 관계는 충분히 다루되 처음에는 핵심만 강조한다. 보충 개념은 필요할 때 탐색하도록 한다.
4. **공간적 일관성을 유지한다.** 노드 선택만으로 핵심 노드가 이리저리 움직이지 않게 하고, 가독성 있는 관계선 통로와 충분한 캔버스 높이를 확보한다.
5. **색·명암은 정보 구분을 위한 도구다.** 선택·연결·비관련 노드의 대비를 명료하게 하고, 전체 화면이 과도하게 어둡거나 복잡해지지 않게 한다. 색만으로 의미를 구분하지 않는다.
6. **대면 강의와 자율 탐색을 함께 지원한다.** 강의 중에는 핵심 관계를 순서대로 강조하고, 강의 후에는 사용자가 자유롭게 탐색한다. 동일한 승인 콘텐츠를 재사용한다.
7. **정확한 지식으로 확장하고 복귀한다.** 개념지도 설명에서 정의와 미션 장면으로 연결하며, 일반망 비유와 실제 구현 범위를 구분한다.
8. **강의실 PC·노트북과 모바일 모두에서 확인한다.** 확대·이동·관계 강조·패널·키보드·작은 화면의 시각 QA를 수행한다.

## 6. 역할과 제작·검토 책임

- **Owner:** 교육 목표·필수 대면 강의 정책·학습 범위 및 게시 승인.
- **GPT / 기획·독립 검토:** 미션별 학습 질문, 강의 흐름·인지부하, 사실 및 관계 검토.
- **Claude Code / 콘텐츠:** 미션 스토리·개념 관계·시각자료·강사 노트 작성 및 출처 확인.
- **Codex / 웹 통합:** 승인된 자료의 상호작용·진입·복귀·반응형·시각 QA.
- **학습자:** 안내받은 후 스스로 미션을 수행하고, 필요한 개념을 탐색하고, 자신의 말로 설명한다.

기존 [거버넌스 계약](../knowledge-encyclopedia/06-agent-governance-model.md)의 상설 역할·Owner Gate·출처/검증 및 Git·Notion 운영 원칙을 변경하지 않는다.

## 7. 신규 미션 스토리 제작 전·후 필수 점검

**기획 착수 전**
- [ ] 공식 미션 목표·시간·실제 구현과 검증 조건을 확인했는가?
- [ ] 학습자 수준, 강의에서 다룰 핵심 질문·최소 선수개념·스토리 흐름을 정했는가?
- [ ] 대면 강의에서 보여줄 개념지도 노드·관계·시연 순서와 실습 출발점을 정했는가?
- [ ] 스토리(흐름), 미션 개념지도(밀도 있는 관계), 용어사전(확장), 학습가이드(실행)의 역할을 분리했는가?

**콘텐츠 독립 검토 시**
- [ ] 화면에 불필요한 선·용어·장식이 주의를 분산하지 않는가?
- [ ] 시각화의 흐름, 관계 유형, 기술적 사실 및 실제 구현과의 경계가 정확한가?
- [ ] 스토리 장면↔개념지도 관계↔용어사전 ID가 검증됐는가?
- [ ] 강사가 직접 설명·시연할 수 있고 학습자가 강의 후 혼자 탐색할 수 있는가?

**웹 통합·공개 승인 전**
- [ ] 스토리→지도→용어 및 학습 맥락 복귀가 실제 동작하는가? 미구현 경로는 명시했는가?
- [ ] 강의 화면과 PC·360/390px 모바일에서 글자·관계·선택·패널·대비를 실제 확인했는가?
- [ ] 학습자가 실습 결과와 핵심 기술의 역할을 스스로 설명할 기회가 있는가?
- [ ] 미션별 승인 커밋과 공식 규정·운영 선택의 구분을 검토했는가?

점검 결과는 기존 미션 상태 기록·QA·handover 중 적절한 한 곳에 **PASS / 수정 필요 / 미검증**으로 기록한다. 새 보고서나 중복 데이터 저장소를 기본으로 추가하지 않는다.

## 8. 효과 검증과 연구 근거

효과적인 디자인의 *가능성*을 뒷받침하는 연구는 있지만, **우리 서비스가 학습시간을 단축했다거나 대면 강의가 반드시 더 좋다는 성과는 아직 검증되지 않았다.** 집중력 100→70 같은 가공 수치는 사용하지 않는다.

학습 효과는 강의 전후 관계 설명, 실습 진입 시간, 미션 결과 검증, 어려운 개념을 자료에서 스스로 찾는지, 일정 기간 후 기억 유지 등을 시범 수업에서 확인한다.

참고 연구:
- Mayer & Moreno (2003), *Nine Ways to Reduce Cognitive Load in Multimedia Learning*. https://doi.org/10.1207/S15326985EP3801_6
- Kirschner, Sweller & Clark (2006), *Why Minimal Guidance During Instruction Does Not Work*. https://doi.org/10.1207/s15326985ep4102_1
- Schroeder et al. (2018), *Studying and Constructing Concept Maps: A Meta-Analysis*. https://doi.org/10.1007/s10648-017-9403-9

## 9. 기준 문서와 변경 관리

이 문서는 **미션 스토리 제작의 학습 정책 기준**이며, 작업자는 시작·콘텐츠 검토·웹 통합 단계에서 재확인한다. 세부 제작 단계는 [`workflow.md`](workflow.md), 실행 주의사항은 저장소의 `AGENTS.md`를 따른다.

Notion은 교육 정책 마일스톤을 사람 중심으로 정리·동기화하는 장소이며, Git에는 제작 AI가 읽을 실행 기준을 남긴다. 정책 변경 시 Owner 승인 버전과 차이를 확인하고 필요할 때 동기화한다.

> **핵심 선언:** 하나의 흐름에서 시작해, 관계를 이해하고, 실습으로 적용하며, 더 넓은 지식으로 확장한다.
