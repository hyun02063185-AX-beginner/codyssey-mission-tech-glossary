# 미션 학습 가이드 작업 절차

> 적용 범위: 코디세이 미션의 별도 장별 학습 가이드. 기존 [거버넌스 계약](../knowledge-encyclopedia/06-agent-governance-model.md)의 Orchestrator·Knowledge Architect·Review Profile·Quality Harness·Owner Gate를 대체하지 않는다. 아래의 GPT·Claude Code·Codex는 제작 단계의 담당 도구다.

새 미션을 시작하거나 다른 채팅에서 이어받으면 `AGENTS.md`, 이 문서, 해당 미션의 상태 기록, 기존 시나리오·QA·Git 이력을 순서대로 확인한다. 대화의 기억만으로 단계가 끝났다고 판단하지 않는다. 각 단계의 담당자·대상 커밋·근거·미검증 항목을 상태 기록에 남긴다.

**독자 기준 (Owner 확정, 2026-10-20): 모든 미션별 학습가이드는 기술 기반이 거의 없는 완전 입문자 L0를 대상으로 한다.** 미션 탐색 메뉴의 L1~L2 기준을 가이드에 적용하지 않는다. 처음 만나는 용어와 작업의 이유를 풀어 설명하며, 기존 제작·공개 가이드도 사용자 피드백에 따라 L0에 맞게 보완할 수 있다. 수정 근거와 대상 버전을 남기고 아래의 검토·승인·공개 절차를 따른다. 상세 정책은 [Notion 운영 정책](https://app.notion.com/p/3ff62d4e038081eba245ca77a511aa52)에서 관리한다.

| 순서 | 담당과 책임 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 1. 범위·시나리오 | GPT가 대상 교육생, 미션의 학습 목표, 원본 자료, 장별 흐름, 사례와 일반 개념의 경계를 정리한다. Owner가 방향을 검토한다. | 승인된 기준 문서 또는 검토 가능한 작업 지시와 출처가 남아 있다. |
| 2. 콘텐츠 제작 | Claude Code가 미션 원본·기존 학습 기록·기준 문서를 확인하고 원고, 그림, 강사 노트를 작성하거나 기존 초안을 책임지고 수정한다. 콘텐츠와 웹 코드를 분리한다. 로컬 커밋과 인수인계까지만 수행한다. | 원고·그림·출처·자체 QA와 커밋 ID가 있다. Push는 Owner가 수행한다. |
| 3. 독립 콘텐츠 검토 | GPT가 Claude Code의 결과를 원본 자료와 대조하여 교육적 흐름, 기술적 사실, 그림, 링크, 모바일 가독성, 일반화 위험을 독립 검토한다. PASS·수정 필요·미검증을 구분한다. | 지적 사항을 콘텐츠 담당이 반영하고 GPT가 차이를 확인한다. Owner가 게시할 원고 커밋을 승인한다. |
| 4. 웹 통합 | Codex가 승인된 원고 커밋을 기준으로 미션 진입점·라우트·렌더링을 연결한다. 공개 route 계약 변경은 Owner Gate를 거친다. 빌드, 브라우저 동선, 모바일·시각 QA와 기존 가이드 회귀를 확인한다. | 승인 커밋과 실제 통합 커밋의 차이, 테스트 결과, 미검증 항목이 기록된다. |
| 5. PR·공개 | Codex가 검토 가능한 PR을 준비한다. Owner가 PR을 검토·병합한다. 병합 후 Pages 공개 주소에서 진입과 핵심 그림·링크를 확인한다. | 공개 화면 검증과 남은 위험을 보고한다. |

앞 단계가 빠진 상태에서 만든 코드·원고·QA는 **참고 초안**으로 보존할 수 있지만 후속 단계의 승인 근거로 소급하지 않는다. 중복 작성을 목적으로 처음부터 다시 만들지는 않는다. 담당자가 원본에서 독립적으로 판단하고 필요한 부분만 수정하며, 검토 결과를 기록한다. 미션 원본이나 현재 서비스 상태를 확인할 수 없으면 미검증으로 남긴다.

Owner 승인 후 내용 또는 웹 코드가 달라졌다면 승인 커밋과 최종 소스를 비교하고 영향 범위만 다시 검증한다. GitHub Actions 빌드 성공을 브라우저·시각 QA의 대용으로 쓰지 않는다. 역할이나 순서를 바꾸려면 먼저 Owner에게 이유와 변경 범위를 보고한다.
