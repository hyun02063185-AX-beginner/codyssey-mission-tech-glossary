# 08. Content Quality 기준

Content Integrity Recovery Cycle 은 **틀린 내용**(회차를 잘못 인용한 문장)을 없앴다.
남은 문제는 틀리지 않았지만 **아무것도 가르치지 않는 문장**이다. 이 문서는 그 둘을
구분하는 기준을 적는다.

- 적용 범위: `content/terms/*.md` 518개
- 기준 확정일: 2026-09-22 / 기준 커밋: `d777bc7`
- 앞 문서: [07. Foundation Decisions](07-foundation-decisions.md)

---

## 1. 두 가지 시험

### Swap Test — 이름을 바꿔도 말이 되는가

> 문장에서 용어 이름만 다른 용어로 바꿨을 때 그대로 말이 되면 **FAIL** 이다.

```
FAIL  `Accessibility / a11y`의 역할을 실제 화면과 요청 흐름에서 분리해 생각하면 됩니다.
      → `CORS`, `쿠키`, `라우팅` 무엇을 넣어도 똑같이 말이 된다. 42개 용어가 이 문장을 썼다.

PASS  화면을 눈으로 보지 않고 쓰는 사람에게는 버튼의 생김새가 아니라 이름이 전부입니다.
      → 다른 용어를 넣으면 말이 되지 않는다.
```

Swap Test 는 문장이 **틀렸는지**를 묻지 않는다. 그 용어에 대해 **무엇이라도 말하는지**를
묻는다. 사실이면서 아무 내용이 없는 문장이 지금 가장 많은 결함이다.

### Content Value Test — 읽고 나서 무엇을 아는가

각 절은 아래 질문 중 자기 몫에 답해야 한다. 답하지 못하면 그 절은 비어 있는 것이다.

| 절 | 답해야 하는 질문 |
|---|---|
| 한 줄 설명 | 이것은 무엇인가 |
| 쉽게 설명하면 | 이미 아는 것에 비유하면 무엇인가 |
| 정확한 설명 | 기술적으로 정확히 무엇인가 |
| 이 미션에서는 왜 필요한가 | 이것을 모르면 무엇을 못 하는가 |
| 코드 예 | 실제로 어떻게 생겼는가 |
| 주의할 점 / 경계 조건 | 언제 깨지는가 |
| 흔한 오해 | 사람들이 무엇을 잘못 아는가 |
| 동료평가 질문 | 이해했는지 어떻게 확인하는가 |

## 2. 절별 기준

### 이 미션에서는 왜 필요한가

이 용어를 **모르면 막히는 지점**을 적는다. 회차를 인용할 때는 실제로 매핑된 회차만
쓴다(`content_generation_guard.py` 가 강제한다). 회차 번호를 적는 것 자체가 목적이
아니다. 회차를 말하면서 아무 내용이 없는 문장도 FAIL 이다.

```
FAIL  M11과 M12에서 model, SQL, persistence 코드를 구현할 때 data 구조와 변경 결과를
      정확히 설명하는 기준입니다.            ← 회차는 맞지만 29개 용어가 공유했다
PASS  M11에서 같은 조건을 두 번 조회했는데 결과가 다르면, 두 조회 사이에 다른 트랜잭션이
      끼어든 것입니다. 격리 수준을 모르면 이 현상을 버그로 착각합니다.
```

### 쉽게 설명하면

**비유이거나 구체적 상황**이어야 한다. "…의 관점에서 확인하면 됩니다" 같은 지시문은
설명이 아니다. 정확한 설명을 쉬운 말로 바꾼 것이지, 정확한 설명을 가리키는 안내문이
아니다.

### 코드 예

- **용어 이름만 적힌 코드 블록은 코드 예가 아니다.** 지금 222개가 그렇다.
- 실행 맥락이 보여야 한다. 모든 시스템 용어에 `ps aux` 를 붙이는 식은 금지다.
- **코드가 필요 없는 용어에는 코드를 넣지 않는다.** `가용성`, `기술 부채` 같은 개념에
  억지 코드를 붙이면 없는 것보다 나쁘다. 이때는 표·비교·절차 같은 `text` 블록이
  더 정직하며, 그것도 어색하면 절 자체를 두지 않는다.

### 흔한 오해 · 동료평가 질문 · 주의할 점

한 분야 전체가 같은 문장을 쓰면 FAIL 이다. "보안 기능 하나를 추가했다고 모든 위협이
사라지는 것은 아닙니다"는 보안 용어 22개에 붙어 있었다. 맞는 말이지만 `CSRF` 와
`해시`와 `TLS` 에 대해 아무것도 말해 주지 않는다.

## 3. 미션 밖에서도 읽히는가

Glossary 는 부트캠프 교재가 아니라 사전이다.

- 모든 용어에 "이 미션에서는…"을 억지로 붙이지 않는다. 여러 회차에 걸치거나 어느
  회차에도 직접 안 걸리는 용어는 **왜 이 개념이 있는가**를 적는 편이 낫다.
- 반대로 회차가 분명한 실습 용어는 회차를 적는 편이 학습자에게 도움이 된다.
- 판단 기준은 "이 용어를 처음 만난 사람이 미션 문서 없이 읽어도 이해되는가"이다.

## 4. 기계 검사의 자리

| 도구 | 보는 것 | 결과 등급 |
|---|---|---|
| `npm run content:integrity` | 매핑되지 않은 회차 인용 | **ERROR** — 사실 오류다 |
| `scripts/audit_term_specificity.py` | 이름을 가려도 남는 공유 문장 틀 | **후보 목록** — 판정이 아니다 |

용어 이름을 `<T>` 로 가린 뒤 같은 문장이 둘 이상의 용어에서 나오면 공유 틀로 센다.
이것은 Swap Test 의 근사치일 뿐이다.

- **공유 틀이 아니어도 FAIL 일 수 있다.** `쉽게 설명하면` 518개는 전부 고유 문장이지만
  253개는 이름만 끼워 넣은 틀이었다. 고유함은 구체성이 아니다.
- **공유 틀이어도 PASS 일 수 있다.** 짧은 정의성 문장은 겹칠 수 있다.
- 그러므로 **고유 본문 개수를 품질 목표로 쓰지 않는다.** 숫자를 올리려고 문장을 바꾸는
  순간 이 기준은 무의미해진다.

## 5. 하지 않는 것

- 새 bulk regeneration script 를 만들지 않는다. R12 가 그렇게 생겼다.
- 같은 틀을 쓴다는 이유만으로 내용을 확인하지 않고 고치지 않는다.
- 애매한 문서를 숫자를 맞추려고 OK 로 넘기지 않는다. `NEEDS_MANUAL_REVIEW` 로 남긴다.
