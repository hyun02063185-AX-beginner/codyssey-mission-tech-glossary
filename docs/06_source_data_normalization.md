# 06. 원천 데이터 정규화 기준

## 1. 목적

AI 또는 수작업으로 추출한 용어 목록을 바로 사전에 게시하지 않는다.

`raw → normalized → reviewed → published`

단계를 거친다.

---

## 2. 원천 데이터 보존

원천 파일은 수정하지 않고 `data/raw/`에 보존한다.

정제된 결과는 `data/curated/`에 별도로 만든다.

이를 통해 다음을 추적할 수 있다.

- 어떤 미션에서 추출했는가
- AI가 어떤 표현으로 처음 추출했는가
- 이후 어떤 표준명으로 변경했는가
- 실제 등장인지 연관 개념인지

---

## 3. 필수 정규화 항목

### 중복

예:

- persistence / 영속성
- Git repository / 저장소

하나의 표준 용어로 합친다.

### 모호한 이름

예:

- `token` → Authentication Token 또는 AI Token
- `image` → Docker Image 등
- `filter` → NPU/Convolution Filter 등

### 유형

파일처럼 보이는 모든 항목을 `파일형식`으로 분류하지 않는다.

### 출처 상태

- direct
- required
- related

세 종류로 명확하게 구분한다.

---

## 4. 숫자 집계

용어 수는 문서에 수동으로 적은 합계보다
정규화된 데이터에서 자동 집계하는 것을 원칙으로 한다.

다음 수치를 별도로 계산한다.

- 실제 직접 등장 용어 수
- 요구사항상 필수 용어 수
- 연관 개념 수
- 중복 제거 후 표준 용어 수
- 분야별 용어 수
- 미션별 용어 수

---

## 5. 예비과정 원천 데이터 등록 시 체크 포인트

예비과정 M01~M03 원천 데이터를 등록한 뒤,
정규화 전에 다음을 확인해야 한다.

1. M02에는 원문 직접 등장 여부가 불확실한 항목이 일부 존재한다.
2. 실제 등장 용어와 요구사항상 필수 용어를 더 명확하게 구분할 필요가 있다.
3. 전체 중복 제거 용어 수와 분야별 합계는 데이터화 후 다시 자동 계산한다.
4. `토큰`, `이미지`, `필터`처럼 다른 분야와 이름이 충돌할 수 있는 용어는 표준명을 조정한다.
5. `README.md`, `Dockerfile`, `main.py`, `JSON` 등의 유형을 세분화한다.

---

## 6. AI 추출 프롬프트 원칙

새 미션에서 용어를 추출할 때는 다음 정보를 반드시 남긴다.

- 과정
- 미션 번호
- 용어 원문
- 표준명 후보
- 분야
- 유형
- 중요도
- 출처 상태
- 미션 내 맥락
- 연관 개념
- 웹툰 후보
- 확인 필요 사항

설명 본문 완성보다 **원천 출처와 맥락 보존**을 우선한다.
