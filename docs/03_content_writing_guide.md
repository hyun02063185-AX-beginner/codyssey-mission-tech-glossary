# 03. 용어 콘텐츠 작성 가이드

## 1. 용어 하나의 기본 구성

### 표준명

사전에서 사용할 대표 이름.

### 한 줄 설명

처음 보는 사람이 10초 안에 핵심을 이해할 수 있는 설명.

### 쉽게 설명하면

일상적 비유 또는 상황을 활용하되,
비유와 실제 기술 개념의 경계를 분명히 한다.

### 정확한 설명

기술적으로 틀리지 않도록 정리한 본 설명.

### 이 미션에서 왜 필요한가

일반적인 기술 설명보다 우선순위가 높은 항목이다.

### 예시

필요한 경우 명령어, 코드, 입력·출력, 상황 예시를 제공한다.

### 관련 용어

선행 개념, 비교 개념, 확장 개념을 연결한다.

### 흔한 오해

초보 학습자가 자주 혼동하는 부분을 짧게 적는다.

### 동료평가 질문

단순 암기보다 이해 여부를 확인할 수 있는 질문을 사용한다.

---

## 2. 설명 깊이 예시

### Port

**한 줄 설명**

한 컴퓨터 안에서 어떤 프로그램과 통신할지를 구분하는 번호.

**쉽게 설명하면**

IP 주소를 건물 주소에 비유한다면 Port는 어느 호실로 갈지를 구분하는 번호와 비슷하다.

**정확한 설명**

네트워크 통신에서 IP 주소가 호스트를 식별한다면,
Port 번호는 해당 호스트 안에서 통신할 애플리케이션 또는 서비스를 구분하는 데 사용된다.

**동료평가 질문**

> IP 주소가 있는데 Port 번호가 또 필요한 이유는 무엇인가?

---

## 3. 피해야 할 설명

### 순환 설명

잘못된 예:

> Container는 컨테이너 기술을 사용하는 실행 단위다.

### 정의 속에 더 어려운 용어를 과도하게 사용

설명에 새로운 전문용어가 필요하다면 관련 용어 링크로 분리한다.

### 비유를 실제 정의처럼 표현

비유에는 가능하면 "비슷하다", "비유하면" 등의 표현을 사용한다.

### 미션과 무관한 지나친 확장

사전의 기본 목적은 현재 미션을 이해하는 것이다.
깊은 내용은 `더 깊게 보기`로 분리한다.

---

## 4. 명령어 항목 작성 원칙

명령어는 다음을 구분한다.

- 명령어가 무엇을 하는가
- 주요 옵션은 무엇인가
- 미션에서는 왜 사용하는가
- 실행 결과에서 무엇을 확인해야 하는가

명령어 전체 매뉴얼을 복제하지 않는다.

---

## 5. 동료평가 질문 작성 원칙

좋은 질문:

- 차이를 설명하게 한다.
- 왜 필요한지 설명하게 한다.
- 결과를 예측하게 한다.
- 잘못된 상황의 원인을 생각하게 한다.

예:

> `docker attach`와 `docker exec`는 어떤 점이 다른가?

나쁜 질문:

> Docker의 정의를 외워서 말해보세요.

---

## 6. 검수 체크리스트

- [ ] 비유가 실제 개념을 왜곡하지 않는가?
- [ ] 미션에서 왜 필요한지가 적혀 있는가?
- [ ] 새로운 전문용어가 무분별하게 늘어나지 않았는가?
- [ ] 관련 용어가 적절히 연결되어 있는가?
- [ ] 핵심 용어라면 동료평가 질문이 있는가?
