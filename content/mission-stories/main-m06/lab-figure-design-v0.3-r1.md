### 1-2. 실습 메모 표시 (신규 공통 규칙)

`실습 메모: AI가 작성한 초안은 사람이 검토한다.`가 나타나는 **모든** 그림·도식(F3, F6 발췌, F8 두 출력, 도식 01·03)에서 그 줄을 같은 방식으로 표시합니다.

- 글자 아래 주황(`--presentation-accent`) 밑줄 3px
- 줄 오른쪽 또는 위에 작은 이름표 **“실습 메모”** (주황 글자, 19px 데스크톱 / 16px 모바일)
- 생성기: 이름표 요소에 `data-topic="practice-memo"`를 붙여 테스트가 그림마다 찾을 수 있게 함

### F3 · S1-2 — README.md 변경 diff 적용

`F3_ROWS` · `F3_NOTES` 교체안 (행 수 14로 같아 기존 배치를 그대로 씁니다):

| # | 글자 | 종류 |
| --- | --- | --- |
| 0 | `$ git status --short` | cmd |
| 1 | ` M README.md` | out |
| 2 | `$ git diff` | cmd |
| 3 | `diff --git a/README.md b/README.md` | out |
| 4 | `··· index · --- · +++ 3줄 생략 ···` | cut |
| 5 | `@@ -76,3 +76,5 @@ python -m unittest …` | hunk |
| 6 | 공백 + 백틱 세 개 (README의 코드 블록을 닫는 줄) | ctx |
| 7 | 공백 하나 (빈 주변 줄) | ctx |
| 8 | `` macOS에서는 `python3`를 사용하세요. … `` (앞 공백 포함) | ctx |
| 9 | `+` | add |
| 10 | `+실습 메모: AI가 작성한 초안은 사람이 검토한다.` | add + **실습 메모 표시** |
| 11 | `(파일 끝 · 뒤쪽 주변 줄 없음)` | cut |
| 12 | `$ git diff --cached` | cmd |
| 13 | `(출력 없음)` | cut |

| 가리키는 줄 | 표식 | 설명 두 줄 |
| --- | --- | --- |
| 1 | M | 고친 파일 / 아직 git add 전 · 오른쪽 칸 |
| 5 | @@ | 위치 표시 / 76번째 줄부터 · 3줄 → 5줄 |
| 7 | 빈칸 | 그대로인 주변 줄 / 앞 3줄 · 파일 끝이라 뒤는 없음 |
| 9 | + | 새로 생긴 줄 / 이번 변경은 2줄 (빈 줄 먼저) |
| — | - | 지워진 줄 / 이번 변경에는 없다 |
| 13 | --cached | git add한 변경 / 이번에는 없다 · 전후 비교는 Lab 03 |

- v0.1 그림과 달리 `+` 줄 순서가 **빈 줄 → 메모**입니다(`printf '\n…\n'`). 위치 설명도 “26번째 줄 근처 · 6줄 → 8줄”에서 바뀝니다.
- 근거 띠: “재현 · 연습 저장소 2026-11-25 · Owner 실행과 같은 변경” (+ “긴 줄은 …로 줄임”)
- 대체 설명 초안: “연습 저장소에서 다시 만든 터미널 화면(재현). git status --short는 ‘ M README.md’를 보여 준다. M은 고친 파일이고 아직 git add 전이라 오른쪽 칸에 있다. git diff의 @@ -76,3 +76,5 @@는 76번째 줄부터 3줄이 5줄이 되었다는 위치 표시다. 앞이 빈칸인 세 줄은 그대로인 주변 줄이고, +로 시작하는 두 줄(빈 줄, ‘실습 메모: AI가 작성한 초안은 사람이 검토한다.’)이 새로 생긴 줄이다. 메모 뒤에 줄이 없어 파일 끝에 추가된 것을 알 수 있다. git diff --cached는 이번에는 출력이 없다.”
- 모바일(360×860): 행 6–8(주변 줄 세 개, 긴 줄은 `macOS에서는 … 않습니다.`로 줄임)은 그대로 두고 메모 줄은 `+실습 메모: AI가 작성한` / `  초안은 사람이 검토한다.` 두 줄 + “↑ 실제로는 한 줄”.
