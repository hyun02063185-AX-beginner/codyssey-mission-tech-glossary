## 인트로와 강의 구성

**초안 안내** 이 미션의 B3-2 프로그램(`main.py`)은 내 Git 변경 내용을 외부 AI API에 보내, 사람이 검토할 커밋 메시지나 PR 설명의 **초안**을 터미널에 출력합니다. 프로그램은 커밋, push, PR 등록을 하지 않습니다.

**학습 목표**

1. REST API 요청을 구성하고, 응답에서 결과를 꺼내며, 네트워크·인증·응답 오류에 대응하는 방법을 설명한다.
2. `model`·`temperature`·`max_tokens` 같은 파라미터가 요청과 결과 품질에 어떤 영향을 주는지 설명한다.
3. Git 명령의 실행 결과가 Python 프로그램의 입력이 되는 자동화 흐름을 설명한다.
4. 커밋·PR 양식과 변경 맥락을 반영해 프롬프트를 구성하는 방법을 설명한다.
5. 결과 글의 길이·양식·표현 제한을 프로그램이 검증하고 다듬는 방법과, 사람이 마지막에 판단하는 이유를 설명한다.

**학습 안내** 각 화면의 **P** 또는 **설명 보기**로 해설을 엽니다. 해설을 순서대로 읽으면 핵심 질문의 답이 하나의 이야기로 이어집니다. 화면 안의 **함께 실습**은 연습 저장소에서 바로 따라 할 수 있는 짧은 실습이고, 자세한 안전장치·추가 탐구·문제 해결은 **상세 참고 · Lab**에 있습니다. Lab을 모두 하지 않아도 스토리만으로 전체 흐름을 이해할 수 있게 구성했습니다. 명령줄에서 프로그램을 실행해 본 경험과 Python의 딕셔너리·리스트를 안다고 가정합니다.

**도식 표**

| Git 명령 | Git이 알려 주는 것 | Git 문맥의 칸 |
| --- | --- | --- |
| `git branch --show-current` | 현재 브랜치 | `Branch:` |

**화면 해설**

Python이 Git에게 묻는 정보는 브랜치, 상태, 파일 이름 목록, 그리고 두 가지 diff입니다. 사용자는 변경을 전부 add했을 수도, 하나도 하지 않았을 수도, 일부만 했을 수도 있으므로 diff를 하나만 읽으면 다른 쪽의 변경을 놓칩니다. 그래서 프로그램은 `git diff --cached`와 `git diff`를 모두 실행해 `Staged diff:`와 `Unstaged diff:` 두 칸에 나눠 담습니다. 새로 만들어 아직 Git이 추적하지 않는 파일은 이름만 담고 내용은 보내지 않는데, `git diff`가 원래 추적하지 않는 파일의 내용을 보여 주지 않기 때문입니다. 이 표의 정보가 Git이 Python에게 주는 전부이며, Git의 일은 여기까지입니다. 이제 Python이 이 명령들을 어떻게 실행하는지 봅니다.

**화면 해설**

프로그램 파일이 실행되어 메모리에서 동작하고 있는 것을 **프로세스**라고 합니다. `python3 main.py`를 실행하면 Python 프로세스가 하나 생기고, 이 프로세스는 Git의 일을 직접 하지 못하므로 Git 프로그램을 따로 실행해야 합니다. 프로세스를 만들고 실행하는 일은 **운영체제**가 맡습니다. `subprocess.run()`은 운영체제에 “`git status --short`를 새 프로세스로 실행해 달라”고 요청하고, Git 프로세스가 끝날 때까지 기다립니다. **화면 해설**

`model`은 어떤 AI 모델에게 글을 맡길지 정하는 값으로, 이 프로그램에는 고정된 기본값이 없어 `--model`이나 환경변수 `CODYSSEY_MODEL`로 반드시 정해야 합니다. `temperature`는 AI가 다음 단어를 고를 때 얼마나 다양하게 고를지를 정하는 값으로, 낮추면 같은 변경에 비슷한 글이 나오기 쉽고 높이면 표현이 다양해지는 대신 양식에서 벗어날 가능성도 커집니다. `max_tokens`는 AI가 만들 글의 길이 상한을 **토큰**(모델이 글을 나눠 처리하는 단위) 수로 정하는 값으로, 너무 작으면 초안이 중간에 끊겨 PR의 필수 섹션이 빠지는 등 검증에 실패할 수 있습니다. **이해 확인** 강의에서 `--max-tokens 20`으로 PR 초안을 만들면 어떤 일이 생길 수 있을까요? → *초안이 상한에서 끊겨 Why·What·How to Test 중 일부가 빠질 수 있고, 그러면 프로그램의 검증에 실패해 오류로 끝납니다. 이때도 요청은 이미 1회 보낸 것입니다(교육용 예상).*

**화면 해설**

전체 흐름을 네 주체의 역할로 다시 정리합니다. **사용자**는 명령으로 초안 종류를 고르고, API 키를 안전하게 설정하며, 마지막에 초안을 판단하고 커밋·push·PR 등록을 직접 합니다. **Git**은 작업 폴더·스테이징 영역·마지막 커밋의 차이를 알려 주기만 하고, 외부와 통신하지 않습니다. **Python**은 사용자 입력을 읽고, Git을 실행해 결과를 받고, 보낼 글을 만들어 검사하고, 요청을 보내고, 응답에서 초안을 꺼내 양식을 검사하고, 결과와 진행 정보를 두 통로로 나눠 알립니다. **외부 AI**는 받은 `system`과 `user`로 글을 쓸 뿐, 내 저장소를 직접 보거나 바꾸지 않습니다. 도식에서 주체를 하나씩 눌러 보며 각자 하지 않는 일까지 말해 보세요. 그것을 구별할 수 있으면 이 미션의 흐름을 다른 사람에게 설명할 준비가 된 것입니다.

**마무리 · 스스로 설명하기** 빈칸을 채워 전체 흐름을 말해 봅니다. “사용자가 `python3 main.py commit`을 실행하면 Python은 ( ① )로 입력을 읽고, ( ② )로 Git을 실행해 ( ③ )를 통해 결과를 받는다. 종료 코드로 성공을 확인한 뒤 Git 문맥을 만들어 ( ④ )하고, API 키는 ( ⑤ )에, 작성 규칙과 Git 문맥은 JSON 본문의 ( ⑥ )와 ( ⑦ )에 담아 HTTPS로 보낸다. 응답 JSON의 `choices[0].message.content`에서 초안을 꺼내 ( ⑧ )을 검사해 stdout에 출력하고, 내용이 맞는지는 ( ⑨ )이 확인한다.” → *① argparse ② subprocess ③ 파이프(stdout·stderr) ④ 민감정보를 검사 ⑤ Authorization 헤더 ⑥ system ⑦ user ⑧ 형식 ⑨ 사람*

| 공식 요구사항 | 실제 구현 (`be21c49`) | 구분 |
| --- | --- | --- |
| Git 프로젝트 루트에서 CLI 실행 | 작업 폴더 **안**인지만 확인. 하위 폴더에서도 실행되며 `Status:`는 현재 폴더 기준 경로(`../../README.md`), `Changed files:`는 루트 기준 경로로 섞임 | 차이 |
| model·temperature·max_tokens 옵션과 기본값 | 세 옵션 모두 있음. model은 고정 기본값 없이 환경변수 필요, temperature·max_tokens는 미지정 시 요청에서 생략 | 부분 |

| 실행 환경 Python 3.10 이상(README) | 2026-11-25 Owner는 Python 3.9.6에서 정상 실행 | 관찰 |

**화면 해설**

이 화면은 스토리 전체를 데이터의 눈으로 다시 봅니다. 사용자가 README.md에 쓴 메모 줄은 Git의 diff에서 `+`가 붙은 줄이 되고, 파이프를 지나 Python의 문자열 `result.stdout`이 되며, `GitChanges`를 거쳐 535자짜리 Git 문맥의 `Unstaged diff:` 칸에 들어갑니다. 이어서 딕셔너리의 `user` 메시지가 되고, JSON 글과 UTF-8 바이트로 바뀌어 HTTPS로 나간 뒤, 외부 AI가 그 줄을 읽고 쓴 초안이 응답 JSON의 `content`로 돌아옵니다. Python은 그 글을 검사해 stdout으로 내보내고, 사람은 그 글을 다시 diff의 메모 줄과 비교합니다. 아래 표는 이 흐름을 공식 요구사항과 비교한 결과입니다. 프로젝트 루트 검사, 커밋 본문 규칙, 재생성은 현재 구현과 차이가 있고, 공급자의 파라미터 지원은 확인되지 않았습니다. 이 스토리는 실제 구현을 기준으로 설명하고 차이를 숨기지 않으며, B3-2 프로그램 자체는 이번 작업에서 고치지 않습니다.

**용어** git-diff, python-subprocess, json-request-response, output-validation

**이해 확인** 메모 줄이 내 컴퓨터 밖으로 처음 나가는 것은 어느 단계인가요? → *Python이 JSON 글을 UTF-8 바이트로 바꿔 HTTPS 요청으로 보낼 때입니다. 그 전의 diff·문자열·Git 문맥·딕셔너리 단계는 모두 내 컴퓨터 안에 있습니다.*
