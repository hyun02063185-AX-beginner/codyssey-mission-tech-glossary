## 1. 이번 개정의 목적

v0.3은 9개 Lab과 스토리 연결을 만들었지만, 두 가지가 학습 과정에서 실제로 작동하기 어려웠습니다.

| v0.3의 문제 | 학습에 미치는 영향 | r1의 조치 |
| --- | --- | --- |
| 9개 Lab 약 140분을 같은 무게로 제시 | 학습자가 “전부 해야 한다”고 느끼고, 미션 흐름을 잡기 전에 세부 실험에서 지침 | 각 Lab을 **A 핵심 실습 / B 추가 탐구 / C 문제 해결**로 나눔. 핵심만 약 75분(§3) |
| 슬라이드(2026-10-20 사례)와 Lab(2026-11-25 사례)의 데이터가 다름 | Lab에서 돌아온 학습자가 그림에서 다른 파일·다른 글자 수·다른 초안을 봄. “같은 데이터가 이동한다”가 화면 경계에서 끊김 | **B안 확정(Owner 지시)**: 모든 학습 콘텐츠를 11-25 README.md 사례로 통일하는 개정 명세 작성([매핑 r1 §1–§3](lab-story-mapping-v0.3-r1.md)) |
| Screen ↔ Lab 연결이 “이 화면을 다시 보세요” 수준 | 돌아와서 **무엇을** 다시 봐야 하는지 모름. 왕복이 일어나도 연결이 생기지 않음 | 연결마다 **왕복 카드**(출발 질문 → 실습 → 관찰 → 도식 → 복귀 화면 → 다시 볼 그림의 특정 부분 → 확인 질문)를 정의([매핑 r1 §4](lab-story-mapping-v0.3-r1.md#4-왕복-카드--screen--lab-학습-동선)) |

**이번 개정의 목표는 콘텐츠의 양이 아니라 실습과 설명 사이의 연결입니다.** 새 Lab이나 새 개념은 추가하지 않았습니다. v0.3에 있던 선택 실험은 B로, 분기 안내는 C로 옮겼고, 핵심 실습 본문은 줄였습니다.

## 2. 학습 순환 (v0.3 유지) 과 왕복 카드

```text
        ┌─────────────── ① 개념 이해 ───────────────┐
        │      (미션 스토리 화면 · P 해설 · 용어사전)      │
        ▼                                             │
  ⑥ 추가 실습                                   ⑤ 개념 재이해
  (B 추가 탐구 · 다음 Lab)                       (복귀 화면에서 지정된 그림 부분을 내 결과로 다시 읽기)
        │                                             ▲
        ▼                                             │
  ② 직접 실습 ──────▶ ③ 결과 관찰 ──────▶ ④ 결과 해설 · 도식화
  (A 핵심 실습 명령)   (관찰 목록)           (접힌 해설 · 도식 01–06)
```

어느 지점에서든 시작할 수 있고, 순서는 강제하지 않습니다(v0.3 그대로).

### 2-1. 왕복 카드 — 순환 한 바퀴의 최소 단위

v0.3은 순환의 단계를 정했지만, 한 바퀴가 **구체적으로 무엇과 무엇을 잇는지**는 학습자에게 맡겼습니다. r1은 주요 연결마다 아래 일곱 칸을 미리 정해 둡니다. 실습 가이드의 각 Lab “A 핵심 실습” 끝과 학습 화면의 복귀 안내가 이 카드를 그대로 씁니다.

| 칸 | 정하는 것 | 예 (S1-2 ↔ Lab 03) |
| --- | --- | --- |
| 출발 질문 | 화면에서 생긴 궁금증 | 왜 Python은 두 가지 diff를 모두 읽을까? |
| 실습 | 핵심 실습의 해당 단계 | Lab 03 A: `git add` 전후로 세 명령 비교 |
| 관찰 | 학습자가 자기 화면에서 볼 것 | 변경 내용은 같은데, 어느 명령 아래에 나오는지가 바뀐다 |
| 도식 | 결과를 정리하는 그림 | 도식 01 Git 변경 영역 비교 |
| 복귀 화면 | 돌아갈 스토리 화면 | S1-2 (이어서 S3-1) |
| 다시 볼 그림 부분 | 복귀 화면 그림의 **특정 요소** | F3의 ` M`(오른쪽 칸)과 “`--cached` 이번에는 없다” · F6의 “git add 전후 변경을 함께 읽음” |
| 확인 질문 | 자기 말로 답할 질문 | 프로그램은 왜 두 diff를 모두 수집하나요? 내 결과의 어느 줄이 근거인가요? |

“다시 볼 그림 부분”이 이번 개정의 핵심입니다. 복귀한 학습자가 그림 전체를 다시 읽는 대신, **자기 결과와 짝이 되는 한 곳**을 찾아 맞춰 보게 합니다. 사례를 통일했기 때문에 이 맞춤이 글자 단위로 가능해졌습니다(예: 내 터미널의 ` M README.md` = F3·F5의 ` M README.md`).

전체 카드 11개는 [매핑 r1 §4](lab-story-mapping-v0.3-r1.md#4-왕복-카드--screen--lab-학습-동선)에 있습니다.

### 2-2. 같은 데이터와 여러 번 다시 만나기

순환이 반복될수록 이해가 깊어지려면 학습자가 **같은 데이터를 다른 자리에서** 다시 만나야 합니다. 사례 통일 후에는 실습 메모 한 줄이 아래 자리에서 모두 같은 글자로 나타납니다.

| 데이터 이동 단계 | 학습자가 직접 만드는 곳 (Lab) | 다시 만나는 그림 (화면) |
| --- | --- | --- |
| README.md 수정 | Lab 03 A ① | — |
| Git 변경 정보 (` M README.md`, `+실습 메모 …`) | Lab 03 A ② · Lab 04 A | F3 (S1-2) · F5 stdout 예 (S2-2) |
| Git 문맥 (535자) | Lab 05 A | F6 발췌·글자 수 (S3-1) |
| API 요청의 `user` 메시지 | Lab 06 A (`user 메시지 == Git 문맥: True`) | F7 요청 상자 (S3-2) · F8 공통 띠 (S4-1) |
| AI가 생성한 초안 | Lab 07 A ③ · Lab 08 A | F2 오른쪽 제목 (S1-1) · F8 두 출력 (S4-1) |
| Python의 검증과 출력 | Lab 08 A · Lab 09 A | F8 주황 고정 문구·`← stderr` (S4-1) · F1 return ① (S4-2) |
| 사람의 검토 | Lab 08 A “사람의 확인” 표 | F1 return ②③ (S4-2) · 마무리 빈칸 |

## 3. 학습 깊이 구분 — 핵심 실습 · 추가 탐구 · 문제 해결

### 3-1. 정의와 규칙

| 수준 | 무엇 | 규칙 |
| --- | --- | --- |
| **A. 핵심 실습** | 미션 전체 기술 흐름을 이해하는 데 필요한 최소 실습. 실행 명령 · 관찰 포인트 · 핵심 결과 · 연결 도식 · 관련 스토리 복귀(왕복 카드) | **A만 해도 §6의 확인 질문 Q1–Q9에 답할 재료가 모두 있어야 합니다.** A의 명령은 결과를 바꾸는 부작용이 없거나(읽기), 연습 저장소 확인 조건을 거친 뒤에만 바꿉니다. |
| **B. 추가 탐구** | A에서 더 궁금해진 것을 확인하는 선택 실험 | A의 관찰 목록이나 확인 질문에서 **파생된 질문 하나**에만 답합니다. 새 개념을 열지 않습니다. 끝나면 A의 끝 상태(대부분 상태 B)로 돌아가는 명령을 함께 줍니다. |
| **C. 문제 해결** | 결과가 예상과 다를 때 찾아보는 자료 | 재현을 요구하지 않습니다. 증상(내 화면에 보인 것) → 원인 → 할 일 순서의 표. 실제 사례는 Owner 기록으로 보여 줍니다(예: HTTP 400). |

웹에서는 A만 펼쳐 보이고, B·C는 접힌 상태로 둡니다([학습 화면 제안 r1](learning-ui-proposal-v0.3-r1.md)).

### 3-2. Lab별 배치와 예상 시간

시간은 교육장 PC에서 처음 해 보는 L0 학습자 기준의 **설계 추정**입니다(측정값 아님). 시범 수업에서 확인합니다.

| Lab | A 핵심 실습 | 핵심 | B 추가 탐구 | 추가 | C 문제 해결 | API(핵심) |
| --- | --- | --- | --- | --- | --- | --- |
| 01 실습 환경 | 연습 폴더 만들기·clone·버전·도움말 | 8분 | B3-2 자체 테스트 실행 | 5분 | Git·Python 없음, clone 실패, 문법 오류 | 0 |
| 02 변경 없음 | `commit` + `echo $?` | 4분 | 통로 하나씩 숨기기 · 순서가 바뀌어 보이는 경우 | 5분 | 이미 고친 상태, 저장소 밖, `$?` 순서 | 0 |
| 03 Git 변경 | 메모 추가 → add 전후 비교 → 스테이징 해제 | 15분 | 양쪽에 나뉜 변경(`MM`) | 10분 | 메모 중복, `??` 파일, 오래된 Git | 0 |
| 04 subprocess | 저장소 안·밖 실행 비교 | 8분 | 옵션 빼기 · 비어 있는 성공 | 7분 | heredoc 갇힘, 잘못된 폴더 | 0 |
| 05 Git 문맥 | 보낼 글 출력·글자 수 | 8분 | 가림 확인 · 새 파일이 섞이면 | 8분 | 모듈 없음, 글자 수 차이, 비밀 경로 중단 | 0 |
| 06 요청 JSON | 보내지 않고 요청 본문 만들기 | 8분 | 줄바꿈·따옴표 표현, `ensure_ascii` | 5분 | `False`, 한글 이스케이프 | 0 |
| 07 첫 요청 | 키 숨김 입력 → 상태 확인 → `commit` 1회 | 10분 | 최소 연결 테스트 (curl · **API 1회 추가**) | 10분 | 설정 부족, 401·403, **400(실제 사례)**, 네트워크, 사용량 제한 | 1 |
| 08 두 초안 | `pr` 1회 → 두 초안 비교 → 사람의 확인 | 10분 | 응답 JSON의 다른 필드 | 5분 | 형식 검사 실패, 변경 없음 | 1 |
| 09 출력 통로 | 출력 분리 실행(비용 없는 경로 기본) · 정리 | 5분 | 실제 초안으로 분리(**API 1회 추가**) | 3분 | `2>` 누락, 오류만 남음 | 0 |
| **합계** | | **약 75분** | | **약 60분** | 필요할 때만 | **2회** |

- **핵심 경로의 API 호출은 2회**(Lab 07 `commit` 1회, Lab 08 `pr` 1회)입니다. 추가 탐구 중 두 곳(Lab 07 최소 연결 테스트, Lab 09 실제 초안 분리)만 각각 1회를 더 씁니다. 문제 해결 자료는 같은 요청을 반복하지 않도록 안내합니다.
- 권장 운영(정책 §4의 “안내된 첫 실습”과 맞춤): **대면 강의 직후** Lab 01–03 핵심(약 30분, 키 없음) → **자기주도** Lab 04–06 핵심(약 25분, 키 없음) → **키 배부 후** Lab 07–09 핵심(약 25분). 추가 탐구는 각 학습자가 고릅니다.

## 4. 설계 원칙 — v0.3 유지 + r1 추가

| # | 원칙 | 적용 |
| --- | --- | --- |
| C1 (확대) | 하나의 사례를 끝까지 쓴다 | v0.3은 Lab 안에서만 같은 사례였습니다. r1은 **슬라이드 그림·P 해설까지** 11-25 사례로 맞추는 개정 명세를 둡니다. 10-20 기록은 삭제하지 않고 “이전 실행 사례”로 보존합니다. |

**섞지 않는 두 기록.** HTTP 200 응답은 “안녕하세요” 최소 요청의 응답이고, COMMIT·PR 초안은 다른 요청의 결과입니다. 어느 문서·그림에서도 두 기록을 한 상자에 넣거나 같은 요청의 결과처럼 잇지 않습니다. 응답 구조(`choices[0].message.content`)를 실제 기록으로 보여 줄 때는 최소 연결 테스트 응답만 쓰고, 초안 글은 그 옆에 별도 상자로 둡니다.

## 6. 학습 효과 검증 기준

v0.3의 확인 질문 Q1–Q9와 판단 수준 0–2([v0.3 §7](learning-cycle-design-v0.3.md#7-학습-효과-검증-기준))를 그대로 씁니다. r1은 **순환 구조가 실제로 작동했는지**를 보는 지표를 더합니다.

| # | 지표 | 확인 방법 (시범 수업) | 순환이 작동했다고 볼 모습 |
| --- | --- | --- | --- |
| L1 | 복귀 후 지목 | 왕복 카드의 복귀 화면을 띄우고 “내 결과와 짝이 되는 곳을 가리켜 보세요” | 지정된 그림 요소를 찾아 자기 터미널의 줄과 대응시킨다 (예: F6의 535자 ↔ 내 `전체 글자 수: 535`) |
| L2 | 핵심만으로 도달 | 추가 탐구를 하지 않은 학습자에게 Q1–Q9 중 3개 | 수준 2(자기 결과를 근거로 이유 설명) 도달. 못 미치면 §3-3 표에서 그 질문의 핵심 재료를 보강 |
| L3 | 자발적 복귀 | 막힌 순간 학습자의 이동을 관찰 | 복귀 링크·결과로 찾아보기·용어사전을 스스로 쓴다 |
| L4 | 새 상황 적용 | 실습에 없던 상황 (예: `MM`이면 Git 문맥 두 칸은? / `AI API 요청 횟수: 1`인데 `오류: … (HTTP 400).`이면?) | 실습 결과와 도식을 근거로 답한다 |
| L5 | 안전 행동 | 실습 정리 단계 수행 여부 (키 지우기 확인 문구, 터미널 닫기) | 안내 없이 핵심 실습의 정리 단계를 마친다 |
| L6 | 소요 시간 | 핵심 경로 실제 시간 | §3-2의 약 75분과 크게 다르면 핵심 범위를 다시 조정 |

이 기준은 설계 목표입니다. 순환형 구조의 학습 효과는 아직 검증되지 않았으며, 시범 수업 결과가 나오기 전까지 효과를 주장하지 않습니다([정책 §8](../../../docs/mission-guides/learning-operation-policy.md)).
