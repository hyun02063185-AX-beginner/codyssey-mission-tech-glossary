## F6 · 보낼 글을 정하고 보내기 전에 검사하기 (S3-1)

**목적** “무엇이 나가고, 무엇은 안 나가고, 나가기 전에 무엇을 하는가”만 남깁니다. v0.2는 6개 항목 + 3단계 검사 + 16,000자 + `--unsafe`를 한 화면에 담아 Scene 3의 절반이 보안 세부에 쓰였습니다. 또 결과 상자의 “검사를 통과한 것만”은 실제 처리와 다릅니다.

### 실제 처리 (`security.py` `prepare_context`, `be21c49`)

1. 기본 모드에서 변경 파일 이름이 비밀 파일 경로 패턴(`.env`, `id_rsa`, `*.pem` 등)과 맞으면 **전송 중단**.
2. 여섯 부분을 하나의 글로 묶음.
3. 기본 모드에서 불완전한 개인키 블록이 있으면 **전송 중단**.
4. 기본 모드에서 개인키 블록·이메일·Bearer 값·`api_key=` 형태 값·알려진 토큰 형식을 `[REDACTED …]`로 **바꿔 쓴 뒤 그 글을 그대로 보냄**.
5. 모든 모드에서 16,000자를 넘으면 **전송 중단**.

따라서 결과 상자에 담기는 것은 “검사를 통과한 항목만”이 아니라 **감지한 값을 가린 뒤 남은 글 전체**입니다. 중단된 경우에는 AI 요청을 만들기 전이므로 요청 횟수는 0회입니다.

### 새 구성 (세 덩어리 + 다음 화면 연결)

| 영역 | 내용 | 근거 표시 |
| --- | --- | --- |
| **A. 보낼 글에 담는 것** (왼쪽 위) | 네 줄로 묶음: 브랜치 · 상태와 바뀐 파일 이름 · 새 파일은 **이름만** · 바뀐 줄(diff, `git add` 전후 모두). 데스크톱은 오른쪽에 [demo-context.txt](assets/evidence/demo-context.txt) 앞부분 발췌(`Branch: main` / `Status:` ` M docs/…/02-python-ai-api.md` / … / `+실습 메모: AI가 생성한 …`) 4~5줄을 작은 고정폭 글씨로 둡니다. 모바일은 발췌를 생략합니다. | 재현 |
| **B. 넣지 않는 것** (왼쪽 아래, 회색) | 새 파일의 내용 · 바뀌지 않은 파일 · API 키 → “다음 화면에서 인증 헤더로 따로” | 구현 |
| **C. 보내기 전 검사 · 기본으로 켜짐** (가운데) | 두 갈래만: **가리고 계속** — 이메일·토큰처럼 보이는 값 → `[REDACTED]` / **전송 멈춤** — 비밀 파일로 보이는 경로 등 → AI 요청 0회. 갈래 아래 작은 글씨 한 줄: “글자 수 한도·검사 끄기 옵션 → 학습가이드 05” | 구현 |

| **→ 다음 화면 연결** (D 오른쪽 또는 아래 화살표) | “다음 화면: 요청의 `user` 메시지가 된다” | — |
| 상단 머리 | v0.2 “모으는 것 · 실제 순서 (재현)” → “내 컴퓨터 밖으로 나갈 글” | — |

## F7 · Python과 외부 AI API의 요청·응답 (S3-2, 강의의 기술적 중심)

**목적** 입문자가 “요청 = 주소 + 방식 + 인증 헤더 + JSON 본문”, “응답 = 상태 + JSON 본문 → 값 꺼내기”를 그림만 보고도 다시 말할 수 있게 합니다. v0.2에 없던 **주소, 응답 JSON의 모양, 상태(성공·401/403), Python 데이터 ↔ JSON 변환**을 더하고, “모델 실행 위치 미확인”을 뺍니다.

### 구성

```
┌ 내 컴퓨터 · Python ───────────────────┐        ┌┄ 외부 서비스 ┄┄┄┄┄┄┄┄┐
│ 요청 만들기                            │  ①요청 ┆                      ┆
│  ⓐ 주소  POST https://…/v1/chat/completions ──────▶  코디세이 AI API     ┆
│  ⓑ 인증 헤더  Authorization: Bearer •••• │ 딕셔너리→JSON 글  요청을 받아       ┆
│        └ 누가 보냈는지 증명 (환경변수의 API 키) │        ┆  JSON으로 응답       ┆
│  ⓒ JSON 본문  model · messages         │        ┆                      ┆
│        system = 작성 규칙               │        └┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┘
│        user   = 앞 화면의 Git 문맥       │  ②응답        │
│                                        │ ◀──────────────┘
│ 응답에서 초안 꺼내기                     │  성공 → JSON 글→딕셔너리
│  { "choices": [ { "message":           │  401·403 → 인증·권한 오류로 멈춤
│      { "content": "커밋 메시지 초안 …" } } ] }  ← 교육용 예시
│  choices[0].message.content → 초안 글 → 다음 장면의 형식 검사
└────────────────────────────────────────┘
요청 구조: 재현 · 모델 ID: 2026-10-20 실제 실행 설정 · 응답 JSON 모양과 상태 예시: 교육용 예시
```

### 요소별 설계

| 요소 | 표시 문구 | 근거 표시 | 비고 |
| --- | --- | --- | --- |
| ⓐ 주소 줄 (신규, 요청 상자 맨 위) | `POST https://copa.codyssey.kr/v1/chat/completions` · 작은 글씨 “주소는 환경변수(또는 실행 옵션)에서 읽는다” | 재현 ([demo-request.json](assets/evidence/demo-request.json)의 `method`·`url`) | 모바일은 `POST …/v1/chat/completions`로 줄임. `POST`는 배지로 강조 |
| ⓑ 인증 헤더 | `Authorization: Bearer ••••` · “누가 보냈는지 증명 · 환경변수의 API 키” | 재현 | 키 값은 절대 표시하지 않음. `Content-Type`은 넣지 않음(학습가이드 02) |
| ⓒ JSON 본문 | `model: gpt-5-mini` · `messages` → `system = 작성 규칙` / `user = 앞 화면의 Git 문맥` | 재현 + 모델 ID는 실제 실행 설정 | `temperature`·`max_tokens`는 넣지 않음 |
| ① 요청 화살표 라벨 | “① 요청 · POST” + 화살표 위 작은 칩 “딕셔너리 → JSON 글” | 구현 | `json.dumps`·UTF-8 인코딩 이름은 학습가이드 02 |
| 외부 서비스 상자 | “코디세이 AI API · 요청을 받아 JSON으로 응답” | — | **“모델 실행 위치 미확인” 삭제** |
| ② 응답 화살표 라벨 | “② 응답” + 두 갈래 칩: “성공 → JSON 글 → 딕셔너리” / “401·403 → 인증·권한 오류로 멈춤” | 401·403 분기: 구현 / 상태 표기 자체: 교육용 예시 | 성공 칩에 숫자를 쓰려면 “성공(예: 200)”으로만. 실제 성공 상태 코드는 기록되지 않음 |
| 응답 JSON 상자 (신규) | 위 구성의 축약 JSON 3줄. 경로 `choices` → `[0]` → `message` → `content`를 같은 강조색으로 이어 칠함 | **교육용 예시 · 원본 응답 미확보** (상자 머리 배지로 표시) | `content` 값은 실제 출력 문구를 쓰지 않고 “커밋 메시지 초안 …”처럼 일반 문구로 둠. 실제 출력은 검증·후처리 후의 글이므로 원본 응답으로 오해되지 않게 함 |
| 꺼낸 값 줄 | `choices[0].message.content` → “초안 글 → 다음 장면의 형식 검사” | 구현 | v0.2 문구 유지 |
| 근거 띠 (맨 아래) | “요청 구조: 재현 · 모델 ID: 2026-10-20 실제 실행 설정 · 응답 JSON 모양과 상태 예시: 교육용 예시” | — | P 패널에 가려져도 되는 유일한 요소 |

### 그림에서 다루지 않는 것 (P 해설 또는 학습가이드 02)

- API 키를 환경변수에 두는 이유(코드·Git 이력에 비밀값을 남기지 않기 위해) → 학습가이드 02, 강사 스크립트
- 네트워크 실패, JSON이 아닌 응답, `content`가 비어 있는 경우의 오류 → 학습가이드 02
- 요청 1회·자동 재시도 없음 → S4-2 해설, v0.1 접힘 설명
- 모델 실행 위치 → 원고 근거 안내

### 배치

- **데스크톱**: 높이를 450 → 약 540으로 늘립니다. Python 상자(왼쪽 60%)를 위아래로 “요청 만들기 / 응답에서 초안 꺼내기” 두 칸으로 나누고, 외부 서비스 상자(오른쪽 30%)는 세로 가운데. 두 화살표는 서로 반대 방향 실선 유지(위 = 요청 →, 아래 = 응답 ←). 응답 칸과 상태 칩은 그림 위쪽 2/3 안(세로 360px 이내)에 들어가야 합니다.
- **모바일**: 360×약 760. 위에서부터 **Python · 요청 만들기**(ⓐⓑⓒ) → ① 요청 화살표(아래 방향, API를 가리킴) → **외부 서비스** → ② 응답 화살표(아래 방향, Python을 가리킴) + 상태 칩 → **Python · 응답에서 초안 꺼내기**(응답 JSON 상자 → 꺼낸 값). 위아래 두 Python 칸은 같은 실선 테두리와 “내 컴퓨터 · Python” 머리로 한 덩어리임을 보여 줍니다. 이렇게 하면 세로 배치에서도 요청은 API 쪽, 응답은 Python 쪽을 가리키는 v0.2 원칙이 지켜집니다.
- 글자 크기는 v0.2와 같게 유지하고, 늘어난 내용은 높이로 흡수합니다(축소 금지).
