## §4 · curl 인증 헤더와 프로세스 인수 (가짜 키 · 로컬 테스트 서버 · 실제 API 아님)
# 서버는 요청을 받고 2초 뒤 응답한다. 그 사이 ps -ww -o args= 로 curl의 명령줄을 확인했다.
A. -H "Authorization: Bearer <키 환경변수>"  (Owner 실제 curl과 같은 형식)  → ps 명령줄에 가짜 키가 펼쳐져 보임
B. printf 'header = "Authorization: Bearer %s"\n' "$CODYSSEY_API_KEY" | curl -sS -K - "$CODYSSEY_API_URL" -H "content-type: application/json" -d '…'
   → ps 명령줄에 키 없음:
     curl -sS -K - http://127.0.0.1:18765/v1/chat/completions -H content-type: application/json -d {"model":"gpt-5-mini","messages":[{"role":"user","content":"hi"}]} -w …
   → 서버가 받은 값: Authorization 헤더 있음(Bearer, 길이 25), Content-Type application/json, 본문 JSON 정상 · HTTP 상태 200(테스트 서버)
$ whence -w printf
printf: builtin
# printf는 zsh 내장 명령이라 별도 프로세스를 만들지 않으므로 키가 다른 프로세스의 명령줄에 나타나지 않는다.
# 한계: 키 안에 " 또는 \ 가 있으면 curl 설정 줄의 해석이 달라질 수 있다(Lab 07 ②의 문자 확인으로 미리 점검).
# 한계: 실제 코디세이 API에 이 형식으로 보내 본 기록은 없다(Owner 실제 성공은 §3의 -H 형식).
