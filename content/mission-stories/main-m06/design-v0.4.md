## 4. 상호작용 설계 (I1–I10)

공통 규칙

- 모든 상호작용은 **교육용 시뮬레이션**입니다. 실제 AI 호출, 터미널 실행, API 키 입력, 출력 수집이 없습니다. 각 도식의 캡션 아래에 `교육용 시뮬레이션 · 실제 실행 기록이 아닙니다` 배지를 둡니다. 도식 안에 실제 기록 값을 보여 줄 때는 그 값 옆에 해당 근거 배지(`실제 · 2026-11-25 Owner`, `재현 · Claude 2026-11-28` 등)를 따로 붙입니다.
- 상태 전환은 버튼 그룹(`role="group"`, `aria-pressed`) 또는 단계 이동 버튼(이전·다음)으로 합니다. 키보드만으로 조작할 수 있고, 상태가 바뀌면 `aria-live="polite"`로 바뀐 내용을 알립니다. 색만으로 의미를 구분하지 않고 글자·아이콘·선 모양을 함께 씁니다.
- 360px 폭에서 가로 넘침이 없어야 합니다. 넓은 도식은 세로로 쌓고, 코드·JSON은 그 상자 안에서만 가로 스크롤합니다.
- 기존 발표 테마(Dark/Light, `PresentationSurface`)를 따릅니다. 새 색을 만들지 않습니다.
- 원고의 `**도식** interactive:<ID>:<초기 상태>`가 초기 상태를 정합니다. 같은 도식을 여러 화면에서 다른 초기 상태로 씁니다.

## 5. 실습 운영 — 화면 속 실습과 Lab의 역할
