## 1. 학습자가 실제로 쓰는 환경

설계의 출발점은 **학습자가 터미널과 이 화면을 동시에 본다**는 사실입니다.

| 환경 | 상황 | 화면에 필요한 것 |
| --- | --- | --- |
| 교육장 PC (macOS) | 브라우저와 터미널을 좌우로 나눠 씀. 화면 너비의 절반(약 640–720px)에서 Lab을 읽음 | 좁은 폭에서도 명령·관찰 목록이 읽힘, 명령 복사 버튼 |
| 강의 화면 (1280×720 투사) | 강사가 S1-2를 설명하다 Lab 03으로 이동해 시연하고 돌아옴 | 큰 글씨, 한 번의 클릭으로 이동·복귀, 시연 중 해설이 미리 펼쳐지지 않음 |
| 모바일 (360·390px) | 터미널이 없음. 강의 후 복습, 이동 중 읽기 | 실행이 아니라 **관찰 기록 읽기** 중심. 표·긴 명령이 깨지지 않음 |

## 2. 화면 구성 대안

| | A. 별도 Lab 페이지 | B. 레이어(드로어) | C. 연속 학습 모드 |
| --- | --- | --- | --- |
| 모습 | `…/main-M06/lab/03` 같은 독립 페이지. 화면에서 “실습으로 확인하기”를 누르면 이동, 상단에 “← S1-2로 돌아가기” | 스토리 화면 위에 오른쪽(또는 아래) 드로어로 Lab을 펼침. 그림은 뒤에 남음 | 스토리 화면과 Lab을 한 줄로 이어 붙인 진행 모드: S1-2 → Lab 03 → S1-2(다시 보기) → … |
| 장점 | 긴 Lab 내용을 온전히 표시. 주소로 공유·북마크 가능. 터미널과 나란히 쓰기 좋음. 용어 복귀 패턴을 그대로 재사용 | 그림을 보면서 실습 지시를 읽음. 화면 이동 없음 | 순환 구조가 화면 순서 자체에 드러남. “다시 보기”가 자연스러움 |
| 단점 | 그림과 실습이 다른 페이지. 왕복 클릭 필요 | Lab이 길어(예: Lab 03·07) 드로어가 그림을 거의 가림. P 패널과 겹침. 좁은 폭에서 사실상 전체 화면이 됨 | 순서가 정해져 “어디서든 시작” 원칙과 긴장. 강의 순서(8화면)와 다른 새 동선을 설계·검수해야 함 |
| 필요한 UI 기능 | 새 라우트, 복귀 링크, 화면별 연결 칩, Lab 목차 | 드로어 컴포넌트, P 패널과의 배타 제어, 포커스 관리, 드로어 안 스크롤 | 진행 표시, “다시 보기” 화면 상태, 건너뛰기, 모드 전환 |
| 공개 route 계약 | **신규 route → Owner Gate** | 기존 route 유지(쿼리만 추가) | 신규 route 또는 모드 쿼리 → Owner Gate |
| 강의 시연 | 좋음(이동·복귀가 분명) | 보통(가림 문제) | 좋음(정해진 순서) |
| 모바일 | 좋음(일반 문서처럼 읽힘) | 나쁨(드로어=전체 화면) | 보통 |
| 구현 범위 | 중 | 중 | 대 |

**제안(결정 아님):** **A를 기본**으로 하고, 각 화면에 “실습으로 확인하기” 칩(M1 필드)을 둡니다. C는 시범 수업에서 A의 왕복이 실제로 쓰이는지 확인한 뒤 “이어 하기” 보기로 검토합니다(r1 웹 제안의 “이어 읽기 보기” 보류와 같은 판단). B는 P 패널 가림 문제가 해결되기 전에는 권하지 않습니다.

## 3. 스토리와 실습 사이의 이동

| 이동 | 진입점 | 동작 제안 |
| --- | --- | --- |
| 화면 → Lab | 각 화면의 “실습으로 확인하기” 칩(주 Lab 1개 + 보조 Lab) | Lab 주소에 출발 화면을 붙임(예: `?from=S1-2`). 용어 링크의 `?b32-story=`와 같은 검증 규칙(허용 값만, 길이 제한) |
| Lab → 화면 | Lab 상단 복귀 띠 “← S1-2로 돌아가기”, Lab 끝 “이 결과를 설명하는 화면” | `from`이 있으면 그 화면으로, 없으면 Lab의 주 연결 화면으로. 돌아가면 그림 영역에 포커스 |
| 화면 → 화면(다시 보기) | 복귀한 화면에 “Lab 03 결과와 비교해 보세요” 한 줄 안내(선택) | 다시 보기 문장(매핑 §3의 “붙잡을 문장”)을 강조 표시할지는 Owner 결정 |
| Lab → Lab | 이전·다음 링크, Lab 목차 | 다음 Lab의 시작 상태가 다르면 상태 카드 안내를 먼저 보여 줌 |
| 결과 → Lab | “결과로 찾아보기” 색인 페이지 | 출력 한 줄을 검색하면 Lab·화면·용어로 이동 |
| Lab → 용어 | 관련 개념의 용어 ID | 기존 용어 페이지로 이동, 복귀 띠는 Lab으로 돌아오게(복귀 대상 일반화 필요) |
| 키보드 | — | 새 단축키는 추가하지 않음(P와 충돌 방지). 칩·링크는 Tab으로 접근 |

## 4. 실습 진행 위치 유지

| 정보 | 저장 위치 제안 | 이유 |
| --- | --- | --- |
| 지금 보고 있는 Lab·단계 | **주소(URL)** — Lab 경로 + 단계 앵커(예: `#관찰`) | 새로고침·공유·뒤로 가기에서 유지. 서버 저장 없음 |
| 출발 화면 | 주소의 `from` 쿼리 | 복귀 링크 |
| 관찰 목록 체크 · 펼친 해설 | 브라우저 `localStorage`(선택 기능, 기기 안에만) | 같은 PC에서 이어 하기. 공용 PC이므로 “기록 지우기” 버튼 필수 |
| 저장소 상태(A/B/C) | 저장하지 않음. Lab 머리에 **필요한 상태와 확인 명령**을 항상 표시 | 실제 상태는 학습자의 터미널에만 있음 |

**저장하지 않을 것:** 학습자의 명령 출력, 입력한 글, API 키. “내 결과 붙여넣기” 입력칸은 만들지 않기를 권합니다. 학습자가 키가 섞인 출력을 붙여넣을 위험이 있습니다. 예측 질문은 화면에 질문만 두고 답은 학습자 노트에 적게 합니다.

## 5. 결과 해설 표시

| 요소 | 제안 |
| --- | --- |
| 관찰 → 해설 순서 | 실행 기록과 해설은 **기본 접힘**. 버튼 문구 “관찰을 마쳤다면 펼치기”. 강의 모드에서도 자동으로 펼치지 않음 |
| 근거 배지 | 결과 상자 머리에 `실제 · 11-25 Owner` / `재현 · Claude` / `예상` / `교육용 예시` 배지. 그림의 근거 띠와 같은 낱말. 색만으로 구분하지 않고 글자 표시 |
| 비교 표 | Lab 03 전후 표는 학습자가 먼저 채워 볼 빈 표(화면에서는 체크·선택형)와 펼친 뒤의 정답 표를 나란히 |
| 출력 강조 | 실습 메모 줄은 모든 출력에서 같은 주황 밑줄 + “실습 메모” 라벨([매핑 §5-2](lab-story-mapping-v0.3.md#5-2-색-기존-r1-그림-팔레트-그대로)) |
| 결과가 다르다면 | “이렇게 나왔다면 → 이유와 할 일” 표를 접힌 목록으로. 가장 흔한 2–3개는 해설 위에 바로 보이게 |
| 이해 확인 | 질문을 먼저 보이고 답은 한 번 더 눌러야 보이게 |
| 도식 | 원고의 ASCII 도식은 초안. 웹에서는 SVG(라이트·다크, 데스크톱·모바일) |
| 명령 블록 | 복사 버튼, 긴 줄 가로 스크롤(줄바꿈하지 않음 — 복사 오류 방지), `heredoc` 블록은 한 번에 복사 |
| 비용 표시 | Lab 07·08 머리에 “API 호출 N회 · 키 필요” 배지 |

## 6. PC와 모바일

**PC (교육장·강의)**

- 640px 폭에서 Lab 본문이 한 단으로 읽혀야 합니다(터미널과 좌우 분할). 표는 가로 스크롤 허용.
- 1280×720 강의 화면에서 화면 → Lab → 화면 왕복이 두 번의 클릭으로 끝나야 합니다.
- 고정 패널(P)과 Lab의 복귀 띠가 동시에 화면을 가리지 않게 합니다.

**모바일 (360·390px)**

- 기본 보기는 **관찰 기록 읽기**: 명령 → 실제 결과(접힘 해제 가능) → 해설. 실행을 전제로 한 문구(“터미널에서 실행하세요”) 옆에 “PC에서 실습”을 표시.
- 비교 표(Lab 03 전후, 결과로 찾아보기)는 카드형으로 바꿔 쌓기.
- 명령 블록은 가로 스크롤, 글자 크기는 줄이지 않기.

**공통 접근성:** 접힘 버튼은 실제 버튼 요소(키보드·스크린 리더), 배지·색 구분에 글자 라벨, 대비는 라이트·다크 모두 확인([정책 §5](../../../docs/mission-guides/learning-operation-policy.md)).
