## 원본과 상태

- `batch-four-concepts.json`이 네 편의 대사·장면 설명·shot·offscreen·쉬운 뜻·비유 경계·근거 URL·사전 연결·버전의 기준이다.
- 각 `episodes/<작품 ID>/`에 생성 그림 `art.png`, 고정 지면 `master.png`, 개별 컷 네 장, `script.md`, 실제 생성 프롬프트를 보관한다.
- 그림은 built-in image_gen으로 제작했다. 기존 터미널 합본은 화풍·인물 참조에만 사용했다. 상세 모델명·seed는 도구가 공개하지 않아 추정하지 않았다.
- Docker 3컷 실행 창에 사진이 들어간 초기 결과는 오해를 키울 수 있어, 일반 앱 화면으로 국소 수정했다. 수정 전 그림과 실제 수정 프롬프트를 함께 보존했다.
- 지면은 기존 v1 2×2·1536×1024, 개별 컷은 736×480. Apple SD Gothic Neo 조판이다. 모바일은 같은 네 컷을 순서대로 읽는다.
- 상태는 모두 `draft`. 완성본 확인 전 공개 승인으로 간주하지 않는다. `episodes.json`, 공개 WebP, 생성 공개 목록을 변경하지 않았으며 현재 공개 8편에 영향이 없다. canonical·관계·taxonomy·지도·공개 route 변경 없음.

## 설명 검토

- Git은 커밋으로 기록한 이력에 집중한다. 자동 저장·무조건 복구라는 인상을 피하고, GitHub는 별도 협업 서비스라는 한 문장을 비유 경계에 넣었다. 근거: Pro Git 공식 문서.
- 셸은 명령 해석 역할에 집중한다. 터미널 창과 셸을 분리하고 자연어·음성 인식으로 설명하지 않았다. 근거: GNU Bash 공식 매뉴얼.
- 캐시는 데이터·계산 결과 재사용을 메뉴 사본에 비유한다. 백업과 구분하고 원본 갱신·최신성·캐시 재사용 조건을 경계에 명시했다. 근거: 기존 사전 cache 설명과 MDN Cache/HTTP caching.
- Docker 이미지는 읽기 전용 파일·설정 묶음이며, 컨테이너를 만들 때 바탕이 된다는 역할을 다뤘다. 이미지가 실행 중인 프로그램이라는 등식·모든 환경에서 동일 실행이라는 과장을 피했다. 근거: Docker 공식 image/container 설명.

## 검증 및 재출력

합본 네 장과 개별 컷 16장의 크기·원본 존재, 대사 32개, 기존 사전 ID 네 개, draft/승인 부재를 확인했다. 각 합본의 한글·말풍선·컷별 순서·인체·소품 및 그림 설명을 시각 확인했다. 검토 HTML의 Chrome 1440/390/360px에서 네 편·이미지 20개·대사 패널 16개·PC/모바일 전환·가로 넘침 없음·페이지 오류 0을 확인했다. 실제 학습자 이해도 검증과 공개 배포는 수행하지 않았다. 변경은 새 원고·그림·검토 자료뿐이므로 기존 앱 테스트/빌드 결과를 재사용하며 같은 전체 검증을 반복하지 않았다.

재출력:

```sh
WEBTOON_CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node scripts/render_webtoon_episodes.mjs --source content/webtoons/batch-four-concepts.json --include-drafts
```

네 편을 함께 기획·제작하고 하나의 검토 페이지에 묶었다. 신규 콘셉트 네 개의 이야기와 기술 경계를 일괄 확인했고, 생성 결과를 보고 필요한 그림만 한 번 수정했다. 후속 공개 때도 승인한 PNG를 재생성·재조판하지 않고 내보낸다.
