# 자주 접하는 작동 개념 네 편 — 제작 원고

## 서비스 반영 승인 — 2026-10-21

Owner가 네 편의 제작 검토본을 전달받은 뒤 “서비스에도 반영해줘”라고 명시적으로 요청했다. 기존 검토 커밋 e28f41c42713c53bcacaa6a5ba09edc38e7b9309의 그림 원본·합본·개별 컷·대사 그대로 승인 상태로 전환해 공개 목록에 추가한다. 총 공개 대상은 19편이다. 아래 제작 당시 draft 기록은 이력으로 보존한다. 실제 배포 결과는 공개 화면 검증 후 릴리스 결과와 Notion에 기록한다.

공개 전 검증: 공개 상태 검사 6개, 웹툰 UI 테스트 5개, 빌드 통과. 서비스 빌드의 Chrome 1440/390/360px에서 신규 네 편의 그림 설명·32개 대사·쉬운 뜻·비유의 경계, PC 합본/모바일 네 컷, 홈·목록 19편, 기존 사전 연결 필터 11개를 확인했다. 신규 공개 자산 44개의 해시가 내보내기 결과와 일치하며 브라우저·네트워크 오류는 0건이다. 검토본의 그림·대본·프롬프트 33개 파일과 기존 공개 15편 레코드가 그대로임을 확인했다. canonical 519개·용어 설명·앱 코드·공개 route 변경은 없다. 검증 후에는 같은 소스를 병합하고 실제 배포본의 표시·자산을 확인한다.

Owner가 미션 용어에 한정하지 않고 일반적으로 많이 듣는 기술용어를 원했다. 세분화 수준이 지나치게 좁은 구현 용어보다 자주 접하는 작동 개념을 우선하며, 서버·데이터베이스·API·오픈소스 네 편을 선택하고 제작을 요청했다.

## 이야기와 배역

| 주제 | 제목 | 기술 인물 조합 | 핵심 장면 |
| --- | --- | --- | --- |
| 서버 | 제 노트북은 퇴근 못 해요? | 학습자 + 기술 멘토 | 노트북 종료 후 접속 실패 → 서버 역할 → 요청/응답 → 사람과 노트북의 퇴근 시간 차이 |
| 데이터베이스 | 주문 내역을 외우라고요? | 개발자 동료 + 기술 멘토 | 채팅에서 기록 찾기 → 정리된 저장 → 조건 조회 → 머리 용량 농담 |
| API | 지도까지 직접 만들어요? | 학습자 + 개발자 동료 | 앱 지도 기능 개발 → 정해진 이용 방식 → 지도 표시 → 종이 지도 접기 |
| 오픈소스 | 고쳐 써도 되는 거였어요? | 학습자 + 기술 멘토 | 작은 글씨 → 코드·라이선스 확인 → 수정·개선 제안 → 너무 커진 글씨 |

각 편은 2×2 합본과 동일한 네 컷을 유지하며 넓은 장면·화면 근접·어깨너머·위에서 내려보기·출입문 반전 등 구도를 다르게 잡았다. 인물은 기존 얼굴·복장의 기술 학습자, 개발자 동료, 기술 멘토다. 주문 앱에서도 가게 주인으로 바꾸지 않았다.

## 정확성 검토

- Web/Backend Architecture 관점: 서버를 특정 대형 하드웨어와 동일시하지 않는다. 웹 서버의 요청/응답 예시이며, 이미 받은 브라우저 화면과 새 요청 실패를 구분한다. API는 프로그램이 사용할 수 있는 기능과 규칙이며 인터넷 통신만으로 한정하지 않는다. 지도 API가 앱 전체를 자동 생성하는 것으로 설명하지 않는다.
- Database 관점: 데이터의 모음과 DBMS를 구분한다. 주문 표는 예시이며 모든 데이터베이스가 관계형 표는 아니다. 저장·조회·수정을 보여 주고 입력·관리까지 자동으로 해결된다고 주장하지 않는다.
- 오픈소스: 무료 또는 코드 열람만으로 정의하지 않는다. 라이선스 조건에 따른 사용·수정·재배포를 설명하고 원작에 개선 제안이 자동 반영된다고 하지 않는다.
- 네 일반 개념과 정확히 일치하는 canonical ID는 현재 519개 사전에 없다. 관련 세부 용어에 억지 연결하지 않고 `termId: null`과 자체 쉬운 뜻·미연결 사유를 보존한다. canonical·taxonomy·지도·공개 route 변경은 없다.

## 제작·검증 상태

`common-terms-four.json`은 별도 `draft` 원고다. 제작 지시는 받았으며 기존 공개 15편의 승인 상태나 그림을 변경하지 않는다. 원본 생성은 built-in image_gen, 한글·말풍선은 기존 template-v1 지면으로 조판한다. 실제 프롬프트·완성 합본·개별 컷·대본을 각 작품 폴더에 보관한다.

네 편의 완성 합본을 시각 검수해 한글·말풍선·장면 순서·손·소품·기술 인물의 일관성을 확인했다. 데이터베이스의 긴 대사 두 개를 두 줄로 줄였고, 오픈소스의 첫 화면을 문서 프로그램으로, 마지막 화면을 커다란 ‘가’ 한 글자로 보정했다. 최초 그림은 art-initial.png와 편집 프롬프트로 보존했다.

합본 4장(1536×1024), 개별 컷 16장(736×480), 그림 원본 4장(1536×1024)의 크기, 대사 32개, 출력 패키지 이미지 20개의 바이트 동일성을 확인했다. 검토 HTML을 Chrome 1440/390/360px에서 열어 이미지 로딩, 합본/모바일 전환, 네 편·16컷·32대사, 설명·출처, 가로 넘침 없음, 브라우저·네트워크 오류 0건을 확인했다. 오픈소스 보정 후 최종 이미지까지 패키지에 반영해 재확인했다.

검증 명령: `WEBTOON_CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node scripts/render_webtoon_episodes.mjs --source content/webtoons/common-terms-four.json --include-drafts <작품 ID>` 및 작업 디렉터리의 `verify_common_four.mjs`. 결과물은 `outputs/webtoon-common-four/index.html`과 네 편의 PNG·대본·프롬프트 패키지에 보관한다.

기존 공개 15편의 메타데이터·그림, 앱 코드·생성 데이터·canonical은 기준 커밋 6c7a1ee5bf71b85618d67eacd6ab857192bdff4c와 차이가 없다. 앱 변경이 없으므로 기존 배포의 테스트·빌드 근거를 재사용하고 검증 범위는 새 제작물·검토 페이지에 한정했다. 실제 학습자 이해도 검증과 이번 네 편의 공개 배포는 수행하지 않았다.
