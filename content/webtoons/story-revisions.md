# 게임 엔진·클라우드 이야기 재구성 — 2026-10-21

Owner 요청: LLM의 ‘1+3을 학습하지 않아 틀린다’는 설명은 타당성만 검토한다. 엔진오일을 가져오는 게임 엔진 이야기와 연결이 어색한 클라우드 이야기는 새로 만든다.

## 제작 결과

- 게임 엔진 v3 「설치했는데, 게임은요?」: 설치 후 완성 게임을 기대→엔진 제공 기능→직접 규칙·콘텐츠 제작→소파에서 기다리는 개발자 반전. 고정 배역은 초록 후드 학습자와 노란 카디건 개발자 동료다.
- 클라우드 v4 「제 노트북만 야근하나요?」: 오래 걸리는 로컬 계산→인터넷으로 쓰는 원격 서버 자원→필요에 따른 자원 조절·비용→결과 해석은 사람의 역할. 고정 배역은 초록 후드 학습자와 안경·갈색 재킷 기술 멘토다.
- `story-revisions.json`에 새 대사·컷 설명·shot·offscreen·버전·쉬운 뜻·비유 경계·기존 사전 연결·근거 URL을 보관한다. `revisions/<기존 작품 ID>-<새 버전>/`에 art/master/panel 네 장, script.md, 실제 image-prompt.md를 보관한다.
- 그림은 built-in image_gen으로 새 제작했다. 참조 합본은 시리즈 화풍·고정 인물 확인용이다. 상세 모델명·seed는 미제공. 기존 template-v1.css·Apple SD Gothic Neo로 1536×1024 합본과 736×480 네 컷을 조판했다.
- 기존 공개 작품 ID는 후속 교체 때 유지할 수 있게 보존했다. ID에 남은 oil/bill 문자열은 이전 이야기 이력이며 새 대본에는 엔진오일·우산·실물 본체 운반 장면이 없다.

## LLM 타당성 검토 — 원고 변경 없음

‘산수 문제에서 오답을 낼 수 있다’는 상황은 가능하지만 ‘학습 자료에 그 식이 없어서 틀렸다’는 원인 설명은 일반적인 LLM 설명으로 성립하지 않는다. 학습한 패턴을 새 입력에 적용할 수 있으며, 오답만으로 학습 데이터의 부재를 판정할 수 없다. 특정 원인을 주장하려면 해당 모델의 학습 데이터와 통제 실험 근거가 필요하다.

근거: [Language Models are Few-Shot Learners, §3.9.1](https://arxiv.org/pdf/2005.14165). 연구진은 3자리 산술 문제의 학습 자료 포함 여부를 제한된 문자열 형식으로 검색하고, 단순 암기만으로 설명하기 어려운 정답과 받아올림 실수를 관찰했다. 이것은 특정 현행 모델이 1+3을 틀린다는 증거가 아니다.

LLM 편의 대본·이미지·공개 데이터는 수정하지 않았다.

## 상태와 검증

새 두 편은 완성된 교체 전 검토본이며 `status: draft`다. 기존 12편과 episodes.json·생성 공개 목록은 그대로다. 새로운 원고와 시각물의 확인 없이 이전 버전의 승인을 승계하지 않는다.

합본 두 장·개별 컷 여덟 장의 크기와 파일 존재, 16개 대사, 1→4 순서, 기술 배역·소품·한글·말풍선·의미 연결을 확인했다. 검토 HTML Chrome 1440/390/360px에서 두 편·이미지 12개·대사 패널 여덟 개·PC/모바일 전환·이전본 비교·가로 넘침 없음·페이지 오류 0을 확인했다. 기존 앱·공개 데이터에 변경이 없어 전체 앱 테스트와 배포를 반복하지 않았다. 실제 학습자 이해도 검증은 하지 않았다.

재출력:

```sh
WEBTOON_CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node scripts/render_webtoon_episodes.mjs --source content/webtoons/story-revisions.json --include-drafts
```
