# Git — 최종이 여덟 개예요!


최종 파일이 여덟 개가 된 동아리 작업실. 파일 이름 대신 변경 이력을 남겨 봅니다.


## 1컷 · 동아리 작업실·넓은 중경

초록 후드 학생이 여러 버전의 행사 포스터 출력물을 들고 당황합니다. 노란 카디건 동료는 멀리 떨어진 게시판 옆에서 돌아봅니다.

초보자: 최종 파일이… / 여덟 개예요!

동료: 어느 게 / 진짜 최종인데요?

## 2컷 · 변경 이력 화면·손 근접

모니터의 기록 목록과 서로 다른 포스터 미리보기를 가까이 보여 줍니다. 두 사람은 화면 밖에서 대화합니다.

초보자: 이름을 바꿔서 / 계속 저장해야 해요? (화면 밖)

동료: Git으로 변경 이력을 / 기록해 두면 돼요. (화면 밖)

## 3컷 · 어깨너머·이전 버전 비교

학생의 어깨너머로 모니터에 나란히 표시된 기록한 이전 포스터와 수정 포스터를 봅니다. 동료는 화면 밖에서 손으로 이전 버전을 가리킵니다.

초보자: 어제 기록한 버전도 / 다시 볼 수 있네요!

동료: 네, 기록한 내용을 / 비교하거나 되돌리죠. (화면 밖)

## 4컷 · 발표 무대·원근과 반응

학생이 작은 발표 무대에서 종이를 거꾸로 든 채 쑥스러워하고, 객석 옆의 동료가 웃으며 답합니다.

초보자: 발표 실수도 / 되돌릴 수 있나요?

동료: 파일은 되돌려도, / 발표는 생방송이에요!


## 쉬운 뜻

Git은 파일의 변경 이력을 기록하고 관리하는 도구예요. 원하는 시점의 상태를 ‘커밋’으로 기록해 두면, 기록한 내용을 나중에 비교하거나 되돌릴 수 있어요. 이런 기록은 인터넷 없이 내 컴퓨터에서도 할 수 있습니다.


## 비유의 경계

파일을 저장할 때마다 Git이 자동으로 기록하는 것은 아니에요. 커밋으로 남긴 이력과 아직 기록하지 않은 변경을 구분해야 해요. GitHub는 Git 저장소를 온라인에 두고 협업하는 별도 서비스이며, 이 편에서는 Git의 이력 기록에 집중했어요.
