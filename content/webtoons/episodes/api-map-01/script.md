# API — 지도까지 직접 만들어요?


앱에 넣을 지도를 처음부터 만들려던 학습자. API로 다른 프로그램의 기능을 이용하는 방법을 만납니다.

## 1컷 · 앱 기획 테이블·넓은 사선 장면

학습자가 직접 스케치한 큰 동네 지도를 펼쳐 놓고 앱 기획을 하다 막막해합니다. 개발자 동료는 태블릿의 지도 기능 예시를 보여 줍니다. 두 사람은 기술 학습자와 개발자입니다.

학습자: 지도 기능까지 / 전부 직접 만들어요?

개발자 동료: 지도 서비스 API를 / 이용해 볼까요?

## 2컷 · 기능 이용 약속·태블릿과 손 근접

태블릿의 안내 화면에 앱 아이콘과 지도 서비스 아이콘이 정해진 입력·결과를 뜻하는 화살표로 연결됩니다. 녹색과 노란색 소매의 손만 보입니다.

학습자: 다른 프로그램 기능을 / 우리 앱에서 써요? (화면 밖)

개발자 동료: 네, 정해진 방식으로 / 요청하고 결과를 받아요. (화면 밖)

## 3컷 · 지도 기능 테스트·스마트폰 근접

학습자가 쥔 스마트폰의 앱에서 검색한 장소가 지도 핀으로 표시됩니다. 뒤쪽에는 개발자 동료가 작업한 노트북 화면이 흐릿하게 보입니다.

학습자: 주소를 보내니 / 지도에 표시됐어요! (화면 밖)

개발자 동료: 제공된 지도 기능을 / 우리 앱에서 쓴 거죠. (화면 밖)

## 4컷 · 작업 테이블 옆·전신 반응

학습자가 커다란 종이 지도를 접다가 양팔 사이에 끼워 넣으며 웃습니다. 개발자 동료는 휴대전화의 완성된 지도 기능을 보여 줍니다.

학습자: 동네 지도는 / 일단 접어도 되겠네요.

개발자 동료: 네, 이제 우리 앱의 / 기능에 집중해요.

## 쉬운 뜻

API는 프로그램이 다른 프로그램의 기능이나 데이터를 사용할 수 있도록 정해 둔 기능과 규칙이에요. 개발자는 그 규칙에 맞춰 기능을 호출하거나 정보를 요청하고, 결과를 자기 앱에서 활용할 수 있어요.

## 비유의 경계

지도 서비스 연동은 API의 한 예예요. 모든 API가 인터넷을 이용하는 것은 아니며 브라우저나 라이브러리에도 API가 있어요. 어떤 기능과 입력·결과를 제공하는지는 API마다 달라요. API가 필요한 기능 전체를 자동으로 만들어 주는 것은 아니며, 사용자는 연동할 코드를 작성하고 서비스의 이용 조건과 제한을 확인해야 해요.
