# 인가(권한 확인) — 로그인했는데 왜 안 돼요?


로그인은 됐지만 수정은 안 되는 파일. 누구인지 확인하는 일과 무엇을 허용할지 판단하는 일은 다릅니다.

## 1컷 · 프로젝트 작업실·중경

초록 후드의 학습자가 로그인한 계정으로 문서를 열었지만 수정할 수 없어 당황합니다. 기술 멘토가 계정의 보기 권한 표시를 가리킵니다.

학습자: 로그인했는데, / 왜 수정은 안 되죠?

기술 멘토: 이 계정은 / 보기 권한만 있어요.

## 2컷 · 계정과 허용 범위·화면 근접

신원 확인 표시와 별도로 보기만 허용된 상태를 보여 주는 화면입니다. 멘토의 손이 읽기와 수정의 구분을 가리킵니다.

학습자: 제가 누군지는 / 확인됐잖아요? (화면 밖)

기술 멘토: 무엇을 해도 되는지는 / 따로 확인해요. (화면 밖)

## 3컷 · 동작별 허용·위에서 내려보기

키보드와 문서 화면을 위에서 봅니다. 보기에는 체크, 수정·삭제에는 자물쇠 표시가 있고 두 사람이 각 행동의 허용 범위를 확인합니다.

학습자: 보기·수정·삭제마다 / 허용 범위가 다르군요! (화면 밖)

기술 멘토: 그 허용 여부를 / 판단하는 게 인가예요. (화면 밖)

## 4컷 · 프로젝트 화면 앞·전신 반응

학습자가 관람객처럼 두 손을 뒤로 모으고 프로젝트 화면을 바라봅니다. 기술 멘토가 필요한 권한을 요청하라고 웃으며 안내합니다.

학습자: 저, 아직 / 관람객이었네요.

기술 멘토: 수정이 필요하면 / 권한부터 요청해요.

## 쉬운 뜻

인가는 사용자가 특정 자료나 기능을 이용해도 되는지 판단하는 과정이에요. 예를 들어 같은 문서를 볼 수 있는 권한과 수정할 수 있는 권한은 다를 수 있어요.

## 비유의 경계

권한은 허용된 범위이고, 인가는 그 권한과 정책에 따라 요청을 허용할지 판단하는 과정이에요. 로그인에 성공해도 모든 작업이 허용되는 것은 아니에요. 실제 서비스에서는 화면의 버튼 표시뿐 아니라 요청을 처리하는 쪽에서도 권한을 확인해야 합니다.
