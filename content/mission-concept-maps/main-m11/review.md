| R07 "관계는 FK 값으로 저장된다" | 관계형 DB에서 1:N은 자식 쪽 FK, N:M은 연결 테이블의 FK 두 개로 표현한다. B6-1의 관계선 5개 = FK 선언 5개(스토리 review §3에서 확인) | PASS |

## 5. 구현 단계에서 주의할 사항

1. **영역 열 순서:** 데이터 관계 | 데이터 구조 | 중심 | 데이터 활용. 지시서의 나열 순서(중심 | 구조 | 관계 | 활용)를 그대로 쓰면 긴 선이 2개가 되고 SQL과 DBMS가 지도 양 끝으로 갈라진다.
2. **선을 긋지 않는 관계를 지킨다:** JOIN ↔ PK·FK, PK ↔ 열 사이에 선을 추가하지 않는다. "연관" 같은 뜻이 넓은 유형으로 선을 보태지 않는다.
3. **흐름처럼 보이지 않게:** R10(SQL → DBMS)에 이동 애니메이션·순서 번호를 붙이지 않는다. 강의 시연 순서(§6)는 "복습 순서이며 실행 순서가 아님"을 화면에 밝힌다.
4. **단독 ID 없는 노드 4개:** DBMS·행·열·관계의 사전 링크는 `extension` 안내 문구와 함께 보여 주거나(`none`이면) 링크를 만들지 않는다. 존재하지 않는 `/terms/dbms` 등으로 연결하지 않는다.
5. **노드 이름:** "데이터베이스" 노드에는 "(관계형)"을 함께 보여 준다. 사전 항목 제목은 "relational database"다.
6. **미구현 표시:** 지도 → 스토리 복귀, 미션 소개의 "개념지도" 카드는 승인·구현 전까지 준비 중으로 둔다(현재 `missionLearning.ts`의 B6-1 자료는 story · guide 두 개).
7. **테마:** B6-1 스토리는 슬라이드 Dark 기본이지만, 개념지도는 공통 UI 기준대로 사이트 테마 토큰을 쓰고 `PresentationSurface`로 감싸지 않는다.
8. **기존 자료 보호:** B2-1/B3-1 지도 데이터·컴포넌트·스타일, 분야 기술지도, canonical 용어 데이터는 고치지 않는다.
9. **시각 QA:** 1280×720 · 1000×720 · 360×800 · 390×844에서 노드 이름(특히 "데이터베이스 (관계형)")의 줄바꿈, 하단 시트에 가려지는 선택 노드, 긴 선 R12의 통로를 실제 화면으로 확인한다.

## 7. 남은 일과 미검증

- **GPT 독립 검토 필요:** 노드 수(11)와 "데이터베이스/관계형 데이터베이스" 통합, "관계" 노드의 필요성, 열 순서 선택.
- **Owner 결정 필요:**
  1. 신규 용어 `dbms` 등록 여부. 지도에서 사전 링크가 없는 핵심 노드 중 DBMS만 대체할 항목이 없다(행·열은 `table`, 관계는 `one-to-many-relationship`이 설명한다). 등록하면 DBMS 노드를 `direct`로 바꾼다.
  2. 사전 `sqlite` 요약의 "relational database" 표현과 분야 기술지도의 `join → foreign-key` 선을 그대로 둘지.
- **미검증:** 실제 웹 화면, 모바일 하단 시트, 강의실 프로젝터. 배치 수치(1536×502, 긴 선 1개)는 저장소 밖 임시 스크립트로 엔진 함수를 실행해 얻은 값이며 화면 렌더링 확인이 아니다.
- **이번 작업에서 바꾸지 않은 것:** 웹 코드, 라우트, B6-1 스토리·상세 ERD, 학습가이드, 용어 데이터, B2-1/B3-1 지도.
