# Claude Code 작업 지시서 — B6-1 Mission Learning Guide 콘텐츠 제작

## 역할

당신은 코딩을 처음 접하는 성인 학습자를 위한 기술 교육 콘텐츠 저자이자 시각 자료 설계자다.

B1-1과 B2-1에서 확립한 Mission Learning Guide의 원칙을 계승해 B6-1의 전체 학습 콘텐츠를 제작한다.

## 1. 작업 목적

미션: **B6-1 — 정보를 깔끔하게 정리하는 디지털 서랍장 만들기**

목표: AI로 만든 SQL 데이터베이스의 구조와 작동 원리를 이해하고, 자신이 만든 결과물을 다른 사람에게 설명할 수 있는 학습 가이드 제작.

코드 리뷰 능력이나 SQL 문법 암기가 목적이 아니다.

대상은 법학, 어문학, 산업공학 등 다양한 전공의 프로그래밍 초심자다.

## 3. 콘텐츠 구성

## 4. 원고 제작 원칙

각 장은 실제 사용 경험에서 출발하는 질문으로 시작한다.

기본 설명 흐름은 다음과 같다.

**궁금증 → 일상적인 설명 → 용어 뜻 → 그림 → 실제 사례 → 장단점과 한계 → 자신의 프로그램에 연결 → 설명할 수 있는 한 문장**

처음 등장하는 용어를 학습자가 이미 안다고 가정하지 않는다.

예를 들어:

- SQL: Structured Query Language
- Query: 질의, 요청
- ERD: Entity Relationship Diagram
- Primary Key: 기본키
- Foreign Key: 외래키
- JOIN: 서로 다른 테이블의 데이터를 연결해 조회
- Index: 데이터를 효율적으로 찾기 위한 색인

영어의 구성과 의미가 이해에 도움이 되는 경우 자연스럽게 설명한다.

반대로 단어 뜻만으로 실제 기능을 정확하게 설명할 수 없는 경우에는 용어의 기술적 의미를 따로 설명한다.

예시는 실제 B6-1 결과물에서 가져온 것과 교육용 단순화 사례를 명확히 구분한다.

SQL 코드를 길게 나열하지 않는다. 필요하면 3~6줄 정도의 핵심 부분을 보여 주고, 자세한 코드는 원본 저장소에 연결한다.

## 5. 반드시 살릴 실제 학습 경험

- 엑셀과 관계형 데이터베이스의 차이
- 학생과 수업의 N:M 관계를 `enrollment`로 분리한 이유
- 수강 신청이 없는 학생과 수강생이 없는 수업을 만든 이유
- INNER JOIN과 LEFT JOIN의 실제 결과 차이
- PK/FK와 무결성 검증
- SQLite의 연결별 외래키 검사 설정
- macOS 환경에서 SQLite를 사용한 경험
- SQL 명령과 터미널 명령의 차이
- SQLite가 데이터를 처리하는 방식과 Python 보조 스크립트의 차이
- 이후 JPA/ORM 학습으로 연결되는 이유

기존 노트의 실제 경험을 활용하되, 확인하지 못한 사용자 발언이나 시행착오를 창작하지 않는다.

### 모바일 품질 기준

- 320px, 360px, 390px 화면을 대상으로 한다.
- 실제 표시 글자 크기 13px 이상을 최소 기준으로 검증한다.
- 360px에서는 가급적 15px 이상의 가독성을 목표로 한다.
- 본문 여백과 SVG 축소 비율을 고려한다.
- PC에서 세로형 그림이 과도하게 확대되지 않도록 한다.
- 긴 그림은 복잡한 내용을 억지로 한 화면에 밀어 넣지 않는다.
- 작은 글자를 확대하는 대신 정보 구조와 줄바꿈을 조정한다.
- 모바일용과 PC용 구성이 다르더라도 전달하는 개념은 같아야 한다.
- 색만으로 관계를 표현하지 않고 번호·선·텍스트를 함께 사용한다.

특히 V03(PK/FK), V06(JOIN), V07(GROUP BY), V10(전체 구조)은 관계의 정확성과 모바일 읽기 편의성을 집중 검증한다.

## 7. 기술적 정확성 주의

- 관계형 데이터베이스와 엑셀의 차이를 지나치게 절대적으로 표현하지 않는다.
- JOIN은 외래키 제약조건이 선언되어 있지 않아도 조건에 따라 수행할 수 있다.
- FOREIGN KEY 검사는 SQLite 연결별 설정과 실제 활성화 여부를 구분한다.
- INDEX가 모든 쿼리를 무조건 빠르게 만드는 것은 아니다.
- 인덱스는 읽기 이점과 저장·수정 비용을 함께 설명한다.
- LEFT JOIN에서 매칭되지 않은 오른쪽 테이블 값은 NULL이 된다.
- GROUP BY의 묶음과 HAVING의 그룹 결과 필터링을 구분한다.
- SQL과 SQLite, SQL 코드와 터미널 명령을 구분한다.
- UPDATE/DELETE는 WHERE 없이 실행할 때의 위험을 정확하게 설명한다.
- 재실행 시 테이블을 삭제하는 기존 `01_schema.sql`을 운영 데이터에 무심코 실행하도록 안내하지 않는다.
- JPA/ORM은 이번 미션에서 사용하지 않은 후속 학습 개념이다.
- 실제 미션 요구와 프로젝트 구현 선택을 구분한다.
