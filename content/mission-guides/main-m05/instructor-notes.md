# B3-1 학습 가이드 — 강사 노트

## 대상과 수업 목표

대상은 B3-1을 수행하는 코디세이 교육생입니다. 네트워크·AWS 경험이 없는 사람도 들어올 수 있고, 각자 선택한 호스팅 방식은 다를 수 있습니다. 수업의 도착점은 **B3-1 사례를 외우는 것**이 아니라 자신의 웹사이트가 어디서 빌드되고, 어떤 경로로 사용자에게 전달되며, 어떤 근거로 배포를 검증했는지 설명하는 것입니다.

첫 질문으로 “내 브라우저에 보이는 화면과 동료의 브라우저에 보이는 화면은 같은 파일에서 왔을까?”를 던질 수 있습니다. 1장에서 배포 지점을 찾고, 2~4장에서 AWS 네트워크를 읽은 뒤, 5~7장에서 관리 접속·파일 제공·검증을 연결합니다.

## 수업에서 구분할 것

| 혼동하기 쉬운 것 | 구분할 질문 |
| --- | --- |
| 소스와 배포 파일 | GitHub의 코드를 그대로 보내는가, `dist/`를 보내는가? |
| VPC 범위와 Public IPv4 | 서버 안의 사설 주소와 외부에서 접속한 주소가 같은가? |
| Public Subnet과 외부 접속 성공 | 경로 외에 Public IPv4·보안 규칙·서비스가 확인됐는가? |
| SG와 SSH 키 | 네트워크 입장 허용과 로그인 자격을 각각 무엇이 결정하는가? |
| 서버의 HTTP 200과 화면 성공 | 외부 브라우저에서 JavaScript와 자산까지 확인했는가? |
| Pages와 EC2 | 같은 커밋이 각각 언제 반영됐는가? |
| 계획과 완료 | 설계 문서에만 있는 자동화·HTTPS 등을 실제 적용으로 말하고 있지 않은가? |

## 다른 방식으로 미션을 수행한 교육생

- 정적 호스팅을 쓰면 VPC·EC2·Nginx를 직접 만들지 않았을 수 있습니다. 2~6장의 AWS 자원 이름을 강요하지 말고, **파일을 제공하는 주체와 공개 주소·접근 제어**를 찾아 설명하게 합니다.
- EC2를 썼더라도 웹 서버, 리전, 주소 범위, 배포 도구는 다를 수 있습니다. B3-1의 IP·리소스 ID·키 이름을 복사하는 실습으로 만들지 않습니다.
- 컨테이너나 로드 밸런서를 선택했다면 “브라우저 요청이 어느 서비스에 먼저 닿는가”를 추가로 그리게 합니다. 이 가이드의 단순 경로를 실제 토폴로지로 취급하지 않습니다.

## 근거와 미확인 사항

배포 사례는 [Codyssey_B3-1 저장소의 고정 커밋](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/tree/c68929943f1904a5c7c8033d2d49a30ace56e3d1)에 근거합니다. 배포 작업 기록은 2026-10-14의 관찰입니다. 현재 AWS 계정·서버에는 접속해 확인하지 않았습니다.

[미정제 미션 용어 추출본](../../../data/raw/main/m05/m05-terminology-raw.md)에는 `GET /health`, HTTPS, Docker 등이 등장하지만, 각각의 **필수 여부와 최종 결과**를 원본 미션과 대조하지 못했습니다. 특히 사례의 [Nginx 설정](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/deploy/b3-1/nginx.conf)에 전용 `/health` 위치 설정은 없습니다. `curl -I http://localhost`의 HTTP 200을 `/health` 구현의 증거로 쓰지 않습니다. HTTPS·Docker도 이 배포 사례의 완료 항목으로 다루지 않습니다.

`docs/architecture.png`는 **계획 단계의 그림**이며 실제 생성·검증된 자원 그림이 아닙니다. 이 가이드에는 재사용하지 않았습니다. 대신 이미 검토된 SSH·CIDR·AWS 역할 그림을 개념 설명용으로 복사했습니다. [기존 그림 검토](../../../drafts/b3-1-content/review.md).

## 학습 확인 질문

1. 내 프로젝트에서 **빌드 결과**가 실제로 올라간 곳은 어디인가요? 그 근거 파일이나 설정은 무엇인가요?
2. 외부 접속이 실패하면 IP·경로·허용 규칙·서버 프로그램을 어떤 순서로 확인하겠나요?
3. SSH 키를 이용한 로그인과 AWS IAM으로 리소스를 조작하는 권한은 왜 다른가요?
4. `curl`의 HTTP 200과 외부 브라우저에서 화면이 정상 작동한 증거는 어떻게 다른가요?
5. 소스에 새 커밋을 올린 뒤 공개 화면까지 바뀌는 과정이 자동인가요? 실행 기록으로 설명할 수 있나요?

평가할 때 교육생의 실제 구현을 기준으로 듣습니다. 용어 이름보다 **근거와 흐름**, 사례와 자신의 선택을 구분하는 설명을 봅니다.
