# B3-1 보강 자료 — 강사 노트

> 대상 원고: [기업 홈페이지 구성도로 읽는 네트워크](README.md). 상태: 콘텐츠 초안(독립 검토 전).

## 수업 목표

교육생이 **기업 홈페이지 예시**의 구성도를 보고 (1) 구역·요소의 위치와 역할, (2) 허용되는 연결, (3) 요청·응답의 실제 이동 순서, (4) 직원의 게시·저장 흐름을 말로 설명하고, (5) B3-1 AWS 구성과 비교해 **무엇이 대응하고 무엇이 없는지** 구분하게 합니다. 용어 암기가 아니라 “이 상자는 어디에 있고, 무슨 일을 하고, 누가 먼저 연결을 시작할 수 있고, 데이터는 어느 방향으로 가는가”를 그림에서 읽는 연습입니다.

## 권장 진행 순서

| 단계 | 하는 일 | 쓰는 그림 |
| --- | --- | --- |
| 1 | 질문으로 시작: “회사 홈페이지는 누구나 보는데, 직원용 시스템은 왜 밖에서 안 열릴까?” 답을 먼저 말로 받습니다. | 없음 |
| 2 | 그림 1에서 **위치→역할→허용/차단** 순서로 읽습니다. 이동 방향은 아직 다루지 않습니다. | 그림 1 |
| 3 | 방문자 요청 한 번을 번호대로 따라갑니다. 방화벽·NAT·경로표를 **세 가지 질문**으로 구분합니다. | 그림 2 |
| 4 | 직원의 게시 흐름을 따라갑니다. 같은 서브넷(스위치)과 다른 서브넷(게이트웨이→경로표→방화벽)을 대비합니다. | 그림 3 |
| 5 | B3-1과 비교합니다. **빈 칸(없는 것)을 먼저** 찾게 한 뒤 대응되는 칸을 봅니다. “게시·저장” 줄은 없는 것(게시 화면·DB·별도 파일 저장소)과 있는 것(서버 디스크의 `dist`)을 나누어 말하게 합니다. | 그림 4, 4 보충 |
| 6 | 자기 배포의 대응표를 채웁니다(다른 호스팅 방식 포함). | 원고 장면 4의 확인 활동 |

그림을 한 번에 다 보여 주지 말고 장면별로 나눕니다. 용어를 한 그림에 모으려 하지 않은 것이 설계 의도입니다.

## 혼동하기 쉬운 것과 확인 질문

| 혼동 | 구분하는 질문 | 바로잡는 말 |
| --- | --- | --- |
| 방화벽 = NAT = 라우터 | “통과시킬까? / 어느 주소로 바꿀까? / 다음 길은?” | 세 장치는 서로 다른 질문에 답합니다. 한 장비에 합쳐져 있어도 일은 다릅니다. |
| NAT가 있으면 안전하다 | “주소를 바꾸는 것과 허용을 판단하는 것은 같은가?” | NAT는 주소 대응입니다. 허용 판단은 방화벽 규칙입니다. |
| DMZ = 내부망의 일부 | “DMZ는 무엇과 무엇 사이에 있나?” | 공개 서비스와 내부망 사이를 **분리**하는 구역입니다. |
| 이 그림이 모든 회사의 표준이다 | “방화벽·라우터는 항상 한 장비인가?” | 배치와 장비 수는 기업마다 다릅니다. NIST 용어집도 DMZ를 여러 방식으로 정의합니다. |
| 저장하면 인터넷에 공개된다 | “저장 구역에 인터넷이 직접 닿나?” | 공개 웹 서버가 공개 상태 자료를 조회해 응답해야 보입니다. |
| 응답에도 별도 허용 규칙이 항상 필요하다 | “연결 상태를 기억하는 장치는 응답을 어떻게 처리하나?” | 허용된 연결의 응답은 그 연결에 속한 응답으로 보고 요청의 반대 방향으로 통과시킵니다. 응답이 지나는 실제 경로와 장비 순서는 기업망과 장비 설정에 따라 다를 수 있습니다. |
| `0.0.0.0/0 → IGW`는 장비다 | “이 줄은 무엇 안에 적힌 것인가?” | Route Table의 규칙 한 줄입니다. 요청이 통과하는 지점이 아닙니다. |
| Security Group = 경계 방화벽 | “어디에 적용되는가?” | EC2의 네트워크 인터페이스에 적용됩니다. |
| Public Subnet = DMZ | “각각을 누가 어떻게 정의하는가?” | Public Subnet은 AWS의 경로 정의, DMZ는 분리 설계 개념입니다. 동일시하지 않습니다. |
| B3-1에 직원망·게시 시스템·DB가 있다 | “B3-1 기록에서 이 상자를 가리켜 보세요.” | 직원용 게시 화면·DB·별도 파일 저장소는 고정된 기록에 없습니다. 다만 빌드된 `dist` 정적 파일은 EC2 서버 디스크에 저장되어 Nginx가 제공합니다. |

## 말할 때 조심할 것

- “회사는 보통 이렇게 한다”는 말을 쓰지 않습니다. “설명을 위한 한 가지 예시”라고 말합니다.
- 그림 4의 “B3-1 AWS” 칸을 **교육생이 따라 만들어야 할 정답**으로 제시하지 않습니다. B3-1의 IP·리소스 값은 당시 기록이며 복사하는 실습이 아닙니다.
- 정적 호스팅이나 다른 클라우드를 쓴 교육생에게 VPC·EC2를 강요하지 않습니다. “내 배포에서 이 역할을 누가 맡았나”만 묻습니다.
- AWS가 모든 역할을 물리 장비와 1:1로 대신한다고 말하지 않습니다. 비슷한 역할이 **다른 위치에 다른 방식으로** 놓일 수 있습니다.
- 인바운드 요청이 Route Table을 “지나간다”고 말하지 않습니다. 경로표는 규칙이며, `0.0.0.0/0 → IGW`는 Subnet 밖으로 나가는 패킷의 다음 대상을 정하는 줄입니다.

## 확인하는 방법

교육생이 직접 그림 한 장을 **빈 칸 채우기**로 설명하게 합니다. 정답 용어보다 근거를 듣습니다.

1. 그림 2의 ②③④를 가리키고 각각이 답하는 질문을 말해 보게 합니다.
2. 그림 3에서 “저장됨”이 보이는데 방문자가 못 본다면 확인할 것 세 가지를 순서대로 말하게 합니다.
3. 그림 4에서 B3-1에 없는 상자를 모두 찾고, 그것을 없는 이유(정적 파일 배포이므로)와 연결해 설명하게 합니다.
4. 그림 4 보충에서 `0.0.0.0/0 → IGW`와 Security Group이 각각 **어디에 속하는지** 말하게 합니다.

평가는 교육생의 실제 구현과 자기 설명을 기준으로 합니다. 용어를 틀리게 말해도 위치·역할·방향의 구분을 맞게 설명하면 부분 통과로 봅니다.

## 접근성·화면 안내

- 각 그림은 대체 설명을 본문에 글로 제공합니다. 그림이 안 보이거나 읽기 어려운 교육생은 대체 설명과 요소별 표만으로 같은 내용을 읽을 수 있습니다.
- 허용/차단은 색만이 아니라 **체크·엑스 모양, 점선 테두리, 글자**로 구분합니다. 요청(실선)과 응답(점선)도 선 모양으로 구분합니다.
- 그림은 가로 360 단위의 세로형입니다. 크게 열기 링크로 파일을 따로 열어 브라우저 확대를 쓸 수 있습니다.
