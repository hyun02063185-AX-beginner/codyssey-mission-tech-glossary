# 1. 웹사이트를 만든 뒤 무엇이 더 필요한가?

> 내 컴퓨터에서 보이는 웹사이트를 다른 사람도 열게 하려면 어떤 일이 필요할까요?

## 내 컴퓨터와 인터넷 사이

`[개념]` 개발 중에는 내 컴퓨터의 개발 서버가 화면을 보여 줄 수 있습니다. 다른 사람에게 공개하려면 웹사이트의 파일을 **외부에서 접근 가능한 곳**에 두고, 요청을 받아 파일을 보낼 방법이 필요합니다. React 같은 정적 웹 앱은 보통 소스 코드를 빌드해 HTML·JavaScript·CSS·이미지 파일을 만든 뒤 제공합니다. 사용자의 브라우저가 이 파일을 받아 화면을 그립니다.

```
소스 코드 → 빌드 → 배포 파일(dist/) → 호스팅 → 브라우저
```

`[B3-1 사례]` 용어사전 소스에서 `npm ci`와 `npm run build`를 실행해 `dist/`를 만들었습니다. 만든 파일을 EC2에 전송해 Nginx가 제공했습니다. [빌드·배포 기록](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/README.md#빌드-확인). EC2에서 개발 서버나 빌드 도구를 계속 실행하는 방식은 아니었습니다.

| 무엇 | B3-1 사례에서 맡은 역할 |
| --- | --- |
| GitHub의 소스 | 수정하고 버전을 남기는 원본 |
| `npm run build` | 브라우저에 보낼 파일 생성 |
| `dist/` | 실제로 서버에 올린 정적 파일 묶음 |
| EC2 | 파일을 보관하고 Nginx를 실행하는 컴퓨터 |
| Nginx | HTTP 요청을 받아 파일을 반환하는 웹 서버 |

`[개념]` **배포**는 파일을 만들고, 제공할 곳에 놓고, 외부에서 제대로 열리는지 확인하는 작업까지 포함합니다. GitHub에 소스를 올리는 것만으로 모든 호스팅 방식에 자동 반영되는 것은 아닙니다. 자동 배포는 별도로 설정한 경우에만 동작합니다.

`[B3-1 사례]` 같은 소스 저장소는 GitHub Pages에도 배포됩니다. 그러나 Pages의 `main` 갱신과 AWS EC2 파일 갱신은 **서로 별개**입니다. 기록상 AWS는 수동 전송했고, 향후 자동화는 설계만 했습니다. [재배포 문서](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/docs/deployment-update-and-automation.md#1-두-저장소와-현재-배포-상태).

## 내 프로젝트에 연결하기

`[확인 활동]` 내 프로젝트에서 ① 소스가 있는 곳 ② 빌드 명령과 결과 폴더 ③ 파일을 제공하는 곳 ④ 새 커밋이 공개 화면에 반영되는 조건을 찾아 적어 보세요. 정적 호스팅을 선택했다면 EC2·Nginx가 없을 수도 있습니다.

**한 문장 정리:** 배포는 내 소스를 공개용 파일로 만들고, 그 파일을 사용자에게 보내는 환경에 놓아 실제 접속까지 확인하는 일입니다.
