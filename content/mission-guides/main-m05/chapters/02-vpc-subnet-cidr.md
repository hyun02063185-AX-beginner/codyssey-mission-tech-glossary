# 2. VPC와 Subnet은 왜 나눌까?

> `10.0.0.0/16`과 `10.0.1.0/24`는 서버 주소일까요, 주소 범위일까요?

## 주소 범위부터 보기

`[개념]` VPC는 AWS에서 정하는 가상 네트워크 범위입니다. Subnet은 그 VPC 주소 범위 안에서 일부를 나눈 영역입니다. CIDR의 `/숫자`는 앞에서 고정할 비트 수입니다. IPv4에서 숫자가 클수록 범위가 좁아집니다. [CIDR 자세히 보기](../../../terms/cidr.md).

![CIDR 범위와 B3-1 주소의 포함 관계](../assets/cidr-range.svg)

[그림 크게 열기](../assets/cidr-range.svg)

| 표기 | 전체 IPv4 주소 수 | 이 사례에서의 의미 |
| --- | ---: | --- |
| `10.0.0.0/16` | 65,536 | VPC의 사설 주소 범위 |
| `10.0.1.0/24` | 256 | 위 범위 안의 한 Subnet |
| `0.0.0.0/0` | 전체 IPv4 공간 | 기본 경로나 모든 IPv4 출발지를 표현 |
| 운영자 주소 `/32` | 1 | SSH 접근을 한 공인 IPv4 주소로 제한할 때 사용 |

`[B3-1 사례]` 배포 기록의 VPC는 `10.0.0.0/16`, Public Subnet은 `10.0.1.0/24`였습니다. `[개념]` `/24`의 전체 주소는 256개이지만, AWS는 Subnet의 앞 4개와 마지막 1개를 예약하므로 **일반적으로 인스턴스에 할당 가능한 IPv4는 251개**입니다. 전체 주소 수와 할당 가능 수를 혼동하지 마세요. [AWS Subnet CIDR 문서](https://docs.aws.amazon.com/vpc/latest/userguide/subnet-sizing.html).

운영자의 공인 IP `/32`는 **VPC 안의 Subnet이 아닙니다.** 4장에서 보안 그룹이 어느 외부 주소에서 SSH 접속을 허용할지 나타내는 별도 범위입니다. `0.0.0.0/0`도 문맥에 따라 뜻이 달라집니다. Route Table에서는 기본 경로의 목적지이고, 보안 그룹에서는 모든 IPv4 출발지를 뜻합니다.

## 내 프로젝트에 연결하기

`[확인 활동]` VPC와 Subnet을 만들었다면 각각의 CIDR을 적고, Subnet이 VPC 안에 포함되는지 살펴보세요. 관리자의 `/32`가 등장하면 **목적지 경로**인지 **접속 허용 출발지**인지 함께 기록하세요. 플랫폼이 네트워크를 대신 관리한다면 VPC를 직접 만들지 않았다고 적으면 됩니다.

**한 문장 정리:** VPC와 Subnet은 사설 주소 범위를 정하고 나누며, CIDR의 숫자는 범위 크기를 읽는 열쇠입니다.
