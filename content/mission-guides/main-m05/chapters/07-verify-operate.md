# 7. 화면이 열린다는 것을 어떻게 확인하고 유지할까?

> `HTTP 200` 한 줄이면 동료의 컴퓨터에서도 웹사이트가 잘 보인다고 말할 수 있을까요?

## 확인할 층을 나누기

`[개념]` 한 단계의 성공은 다음 단계의 성공을 보장하지 않습니다. 빌드, 서버 내부 응답, 외부 연결, 브라우저 화면을 나누어 확인하면 문제 위치를 좁힐 수 있습니다.

| 층 | 확인 질문 | B3-1에서 남긴 증거 |
| --- | --- | --- |
| 빌드 | 공개 파일이 만들어졌나? | `npm run build` 성공, `dist/index.html` 생성 |
| 서버 설정 | 설정 문법과 내부 HTTP는 정상인가? | `nginx -t` 성공, `curl -I http://localhost`가 HTTP 200 |
| 외부 접속 | 외부 브라우저에서 보이나? | 당시 공개 주소의 용어사전 화면 확인 |
| 운영 | 새 버전과 비용을 관리하나? | 수동 재배포 절차와 정리 계획 문서화 |

출처: [B3-1 README](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/README.md#실제-검증과-동료-평가-url), [배포 기록](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/docs/deployment-log-2026-10-14.md). 이 기록으로 **현재 시점**의 가동 여부나 최신 소스 반영 여부는 확인할 수 없습니다. `[미확인]`

## 실패 메시지로 첫 확인 지점 찾기

| 증상 | 우선 확인할 것 |
| --- | --- |
| SSH 연결 시간 초과 | 현재 Public IP, 경로, 22번 보안 그룹 규칙, 현재 작업자 IP |
| `Permission denied (publickey)` | 사용자 이름, 키 파일, 인스턴스에 등록된 공개키 |
| 서버 내부 HTTP 200, 외부 브라우저 실패 | 80번 접근 규칙, Public IP·IGW 경로, 브라우저의 자산 요청 |
| 첫 화면은 열리지만 일부 화면 실패 | 브라우저 개발자 도구의 오류와 정적 파일 경로 |

이는 [B3-1 문제 해결 기록](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/docs/troubleshooting.md)의 **진단 순서**를 학습용으로 줄인 것입니다. SSH 접속 오류를 해결하려고 22번 포트를 모든 주소에 여는 식으로 원인 확인을 건너뛰지 마세요.

## 공개 후에도 남는 일

`[B3-1 사례]` Pages는 소스 `main` 푸시 후 별도 워크플로로 배포되지만, AWS EC2는 기록상 **수동으로 빌드 파일을 전송**합니다. [OIDC·S3·SSM 방식은 향후 설계](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/docs/deployment-update-and-automation.md)로, 실제 적용된 자동화가 아닙니다. 새 기능이 GitHub에 올라가도 AWS에 같은 버전이 보인다고 추정할 수 없습니다.

`[개념]` IAM은 “누가 어떤 AWS 작업을 할 수 있는가”를 다룹니다. 웹 방문자가 HTTP로 페이지를 보는 권한, 관리자가 SSH 키로 Linux에 로그인하는 자격, 작업자가 AWS API로 리소스를 만드는 **IAM 권한**은 서로 다릅니다. `[B3-1 사례]` 정적 파일만 제공한 EC2에는 IAM 인스턴스 프로필을 붙이지 않았고, 작업자 권한의 최소 범위가 실제로 검증되었다고 기록하지 않았습니다. 향후 SSM 자동화를 적용한다면 필요한 인스턴스 역할부터 새로 검토해야 합니다. [B3-1의 IAM 기록](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/README.md#iam-최소권한).

`[개념]` AWS 실습에서는 인스턴스를 쓰는 동안과 종료 후에도 남는 리소스의 비용을 확인해야 합니다. B3-1 기록은 EC2·Public IPv4·EBS를 확인하고, 평가가 끝난 뒤 정리하도록 계획했습니다. **예산 알림은 비용을 자동으로 막는 장치가 아닙니다.** 실제 요금·무료 혜택·현재 리소스는 계정과 시점에 따라 달라집니다. [AWS Budgets 안내](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-managing-costs.html).

## 내 프로젝트에 연결하기

`[확인 활동]` 내 결과물을 다른 기기에서 열어 보고, 배포한 커밋·확인 시각·URL과 화면 결과를 기록해 보세요. 공개 주소가 바뀌거나 서버를 종료했다면 오래된 검증 기록을 현재 상태로 소개하지 않습니다. 배포 자동화가 있다면 실제 실행 기록을, 없다면 수동 갱신 절차를 적으세요. AWS를 직접 썼다면 실습 종료 뒤 어떤 리소스가 남는지도 확인하세요.

**한 문장 정리:** 배포 완료는 빌드·내부 응답·외부 화면을 각각 확인하고, 이후 버전과 비용을 관리할 방법까지 아는 상태입니다.
