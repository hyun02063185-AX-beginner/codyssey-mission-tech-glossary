# 6. EC2와 Nginx는 각각 무엇을 할까?

> EC2가 켜져 있으면 `dist/`의 웹사이트가 자동으로 보일까요?

## 컴퓨터와 웹 서버 프로그램

`[개념]` EC2는 AWS에서 빌려 쓰는 가상 컴퓨터이고, Nginx는 그 안에서 HTTP 요청에 응답하는 **프로그램**입니다. 파일을 서버에 복사한 것과 파일을 웹으로 제공하는 것은 다른 단계입니다. Nginx에는 요청을 들을 포트와 파일을 찾을 위치(`root`)가 정해져 있어야 합니다.

`[B3-1 사례]` [Nginx 설정](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/deploy/b3-1/nginx.conf)은 TCP 80에서 요청을 받고 `/var/www/b3-1`을 문서 루트로 사용합니다. 빌드된 `dist`의 **내용물**을 이 경로에 복사했습니다. 따라서 브라우저가 `/`을 요청하면 Nginx가 `index.html`을 보낼 수 있습니다.

```
브라우저가 GET / 요청
  → 네트워크 규칙을 통과
  → EC2의 Nginx가 80번 포트에서 요청을 받음
  → /var/www/b3-1/index.html 및 필요한 정적 파일 반환
  → 브라우저가 JavaScript를 실행해 화면 표시
```

이 흐름은 정적 파일 제공을 단순화한 것입니다. `curl -I http://localhost`가 HTTP 200을 보여도 **브라우저 화면과 모든 JavaScript 파일이 제대로 동작했다는 뜻은 아닙니다.** B3-1은 서버 안의 응답과 외부 브라우저의 용어사전 화면을 별도로 확인했습니다. [검증 기록](https://github.com/hyun02063185-AX-beginner/Codyssey_B3-1/blob/c68929943f1904a5c7c8033d2d49a30ace56e3d1/docs/deployment-log-2026-10-14.md#검증-결과).

`[B3-1 사례]` 주소의 `/#/terms`에서 `#` 뒤쪽은 React의 `HashRouter`가 브라우저 안에서 해석합니다. HTTP 요청에서는 해시 부분이 서버로 전송되지 않습니다. 그러므로 Nginx가 `/terms`라는 서버 경로를 따로 제공해야 하는 구조가 아닙니다. B3-1의 Vite 설정은 상대 기본 경로(`base: './'`)였습니다.

## 내 프로젝트에 연결하기

`[확인 활동]` 내 배포에서 ① 공개 파일이 생기는 위치 ② HTTP 요청을 받는 서비스 ③ 정적 파일 루트 또는 호스팅 설정 ④ 브라우저가 화면을 그리는 방식을 찾아보세요. Nginx 대신 다른 웹 서버나 관리형 정적 호스팅을 사용할 수 있습니다.

**한 문장 정리:** EC2는 프로그램이 실행되는 컴퓨터이고, Nginx는 그 안에서 빌드 파일을 HTTP로 사용자에게 보내는 웹 서버입니다.
