# B2-1 강사용 노트 — 설명 깊이 조절을 위한 참고

> 학습자에게 의무적으로 가르칠 강의 대본이 아닙니다. 전공과 경험이 서로 다른 성인 초심자의 질문에 따라 설명의 깊이를 바꾸기 위한 참고자료입니다.

## 전체 운영 원칙

- 먼저 **기능 시연과 그림**을 보여주고, 기술 용어의 이름은 뒤에서 붙입니다.
- 그림의 한 문장을 설명할 수 있으면 해당 장의 기본 학습 목표는 도달한 것으로 봅니다.
- `ledger`라는 이름을 다른 학습자에게 강요하지 않습니다. `python app.py`와 `python -m 패키지`는 서로 다른 실행 방식의 예시입니다.
- Type Hint·Decorator·Generator를 쓴 **이유**와 **쓰지 않은 경우 가능한 다른 구현**을 함께 보여 주되, 모든 사람에게 동일한 코드를 요구하지 않습니다.
- 직접 소스 파일과 함수를 보는 활동은 선택입니다. 코드 이해 부족을 학습 목표 미달로 판단하지 않습니다.
- 원고의 `[요구 추적]`은 M03 저장소에 보존된 대응표에 근거합니다. 원본 코디세이 문서 확인 전에는 '공식이 반드시 이렇게 명시했다'고 단정하지 않습니다.

## 장별 포인트

### 01 CLI
**오해:** `-m`과 `--limit`이 같은 프로그램의 옵션이다. **정리:** Python 옵션과 사용자 프로그램 옵션은 소속이 다릅니다. `argparse`의 이름을 argument + parse로 풀고, CLI와 GUI를 비교한 뒤 명령을 분해하세요. `-`/`--` 관련 원문 문구 차이는 '확인 필요'로 남깁니다.

### 02 CRUD
**오해:** 클래스와 `dataclass`를 알아야 CRUD를 할 수 있다. **정리:** CRUD는 네 가지 기본 작업이고 객체는 데이터를 묶는 방법 가운데 하나입니다. 자료 구조를 배우기 전에 거래 한 건이 어떤 필드를 갖는지 질문하세요.

### 03 파일 저장
**오해:** 파일에 저장했으니 CSV와 JSONL이 자동으로 같은 상태다. **정리:** 영구 저장과 가져오기·내보내기는 다릅니다. 예시 JSONL·CSV 줄은 학습용 축약본임을 알려 주세요. 중복 import·ID 재발급은 M03 구현입니다.

### 04 Generator
**오해:** 최근 5건만 보여 주니 파일에서 5줄만 읽었다. **정리:** M03에서는 전체 파일을 읽으면서 `deque`가 5건만 유지합니다. `yield`와 `deque`는 서로 다른 역할입니다. Generator는 속도보다 **순차 전달·메모리 사용 방식**의 차이로 설명하세요.

### 05 검색·요약
**오해:** 데이터가 기능별로 여러 벌 저장된다. **정리:** 같은 거래를 어떤 규칙으로 처리하느냐에 따라 결과가 달라집니다. M03 월 예산은 거래를 막는 규칙이 아닌 보고용 비교 기준입니다.

### 06 안전한 수정
**오해:** 임시 파일과 `os.replace()`가 모든 파일 사고를 막는다. **정리:** 원본을 바로 덮어쓰는 위험을 줄이려는 설계입니다. 동시 쓰기 잠금이나 백업까지 해결하지 않습니다. M03 update/delete는 결과 전체를 리스트로 모은다는 점도 설명할 수 있습니다.

### 07 Decorator
**오해:** Decorator는 모든 오류를 잡아 없앤다. **정리:** M03에서는 예상된 `LedgerError`에 대해 공통 안내를 제공합니다. 의도치 않은 버그는 일부러 숨기지 않습니다. `@dataclass`와 `@handle_errors`는 문법은 같지만 목적이 다릅니다.

### 08 Type Hint
**오해:** `amount: int`가 잘못된 값의 실행을 자동으로 막는다. **정리:** Type Hint는 기대 자료형 안내이고, `argparse`의 형 변환과 Validator의 업무 규칙 검사는 별개의 층위입니다. Parameter / Argument는 이름보다 '받는 자리 / 실제 넣은 값'으로 시작하세요.

### 09 통합
**오해:** 모든 기술이 프로그램 실행 순서대로 한 번씩 실행된다. **정리:** CLI·Service·Repository는 역할 구분, Type Hint는 코드 안내, Decorator는 함수 호출 경로, Generator는 데이터 공급, CSV는 필요한 때만 데이터 교환에 관여합니다. 그림의 선 종류를 해설하세요.

## 강의 수준 조절 질문 (시험 문항 아님)

- "지금 내 프로그램을 사용한다면 어디에 어떤 명령을 입력하나요?"
- "거래를 추가했을 때 프로그램을 껐다 켜도 값이 남아 있나요? 어디에 남나요?"
- "같은 데이터를 보고 검색 결과와 합계가 달라지는 이유를 설명해 주실 수 있나요?"
- "AI가 만든 코드에서 이해한 내용과 아직 확인하지 못한 내용을 구분해 볼까요?"

대답을 강요하거나 점수화하지 않습니다. 학습자의 설명을 듣고 필요한 개념을 선택해 보충할 때 사용합니다.

## 자료 수정 전에 확인할 사항

- 각 장의 실제 코드 예시가 최신 M03 저장소와 여전히 맞는지
- 코디세이 공식 미션 원문에서 요구 표현을 독립적으로 확인했는지
- 다른 교육생의 실제 CLI·저장 형식·함수 구조에서도 공통 설명이 통하는지
- SVG의 관계선이 실제 실행 순서인지, 데이터 전달인지, 단순 역할 관계인지
