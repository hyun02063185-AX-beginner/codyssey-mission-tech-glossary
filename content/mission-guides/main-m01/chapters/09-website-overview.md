## 용어 나열이 아니라 협력으로 보기

HTML, CSS, JavaScript, localStorage, fetch, GitHub API, GitHub Pages — 이름만 나열하면 외울 것이 많아 보입니다. 하지만 하나의 질문으로 보면 단순해집니다.

> **사용자가 보는 "웹사이트 화면"을 만들기 위해 누가 무슨 일을 하는가?**

- **HTML**은 화면에 **무엇이 있는지**(내용·구조)를 정합니다.
- **CSS**는 그것이 **어떻게 보일지**(모양·화면 폭별 배치)를 정합니다.
- **JavaScript**는 사용자 행동에 **어떻게 반응할지**(동작·상태)를 정합니다.
- **브라우저 기능**은 JavaScript가 불러 쓰는 도구입니다. 이벤트를 알려 주고, 값을 기억하고(localStorage), 서버에 요청합니다(fetch).
- **GitHub API**는 화면에 쓸 **외부 데이터**를 줍니다.
- **GitHub Pages**는 이 모든 파일을 **인터넷에 공개**합니다.

## 한 장으로 보는 전체 구조

![V09: 위에서 아래로 보는 전체 구조도. 맨 위 GitHub Pages가 파일을 공개하고, 내 파일(HTML, CSS, JavaScript)을 브라우저가 읽고 실행합니다. 브라우저 안에는 웹사이트 화면과 JavaScript가 불러 쓰는 브라우저 기능(DOM·이벤트, Intersection Observer, localStorage, fetch)이 있고, fetch는 외부 서비스인 GitHub API와 요청과 응답을 주고받습니다. 아래에는 2장부터 8장까지 기능별로 HTML, CSS, JavaScript, 브라우저 기능, GitHub 중 누가 일하는지 카드로 정리되어 있습니다.](../assets/v09-website-overview.svg)

*교육용 단순화 모델입니다. 그림의 숫자는 해당 내용을 다룬 장입니다.*

### 그림 읽는 법

1. **위에서 아래로** 읽습니다. 맨 위 GitHub Pages가 내 파일을 **공개**하면, 방문자의 브라우저가 그 파일을 **받아 옵니다.**
2. **내 파일**은 세 가지입니다. HTML은 내용·구조, CSS는 모양, JavaScript는 동작을 맡습니다. (1장)
3. **브라우저 안**의 왼쪽은 HTML과 CSS가 만든 **화면**, 오른쪽은 JavaScript가 불러 쓰는 **브라우저 기능**입니다. 화살표는 "JavaScript가 오른쪽 기능으로 왼쪽 화면을 바꾼다"를 뜻합니다.
4. 오른쪽 기능 중 **fetch**는 브라우저 밖의 **GitHub API**와 **요청 ↔ 응답**을 주고받습니다. (7장) 양쪽 화살표는 서로 주고받는다는 뜻입니다.
5. 아래 **카드**는 2장부터 8장까지의 기능별로 **누가 일하는지**를 보여 줍니다. 채워진 칸이 그 기능에서 일하는 쪽이고, 점선 칸은 직접 일하지 않는 쪽입니다.

> **하나의 웹사이트는 HTML·CSS·JavaScript가 화면을 만들고, 브라우저 기능이 그 화면을 움직이며, 외부 서비스가 데이터를 주고, GitHub Pages가 그 전체를 세상에 공개하는 구조입니다.**

### 선이 뜻하는 것

이 가이드의 그림은 **선의 종류가 다르면 뜻이 다릅니다.** 지금까지 만난 것을 모아 보면 이렇습니다.

- **불러옴·연결**(점선): 파일이 파일을 불러온다(1장), 미리 등록해 둔다(4장), JavaScript가 기능을 불러 쓴다, Pages가 파일을 공개한다(8장)
- **대응**(짧은 선): 화면 구역과 HTML 요소의 짝(2장)
- **실행 순서**(번호 있는 실선): 클릭에서 화면 변경까지(4장), 테마 전환·복원(5장), 검증 분기(6장), 요청부터 렌더링까지(7장), 로컬에서 공개까지(8장)
- **주고받음**(양쪽 화살표): 요청 ↔ 응답(7장)
- **저장**(점선 상자): localStorage(5장)

## 방문자가 주소를 열면

전체 구조가 **시간 순서로** 어떻게 움직이는지 한 번 따라가 봅니다. 괄호는 해당 내용을 다룬 장입니다. `[AI 보충]` 교육용 단순화이며, 실제로는 더 많은 일이 동시에 일어납니다.

1. 방문자가 **공개 URL**을 엽니다. GitHub Pages가 `index.html`을 내려 줍니다. (8장)
2. 브라우저가 `index.html`을 읽으면서 `link`·`script`가 가리키는 **CSS·JavaScript·이미지**를 불러옵니다. (1장)
3. 브라우저가 HTML로 **구조(DOM)** 를 만들고 CSS로 **모양**을 입혀 화면을 그립니다. 폭에 따라 규칙이 달라집니다. (2·3장)
4. HTML을 다 읽은 뒤 **JavaScript가 실행**됩니다. (`defer`) 가장 먼저 이런 일을 합니다.
   - 저장된 **테마를 읽어** 적용합니다. (5장)
   - 버튼·폼에 **이벤트를 등록**합니다. (4·6장)
   - 섹션을 **관찰 대상**으로 등록합니다. (4장)
   - **GitHub API에 요청**을 보냅니다. 응답을 기다리는 동안은 **로딩 상태**입니다. (7장)
5. GitHub API의 **응답**이 오면 JavaScript가 확인하고 가공해 **카드**로 그리거나 오류·빈 결과 안내를 보여 줍니다. (7장)
6. 방문자가 **누르고, 스크롤하고, 입력합니다.** 등록된 함수가 불려 DOM을 바꾸고(4장), 폼은 검증해 오류를 보여 주며(6장), 다크모드는 바꾸고 **저장**합니다(5장).
7. 다음에 방문자가 다시 오면 4번에서 **저장된 테마**가 복원됩니다.

이 흐름 속에서 앞에서 배운 모든 개념이 **각자의 자리**에서 일합니다.

## 💻 PC에서 보는 전체 관계도

모바일용 그림은 위에서 아래로 읽도록 세로로 만들었습니다. 화면이 넓다면 **같은 내용을 한 장에서** 보는 그림이 관계를 파악하기 쉽습니다.

![V09 PC용: 가운데 웹사이트 화면을 중심으로, 왼쪽에 내 파일 세 가지(JavaScript, CSS, HTML)가 DOM 변경·모양 적용·구조 생성으로 연결되고, 오른쪽에 JavaScript가 불러 쓰는 브라우저 기능 네 가지(DOM·이벤트, Intersection Observer, localStorage, fetch)가 있습니다. fetch는 오른쪽 아래의 GitHub API와 요청과 응답으로 이어지고, 왼쪽 아래의 GitHub Pages는 내 파일을 공개합니다.](../assets/v09-website-overview-wide.svg)

*PC용 보조 그림입니다. 내용은 위의 세로 그림과 같습니다.*

### 그림 읽는 법

- **가운데**가 사용자가 보는 **웹사이트 화면**입니다. 안의 작은 상자는 장별 기능입니다.
- **왼쪽 세 상자**(내 파일)에서 화면으로 가는 실선은 **실행**입니다. JavaScript는 DOM을 바꾸고, CSS는 모양을 입히고, HTML은 구조를 만듭니다.
- **위쪽을 도는 점선**은 JavaScript가 **오른쪽의 브라우저 기능**을 불러 쓴다는 뜻입니다.
- **화면과 브라우저 기능 사이 양쪽 화살표**는 화면에서 일어난 일(클릭·스크롤)이 기능으로 알려지고, 기능의 결과(테마·데이터)가 화면에 반영되는 **서로 주고받음**입니다.
- **오른쪽 아래**: fetch ↔ GitHub API는 **요청과 응답**입니다. 점선 상자의 localStorage는 값을 **저장**하는 곳입니다.
- **왼쪽 아래**: GitHub Pages가 점선으로 내 파일 세 가지를 **공개**합니다.

## 핵심 내용 정리

- 웹사이트의 모든 기술은 **사용자가 보는 화면 하나**를 만들고 움직이고 공개하기 위해 일합니다.
- **HTML(내용·구조) · CSS(모양) · JavaScript(동작)** 가 화면을 만들고, **브라우저 기능**(이벤트, localStorage, fetch)이 JavaScript를 돕고, **GitHub API**가 데이터를, **GitHub Pages**가 공개를 맡습니다.
- 어떤 기능이든 **"누가 일하는가?"** 를 물으면 설명할 수 있습니다. 직접 일하지 않는 쪽까지 구분하면 더 정확합니다.

이 가이드의 모든 그림은 같은 방식으로 그렸습니다. 선의 종류를 구분하며 읽으면, 새 코드를 만나도 **어디에서 무슨 일을 하는지** 짚어 낼 수 있습니다.
