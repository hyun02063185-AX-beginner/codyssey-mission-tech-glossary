# Chapter 2 — 웹페이지의 구역은 코드에서 어떻게 구분될까?

> 화면을 스크롤하면 소개, 기술, 프로젝트, 연락처가 구역별로 나뉘어 보입니다. 눈으로는 쉽게 나뉘는데, **코드에서는 이 구역을 어떻게 구분할까요?**

**이 장에서 알게 되는 것**

- 화면의 구역이 코드에서는 **어떤 태그**로 만들어지는지
- `div`가 아니라 `section`·`header`처럼 **의미 있는 태그**를 쓰는 이유
- 메뉴를 누르면 해당 구역으로 이동하는 **원리**(`id`와 `#`)

📱 앞부분(그림까지)만 읽어도 핵심을 알 수 있습니다. 💻 뒤쪽은 컴퓨터 앞에서 내 프로젝트를 열고 읽으면 좋습니다.

> 표기 규칙(`[공식]` `[사전]` `[권장]` `[AI 보충]`)은 [README](../README.md#표기-규칙)를 참고하세요.

## 눈으로 보는 구역과 코드의 구역

> **화면의 구역은 어떤 기준으로 구분할까?** `[시나리오]`

화면에서 구역을 나누는 것은 **배경색과 간격** 같은 모양입니다. 그런데 모양은 CSS의 일입니다. 1장에서 보았듯 CSS를 끄면 색과 간격은 사라지지만, **구역 자체는 코드에 그대로 남아 있습니다.** 그 구역을 만드는 것이 **HTML의 태그**입니다.

미션은 **Hero·About·Skills·Projects·Contact·Footer** 여섯 구역을 요구합니다. `[공식]` 이 구역들이 코드에서 어떻게 보이는지 그림으로 먼저 살펴봅니다.

## 화면 구역과 HTML 요소 한눈에 보기

![V02: 화면의 구역(메뉴·Hero·About·Skills·Projects·Contact·Footer)과 그것을 만드는 HTML 요소(header, main 안의 section 다섯 개, footer)를 선으로 연결한 대응도. 아래에는 div class="header"와 header 태그의 차이, 그리고 화면 구역과 요소가 항상 1:1로 대응하지는 않는다는 주의가 있습니다.](../assets/v02-html-structure.svg)

*일반화한 구성 예입니다. 내 프로젝트의 구조는 다를 수 있습니다.*

### 그림 읽는 법

1. **왼쪽 화면**의 구역 하나를 고릅니다. (예: Projects)
2. **선**을 따라 오른쪽으로 가면 `<section id="projects">`가 나옵니다.
3. 점선 테두리 **`<main>`** 이 다섯 구역을 감싸고 있습니다. 서로 안에 들어 있는 **포함 관계**입니다.
4. 맨 아래 비교 상자에서는 `<div class="header">`와 `<header>`의 차이를 보여 줍니다.

이 그림의 선은 **대응 관계**입니다. 코드가 실행되는 순서가 아닙니다. (4장 V04의 번호 화살표와 구별하세요.)

> **구역과 요소가 언제나 1:1은 아닙니다.** 실제 HTML 구조에 따라 이렇게 달라질 수 있습니다. `[AI 보충]`
>
> - 한 구역이 **여러 요소가 겹쳐서** 만들어질 수 있습니다. (`section` 안에 스타일용 `div`가 한 겹 더 있는 경우)
> - 한 요소가 **여러 구역을 감쌀 수** 있습니다. (`main`은 Hero~Contact 전체를 감싸고, `header`가 Hero까지 품기도 합니다)
> - **두 구역이 한 요소에** 있을 수 있습니다. (About과 Skills를 한 `section`에 합친 경우)
> - 화면에서는 구역처럼 안 보이는 요소도 있습니다. (배경 장식용·레이아웃용 `div`)
>
> 그래서 "이 구역 = 이 태그 하나"로 외우기보다, **"내 사이트에서 이 구역을 감싸는 요소가 무엇인가"** 를 개발자 도구로 직접 확인하세요. 구역 전체를 감싸는 **가장 바깥 요소**를 찾는 것이 요령입니다.

## 태그에 의미가 있다는 것

[시맨틱 HTML](../../../terms/semantic-html.md)은 **겉모양이 아니라 내용의 역할을 이름으로 알려 주는 태그**를 쓰는 방식입니다. `[사전]`

이 미션에서 자주 만나는 태그입니다. `[사전]` `[AI 보충]`

- `<header>` — 머리말 영역. 맨 위 로고와 메뉴
- `<nav>` — 이동 링크 모음. 메뉴 항목들
- `<main>` — 페이지의 핵심 내용. 보통 한 개이며 Hero~Contact를 감쌈
- `<section>` — 주제가 하나인 구역. 보통 제목과 함께. About, Skills, Projects 등
- `<article>` — 따로 떼어도 이해되는 독립 덩어리. 프로젝트 카드 하나
- `<footer>` — 바닥글 영역. 저작권, 연락처
- `<h1>`~`<h3>` — 제목(단계가 있음)
- `<a>`, `<form>` — 링크, 입력받는 양식

### 태그와 `class`는 다릅니다

- **태그**(`<header>`)는 요소의 **종류와 역할**입니다. 브라우저, 검색 도구, 화면 낭독기가 읽습니다.
- **class**(`class="header"`)는 개발자가 붙인 **이름표**입니다. 주로 CSS와 JavaScript가 사용합니다.

`<div class="header">`는 이름만 header일 뿐, 브라우저에게는 **의미 없는 상자**입니다. V02 아래쪽 비교 상자가 이 차이입니다. `[사전]`

### 의미가 있으면 무엇이 좋을까?

- 눈으로 보기 어려운 사람이 쓰는 **화면 낭독기** 같은 도구가 "메뉴", "본문", "바닥글"로 **바로 이동**할 수 있습니다.
- 검색 도구가 페이지 구조를 파악하기 쉽습니다.
- 코드를 보는 사람(나, 동료, **AI**)이 **구조를 빨리 이해**합니다. 동료평가에서 코드를 볼 때도 마찬가지입니다.

`[사전]` 시맨틱 HTML 항목의 설명(보조기술, 검색 도구, 다른 개발자)을 풀어 쓴 것입니다.

### 제목(`h1`~`h6`)은 글자 크기가 아니라 차례입니다

제목 태그의 숫자는 **단계**입니다. 책의 장·절 번호처럼 읽으세요. 글자가 크게 보이는 것은 브라우저의 기본 모양일 뿐이고, 크기는 CSS가 바꿉니다. `[사전]`

```
h1  김코디 포트폴리오     ← 페이지 전체 제목
 ├ h2  About              ← 구역 제목
 ├ h2  Skills
 ├ h2  Projects
 │   ├ h3  프로젝트 1     ← 카드 제목
 │   └ h3  프로젝트 2
 └ h2  Contact
```

제목만 훑어도 페이지 구조가 보이면 잘 만든 것입니다. 제목 단계를 건너뛰어(`h1` 다음에 갑자기 `h4`) 쓰면 "차례"가 어색해집니다.

## 메뉴를 누르면 어떻게 그 구역으로 갈까?

메뉴 항목을 누르면 주소 끝에 `#projects` 같은 글자가 붙으면서 해당 구역으로 이동합니다. 이 글자가 **구역의 이름표**입니다.

```
<a href="#projects">Projects</a>
        ↓ 같은 이름을 찾아 이동
<section id="projects"> … </section>
```

- `id="projects"` — 구역에 **이름표**를 붙입니다. 페이지 안에서 **하나뿐**이어야 합니다.
- `href="#projects"` — 그 이름표를 가진 곳으로 이동하라는 링크입니다.

이 연결은 **이름이 같을 때만** 작동합니다. 한 글자라도 다르면 메뉴를 눌러도 아무 일도 일어나지 않습니다. 이것은 **참조 관계**(이름으로 가리킴)이며 "실행 순서"가 아닙니다.

## 브라우저는 이것을 "나무"로 만듭니다

브라우저는 HTML을 읽어 **부모-자식 관계의 나무 구조**를 메모리에 만드는데, 이것을 [DOM](../../../terms/dom.md)이라고 합니다. 4장에서 JavaScript가 이 나무를 바꾸는 방법을 다룹니다. 지금은 **"HTML의 포함 관계가 곧 나무 구조"** 라는 것만 기억하면 됩니다. `[사전]`

```
body
 ├ header
 │   └ nav
 ├ main
 │   ├ section#hero
 │   ├ section#about
 │   ├ section#skills
 │   ├ section#projects ── article × 3
 │   └ section#contact  ── form
 └ footer
```

## 💻 개발자 도구로 구역의 태그 확인하기

### 개발자 도구로 구역의 태그 보기

1. **F12**로 개발자 도구를 열고, 왼쪽 위의 **화살표 모양 버튼**을 누릅니다. (`Ctrl + Shift + C`, Mac은 `Cmd + Shift + C`)
2. 화면에서 구역 하나(예: About)의 **빈 곳**에 마우스를 올리면 그 구역이 색으로 칠해집니다.
3. 클릭하면 아래 **Elements** 패널에서 선택된 줄이 보입니다. `<section …>`처럼 `<`로 시작하는 이름이 그 구역의 태그입니다.

클릭한 요소가 구역의 **안쪽 조각**(글자, 카드, 감싸는 `div`)일 수도 있습니다. Elements에서 **위쪽 줄(부모)** 로 올라가며 구역 전체를 감싸는 바깥 요소를 찾아보세요. 눈에 보이던 "다른 색 구역"이 코드에서는 **이름을 가진 요소**라는 것이 보입니다.

### 메뉴가 이름표를 따라가는 모습 보기

메뉴 항목 하나를 누른 뒤 주소창 맨 끝을 보세요. `#projects`처럼 `#`으로 시작하는 글자가 붙어 있습니다. Elements에서 `id="projects"`를 찾으면 그 구역에 같은 이름표가 달려 있습니다.

## 내 프로젝트에서 구역 구조 찾아보기

### 찾는 방법

- **화면 → 코드**: 개발자 도구의 화살표 버튼(`Ctrl+Shift+C`)으로 구역을 클릭해 Elements에서 태그를 확인합니다.
- **코드 → 화면**: Elements에서 `<section …>` 줄 위에 마우스를 올리면 화면에서 그 구역이 칠해집니다.
- **편집기 검색**: `Ctrl+Shift+F`로 `<section`, `<header`, `<main`, `<footer`, `id="`, `<h1`, `<h2`를 검색합니다.

### 일반화 예제 — 구조만 보는 뼈대

> 🔷 **일반화 예제** 구조를 보여 주려고 새로 쓴 코드입니다. 내용은 `…`로 줄였습니다. **내 프로젝트의 코드가 아닙니다.**

```html
<body>
  <header>
    <nav>
      <a href="#about">About</a>
      <a href="#projects">Projects</a>
      <a href="#contact">Contact</a>
    </nav>
  </header>

  <main>
    <section id="hero">
      <h1>안녕하세요, 김코디입니다</h1>
    </section>

    <section id="about">
      <h2>About</h2>
      <p>…</p>
    </section>

    <section id="projects">
      <h2>Projects</h2>
      <article><h3>프로젝트 1</h3></article>
      <article><h3>프로젝트 2</h3></article>
    </section>

    <section id="contact">
      <h2>Contact</h2>
      <form>…</form>
    </section>
  </main>

  <footer>
    <p>© 2026 김코디</p>
  </footer>
</body>
```

이 코드는 이렇게 읽습니다.

- `<a href="#about">`와 `<section id="about">`은 **이름이 같아서** 연결됩니다.
- `<main>` 안에 `section`들이 들어 있어 핵심 내용이 **구역으로 나뉩니다.**
- `h1`은 하나, 구역마다 `h2`, 카드마다 `h3`로 **제목 단계가 차례**를 이룹니다.

### "이름만 있는 태그"를 찾는 방법

편집기 검색창에 `class="header"`, `class="footer"`, `class="hero"`를 넣어 보세요. 해당 줄이 **`<div>`로 시작한다면** 이름표(class)만 있고 태그 의미는 없는 경우입니다. 반드시 잘못은 아니지만, **"왜 `header`·`section`이 아니라 `div`인가요?"** 라는 질문에는 답할 수 있어야 합니다.

### 구현 상태 점검

- Hero, About, Skills, Projects, Contact, Footer 여섯 구역이 모두 있다 `[공식]`
- `header`, `main`, `footer` 같은 의미 태그가 있다 `[공식]`
- 구역마다 적절한 제목 태그가 있다 `[공식]`, 단계가 `h1 → h2 → h3`처럼 건너뛰지 않는다 `[권장]`
- 메뉴의 `href="#…"`와 구역의 `id="…"`가 **글자까지 똑같다** `[권장]` (메뉴가 안 움직이는 가장 흔한 원인)
- 의미 없는 `div`만 줄줄이 나열하지 않았다 `[공식]`

## AI에게 구조를 설명시키는 법

> 1장의 네 가지 규칙(**수정하지 말고 설명만 / 파일·줄 번호 / 내 화면과 연결 / 답은 가설**)을 그대로 적용합니다.

> **구조 지도**
> 이 프로젝트의 `index.html`에서 Hero, About, Skills, Projects, Contact, Footer 구역이 **어떤 태그와 `id`**로 만들어졌는지 표로 정리해 줘. 파일 이름과 줄 번호를 같이 알려 주고, 코드는 수정하지 마. 초보자가 이해할 수 있는 말로 설명해 줘.

> **제목 흐름 점검**
> `index.html`의 제목 태그(`h1`~`h6`)를 위에서 아래로 목록으로 뽑아 줘. 단계가 건너뛰거나 `h1`이 여러 개인 곳이 있는지 알려 주고, 있다면 줄 번호로 알려 줘. 고치지는 말고 설명만.

> **div와 시맨틱 태그**
> 이 프로젝트에서 `div`로 만든 곳 중에 `header`·`nav`·`main`·`section`·`footer` 같은 시맨틱 태그로 바꿀 수 있는 곳이 있는지 알려 줘. **바꾸지는 말고**, 어느 줄이 왜 바꿀 후보인지만 설명해 줘. 바꾸지 않아도 되는 곳은 그 이유도 말해 줘.

> **메뉴 연결 검사**
> 메뉴의 `href="#…"` 값과 구역의 `id` 값이 서로 맞는지 모두 비교해 표로 보여 줘. 맞지 않는 항목이 있으면 줄 번호로 알려 줘. 수정은 하지 마.

### AI의 답을 확인하는 법

| AI가 말한 것 | 내가 확인할 것 |
| --- | --- |
| "`id="projects"`가 있습니다" | 편집기에서 `id="projects"`를 검색해 1개만 나오는지 |
| "`h1`이 하나입니다" | `<h1` 검색 결과 개수 |
| "이 `div`는 바꿀 후보입니다" | 그 `div`가 정말 머리말·구역·바닥글 역할인지 **화면과 비교** |

## 한 번에 정리하기

- 화면의 구역은 코드에서 **의미를 가진 태그**로 구분됩니다. 다만 구역과 요소가 **항상 1:1은 아닙니다.**
- 제목 태그는 글자 크기가 아니라 **차례**이고, 메뉴와 구역은 **`id`와 `#`** 로 이어집니다.
- 눈으로 보는 구분은 CSS, 코드의 구분은 HTML이 만듭니다.
