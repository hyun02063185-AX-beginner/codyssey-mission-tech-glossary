## 3. 선 — 개념의 역할과 연결 관계

```
화면 구역 → HTML 요소 → 태그 의미 → 문서 구조
```

### 3-1. 이 선은 무슨 뜻일까?

| 연결 | 관계의 종류 | 쉬운 말 |
| --- | --- | --- |
| 화면 구역 → HTML 요소 | **대응** | 눈에 보이는 한 덩어리는 코드에서도 한 덩어리(요소)입니다 |
| HTML 요소 → 태그 의미 | **이름(역할)** | 요소의 이름(`header`, `section` …)이 그 덩어리의 **역할**을 알려 줍니다 |
| 태그 의미 → 문서 구조 | **포함·순서** | 이 역할들이 서로 안에 들어 있고 위아래로 놓이며 **문서의 뼈대**가 됩니다 |

> 눈으로 보는 구분은 **CSS**(배경색·간격)가 만들고, 코드의 구분은 **HTML**이 만듭니다. 둘은 겹치지만 **같은 것이 아닙니다.** CSS를 지워도 HTML 구분은 남습니다. (1장 관찰 ③에서 확인한 것과 같습니다.)

### 3-2. 의미 있는 태그 — "시맨틱 HTML"

[시맨틱 HTML](../../../terms/semantic-html.md)은 **겉모양이 아니라 내용의 역할을 이름으로 알려 주는 태그**를 쓰는 방식입니다. `[사전]`

이 미션에서 자주 만나는 태그입니다. `[사전]` `[AI 보충]`

| 태그 | 역할 | 이 사이트에서는 |
| --- | --- | --- |
| `<header>` | 머리말 영역 | 맨 위 로고·메뉴 |
| `<nav>` | 이동 링크 모음 | 메뉴 항목들 |
| `<main>` | 페이지의 핵심 내용 (보통 한 개) | Hero~Contact를 감쌈 |
| `<section>` | 주제가 하나인 구역 (보통 제목과 함께) | About, Skills, Projects 등 |
| `<article>` | 따로 떼어도 이해되는 독립 덩어리 | 프로젝트 카드 하나 |
| `<footer>` | 바닥글 영역 | 저작권, 연락처 |
| `<h1>`~`<h3>` | 제목 (단계가 있음) | 아래 3-3 |
| `<a>` | 링크 | 메뉴 항목, 프로젝트 보기 |
| `<form>` | 입력받는 양식 | Contact 폼 |

### 3-3. 제목(`h1`~`h6`)은 글자 크기가 아니라 **차례**입니다

제목 태그의 숫자는 **단계**입니다. 책의 장·절 번호처럼 읽으세요. 글자가 크게 보이는 것은 브라우저의 기본 모양일 뿐이고, 크기는 CSS가 바꿉니다. `[사전]`

```
h1  김코디 포트폴리오            ← 페이지 전체의 제목 (보통 하나)
 ├ h2  About                     ← 구역 제목
 ├ h2  Skills
 ├ h2  Projects
 │   ├ h3  프로젝트 1            ← 카드 제목
 │   └ h3  프로젝트 2
 └ h2  Contact
```

제목만 훑어도 페이지 구조가 보이면 잘 만든 것입니다. 제목 단계를 건너뛰어(`h1` 다음에 갑자기 `h4`) 쓰면 "차례"가 어색해집니다.

### 3-4. 메뉴가 구역을 찾아가는 방법 — `id`와 `#`

관찰 ②에서 본 `#projects`는 이렇게 이어집니다.

```
<a href="#projects">Projects</a>   →   <section id="projects"> … </section>
 (메뉴 링크: "이름이 projects인 곳으로")      (구역: "내 이름표는 projects")
```

| 코드 | 역할 |
| --- | --- |
| `id="projects"` | 구역에 **이름표**를 붙임 (페이지 안에서 **하나뿐**이어야 함) |
| `href="#projects"` | 그 이름표를 가진 곳으로 이동하라는 링크 |

이 연결은 **이름이 같을 때만** 작동합니다. 한 글자라도 다르면 메뉴를 눌러도 아무 일도 일어나지 않습니다. 이것은 **참조 관계**(이름으로 가리킴)이며 "실행 순서"가 아닙니다.

### 3-5. 태그와 `class`는 다릅니다

| | 무엇인가 | 누가 쓰나 |
| --- | --- | --- |
| **태그** (`<header>`) | 요소의 **종류와 역할** | 브라우저, 검색 도구, 화면 낭독기 |
| **class** (`class="header"`) | 개발자가 붙인 **이름표** (CSS가 모양을 줄 때 사용) | 주로 CSS·JavaScript |

`<div class="header">`는 이름만 header일 뿐, 브라우저에게는 **의미 없는 상자**입니다. V02 아래쪽 비교 그림이 이 차이입니다. `[사전]`

### 3-6. 의미가 있으면 무엇이 좋을까?

- 눈으로 못 보는 사람이 쓰는 **화면 낭독기** 같은 도구가 "메뉴", "본문", "바닥글"로 **바로 이동**할 수 있습니다.
- 검색 도구가 페이지 구조를 파악하기 쉽습니다.
- 코드를 보는 사람(나, 동료, **AI**)이 **구조를 빨리 이해**합니다. 동료평가에서 코드를 볼 때도 마찬가지입니다.

`[사전]` 위 내용은 시맨틱 HTML 항목의 설명(보조기술, 검색 도구, 다른 개발자)을 풀어 쓴 것입니다.

### 3-7. 브라우저는 이것을 "나무"로 만듭니다 (맛보기)

브라우저는 HTML을 읽어 **부모-자식 관계의 나무 구조**를 메모리에 만드는데, 이것을 [DOM](../../../terms/dom.md)이라고 합니다. 4장에서 JavaScript가 이 나무를 바꾸는 방법을 다룹니다. 지금은 **"HTML의 포함 관계가 곧 나무 구조"** 라는 것만 기억하세요. `[사전]`

```
body
 ├ header
 │   └ nav
 ├ main
 │   ├ section#hero
 │   ├ section#about
 │   ├ section#skills
 │   ├ section#projects ── article × 3
 │   └ section#contact  ── form
 └ footer
```

## 4. 면 — V02: 화면 구역과 HTML 요소의 대응

![V02: 화면의 구역(메뉴·Hero·About·Skills·Projects·Contact·Footer)과 그것을 만드는 HTML 요소(header, main 안의 section 다섯 개, footer)를 선으로 연결한 대응도. 아래에는 div class="header"와 header 태그의 차이가 비교되어 있습니다.](../assets/v02-html-structure.svg)

**일반화한 구성 예**입니다. 내 프로젝트는 Hero를 `header` 안에 넣거나, 카드를 `article` 대신 `div`로 만들거나, About과 Skills를 한 `section`에 합쳤을 수 있습니다. **구조가 다르면 다른 대로 설명하면 됩니다.** 중요한 것은 "내 사이트에서는 이렇게 대응된다"는 근거입니다.

### 그림 읽는 순서

1. **왼쪽 화면**의 구역 하나를 고릅니다. (예: Projects)
2. **선**을 따라 오른쪽 HTML로 갑니다. `<section id="projects">`입니다.
3. 점선 테두리 **`<main>`** 이 다섯 구역을 감싸고 있는지 봅니다. (**포함 관계**)
4. 맨 아래 비교 상자에서 `<div class="header">`와 `<header>` 중 어느 쪽이 **의미를 가진 쪽**인지 말해 봅니다.

이 그림의 선은 **대응 관계**입니다. 코드가 실행되는 순서를 나타내는 선이 아닙니다. (4장 V04의 번호 화살표와 구별하세요.)

### 면 — 한 문장

> **구역마다 알맞은 이름의 태그를 쓰고 그 태그들이 서로 포함·나열되어, 사람과 도구 모두가 읽을 수 있는 문서 구조가 됩니다.**

## 5. 코드 확인 — 내 프로젝트에서 찾기

### 5-1. 찾는 방법

| 방법 | 어떻게 |
| --- | --- |
| 화면 → 코드 | 개발자 도구의 화살표 버튼(`Ctrl+Shift+C`)으로 구역 클릭 → Elements에서 태그 확인 |
| 코드 → 화면 | Elements에서 `<section …>` 줄 위에 마우스를 올리면 화면에서 그 구역이 칠해짐 |
| 편집기 검색 | `Ctrl+Shift+F`로 `<section`, `<header`, `<main`, `<footer`, `id="`, `<h1`, `<h2` 검색 |

### 5-2. 일반화 예제 — 구조만 보는 뼈대

> 🔷 **일반화 예제** 구조를 보여 주려고 새로 쓴 코드입니다. 내용은 `…`로 줄였습니다. **내 프로젝트의 코드가 아닙니다.**

```html
<body>
  <header>
    <nav>
      <a href="#about">About</a>
      <a href="#projects">Projects</a>
      <a href="#contact">Contact</a>
    </nav>
  </header>

  <main>
    <section id="hero">
      <h1>안녕하세요, 김코디입니다</h1>
    </section>

    <section id="about">
      <h2>About</h2>
      <p>…</p>
    </section>

    <section id="projects">
      <h2>Projects</h2>
      <article><h3>프로젝트 1</h3><p>…</p></article>
      <article><h3>프로젝트 2</h3><p>…</p></article>
    </section>

    <section id="contact">
      <h2>Contact</h2>
      <form>…</form>
    </section>
  </main>

  <footer>
    <p>© 2026 김코디</p>
  </footer>
</body>
```

| 줄을 이렇게 읽습니다 | 뜻 |
| --- | --- |
| `<a href="#about">` ↔ `<section id="about">` | 이름이 같아서 연결됨 |
| `<main>` 안에 `section`들 | 핵심 내용이 구역으로 나뉨 |
| `h1` 하나, 구역마다 `h2`, 카드마다 `h3` | 제목 단계가 차례를 이룸 |

### 5-3. 내 사이트의 대응표 (직접 채우기)

| 화면의 구역 | 감싸는 태그 | `id` | 제목 태그와 글자 | 코드 위치 (파일 : 줄) |
| --- | --- | --- | --- | --- |
| 메뉴 줄 | | — | — | |
| Hero | | | | |
| About | | | | |
| Skills | | | | |
| Projects | | | | |
| Contact | | | | |
| Footer | | — | — | |

### 5-4. 점검 체크리스트 `[공식]`

- ☐ Hero, About, Skills, Projects, Contact, Footer 여섯 구역이 모두 있다.
- ☐ `header`, `main`, `footer`가 있다.
- ☐ 구역마다 제목 태그가 있고, 단계가 `h1 → h2 → h3`처럼 자연스럽다.
- ☐ 메뉴의 `href="#…"`와 구역의 `id="…"`가 **글자까지 똑같다.**
- ☐ 의미 없는 `div`만 줄줄이 나열하지 않았다.

### 5-5. 빠르게 "이름만 있는 태그" 찾기

편집기 검색창에 `class="header"`, `class="footer"`, `class="hero"`를 넣어 보세요. 해당 줄이 **`<div>`로 시작한다면** 이름표(class)만 있고 태그 의미는 없는 경우입니다. 반드시 잘못은 아니지만, **"왜 `header`·`section`이 아니라 `div`인가요?"** 라는 질문에 답할 수 있어야 합니다.

## 6. AI에게 물어보기

> 1장의 네 가지 규칙(**수정하지 말고 설명만 / 파일·줄 번호 / 내 화면과 연결 / 답은 가설**)을 그대로 적용합니다.

> **① 구조 지도**
> 이 프로젝트의 `index.html`에서 Hero, About, Skills, Projects, Contact, Footer 구역이 **어떤 태그와 `id`**로 만들어졌는지 표로 정리해 줘. 파일 이름과 줄 번호를 같이 알려 주고, 코드는 수정하지 마. 초보자가 이해할 수 있는 말로 설명해 줘.

> **② 제목 흐름 점검**
> `index.html`의 제목 태그(`h1`~`h6`)를 위에서 아래로 목록으로 뽑아 줘. 단계가 건너뛰거나 `h1`이 여러 개인 곳이 있는지 알려 주고, 있다면 줄 번호로 알려 줘. 고치지는 말고 설명만.

> **③ div와 시맨틱 태그**
> 이 프로젝트에서 `div`로 만든 곳 중에 `header`·`nav`·`main`·`section`·`footer` 같은 시맨틱 태그로 바꿀 수 있는 곳이 있는지 알려 줘. **바꾸지는 말고**, 어느 줄이 왜 바꿀 후보인지만 설명해 줘. 바꾸지 않아도 되는 곳은 그 이유도 말해 줘.

> **④ 메뉴 연결 검사**
> 메뉴의 `href="#…"` 값과 구역의 `id` 값이 서로 맞는지 모두 비교해 표로 보여 줘. 맞지 않는 항목이 있으면 줄 번호로 알려 줘. 수정은 하지 마.

### AI 답을 확인하는 법

| AI가 말한 것 | 내가 확인할 것 |
| --- | --- |
| "`id="projects"`가 있습니다" | 편집기에서 `id="projects"` 검색, 1개만 나오는지 |
| "`h1`이 하나입니다" | `<h1` 검색 결과 개수 |
| "이 `div`는 바꿀 후보입니다" | 그 `div`가 정말 머리말·구역·바닥글 역할인지 **화면과 비교** |

## 7. 자기 설명

### 빈칸 설명 틀

> 화면의 구역은 코드에서 `________` 같은 태그로 나뉩니다.
> 예를 들어 우리 사이트의 `________` 구역은 `________` 태그와 `id="________"`로 만들어졌고, 메뉴의 `href="#________"`가 이것을 가리킵니다.
> 같은 모양이어도 `div`가 아니라 `section`·`header`를 쓰는 이유는 `________` 때문입니다.

### 좋은 설명의 기준

- ☐ 눈에 보이는 구분(CSS)과 코드의 구분(HTML)을 **구별해서** 말했다.
- ☐ 메뉴와 구역이 **`id`로 이어진다**는 것을 내 사이트의 실제 이름으로 말했다.
- ☐ "시맨틱 태그가 예뻐 보이게 한다"고 **말하지 않았다.** (의미를 알려 주는 것이지 모양이 아닙니다.)

### 동료평가에서 받을 수 있는 질문 `[공식]`

- 시맨틱 태그를 쓰면 구조 이해에 어떤 도움이 되나요?
- 겉모양이 같은 두 페이지에서 시맨틱 태그 사용이 왜 차이를 만들까요?

### 흔한 함정 `[공식]`

| 함정 | 확인 방법 |
| --- | --- |
| 섹션 이름은 화면에 있는데 의미 구조는 없음 | 개발자 도구에서 구역의 태그 이름 확인 |
| `class`만 `hero`·`footer`이고 태그는 전부 `div` | `class="hero"` 등 검색 |

## 정리

- 화면의 구역은 코드에서 **의미를 가진 태그**로 구분됩니다.
- 제목 태그는 글자 크기가 아니라 **차례**이고, 메뉴와 구역은 **`id`와 `#`** 로 이어집니다.
- 눈으로 보는 구분은 CSS, 코드의 구분은 HTML이 만듭니다.
