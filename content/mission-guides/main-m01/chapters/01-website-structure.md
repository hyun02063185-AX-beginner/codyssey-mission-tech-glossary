# Chapter 1 — 웹사이트는 어떤 파일들로 만들어질까?

> AI가 만들어 준 프로젝트 폴더를 열면 `index.html`, `css`, `js`, `images`가 보입니다. **파일이 왜 이렇게 나뉘어 있고, 서로 어떻게 이어질까요?**

**이 장에서 알게 되는 것**

- HTML·CSS·JavaScript가 각각 **무엇을 맡는지**
- `index.html`이 다른 파일을 **어떻게 불러오는지**, `defer`가 왜 필요한지
- "순수 HTML·CSS·JavaScript"로 만들었는지 **어디서 확인하는지**

📱 모바일에서는 **핵심 그림과 핵심 개념 설명**(아래 "미션이 요구하는 파일 구조" 앞까지)만 읽어도 충분합니다. 💻 그 뒤의 직접 확인과 코드 분석은 컴퓨터 앞에서 내 프로젝트를 열고 읽으면 좋습니다.

> 표기 규칙(`[공식]` `[사전]` `[권장]` `[AI 보충]`)과 코드 종류 구분은 [README](../README.md#표기-규칙)에 있습니다.

## HTML 파일 하나만 있으면 안 될까?

HTML 파일 하나만 있어도 브라우저에는 화면이 나옵니다. 글자도 보이고 링크도 눌립니다. `[시나리오]`

그런데 AI는 왜 굳이 CSS 파일과 JavaScript 파일을 따로 만들어 줬을까요?

가장 쉬운 답은 **파일이 하는 일이 서로 다르기 때문**입니다. 아래에서 그 차이를 하나씩 살펴봅니다.

## 웹사이트를 이루는 세 가지 역할

![V01: HTML은 내용, CSS는 모양, JavaScript는 동작을 맡는 구조도. 파일 연결, 브라우저가 읽는 순서, 화면 분해로 구성됩니다.](../assets/v01-web-components.svg)

*일반화한 구성 예입니다. 실제 프로젝트의 파일 이름과 구성은 다를 수 있습니다.*

### 그림 읽는 법

1. **맨 위**: `index.html`에서 점선이 세 파일로 내려갑니다. 점선은 "이 파일을 불러온다"는 뜻입니다.
2. **가운데**: 번호 1→4는 브라우저가 읽고 실행하는 **순서**입니다. 이해를 돕기 위해 단순화한 모델이며, 실제 브라우저는 파일을 동시에 받는 등 더 복잡하게 움직입니다.
3. **아래**: 같은 화면 한 장을 H(내용)·C(모양)·J(동작)로 나눠 봅니다.

### 세 가지 역할

- [**HTML**](../../../terms/html.md) — 페이지에 **무엇이 있는지**와 그 역할을 적습니다. 제목, 소개 글, 메뉴, 카드, 폼이 여기에 있습니다.
- [**CSS**](../../../terms/css.md) — 그것이 **어떻게 보일지** 정합니다. 색, 글자 크기, 간격, 화면 폭에 따른 배치가 여기에 있습니다.
- [**JavaScript**](../../../terms/javascript.md) — 사용자 행동에 **어떻게 반응할지** 적습니다. 메뉴 열기, 다크모드, 폼 검사, GitHub 데이터 불러오기가 여기에 있습니다.

`[사전]` 기술용어사전의 정의를 쉬운 말로 줄였습니다.

### 햄버거 메뉴(☰) 하나에도 세 파일이 모두 일합니다

| 역할 | 맡은 일 |
| --- | --- |
| HTML | 버튼과 메뉴 항목이 **있다**고 적음 |
| CSS | 버튼의 모양·위치, 좁은 화면에서만 **보이게** 하는 규칙 |
| JavaScript | 버튼을 **누르면** 메뉴를 열고 닫음 |

> **집에 비유하면** HTML은 벽과 방 구조, CSS는 인테리어, JavaScript는 전등 스위치와 전기 배선입니다. `[AI 보충]`
>
> **실제 기술에서는** 조금 다릅니다. CSS와 JavaScript는 HTML 요소를 **찾아서** 일하므로, HTML이 없으면 일할 대상이 없습니다. 또 조건에 따라 판단하고 계산하는 일은 JavaScript만 합니다.

> 이 그림은 전체 웹사이트 구조도(V09)에서 **GitHub API·GitHub Pages**까지 확장됩니다. 지금은 세 가지 역할만 확실히 잡아 두세요.

## 파일은 어떻게 서로를 찾을까?

### `index.html`이 시작점입니다

브라우저는 `index.html`을 **가장 먼저** 읽습니다. 그리고 그 안에 적힌 줄을 보고 나머지 파일을 불러옵니다. [`index.html`](../../../terms/index-html.md)이 길잡이 역할을 하는 셈입니다.

아래는 **일반화 예제**입니다. 내 프로젝트의 파일 이름은 다를 수 있습니다.

| 줄 | 하는 일 |
| --- | --- |
| `<link rel="stylesheet" href="css/style.css">` | "모양은 이 CSS 파일을 보세요" |
| `<script src="js/main.js" defer></script>` | "동작은 이 JS 파일을 보세요" |
| `<img src="images/profile.jpg" alt="…">` | "여기에 이 그림을 넣으세요" |

"불러온다"는 **파일 사이의 관계**이고, 브라우저가 읽는 **순서**와는 다른 이야기입니다. V01에서 두 가지를 다른 선으로 그린 이유입니다.

한 파일에 다 넣어도 화면은 나옵니다. 하지만 나누면 "모양을 고치고 싶을 땐 CSS 파일만 열면 된다"처럼 **찾을 위치가 정해집니다.** 이 가이드가 말하는 "기능에서 코드 위치로 찾아가기"의 바탕입니다.

### `defer`는 왜 붙일까?

[`defer`](../../../terms/defer.md)는 `script` 줄에 붙이는 표시로, **"HTML을 다 읽은 뒤에 이 JavaScript를 실행해 달라"** 는 뜻입니다. `[사전]` `[공식]`

JavaScript는 화면의 버튼이나 메뉴 같은 **요소를 찾아서** 일합니다. HTML을 다 읽기 전에 코드가 먼저 실행되면, 찾으려던 요소가 **아직 없을 수 있습니다.** `defer`는 이 문제를 줄여 줍니다. (4장에서 실제 오류 화면으로 다시 만납니다.)

### 같은 파일도 적는 방법에 따라 달라집니다

- `css/style.css` — 지금 파일을 **기준으로** css 폴더 안을 가리킵니다. 대부분 배포 후에도 정상입니다.
- `/css/style.css` — 사이트의 **맨 위(루트)** 에서 시작합니다. GitHub Pages의 프로젝트 주소(`사용자.github.io/저장소/`)에서는 저장소 이름이 빠져 **깨질 수 있습니다.**

로컬에서는 되는데 배포하면 깨지는 대표 원인입니다. 배포는 8장에서 다룹니다. `[사전]` `[AI 보충]`

## "순수 HTML·CSS·JavaScript"는 무엇을 뜻할까?

미션은 **외부 UI·프레임워크 라이브러리 없이** 만들도록 합니다. `[공식]` 원천 자료의 금지 예시는 React, Vue, jQuery, Bootstrap, Tailwind입니다.

그런데 라이브러리를 썼는지는 **한 가지 검색으로 확정할 수 없습니다.** 흔적이 남는 곳이 여럿이기 때문입니다. `[AI 보충]`

- **`index.html`의 `script`·`link`** — `src`·`href`가 `https://…`(CDN 등)이거나 `jquery`, `bootstrap` 같은 이름이 있는가
- **JavaScript의 `import`·`require`** — 내 파일이 아닌 **패키지 이름**을 불러오는가 (`import React from 'react'` 같은 모양)
- **맨 위 폴더의 설정 파일** — `package.json`(의존 목록), `node_modules/` 폴더, `package-lock.json`
- **내려받아 둔 파일** — `css/`, `js/`에 `bootstrap.min.css`, `jquery.min.js` 같은 큰 파일
- **CSS의 `@import`** — 외부 CSS를 가져오는가

> **`https://` 검색은 한 가지 방법일 뿐입니다.**
> - `https://`가 **나와도** 라이브러리가 아닐 수 있습니다. (링크 `<a href="https://github.com/…">`, 이미지 주소, 7장에서 만날 GitHub API 주소)
> - `https://`가 **없어도** 라이브러리가 있을 수 있습니다. (내려받아 폴더에 넣었거나 `package.json`으로 설치한 경우)

**GitHub API에서 데이터를 가져오는 것**은 라이브러리를 쓰는 것이 아니라 "데이터를 요청하는 것"입니다. 7장에서 구분합니다.

> ⚠️ **검토 필요** 웹폰트나 아이콘처럼 외부 주소로 불러오는 자원이 "외부 라이브러리"에 해당하는지는 이 저장소의 자료만으로 단정할 수 없습니다. 내 프로젝트에 있다면 미션 원문 또는 운영진에게 확인하세요.

## 미션이 요구하는 파일 구조

- 순수 HTML·CSS·JavaScript로 구현하고, 외부 UI·프레임워크 라이브러리를 사용하지 않는다 `[공식]`
- `index.html`, `css/`, `js/`, `images/`로 역할을 나누고, JavaScript는 `defer`로 연결한다 `[공식]`
- inline style 없이 구현한다 `[공식]`

## 💻 브라우저가 받아 오는 파일 직접 보기

### 브라우저가 받아 오는 파일 보기

1. 내 사이트를 연 상태에서 **F12**를 누릅니다. (Mac은 `Cmd + Option + I`)
2. 위쪽 탭에서 **Network(네트워크)** 를 고릅니다.
3. 페이지를 **새로고침**합니다. (`Ctrl + R`) 새로고침해야 목록이 채워집니다.

목록에 `index.html`, CSS 파일, JS 파일, 이미지 파일이 나란히 보입니다. 앞에서 읽은 "브라우저가 `index.html`을 먼저 받고, 거기 적힌 파일을 이어서 받아 온다"는 설명이 눈에 보이는 순간입니다. 이름은 프로젝트마다 다르니 확장자(`.html` `.css` `.js` `.jpg`)로 찾으세요.

### 파일이 없으면 어떻게 보일까 (선택)

> ⚠️ **원본 폴더에서는 하지 않습니다.** 폴더를 통째로 복사해 `실험용` 폴더에서만 합니다.

복사본의 `index.html`을 AI에게 보여 주고 *"실험용으로 CSS 연결 줄(`<link rel="stylesheet" …>`)만 주석 처리해 줘. 다른 건 건드리지 마."* 라고 부탁합니다. 다음에는 JavaScript 연결 줄(`<script …>`)로 같은 방식으로 해 봅니다.

- **CSS 연결을 끄면** 글자와 사진은 그대로인데 색·간격·배치가 사라집니다. **내용은 HTML, 모양은 CSS**라는 뜻입니다.
- **JavaScript 연결을 끄면** 모양은 그대로인데 메뉴 버튼을 눌러도 아무 일도 없습니다. **반응은 JavaScript**라는 뜻입니다.

끝나면 `실험용` 폴더를 지웁니다. 원본은 그대로입니다.

## 내 프로젝트의 파일과 연결 줄 찾아보기

> 목표는 코드를 외우는 것이 아니라 **"이 기능은 어느 파일의 어느 줄일까?"** 를 찾아갈 수 있게 되는 것입니다.

### 무엇을 어디서 확인하나

| 확인할 것 | 방법 |
| --- | --- |
| 폴더 구성 | 맨 위 폴더에 `index.html`, `css/`, `js/`, `images/`가 있는지 |
| CSS·JS를 불러오는 줄 | `index.html`에서 `<link`, `<script` 검색. `defer`가 있는지 |
| 외부 자원 | `<script`·`<link` 줄의 주소가 `https://…`인지, `import`·`package.json`·`node_modules/`가 있는지 |
| 직접 쓴 스타일 | `index.html`에서 `style="` 검색 |

> 💡 편집기(VS Code)에서 프로젝트 전체 검색은 `Ctrl + Shift + F`(Mac `Cmd + Shift + F`)입니다.

### 일반화 예제 — 가장 단순한 `index.html`

> 🔷 **일반화 예제** 개념을 보여 주려고 새로 쓴 코드입니다. **내 프로젝트의 코드가 아닙니다.** 모양이 비슷한 줄을 내 `index.html`에서 찾아 비교해 보세요.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport"
        content="width=device-width,
                 initial-scale=1">
  <title>김코디 | 포트폴리오</title>
  <link rel="stylesheet"
        href="css/style.css">
  <script src="js/main.js"
          defer></script>
</head>
<body>
  <h1>안녕하세요, 김코디입니다</h1>
  <img src="images/profile.jpg"
       alt="김코디의 프로필 사진">
</body>
</html>
```

| 줄 | 하는 일 | 역할 |
| --- | --- | --- |
| `<link … href="css/style.css">` | CSS 파일 연결 | 모양 |
| `<script … defer>` | JS 파일 연결. HTML을 다 읽은 뒤 실행 | 동작 |
| `<h1>…</h1>` | 가장 큰 제목 | 내용 |
| `<img … alt="…">` | 이미지 삽입. `alt`는 사진을 못 볼 때 읽히는 설명 | 내용 |
| `<meta name="viewport" …>` | 모바일에서 화면 폭에 맞게 보이도록 알려 줌 (3장에서 다시) | 모양에 영향 |

### 화면에서 코드로 찾아가 보기

화면에 보이는 것 하나에서 출발해 **어느 파일의 어디**인지 따라가 봅니다. 예를 들면 이렇습니다.

| 화면에서 보이는 것 | 역할 | 찾아갈 곳 |
| --- | --- | --- |
| 맨 위 큰 제목 글씨 | 내용 | `index.html`의 `<h1>` |
| 제목 글자의 색 | 모양 | CSS 파일의 `h1` 규칙 |
| 메뉴 버튼을 누르면 메뉴가 열림 | 동작 | JS 파일의 클릭 처리 코드 |
| 프로필 사진 | 내용 | `index.html`의 `<img>`, 파일은 `images/` |

## AI에게 파일 구조를 물어볼 때

### 코드를 물을 때 지킬 네 가지

1. **"수정하지 말고 설명만 해 줘"** 라고 먼저 말합니다. 잘 되던 코드가 바뀌는 사고를 막습니다.
2. **"파일 이름과 줄 번호를 같이 알려 줘"** 라고 요구합니다. 근거 없는 설명을 걸러냅니다.
3. **내 화면의 동작과 연결**해서 묻습니다. ("이 버튼을 누르면…")
4. AI의 답은 **가설**입니다. 알려 준 줄을 직접 열어 화면과 맞는지 확인합니다.

### 질문 예시

> **파일 지도 만들기**
> 이 프로젝트의 폴더와 파일 구조를 표로 정리해 줘. 각 파일이 HTML·CSS·JavaScript 중 어떤 역할인지, 그리고 어떤 파일이 어떤 파일을 불러오는지 `index.html`의 **줄 번호와 함께** 알려 줘. **코드는 수정하지 말고 설명만** 해 줘. 초보자도 이해할 수 있게 써 줘.

> **연결 줄 설명**
> `index.html`의 `<head>`에 있는 `<link>`와 `<script>` 줄을 한 줄씩 초보자 말로 설명해 줘. `defer`가 있을 때와 없을 때 이 프로젝트에서 무엇이 달라지는지도 알려 줘. 수정은 하지 마.

> **순수 HTML·CSS·JS 점검**
> 이 프로젝트가 외부 라이브러리나 프레임워크(React, Vue, jQuery, Bootstrap, Tailwind 등) 없이 만들어졌는지 점검해 줘. `index.html`의 `script`·`link`, JavaScript의 `import`·`require`, CSS의 `@import`, `package.json`·`node_modules/` 같은 의존성 파일, 내려받아 둔 `.min.js`·`.min.css` 파일을 **모두** 확인하고, 확인한 곳마다 결과(파일명·줄 번호)를 알려 줘. 없다면 "어디를 확인했고 무엇이 없었다"고 근거와 함께 말해 줘. 수정은 하지 마.

> **기능 하나를 세 역할로 나누기**
> 화면의 **[햄버거 메뉴 버튼]** 이 HTML, CSS, JavaScript 각각에서 어떤 코드로 만들어지는지 파일 이름과 줄 번호로 알려 줘. 세 가지를 표로 정리하고, 수정은 하지 마.

### AI의 답을 확인하는 법

| AI가 말한 것 | 내가 확인할 것 |
| --- | --- |

## 동료평가에서 이렇게 설명하면 됩니다

**동료평가에서 받을 수 있는 질문** `[공식]`

- 외부 라이브러리 없이 상태 변경을 화면에 반영한 흐름은 무엇인가요?
- `defer` 없이 `head`에서 스크립트를 실행하면 어떤 문제가 생길 수 있나요?

**이렇게 설명할 수 있습니다** (예시이며, 내 사이트의 실제 파일 이름으로 바꿔 말하면 됩니다)

> 우리 사이트는 HTML, CSS, JavaScript 파일로 이루어져 있습니다. HTML은 내용과 구조, CSS는 모양, JavaScript는 메뉴처럼 사용자 행동에 대한 반응을 맡습니다. 브라우저는 먼저 `index.html`을 읽고, 그 안의 `link`와 `script` 줄을 보고 나머지 파일을 불러옵니다. JavaScript에 `defer`를 붙인 이유는 HTML을 다 읽은 뒤에 실행해야 버튼 같은 요소를 찾을 수 있기 때문입니다.

**자주 하는 실수** `[공식]` `[AI 보충]`

- 금지된 라이브러리를 습관적으로 포함함 → 위의 확인 목록으로 여러 곳을 함께 확인
- 파일은 나눴지만 경로가 틀려 CSS·JS가 적용되지 않음 → Network 탭에서 빨간 줄(실패) 확인
- `index.html` 안에 `style="…"`나 `onclick="…"`이 섞임 → `style="`, `onclick=` 검색

## 정리하면

- 웹사이트는 **HTML(내용·구조) + CSS(모양) + JavaScript(동작)** 파일이 협력해 만들어집니다.
- `index.html`이 시작점이고, `link`·`script`·`img` 줄로 나머지 파일을 **불러옵니다.**
- `defer`는 **HTML을 다 읽은 뒤** JavaScript를 실행하게 합니다.
- 라이브러리 사용 여부는 `https://` 검색 한 번이 아니라 **여러 곳을 함께** 확인합니다.
