## 1. 관찰 — 내 사이트를 열고 파일을 확인하기

> 아래 세 가지를 **순서대로** 해 보고, 보이는 대로 적습니다. 정답을 맞히는 활동이 아닙니다.

### 관찰 ① 화면에서 세 가지 종류를 찾아보기

내 사이트를 브라우저로 열고 다음을 각각 3개 이상 찾아 적습니다.

| 종류 | 찾을 것 | 내가 찾은 것 |
| --- | --- | --- |
| **내용** | 글자, 제목, 사진, 링크처럼 "무엇이 있는지" | |
| **모양** | 색, 글자 크기, 간격, 둥근 모서리처럼 "어떻게 보이는지" | |
| **반응** | 누르면·스크롤하면·입력하면 일어나는 변화 | |

### 관찰 ② 브라우저가 받아 오는 파일 목록 보기

1. 사이트를 연 상태에서 **F12**를 누릅니다. (Mac은 `Cmd + Option + I`)
2. 위쪽 탭에서 **Network(네트워크)** 를 고릅니다.
3. 페이지를 **새로고침**합니다. (`Ctrl + R`, Mac은 `Cmd + R`) — 새로고침해야 목록이 채워집니다.
4. 목록에서 이름이 `index.html`, `style.css`, `main.js`(또는 비슷한 이름), 이미지 파일인 줄을 찾아봅니다.

> 이름은 프로젝트마다 다릅니다. 확장자(`.html` `.css` `.js` `.jpg` `.png` 등)로 찾으세요.

내 프로젝트의 파일 개수와 이름을 적어 둡니다.

| 확장자 | 내 사이트에서 받아 온 파일 이름 |
| --- | --- |
| `.html` | |
| `.css` | |
| `.js` | |
| 이미지 | |

### 관찰 ③ "없으면 어떻게 보일까" 실험 (복사본에서만)

> ⚠️ **원본 폴더에서 하지 않습니다.** 제출할 프로젝트가 망가질 수 있습니다. 폴더를 통째로 복사해 `실험용` 폴더를 만든 뒤 그 안에서 합니다.

1. 복사한 폴더의 `index.html`을 AI에게 보여 주고 이렇게 부탁합니다.
   *"실험용으로 CSS 연결 줄(`<link rel="stylesheet" …>`)만 주석 처리해 줘. 다른 건 건드리지 마."*
2. 브라우저에서 `실험용/index.html`을 엽니다. 무엇이 사라졌고, 무엇이 남았나요?
3. 원상 복구한 뒤, 이번에는 JavaScript 연결 줄(`<script …>`)만 주석 처리해 같은 방식으로 봅니다. 메뉴 버튼을 눌러 보세요.
4. 끝나면 `실험용` 폴더를 지웁니다. 원본은 그대로입니다.

| 실험 | 화면에서 남은 것 | 사라지거나 멈춘 것 |
| --- | --- | --- |
| CSS 연결을 끔 | | |
| JavaScript 연결을 끔 | | |

## 3. 선 — 개념의 역할과 연결 관계

점 하나하나를 **선**으로 이으면 이런 한 줄이 됩니다.

```
파일과 폴더 → HTML 구조 → CSS 표현 → JavaScript 동작 → 브라우저 화면
```

### 3-1. 이 선의 화살표는 무슨 뜻일까?

화살표라고 모두 같은 뜻이 아닙니다. 하나씩 나눠 봅니다. `[AI 보충]`

| 연결 | 관계의 종류 | 쉬운 말 |
| --- | --- | --- |
| 폴더 → `index.html` | 시작점 | 브라우저는 이 파일을 가장 먼저 읽습니다 |
| `index.html` → CSS 파일 | **불러옴(참조)** | HTML이 "이 모양 파일을 쓰겠다"고 가리킵니다 |
| `index.html` → JS 파일 | **불러옴(참조)** | HTML이 "이 동작 파일을 쓰겠다"고 가리킵니다 |
| CSS → 화면 | **적용** | HTML 요소에 색·크기·배치 규칙을 입힙니다 |
| JavaScript → 화면 | **조작** | 사용자 행동에 반응해 요소를 바꿉니다 |

"불러온다"는 **구조 관계**이고, 브라우저가 읽는 **순서**와는 다른 이야기입니다. V01 그림에서도 두 가지를 다른 선으로 그렸습니다.

### 3-2. 세 가지 역할

| | 한 문장 | 쉽게 말하면 | 이 사이트에서는 |
| --- | --- | --- | --- |
| [**HTML**](../../../terms/html.md) | 페이지에 **무엇이 있는지**와 그 역할을 적는 문서 | 뼈대 | 제목, 소개 글, 메뉴, 카드, 폼 |
| [**CSS**](../../../terms/css.md) | 그것이 **어떻게 보일지** 정하는 규칙 | 겉모양 | 색, 글자 크기, 간격, 화면 폭별 배치 |
| [**JavaScript**](../../../terms/javascript.md) | 사용자 행동에 **어떻게 반응할지** 적은 코드 | 움직임 | 메뉴 열기, 다크모드, 폼 검사, GitHub 데이터 불러오기 |

`[사전]` 위 한 문장은 기술용어사전 정의를 초보자 말로 줄인 것입니다.

> **비유와 그 한계** `[AI 보충]`
> 집에 비유하면 HTML은 벽과 방 구조, CSS는 인테리어, JavaScript는 전등 스위치와 전기 배선입니다.
> **실제 기술에서는** 이렇게 다릅니다. CSS와 JavaScript는 HTML 요소를 **찾아서** 일하므로 HTML이 없으면 일할 대상이 없습니다. 또 HTML·CSS는 "프로그램"이 아니라 설명서에 가깝고, 조건에 따라 판단하고 계산하는 일은 JavaScript만 합니다.

### 3-3. 왜 파일을 나누고, 어떻게 이어질까?

한 파일에 다 넣어도 화면은 나옵니다. 하지만 나누면 "모양을 고치고 싶을 때 CSS 파일만 열면 된다"처럼 **찾는 위치가 정해집니다.** 이것이 이 가이드 전체에서 쓰는 방법, **"기능 → 코드 위치 찾기"** 의 바탕입니다.

[`index.html`](../../../terms/index-html.md)이 다른 파일을 이렇게 가리킵니다. 아래는 **일반화 예제**이며 내 프로젝트의 이름은 다를 수 있습니다.

| 가리키는 줄 | 하는 일 | 쉬운 말 |
| --- | --- | --- |
| `<link rel="stylesheet" href="css/style.css">` | CSS 파일을 불러옴 | "모양은 이 파일을 보세요" |
| `<script src="js/main.js" defer></script>` | JavaScript 파일을 불러옴 | "동작은 이 파일을 보세요" |
| `<img src="images/profile.jpg" alt="…">` | 이미지를 끼워 넣음 | "여기에 이 그림을 넣으세요" |

### 3-4. `defer` — 왜 붙일까?

[`defer`](../../../terms/defer.md)는 `script` 태그에 붙이는 표시로, **"HTML을 다 읽은 뒤에 이 JavaScript를 실행해 달라"** 는 뜻입니다. `[사전]` `[공식]`

왜 필요할까요? JavaScript는 화면의 버튼이나 메뉴 같은 **요소를 찾아서** 일합니다. HTML을 아직 다 읽지 않았는데 코드가 먼저 실행되면 찾으려던 요소가 **아직 없습니다.** `defer`는 이 문제를 줄입니다. (4장에서 실제 오류 화면으로 다시 만납니다.)

### 3-5. 경로 — 같은 파일을 가리켜도 쓰는 방법이 다릅니다

| 쓴 모양 | 뜻 | 배포 후 |
| --- | --- | --- |
| `css/style.css` | 지금 파일 **기준으로** css 폴더 안 | 대부분 정상 |
| `/css/style.css` | 사이트의 **맨 위(루트)** 에서 시작 | GitHub Pages의 프로젝트 주소(`사용자.github.io/저장소/`)에서는 저장소 이름이 빠져 **깨질 수 있음** |

로컬에서는 되는데 배포하면 깨지는 대표 원인이 이것입니다. 배포는 8장에서 다룹니다. `[사전]` `[AI 보충]`

### 3-6. "순수 HTML·CSS·JavaScript"란?

미션은 **외부 UI·프레임워크 라이브러리 없이** 만들도록 합니다. `[공식]` 원천 자료의 금지 예시는 React, Vue, jQuery, Bootstrap, Tailwind입니다.

- 쉽게 구분하는 방법: 코드에 **`https://…`로 시작하는 주소**에서 `<script>`나 `<link>`를 불러오면 외부 도구일 가능성이 큽니다.
- **GitHub API에서 데이터를 가져오는 것**은 라이브러리를 쓰는 것이 아니라 "데이터를 요청하는 것"입니다. 7장에서 구분합니다.

> ⚠️ **검토 필요** 웹폰트나 아이콘처럼 외부 주소로 불러오는 자원이 "외부 라이브러리"에 해당하는지는 이 저장소의 자료만으로 단정할 수 없습니다. 내 프로젝트에 있다면 미션 원문 또는 운영진에게 확인하세요.

## 5. 코드 확인 — 내 프로젝트에서 찾기

> 🎯 **목표는 암기가 아니라 위치 찾기**입니다. "이 기능은 어느 파일의 어느 줄일까?"를 말할 수 있으면 충분합니다.

### 5-1. 찾을 것 체크리스트

| 찾을 것 | 어디에 있나 | 확인 방법 | 내 결과 |
| --- | --- | --- | --- |
| `index.html` | 프로젝트 맨 위 폴더 | 파일 탐색기에서 확인 | ☐ |
| `css/` 폴더와 CSS 파일 | `index.html`과 같은 위치 | 폴더 열기 | ☐ |
| `js/` 폴더와 JS 파일 | 같은 위치 | 폴더 열기 | ☐ |
| `images/` 폴더 | 같은 위치 | 폴더 열기 | ☐ |
| CSS를 불러오는 줄 | `index.html`의 `<head>` 안 | 편집기에서 `<link` 검색 | ☐ 줄 번호: |
| JS를 불러오는 줄과 `defer` | `index.html` | `<script` 검색 | ☐ 줄 번호: |
| 외부 주소(`https://`)로 불러오는 줄 | `index.html` | `https://` 검색 | ☐ 없음 / ☐ 있음 → 무엇? |
| 태그 안에 직접 쓴 스타일 | `index.html` 전체 | `style="` 검색 | ☐ 없음 / ☐ 있음 |

> 💡 편집기(VS Code)에서 프로젝트 전체 검색은 `Ctrl + Shift + F`(Mac `Cmd + Shift + F`)입니다.
> `style="`을 찾는 이유: 미션은 **inline style 없이** 만들도록 합니다. `[공식]`

### 5-2. 일반화 예제 — 가장 단순한 `index.html`

> 🔷 **일반화 예제** 개념을 보여 주려고 새로 쓴 코드입니다. **내 프로젝트의 코드가 아닙니다.** 모양이 비슷한 줄을 내 `index.html`에서 찾아 비교하세요.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>김코디 | 포트폴리오</title>
  <link rel="stylesheet" href="css/style.css">
  <script src="js/main.js" defer></script>
</head>
<body>
  <h1>안녕하세요, 김코디입니다</h1>
  <img src="images/profile.jpg" alt="김코디의 프로필 사진">
</body>
</html>
```

| 줄 | 하는 일 | 어느 역할? |
| --- | --- | --- |
| `<link rel="stylesheet" href="css/style.css">` | CSS 파일 연결 | 모양 |
| `<script src="js/main.js" defer></script>` | JS 파일 연결, HTML을 다 읽은 뒤 실행 | 동작 |
| `<h1>…</h1>` | 가장 큰 제목 | 내용 |
| `<img src="…" alt="…">` | 이미지 삽입. `alt`는 사진을 못 볼 때 읽히는 설명 | 내용 |
| `<meta name="viewport" …>` | 모바일에서 화면 폭에 맞게 보이도록 알려 줌 (3장에서 다시) | 모양에 영향 |

### 5-3. 화면 요소 ↔ 코드 위치 연결표 (직접 채우기)

내 사이트에서 아래 요소를 찾아 어느 파일의 몇 번째 줄인지 적습니다. 첫 줄은 **작성 예시**입니다.

| 화면에서 보이는 것 | 역할 | 코드 위치 (파일 : 줄) |
| --- | --- | --- |
| (예시) 맨 위 큰 제목 글씨 | 내용 → HTML | (예시) `index.html : 18` |
| 제목 글자의 색 | 모양 → CSS | |
| 메뉴 버튼을 누르면 메뉴가 열림 | 동작 → JavaScript | |
| 프로필 사진 | 내용 → HTML, 파일은 `images/` | |

## 6. AI에게 물어보기

### AI에게 코드를 물을 때 지킬 네 가지

1. **"수정하지 말고 설명만 해 줘"** 라고 먼저 말합니다. 잘 되던 코드가 바뀌는 사고를 막습니다.
2. **"파일 이름과 줄 번호를 같이 알려 줘"** 라고 요구합니다. 근거 없는 설명을 걸러냅니다.
3. **내 화면의 동작과 연결**해서 묻습니다. ("이 버튼을 누르면…")
4. AI 답은 **가설**입니다. 알려 준 줄을 직접 열어 보고, 화면과 맞는지 확인합니다.

### 질문 예시

> **① 파일 지도 만들기**
> 이 프로젝트의 폴더와 파일 구조를 표로 정리해 줘. 각 파일이 HTML·CSS·JavaScript 중 어떤 역할인지, 그리고 어떤 파일이 어떤 파일을 불러오는지 `index.html`의 **줄 번호와 함께** 알려 줘. **코드는 수정하지 말고 설명만** 해 줘. 초보자도 이해할 수 있게 써 줘.

> **② 연결 줄 설명**
> `index.html`의 `<head>`에 있는 `<link>`와 `<script>` 줄을 한 줄씩 초보자 말로 설명해 줘. `defer`가 있을 때와 없을 때 이 프로젝트에서 무엇이 달라지는지도 알려 줘. 수정은 하지 마.

> **③ 순수 HTML·CSS·JS 점검**
> 이 프로젝트가 외부 라이브러리나 프레임워크(React, Vue, jQuery, Bootstrap, Tailwind 등) 없이 만들어졌는지 점검해 줘. 어떤 패턴으로 검색했는지, 찾았다면 파일명과 줄 번호를, 없다면 "없다"고 근거와 함께 알려 줘.

> **④ 기능 하나를 세 역할로 분해**
> 화면의 **[햄버거 메뉴 버튼]** 이 HTML, CSS, JavaScript 각각에서 어떤 코드로 만들어지는지 파일 이름과 줄 번호로 알려 줘. 세 가지를 표로 정리하고, 수정은 하지 마.

### AI 답을 확인하는 법

| AI가 말한 것 | 내가 확인할 것 |
| --- | --- |
| "`index.html` 12번째 줄에서 CSS를 불러옵니다" | 편집기에서 그 줄을 열어 `<link`가 맞는지 |
| "외부 라이브러리는 없습니다" | `https://`로 검색해 직접 한 번 더 확인 |
| "이 코드가 메뉴를 엽니다" | 개발자 도구 Elements/Sources에서 그 파일이 실제로 로드되는지 (Network 탭 확인) |

> 우리 사이트는 `________`, `________`, `________` 파일로 이루어져 있습니다.
> **HTML**은 `________`을, **CSS**는 `________`을, **JavaScript**는 `________`을 맡습니다.
> 브라우저는 먼저 `________` 파일을 읽고, 그 안의 `________`와 `________` 줄을 보고 나머지 파일을 불러옵니다.
> JavaScript에 `defer`를 붙이는 이유는 `________` 때문입니다.

### 좋은 설명의 기준 (스스로 점검)

- ☐ HTML·CSS·JavaScript를 **내 사이트의 실제 예**(메뉴, 색, 제목 등)로 말했다.
- ☐ "불러온다"(구조)와 "먼저 읽는다"(순서)를 **섞지 않고** 말했다.
- ☐ `defer`를 **"HTML을 다 읽은 뒤 실행"** 이라고 말했다.
- ☐ 코드를 외우지 않고 **"어디를 보면 된다"** 로 설명했다.
