# Chapter 5 — 다크모드는 왜 새로고침 후에도 유지될까?

> 다크모드를 켜고 새로고침했는데도 화면이 그대로 어둡습니다. 페이지를 새로 읽어 왔는데 **브라우저는 내 선택을 어떻게 기억하고 있을까요?**

**이 장에서 알게 되는 것**

- 테마를 **바꾸는 일**과 선택을 **기억하는 일**이 서로 다른 책임이라는 점
- **localStorage**가 무엇이고 어떻게 값을 저장하고 읽는지
- 페이지를 다시 열 때 저장된 테마가 **어떤 순서로 복원되는지**

## 새로고침해도 그대로인 이유

> **페이지를 다시 열어도 다크모드를 기억하는 이유는?** `[시나리오]`

다크모드 버튼을 누르면 화면이 어두워집니다. 그런데 새로고침은 **페이지를 처음부터 다시 읽는 일**입니다. JavaScript가 방금 바꿔 둔 상태도 함께 사라집니다. 그래도 어두운 화면이 유지되려면 두 가지가 필요합니다.

1. **화면을 바꾸는 일** — 테마를 실제로 화면에 적용합니다.
2. **선택을 기억하는 일** — 다음에 열 때 쓸 수 있게 어딘가에 남겨 둡니다.

이 둘을 **서로 다른 책임**으로 나눠 보는 것이 이 장의 핵심입니다. `[사전]`

## 테마를 바꾸는 흐름과 다시 열 때의 흐름

*교육용 단순화 모델입니다. 실제 코드의 구성은 프로젝트마다 다를 수 있습니다.*

### 그림 읽는 법

1. **위쪽 ①**: 버튼을 누르면 새 테마를 정하고, 그다음 일이 **두 갈래**로 나뉩니다. ③은 **화면 담당**, ④는 **기억 담당**입니다.
2. **가운데**: ④가 값을 localStorage에 **씁니다**(점선). 이 값은 탭을 닫아도 남아 있습니다.
3. **아래쪽 ②**: 페이지를 다시 열면 저장된 값을 **읽고**(점선), 위의 ③과 **같은 방법**으로 화면에 적용합니다.
4. 실선 화살표는 **실행 순서**, 점선 화살표는 **저장소와 주고받는 값**입니다.

> **테마를 화면에 적용하는 일과 선택을 저장하는 일은 따로 일하고, 저장된 값이 두 흐름을 이어 줍니다.**

## 화면을 바꾸는 쪽: 속성 하나와 CSS 변수

3장에서 만난 **CSS 변수**가 여기서 쓰입니다. 다크모드는 보통 이렇게 만듭니다. `[사전]`

- `<html>` 같은 **위쪽 요소에** `data-theme="dark"` 같은 속성이나 class를 붙입니다.
- CSS에서 그 속성이 있을 때 **변수의 값만 바꿔치기**합니다. 그러면 `var(--color-bg)`로 색을 쓰던 곳이 한꺼번에 바뀝니다.

[다크모드](../../../terms/dark-mode.md)는 **배경색만 어둡게 바꾸는 기능이 아닙니다.** 글자, 테두리, 링크, 포커스 표시의 대비도 함께 설계해야 합니다. `[사전]` 어두운 배경에 어두운 글자가 남으면 읽을 수 없습니다.

> 운영체제의 다크모드 설정을 따르는 방법(`prefers-color-scheme`)도 있습니다. 이 장은 **사용자가 버튼으로 고르는 방식**을 다룹니다. `[AI 보충]`

## 기억하는 쪽: localStorage

[localStorage](../../../terms/local-storage.md)는 브라우저 안에 **이름(key)과 값(value)** 을 문자열로 남겨 두는 저장소입니다. `[사전]` 쉽게 말해 브라우저 안의 메모장에 `theme`라는 이름으로 `"dark"`를 적어 두는 것입니다.

- **쓰기**: `localStorage.setItem('theme', 'dark')`
- **읽기**: `localStorage.getItem('theme')` → `"dark"`. **저장된 값이 없으면 `null`** 이 나옵니다.
- **문자열만** 저장됩니다. 객체를 넣으려면 `JSON.stringify`로 문자열로 바꿔야 합니다.
- **같은 주소(origin) 안에서만** 보입니다. 내 컴퓨터의 `localhost`에서 저장한 값은 배포한 `github.io`에서 보이지 않습니다.
- **탭을 닫아도 남습니다.** 사용자가 직접 지우거나 코드가 지울 때까지 유지됩니다.

### 알아 둘 점

- **비밀번호나 인증 토큰은 저장하지 않습니다.** 페이지의 모든 스크립트가 읽을 수 있고, 사용자가 개발자 도구로 직접 고칠 수도 있습니다. `[사전]`
- 브라우저 설정(사생활 보호 모드 등)에 따라 **저장이 막힐 수 있어서**, 접근을 `try/catch`로 감싸는 것이 안전합니다. `[사전]`
- 저장 위치는 여러 가지입니다. [Client-side Storage](../../../terms/client-side-storage.md)에서 localStorage, sessionStorage, cookie, IndexedDB의 수명과 용도를 비교합니다. 테마처럼 **오래 남아야 하고 서버는 몰라도 되는 값**에는 localStorage가 알맞습니다. `[사전]`

### 변수에 저장하면 왜 안 될까?

`let theme = 'dark'`처럼 JavaScript 변수에 담긴 값은 **지금 열려 있는 페이지의 메모리**에만 있습니다. 새로고침하면 페이지가 새로 만들어지면서 변수도 처음 값으로 돌아갑니다. 그래서 "기억"하려면 페이지 **밖**에 남겨야 하고, 브라우저가 그 자리를 localStorage로 제공합니다. `[사전]`

## 다시 열 때 어떤 테마로 시작할까

페이지를 열면 JavaScript가 실행되며 다음 순서로 테마를 정합니다. `[AI 보충]`

1. 저장된 값을 **읽습니다.**
2. `"dark"` 또는 `"light"`이면 그 값을 **적용합니다.**
3. 값이 **없거나(`null`) 예상 밖이면** 기본 테마(예: light)를 씁니다. 처음 방문한 사람은 저장된 값이 없기 때문입니다.

### 잠깐 밝았다가 어두워지는 깜빡임

JavaScript를 `defer`로 연결하면 HTML을 다 읽은 **뒤에** 실행됩니다(1장). 그 사이 브라우저가 기본(밝은) 테마로 화면을 먼저 그리면, 잠깐 밝은 화면이 보였다가 어두워질 수 있습니다. 동료평가 자료에도 **"저장은 하지만 초기 적용이 늦어 깜빡임"** 이 흔한 실수로 올라 있습니다. `[공식]`

적용을 일찍 하는 방법도 있습니다. 다만 미션은 JavaScript를 `defer`로 연결하도록 요구하므로, 그 방식을 써도 되는지는 **미션 원문에서 확인**하세요.

## 💻 저장된 값을 개발자 도구로 직접 보기

### localStorage를 눈으로 확인하기

1. 내 사이트에서 **F12**를 누르고 위쪽 탭에서 **Application(애플리케이션)** 을 고릅니다. (안 보이면 `»`를 눌러 펼칩니다.)
2. 왼쪽에서 **Local Storage**를 펼치고 내 사이트 주소를 누릅니다.
3. 테마 버튼을 눌러 보세요. 목록에 `theme` 같은 이름과 `dark`·`light` 값이 나타나거나 바뀝니다.

### 직접 실험해 보기

- **값을 지우고 새로고침**: 그 줄을 선택해 지우고(Delete) 새로고침하면 기본 테마로 돌아갑니다. "저장된 값이 곧 선택"이라는 것이 눈에 보입니다.
- **`<html>` 속성 보기**: Elements 패널에서 맨 위 `<html …>` 줄을 보면 테마를 바꿀 때 `data-theme`(또는 class)가 붙었다 떨어지는 것이 보입니다. **화면 담당**이 하는 일입니다.
- **주소가 다르면 저장도 다름**: 배포한 뒤에는 로컬 주소와 배포 주소의 localStorage가 **서로 다릅니다.** 배포 사이트에서 처음에는 기본 테마로 보이는 것이 정상입니다.

## 내 프로젝트에서 테마 저장과 복원 찾아보기

### 찾는 방법

- **편집기 검색**: `localStorage`, `getItem`, `setItem`, `data-theme`, `classList`, `prefers-color-scheme`
- **화면 담당**: CSS에서 `[data-theme="dark"]` 또는 `.dark` 같은 규칙과 그 안에서 바뀌는 변수를 찾습니다.
- **기억 담당**: JavaScript에서 `setItem`(저장)과 `getItem`(읽기)이 **각각 어디에 있는지** 찾습니다. 한 곳에 몰려 있을 수도, 나뉘어 있을 수도 있습니다.

### 일반화 예제 — 화면 담당(CSS)

> 🔷 **일반화 예제** 구조를 보여 주려고 새로 쓴 코드입니다. 이름은 **가정**이며 **내 프로젝트의 코드가 아닙니다.**

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1c2721;
}

/* data-theme="dark"일 때
   변수 값만 바꿔치기 */
[data-theme="dark"] {
  --color-bg: #14201b;
  --color-text: #e8efe9;
}

body {
  background: var(--color-bg);
  color: var(--color-text);
}
```

`<html>`에 `data-theme="dark"`가 붙으면 `--color-bg`와 `--color-text`의 값이 바뀌고, `var(...)`로 이 값을 쓰는 곳이 모두 따라 바뀝니다.

### 일반화 예제 — 적용·저장·복원(JavaScript)

```js
const STORAGE_KEY = 'theme';
const root = document.documentElement;
const toggle =
  document.querySelector('.theme-toggle');

// 화면 담당: 테마를 화면에 적용
function applyTheme(theme) {
  root.dataset.theme = theme;
}

// 기억 담당: 저장된 값 읽기
function loadTheme() {
  try {
    return localStorage.getItem(STORAGE_KEY);
  } catch {
    // 저장소를 쓸 수 없는 환경
    return null;
  }
}

// 기억 담당: 값 저장하기
function saveTheme(theme) {
  try {
    localStorage.setItem(STORAGE_KEY, theme);
  } catch {
    // 저장에 실패해도 화면은 계속 동작
  }
}

// ② 다시 열 때: 읽어서 적용
// (값이 없으면 light)
applyTheme(loadTheme() ?? 'light');

// ① 눌렀을 때: 바꾸고 → 적용하고 → 저장
toggle.addEventListener('click', () => {
  const next =
    root.dataset.theme === 'dark'
      ? 'light'
      : 'dark';
  applyTheme(next);
  saveTheme(next);
});
```

이 코드는 이렇게 읽습니다.

- `applyTheme` — **화면 담당**입니다. `<html>`의 `data-theme`만 바꿉니다.
- `loadTheme`·`saveTheme` — **기억 담당**입니다. localStorage를 읽고 씁니다.
- 맨 아래 `addEventListener` — V05의 ①입니다. **바꾸고 → 적용하고 → 저장**합니다.
- `applyTheme(loadTheme() ?? 'light')` — V05의 ②입니다. **읽고 → 적용**합니다. `??`는 값이 `null`일 때 오른쪽 값을 쓰라는 뜻입니다.
- 두 흐름 모두 `applyTheme`을 **같이 씁니다.** V05에서 ③이 두 번 나오는 이유입니다.

### 구현 상태 점검 `[공식]`

- 테마 전환 버튼이 동작한다
- 저장하는 코드(`setItem`)가 있다
- 페이지를 열 때 읽는 코드(`getItem`)가 있고, **저장된 값이 없을 때**도 처리한다
- 테마를 바꾼 뒤 새로고침해도 유지된다
- 다크 화면에서 글자·테두리·링크·포커스가 모두 읽힌다

- 비밀번호를 localStorage에 저장하면 안 되는 이유는 무엇인가요? (localStorage 사전의 질문)

**이렇게 설명할 수 있습니다** (예시이며, 내 사이트의 실제 이름으로 바꿔 말하면 됩니다)

> 테마 버튼을 누르면 `applyTheme`이 `<html>`의 `data-theme`를 바꿔 CSS 변수 값이 바뀌고, 같은 시점에 `saveTheme`이 localStorage에 `theme` 값을 저장합니다. 화면을 바꾸는 일과 선택을 기억하는 일은 책임이 다릅니다. 변수에만 담으면 새로고침 때 페이지가 새로 만들어지며 사라지기 때문에, 페이지를 열 때 `getItem`으로 저장된 값을 읽어 같은 `applyTheme`으로 적용합니다. 저장된 값이 없으면 기본 테마를 씁니다.

**자주 하는 실수** `[공식]` `[사전]`

- 배경색만 어둡게 바꿔 글자·테두리·포커스의 대비를 놓침 → 다크 화면 전체를 눈으로 확인
- 저장만 하고 페이지를 열 때 읽는 코드가 없음 → 값을 지우고 새로고침, 저장된 값 유지 확인
- 저장은 하는데 초기 적용이 늦어 깜빡임 → 새로고침 직후 화면 관찰
- localStorage에 민감한 값을 저장함 → 저장하는 값이 테마 같은 **선호 설정**뿐인지 확인

## 핵심 내용 정리

- 다크모드는 **화면에 적용하는 일**(속성 + CSS 변수)과 **선택을 기억하는 일**(localStorage)이 합쳐진 기능입니다.
- localStorage는 **같은 주소 안에서, 문자열로, 탭을 닫아도** 남습니다. 값이 없으면 `null`입니다.
- 페이지를 열 때는 **읽고 → 같은 방법으로 적용**합니다. 변수만으로는 새로고침을 넘어 기억할 수 없습니다.
