## 3. 선 — 개념의 역할과 연결 관계

```
화면 크기 → Media Query → CSS 배치 규칙 → Flexbox·Grid → 레이아웃
```

### 3-1. 이 선은 무슨 뜻일까?

| 연결 | 관계의 종류 | 쉬운 말 |
| --- | --- | --- |
| 화면 크기 → Media Query | **조건 검사** | 브라우저가 지금 화면 폭이 몇 px인지 알려 줍니다 |
| Media Query → CSS 배치 규칙 | **스위치** | 조건이 맞으면 안쪽 규칙을 추가로 켭니다 |
| CSS 배치 규칙 → Flexbox·Grid | **배치 방법 선택** | 한 줄로 늘어놓을지, 행·열 격자로 놓을지 정합니다 |
| Flexbox·Grid → 레이아웃 | **결과** | 눈에 보이는 배치가 나옵니다 |

**HTML은 이 선 어디에도 나오지 않습니다.** 바뀌는 것은 CSS 규칙뿐이고, HTML 구조는 모든 화면 폭에서 같습니다. (V03 가운데 초록 상자가 이 사실입니다.)

### 3-2. 숨은 조건 — `viewport` 설정 한 줄

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

이 줄은 `index.html`의 `<head>`에 있습니다. 휴대폰 브라우저에게 **"기기의 실제 화면 폭을 기준으로 그려 주세요"** 라고 알립니다. 이 줄이 없으면 휴대폰이 데스크톱 폭(대략 980px)으로 그린 뒤 줄여서 보여 주고, 모바일 규칙이 기대대로 적용되지 않을 수 있습니다. `[AI 보충]`

### 3-3. Media Query — 조건부 규칙

```css
@media (min-width: 768px) {
  /* 화면 폭이 768px 이상일 때만 이 안의 규칙이 추가로 적용됩니다 */
}
```

- `@media` : "조건이 맞을 때만" 이라는 표시
- `(min-width: 768px)` : 화면 폭이 **768px 이상**이라는 조건 (768 포함)
- `{ … }` : 조건이 맞을 때 켤 규칙들

[CSS Media Query](../../../terms/css-media-query.md)는 폭뿐 아니라 사용자 환경도 조건으로 쓸 수 있습니다. `[사전]` 이 장은 폭만 다룹니다.

### 3-4. Mobile First — 작은 화면이 기본, 큰 화면이 덧붙임

[모바일 퍼스트](../../../terms/mobile-first.md)는 **가장 작은 화면의 규칙을 먼저(기본값으로) 쓰고, 화면이 넓어지면 `min-width` 조건으로 규칙을 덧붙이는** 방식입니다. `[사전]` `[공식]`

```
기본 규칙 ──────────────────────────────────▶ 모든 폭에 적용
        768px 이상 규칙 ───────────────────▶ 덧붙음
                    1024px 이상 규칙 ──────▶ 또 덧붙음
```

이 그림이 V03 위쪽 막대 세 개입니다. 규칙은 **쌓입니다.** 1100px 화면에서는 세 가지가 **모두** 적용됩니다.

두 가지를 기억하세요. `[AI 보충]`

1. 같은 요소를 두 규칙이 건드리면 **나중에 적힌 규칙**(같은 힘일 때)이 앞의 규칙을 덮습니다. 그래서 보통 `@media` 블록은 **기본 규칙 아래**에 둡니다.
2. 왜 작은 화면부터일까요? 좁은 화면은 자리가 부족해서 **무엇이 꼭 필요한지** 먼저 정하게 됩니다. 그 뒤 공간이 생기면 늘리는 편이 쉽습니다.

> 반대로 "큰 화면이 기본, `max-width`로 줄임"도 있습니다. 이 미션은 **Mobile First**를 요구하므로 `min-width` 방식으로 설명합니다.

### 3-5. Breakpoint — "바뀌는 지점"

[브레이크포인트](../../../terms/breakpoint.md)는 배치가 **바뀌는 화면 폭**입니다. 이 미션은 **768px와 1024px** 에서 전환하는 것을 확인합니다. `[공식]`

- 이 숫자는 "아이패드 폭" 같은 **기기 이름이 아니라**, 콘텐츠가 어색해지는 지점을 기준으로 정하는 것이 원칙입니다. `[사전]`
- 768과 1024는 **모든 사이트의 정답이 아니라 이 미션에서 검증하는 기준**입니다. `[사전]`
- **경계 사이**(예: 900px)도 깨지지 않아야 합니다. 관찰 ②에서 900을 넣은 이유입니다.

### 3-6. Flexbox와 Grid — 무엇이 다른가

| | [Flexbox](../../../terms/css-flexbox.md) | [Grid](../../../terms/css-grid.md) |
| --- | --- | --- |
| 한 줄 | **한 방향**으로 늘어놓고 남는 공간을 나눔 | **행과 열**을 함께 정해 격자로 놓음 |
| 알맞은 곳 | 메뉴 항목처럼 한 줄 | 프로젝트 카드처럼 여러 줄·여러 칸 |
| 이 미션 | 내비게이션 `[공식]` | 프로젝트 카드 `[공식]` |
| 대표 코드 | `display: flex; gap: 1rem;` | `display: grid; grid-template-columns: repeat(3, 1fr);` |

`[사전]` 읽는 법 — `repeat(3, 1fr)` 은 "같은 폭의 열 3개", `1fr`은 **남는 공간을 1:1로 나눈 한 몫**이고, `gap`은 **칸 사이 간격**입니다. `[AI 보충]`

> 둘은 경쟁하지 않습니다. "한 방향 정렬은 Flexbox, 2차원 격자는 Grid"가 일반적 구분이며 `[사전]`, 이 미션이 메뉴와 카드를 나눠 요구한 이유입니다.

### 3-7. CSS 변수 — 값에 이름 붙이기 `[시나리오]`

```css
:root { --color-bg: #ffffff; }          /* 이름 붙이기(정의) */
body  { background: var(--color-bg); }  /* 사용하기 */
```

- `--color-bg` 처럼 **`--`로 시작하는 이름**이 변수입니다.
- `var(--color-bg)` 는 "그 이름에 저장된 값을 여기에 쓰라"는 뜻입니다.
- 색·간격 같은 값이 여러 곳에 흩어지지 않고 **한 곳에서 관리**됩니다.
- 5장(다크모드)에서 이 값을 **통째로 바꿔치기**하는 방식이 나옵니다. 지금은 "값에 이름을 붙여 두는 것"만 알면 됩니다. `[AI 보충]`

### 3-8. 단위와 "옆으로 밀림" `[AI 보충]`

| 쓴 모양 | 성질 | 좁은 화면에서 |
| --- | --- | --- |
| `width: 1200px` | **고정**. 화면이 좁아도 1200px | 옆으로 밀림(가로 스크롤) 위험 |
| `max-width: 100%`, `width: 100%` | 부모 폭에 **맞춤** | 안전한 편 |
| `rem` | 글자 크기에 비례 | 글자 키우기에 대응 |
| `fr` | Grid에서 남는 공간의 몫 | 칸 폭이 자연스럽게 변함 |

요소 하나의 고정 폭이 화면보다 크면 페이지 전체에 가로 스크롤이 생깁니다. 이것이 동료평가에서 자주 보는 문제입니다. `[공식]`

## 4. 면 — V03: 같은 HTML, 화면 폭마다 다른 배치

![V03: CSS 규칙이 모바일 기본, 768px 이상, 1024px 이상으로 쌓이는 막대 그래프와, 같은 웹페이지를 모바일·태블릿·데스크톱 폭으로 나란히 비교한 그림. 모바일은 메뉴가 햄버거 뒤에 접히고 카드 1열, 태블릿은 메뉴 가로 한 줄에 카드 2열, 데스크톱은 카드 3열입니다.](../assets/v03-responsive-layout.svg)

**일반화한 예**입니다. 내 사이트의 메뉴 방식과 열 개수는 다를 수 있습니다. 그림은 "구조"를 보여 주는 것이니, 내 사이트의 **실제 숫자는 관찰 ②의 표**를 기준으로 하세요.

### 그림 읽는 순서

1. **위쪽 막대**: 규칙이 어떻게 쌓이는지(기본 → 768 → 1024)를 봅니다. **포함·누적** 관계입니다.
2. **가운데 세 화면**: 카드 `1·2·3`이 **같은 순서와 같은 HTML**인데 놓인 모양만 다른 것을 봅니다.
3. **초록 상자**: "HTML 구조는 세 화면에서 똑같습니다"를 소리 내어 읽습니다.
4. **아래 설명**: 메뉴는 Flexbox, 카드는 Grid가 맡습니다. 마지막 상자는 이 변화를 만드는 코드의 모양입니다.

### 면 — 한 문장

> **HTML 구조는 하나로 두고, 화면 폭이라는 조건에 따라 CSS가 서로 다른 배치 규칙을 켜서 여러 화면에 대응합니다.**

### 1장·4장과 이어지는 곳

모바일에서 햄버거 버튼이 **보이게 하고** 메뉴 항목을 **숨기는** 것은 CSS입니다. 버튼을 **눌렀을 때 열고 닫는** 것은 JavaScript입니다. 한 기능에 **둘이 나눠 일합니다.** (4장)

## 5. 코드 확인 — 내 프로젝트에서 찾기

### 5-1. 찾는 방법

| 방법 | 어떻게 |
| --- | --- |
| 편집기 검색 | `Ctrl+Shift+F`로 `@media`, `min-width`, `display: flex`, `display: grid`, `grid-template-columns`, `:root`, `var(--` 검색 |
| 개발자 도구 Styles | 요소를 선택하면 오른쪽 **Styles** 패널에 그 요소에 적용된 CSS 규칙이 나옵니다. `@media (min-width: 768px)` 아래에 있는 규칙은 폭을 바꾸면 켜지고 꺼집니다. 규칙 오른쪽 `style.css:줄번호`가 코드 위치입니다. |
| 화면 → 코드 | 관찰 ②에서 바뀐 메뉴·카드를 요소 선택 도구(`Ctrl+Shift+C`)로 클릭 → Styles에서 해당 규칙 확인 |

### 5-2. 일반화 예제 — Mobile First CSS의 모양

> 🔷 **일반화 예제** 구조를 보여 주려고 새로 쓴 코드입니다. 클래스 이름(`site-menu` 등)은 **가정**입니다. **내 프로젝트의 코드가 아닙니다.**

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1c2721;
  --space: 1rem;
}

body {
  background: var(--color-bg);
  color: var(--color-text);
}

/* 기본 규칙: 모바일 기준 */
.site-menu   { display: none; }
.menu-toggle { display: block; }
.projects    { display: grid; grid-template-columns: 1fr; gap: var(--space); }

/* 768px 이상: 규칙을 덧붙임 */
@media (min-width: 768px) {
  .menu-toggle { display: none; }
  .site-menu   { display: flex; gap: var(--space); }
  .projects    { grid-template-columns: repeat(2, 1fr); }
}

/* 1024px 이상: 또 덧붙임 */
@media (min-width: 1024px) {
  .projects { grid-template-columns: repeat(3, 1fr); }
}
```

| 부분 | 읽는 법 |
| --- | --- |
| `:root { --… }` / `var(--…)` | 값에 이름을 붙이고 가져다 씀 (CSS 변수) |
| 맨 위 `.site-menu`, `.menu-toggle`, `.projects` | **기본 규칙(모바일)**: 메뉴 항목은 숨기고 ☰ 버튼을 보이고, 카드는 1열 |
| `@media (min-width: 768px) { … }` | 768 이상: ☰ 숨기고 메뉴를 가로(`flex`)로, 카드를 2열로 |
| `@media (min-width: 1024px) { … }` | 1024 이상: 카드를 3열로 |
| 순서(기본 → 768 → 1024) | 덧붙이는 규칙이 **아래에** 있어 앞의 규칙을 덮음 |

### 5-3. 내 CSS에서 찾기 (직접 채우기)

| 찾을 것 | 내가 찾은 것 | 코드 위치 (파일 : 줄) |
| --- | --- | --- |
| `index.html`의 `viewport` 줄 | ☐ 있다 ☐ 없다 | |
| 맨 위 **기본 규칙**이 모바일 기준인가 (`@media` 바깥 규칙) | ☐ 예 ☐ 아니오 | |
| `@media` 규칙의 개수와 숫자 | 개, 숫자: | |
| 메뉴를 Flexbox로 배치한 규칙 | | |

### 5-4. 점검 체크리스트 `[공식]`

- ☐ 기본 규칙은 작은 화면 기준이고, 큰 화면은 `min-width`로 덧붙인다.
- ☐ 768px와 1024px 전후에서 메뉴·카드가 깨지거나 겹치지 않는다.
- ☐ 메뉴는 Flexbox, 카드는 Grid로 배치했다.
- ☐ 좁은 화면(360px 정도)에서 옆으로 밀리는 가로 스크롤이 없다.
- ☐ 카드마다 고정 너비와 margin을 따로 주지 않았다.
- ☐ (`[시나리오]`) CSS 변수를 사용한다.

> **① 미디어 쿼리 지도**

> **② 메뉴가 바뀌는 과정**

> **④ 옆으로 밀림 후보 찾기**
> 좁은 화면에서 가로 스크롤을 만들 수 있는 CSS(고정 `px` 너비, 화면보다 큰 요소 등)를 **후보로만** 찾아서 파일·줄 번호와 이유를 알려 줘. 고치지는 마.

## 7. 자기 설명

### 빈칸 설명 틀

> 같은 사이트가 화면 폭에 따라 다르게 보이는 이유는, CSS의 `________`로 **화면 폭이 `____px` 이상인지** 검사해서 배치 규칙을 바꾸기 때문입니다.
> 이 사이트는 **작은 화면이 기본**이고, 768px 이상에서 `________`가 바뀌고, 1024px 이상에서 `________`가 바뀝니다. (Mobile First)
> 메뉴는 `________`로, 카드는 `________`로 배치합니다. 이 둘은 `________`이 다릅니다.
> 이때 **HTML은 바뀌지 않습니다.** 바뀌는 것은 `________`입니다.

### 좋은 설명의 기준

- ☐ "화면이 줄어들어서"가 아니라 **"조건에 따라 다른 규칙이 켜져서"** 라고 말했다.
- ☐ **내 사이트의 실제 숫자**(관찰 ② 표)를 말했다.
- ☐ Flexbox와 Grid를 **"한 방향 / 행과 열"** 로 구분했다.
- ☐ HTML이 두 벌이 아니라는 것을 말했다.

### 동료평가에서 받을 수 있는 질문 `[공식]`

- Mobile First에서 작은 화면부터 설계하면 어떤 판단이 쉬워지나요?
- 브레이크포인트를 기기 이름이 아니라 콘텐츠 기준으로 정해야 하는 이유는 무엇인가요?
- 내비게이션 정렬에는 Flexbox가, 카드 전체 배치에는 Grid가 더 맞을 수 있는 이유는 무엇인가요?

### 흔한 함정 `[공식]`

| 함정 | 확인 방법 |
| --- | --- |
| 데스크톱만 맞고 좁은 화면에서 옆으로 넘침 | 폭 360에서 가로 스크롤 확인 |
| 특정 기기 폭만 맞추고 그 사이 폭이 깨짐 | 900·1023·1100 등 사이 폭 확인 |
| 카드마다 고정 너비와 margin을 줘서 폭마다 깨짐 | 카드 CSS에서 `px` 고정 폭 검색 |
| 2차원 카드 격자를 Flexbox 수치 조절로 억지로 맞춤 | 카드 컨테이너가 `display: grid`인지 확인 |

## 정리

- 화면 폭이라는 **조건**을 보고 CSS가 서로 다른 **배치 규칙**을 켭니다. HTML은 그대로입니다.
- **Mobile First**: 작은 화면이 기본, 768px·1024px에서 규칙이 **덧붙습니다.**
- 메뉴는 **Flexbox**(한 방향), 카드는 **Grid**(행과 열)입니다.
