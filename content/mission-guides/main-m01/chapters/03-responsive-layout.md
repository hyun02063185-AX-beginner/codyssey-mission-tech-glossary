# Chapter 3 — 화면 크기에 따라 디자인이 달라지는 이유

> 같은 웹사이트인데 휴대폰으로 보면 메뉴가 ☰ 버튼 뒤로 숨고 카드가 한 줄로 쌓입니다. 컴퓨터에서는 메뉴가 펼쳐지고 카드가 나란히 놓입니다. **코드는 이 차이를 어떻게 만들까요?**

**이 장에서 알게 되는 것**

- 화면 폭에 따라 배치가 바뀌는 **원리**(Media Query)
- **Mobile First**가 무엇이고 768px·1024px에서 무엇이 바뀌는지
- 메뉴에는 **Flexbox**, 카드에는 **Grid**를 쓰는 이유
- **CSS 변수**가 무엇이고 왜 쓰는지

📱 앞부분(그림까지)만 읽어도 핵심을 알 수 있습니다. 💻 뒤쪽은 컴퓨터 앞에서 내 프로젝트를 열고 읽으면 좋습니다.

## 같은 사이트가 왜 다르게 보일까?

> **같은 웹사이트가 PC와 모바일에서 다르게 보이는 이유는?** `[시나리오]`

"PC용 HTML과 모바일용 HTML이 따로 있는 것 아닐까?" 하고 생각하기 쉽습니다. 그렇지 않습니다. **HTML은 하나이고, CSS 안에 "화면 폭이 이만큼이면 이렇게 배치하라"는 조건부 규칙이 들어 있습니다.**

## 같은 HTML, 화면 폭마다 다른 배치

![V03: CSS 규칙이 모바일 기본, 768px 이상, 1024px 이상으로 쌓이는 막대 그래프와, 같은 웹페이지를 모바일·태블릿·데스크톱 폭으로 위에서 아래로 비교한 그림. 모바일은 메뉴가 햄버거 뒤에 접히고 카드 1열, 태블릿은 메뉴 가로 한 줄에 카드 2열, 데스크톱은 카드 3열입니다.](../assets/v03-responsive-layout.svg)

*일반화한 예입니다. 내 사이트의 메뉴 방식과 열 개수는 다를 수 있습니다. 내 사이트의 실제 숫자는 아래 "화면 폭을 바꿔 가며 확인하기"로 확인하세요.*

### 그림 읽는 법

1. **위쪽 막대**: 규칙이 기본 → 768px → 1024px 순서로 **쌓이는** 모습입니다. 1100px 화면에서는 세 가지가 **모두** 적용됩니다.
2. **가운데 세 화면**: 카드 `1·2·3`이 **같은 HTML**인데 놓인 모양만 다릅니다.
3. **초록 상자**: "HTML 구조는 세 화면에서 똑같습니다."
4. **아래 상자**: 이 변화를 만드는 코드는 CSS 안의 `@media` 규칙입니다.

> **HTML 구조는 하나로 두고, 화면 폭이라는 조건에 따라 CSS가 서로 다른 배치 규칙을 켜서 여러 화면에 대응합니다.**

모바일에서 햄버거 버튼을 **보이게 하고** 메뉴 항목을 **숨기는** 것은 CSS입니다. 버튼을 **눌렀을 때 열고 닫는** 것은 JavaScript입니다. 한 기능을 둘이 나눠 맡습니다. (4장)

## 화면 폭을 읽는 방법: Media Query

코드가 배치를 바꾸는 흐름은 이렇습니다.

1. 브라우저가 지금 **화면 폭**이 몇 px인지 알려 줍니다. (조건 검사)
2. **Media Query**가 조건이 맞을 때만 안쪽 규칙을 추가로 켭니다. (스위치)
3. 켜진 규칙이 **Flexbox 또는 Grid**로 배치 방법을 정합니다.
4. 눈에 보이는 **레이아웃**이 나옵니다.

**HTML은 이 흐름 어디에도 나오지 않습니다.** 바뀌는 것은 CSS 규칙뿐입니다.

### Media Query는 이렇게 생겼습니다

```css
@media (min-width: 768px) {
  /* 화면 폭이 768px 이상일 때만
     이 안의 규칙이 추가로 적용됩니다 */
}
```

- `@media` — "조건이 맞을 때만"이라는 표시
- `(min-width: 768px)` — 화면 폭이 **768px 이상**이라는 조건 (768 포함)
- `{ … }` — 조건이 맞을 때 켤 규칙들

[CSS Media Query](../../../terms/css-media-query.md)는 폭뿐 아니라 사용자 환경도 조건으로 쓸 수 있습니다. `[사전]` 이 장은 폭만 다룹니다.

### 숨은 조건: `viewport` 설정 한 줄

```html
<meta name="viewport"
      content="width=device-width,
               initial-scale=1">
```

이 줄은 `index.html`의 `<head>`에 있습니다. 휴대폰 브라우저에게 **"기기의 실제 화면 폭을 기준으로 그려 주세요"** 라고 알립니다. 이 줄이 없으면 휴대폰이 데스크톱 폭(대략 980px)으로 그린 뒤 줄여서 보여 주고, 모바일 규칙이 기대대로 적용되지 않을 수 있습니다. `[권장]`

## 작은 화면부터 쌓아 올리기: Mobile First

[모바일 퍼스트](../../../terms/mobile-first.md)는 **가장 작은 화면의 규칙을 기본값으로 먼저 쓰고, 화면이 넓어지면 `min-width` 조건으로 규칙을 덧붙이는** 방식입니다. `[사전]` `[공식]`

```
기본 규칙 ────────────────▶ 모든 폭
     768px 이상 규칙 ─────▶ 덧붙음
         1024px 이상 규칙 ▶ 또 덧붙음
```

이것이 V03 위쪽 막대 세 개입니다. 규칙은 **쌓입니다.** `[AI 보충]`

- 같은 요소를 두 규칙이 건드리면 **나중에 적힌 규칙**(같은 힘일 때)이 앞의 규칙을 덮습니다. 그래서 보통 `@media` 블록을 **기본 규칙 아래**에 둡니다. `[권장]`
- 왜 작은 화면부터일까요? 좁은 화면은 자리가 부족해서 **무엇이 꼭 필요한지** 먼저 정하게 됩니다. 그 뒤 공간이 생기면 늘리는 편이 쉽습니다.

> 반대로 "큰 화면이 기본, `max-width`로 줄임"도 있습니다. 이 미션은 **Mobile First**를 요구하므로 `min-width` 방식으로 설명합니다.

### 768px와 1024px는 "바뀌는 지점"입니다

[브레이크포인트](../../../terms/breakpoint.md)는 배치가 **바뀌는 화면 폭**입니다. 이 미션은 **768px와 1024px** 에서 전환하는 것을 확인합니다. `[공식]`

- 이 숫자는 "아이패드 폭" 같은 **기기 이름이 아니라**, 콘텐츠가 어색해지는 지점을 기준으로 정하는 것이 원칙입니다. `[사전]`
- 768과 1024는 **모든 사이트의 정답이 아니라 이 미션에서 검증하는 기준**입니다. `[사전]`
- **경계 사이**(예: 900px)도 깨지지 않아야 합니다.

## 메뉴는 Flexbox, 카드는 Grid

- [**Flexbox**](../../../terms/css-flexbox.md) — **한 방향**으로 늘어놓고 남는 공간을 나눕니다. 메뉴 항목처럼 **한 줄**에 알맞습니다. 이 미션에서는 내비게이션에 씁니다. `[공식]`
- [**Grid**](../../../terms/css-grid.md) — **행과 열**을 함께 정해 격자로 놓습니다. 프로젝트 카드처럼 **여러 줄·여러 칸**에 알맞습니다. 이 미션에서는 카드에 씁니다. `[공식]`

대표 코드는 이런 모양입니다.

```css
/* Flexbox: 한 줄로 늘어놓기 */
display: flex;
gap: 1rem;

/* Grid: 같은 폭의 열 3개 */
display: grid;
grid-template-columns: repeat(3, 1fr);
```

`[사전]` 읽는 법 — `repeat(3, 1fr)`은 "같은 폭의 열 3개", `1fr`은 **남는 공간을 1:1로 나눈 한 몫**이고, `gap`은 **칸 사이 간격**입니다. `[AI 보충]`

> 둘은 경쟁하지 않습니다. "한 방향 정렬은 Flexbox, 2차원 격자는 Grid"가 일반적인 구분이며 `[사전]`, 이 미션이 메뉴와 카드를 나눠 요구한 이유입니다.

## 값에 이름 붙이기: CSS 변수

```css
/* 이름 붙이기(정의) */
:root { --color-bg: #ffffff; }

/* 사용하기 */
body { background: var(--color-bg); }
```

- `--color-bg`처럼 **`--`로 시작하는 이름**이 변수입니다.
- `var(--color-bg)`는 "그 이름에 저장된 값을 여기에 쓰라"는 뜻입니다.
- 색·간격 같은 값이 여러 곳에 흩어지지 않고 **한 곳에서 관리**됩니다.
- 5장(다크모드)에서 이 값을 **통째로 바꿔치기**하는 방식이 나옵니다. 지금은 "값에 이름을 붙여 두는 것"만 알면 됩니다. `[AI 보충]`

> **동료평가와의 연결** B1-1 동료평가에는 CSS 변수(`:root`)를 **왜 썼는지** 묻는 문항이 있습니다. `[공식]` "AI가 그렇게 만들었다"가 아니라 "색·간격을 한 곳에서 관리하려고"처럼 **이유**를 내 코드의 실제 변수 이름으로 말할 수 있으면 됩니다. 다만 CSS 변수가 **필수 구현 조건**인지는 이 저장소의 자료만으로는 확정하지 못했습니다.

## 화면이 옆으로 밀리는 이유 `[권장]`

폭을 줄였더니 화면이 옆으로 밀리고 가로 스크롤이 생기는 경우가 있습니다. 대개 **고정 폭** 때문입니다.

- `width: 1200px` — **고정**입니다. 화면이 좁아도 1200px이라 옆으로 밀릴 위험이 있습니다.
- `max-width: 100%`, `width: 100%` — 부모 폭에 **맞춥니다.** 안전한 편입니다.
- `rem` — 글자 크기에 비례합니다.
- `fr` — Grid에서 남는 공간의 몫이라 칸 폭이 자연스럽게 변합니다.

**가로 overflow 없이 읽을 수 있는지**는 동료평가 확인 포인트입니다 `[공식]`. 반면 "고정 `px` 폭을 쓰지 말라"는 **미션 요구가 아니라 이 문제를 피하기 위한 일반적 권고**입니다 `[권장]`.

## 💻 화면 폭을 바꿔 가며 확인하기

### 화면 폭을 바꾸는 방법

- **개발자 도구의 장치 모드**: **F12** → 왼쪽 위 **휴대폰·태블릿 아이콘**(`Ctrl + Shift + M`, Mac은 `Cmd + Shift + M`). 위쪽 숫자 칸에 폭을 직접 입력합니다.
- **브라우저 창 크기**: 창 오른쪽 가장자리를 마우스로 끌어 좁힙니다.

> 💡 **확대 기능도 폭을 바꿉니다.** `Ctrl`을 누른 채 `+`로 200%까지 확대하면 같은 화면의 "CSS 폭"이 절반이 되어, 넓은 모니터에서도 모바일 규칙을 볼 수 있습니다.

### 어느 폭에서 무엇이 바뀌나

폭을 **360 → 767 → 768 → 900 → 1023 → 1024 → 1280** 순서로 바꿔 보세요. 특히 **767과 768, 1023과 1024** 사이에서 메뉴와 카드가 어떻게 달라지는지 눈여겨보면, 앞에서 읽은 "조건에 따라 규칙이 켜진다"가 눈에 보입니다. 바뀌는 지점이 정확히 768이나 1024가 아니라면 그것도 중요한 발견입니다. 내 사이트가 실제로 어디서 바뀌는지가 코드의 `@media` 숫자와 같은지 확인하세요.

좁은 폭(360 정도)에서 **가로 스크롤이 생기지 않는지**도 함께 봅니다.

### 도전: 메뉴를 열어 둔 채 넓혀 보기 (선택)

좁은 폭에서 ☰ 메뉴를 **열어 둔 채로** 창을 넓혀 보세요. 메뉴가 깔끔하게 가로로 바뀌나요, 아니면 이상하게 남나요? 이유를 지금 몰라도 괜찮습니다. 4장을 읽은 뒤 AI에게 물어볼 거리로 삼으세요.

## 내 CSS에서 규칙 찾아보기

### 찾는 방법

- **편집기 검색**: `Ctrl+Shift+F`로 `@media`, `min-width`, `display: flex`, `display: grid`, `grid-template-columns`, `:root`, `var(--`를 검색합니다.
- **개발자 도구 Styles**: 요소를 선택하면 오른쪽 **Styles** 패널에 그 요소에 적용된 CSS 규칙이 나옵니다. `@media (min-width: 768px)` 아래에 있는 규칙은 폭을 바꾸면 켜지고 꺼집니다. 규칙 오른쪽의 `style.css:줄번호`가 코드 위치입니다.
- **화면 → 코드**: 폭에 따라 바뀌는 메뉴·카드를 요소 선택 도구(`Ctrl+Shift+C`)로 클릭하고 Styles에서 해당 규칙을 확인합니다.

### 일반화 예제 — Mobile First CSS의 모양

> 🔷 **일반화 예제** 구조를 보여 주려고 새로 쓴 코드입니다. 클래스 이름(`site-menu` 등)은 **가정**입니다. **내 프로젝트의 코드가 아닙니다.**

```css
:root {
  --color-bg: #ffffff;
  --color-text: #1c2721;
  --space: 1rem;
}

body {
  background: var(--color-bg);
  color: var(--color-text);
}

/* 기본 규칙: 모바일 기준 */
.site-menu   { display: none; }
.menu-toggle { display: block; }
.projects {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space);
}

/* 768px 이상: 규칙을 덧붙임 */
@media (min-width: 768px) {
  .menu-toggle { display: none; }
  .site-menu {
    display: flex;
    gap: var(--space);
  }
  .projects {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 1024px 이상: 또 덧붙임 */
@media (min-width: 1024px) {
  .projects {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

이 코드는 이렇게 읽습니다.

- `:root { --… }`와 `var(--…)` — 값에 이름을 붙이고 가져다 씁니다. (CSS 변수)
- 맨 위 `.site-menu`, `.menu-toggle`, `.projects` — **기본 규칙(모바일)**: 메뉴 항목은 숨기고 ☰ 버튼을 보이고, 카드는 1열입니다.
- `@media (min-width: 768px)` — 768 이상: ☰를 숨기고 메뉴를 가로(`flex`)로, 카드를 2열로 바꿉니다.
- `@media (min-width: 1024px)` — 1024 이상: 카드를 3열로 바꿉니다.
- 덧붙이는 규칙이 **아래에** 있어 앞의 규칙을 덮습니다.

### 구현 상태 점검

**미션 요구·동료평가 확인 `[공식]`**

- 기본 규칙은 작은 화면 기준이고, 큰 화면은 `min-width`로 덧붙인다.
- 768px와 1024px 전후에서 메뉴·카드가 깨지거나 겹치지 않는다.
- 메뉴는 Flexbox, 카드는 Grid로 배치했다.
- 좁은 화면(360px 정도)에서 옆으로 밀리는 가로 스크롤이 없다.
- CSS 변수(`:root`)를 **썼다면 그 이유를**, 쓰지 않았다면 그 이유를 설명할 수 있다. (필수 구현 여부는 미션 원문 확인)

**내 코드를 더 단단하게 하는 권고 `[권장]` — 요구가 아닙니다**

- `index.html`에 `viewport` 설정 줄이 있다.
- 카드마다 고정 너비와 margin을 따로 주지 않고, 간격은 `gap`처럼 한 곳에서 관리한다.
- `@media` 블록이 기본 규칙 **아래**에 있다.
- 요소의 폭을 고정 `px`보다 `%`·`max-width`·`fr`로 두었다.

## AI에게 CSS를 설명시키는 법

> 1장의 네 가지 규칙(**수정하지 말고 설명만 / 파일·줄 번호 / 내 화면과 연결 / 답은 가설**)을 그대로 적용합니다.

> **미디어 쿼리 지도**
> 이 프로젝트의 CSS에서 `@media` 규칙을 모두 찾아 표로 정리해 줘. 각 규칙의 **조건, 안에서 바뀌는 것, 파일 이름과 줄 번호**를 알려 주고, `@media` 바깥의 **기본 규칙이 어느 화면 폭 기준인지**도 설명해 줘. 코드는 수정하지 마.

> **메뉴가 바뀌는 과정**
> 모바일에서는 햄버거 버튼이 보이고 768px 이상에서는 메뉴가 가로로 펼쳐지는 이 사이트의 동작을 CSS 줄 번호로 설명해 줘. **어느 규칙이 숨기고, 어느 규칙이 보이게 하는지** 구분해서 알려 줘. 수정은 하지 마.

> **카드 격자**
> 프로젝트 카드 레이아웃(Grid) 코드를 찾아서, 폭이 360px / 768px / 900px / 1024px일 때 각각 **몇 열**이 되는지 근거 줄과 함께 설명해 줘. 수정은 하지 마.

> **옆으로 밀림 후보 찾기**
> 좁은 화면에서 가로 스크롤을 만들 수 있는 CSS(고정 `px` 너비, 화면보다 큰 요소 등)를 **후보로만** 찾아서 파일·줄 번호와 이유를 알려 줘. 고치지는 마.

> **CSS 변수의 이유**
> 이 프로젝트의 `:root`에 정의된 CSS 변수를 모두 표로 정리해 줘. 각 변수가 **어떤 값이고 어디에서 쓰이는지** 파일·줄 번호와 함께 알려 주고, 이 변수를 쓰면 **한 곳만 바꿔서 여러 곳이 바뀌는 예**가 이 프로젝트에 있는지 설명해 줘. 쓰지 않은 값(하드코딩된 색·간격)이 많다면 그 후보도 알려 줘. 수정은 하지 마.

> **메뉴를 연 채 넓힐 때** (4장을 읽은 뒤에 물어보세요)
> 모바일에서 메뉴를 연 채 창을 넓히면 이 사이트에서는 어떤 일이 일어나? CSS와 JavaScript의 어느 줄 때문인지 설명해 줘. 수정은 하지 말고 설명만.

### AI의 답을 확인하는 법

| AI가 말한 것 | 내가 확인할 것 |
| --- | --- |
| "`style.css` 87번째 줄에서 카드가 2열이 됩니다" | 줄을 열어 보고, 폭을 768로 바꿨을 때 정말 2열이 되는지 |
| "900px에서는 2열입니다" | 장치 모드에서 폭에 900을 입력해 보기 |
| "고정 폭이라 위험합니다" | 그 요소가 실제로 화면 밖으로 나가는지 폭을 줄여 확인 |

## 동료평가에서는 이렇게 설명합니다

**동료평가에서 받을 수 있는 질문** `[공식]`

- Mobile First에서 작은 화면부터 설계하면 어떤 판단이 쉬워지나요?
- 브레이크포인트를 기기 이름이 아니라 콘텐츠 기준으로 정해야 하는 이유는 무엇인가요?
- 내비게이션 정렬에는 Flexbox가, 카드 전체 배치에는 Grid가 더 맞을 수 있는 이유는 무엇인가요?
- CSS 변수(`:root`)를 사용한 이유는 무엇인가요? (B1-1 Notion 동료평가 문항)

**이렇게 설명할 수 있습니다** (예시이며, 내 사이트의 실제 숫자와 변수 이름으로 바꿔 말하면 됩니다)

> 같은 HTML을 쓰되, CSS의 `@media (min-width: …)`로 화면 폭을 검사해서 배치 규칙을 바꿉니다. 이 사이트는 작은 화면이 기본이고, 768px 이상에서 메뉴가 가로로 펼쳐지고 카드가 2열이 되며, 1024px 이상에서 3열이 됩니다. 메뉴는 한 방향 정렬이라 Flexbox로, 카드는 행과 열이 필요해서 Grid로 배치했습니다. 색 같은 값은 `:root`의 CSS 변수에 모아 두어 한 곳만 고치면 되도록 했습니다.

**흔한 실수** (동료평가 참고 자료의 예시)

- 데스크톱만 맞고 좁은 화면에서 옆으로 넘침 → 폭 360에서 가로 스크롤 확인
- 특정 기기 폭만 맞추고 그 사이 폭이 깨짐 → 900·1023·1100 등 사이 폭 확인
- 카드마다 고정 너비와 margin을 줘서 폭마다 깨짐 (※ 미션 요구가 아니라 흔한 실수의 예) → 카드 CSS에서 `px` 고정 폭 검색
- 2차원 카드 격자를 Flexbox 수치 조절로 억지로 맞춤 → 카드 컨테이너가 `display: grid`인지 확인

## 핵심만 다시 보기

- 화면 폭이라는 **조건**을 보고 CSS가 서로 다른 **배치 규칙**을 켭니다. HTML은 그대로입니다.
- **Mobile First**: 작은 화면이 기본, 768px·1024px에서 규칙이 **덧붙습니다.**
- 메뉴는 **Flexbox**(한 방향), 카드는 **Grid**(행과 열)입니다.
- CSS 변수는 값을 **한 곳에서 관리**하게 해 주며, 동료평가에서 쓴 이유를 설명할 수 있어야 합니다.
