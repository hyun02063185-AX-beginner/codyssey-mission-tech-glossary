# Client-side Storage

## 한 줄 설명

browser가 사용자 기기에 data를 저장해 다음 방문에도 쓰게 하는 저장 영역.

## 쉽게 설명하면

브라우저가 사용자 기기에 값을 남겨 두는 자리입니다. 탭을 닫아도 남는 것과 닫으면 사라지는 것이 따로 있습니다.

## 정확한 설명

localStorage, sessionStorage, IndexedDB, cookie는 수명·용량·전송 경계가 서로 다르다.

## 이 미션에서는 왜 필요한가

이 회차에서 다크 모드 설정 같은 선택을 다음 방문에도 유지하려면 어딘가 저장해야 합니다. 어디에 저장하느냐에 따라 수명과 서버로 전송되는지 여부가 달라지므로, 저장할 값의 성격에 맞춰 골라야 합니다.

## 코드 예

```text
                수명              서버로 전송   용량
localStorage    지울 때까지        안 됨        약 5MB
sessionStorage  탭을 닫으면 사라짐  안 됨        약 5MB
cookie          만료 시각까지      매 요청마다   약 4KB
IndexedDB       지울 때까지        안 됨        훨씬 큼

테마 설정      → localStorage (오래 남아야 하고 서버는 몰라도 된다)
작성 중 초안   → sessionStorage (그 탭에서만 의미 있다)
로그인 세션    → 서버가 읽어야 하므로 cookie, 그것도 HttpOnly
```

## 주의할 점 / 경계 조건

저장 공간은 같은 출처(origin)별로 나뉩니다. `localhost:5173`에 저장한 값은 배포한 주소에서 읽히지 않으므로, 로컬에서 되던 것이 배포 후 초기 상태로 보일 수 있습니다.

## 관련 용어

- `local-storage`
- `cookie`
- `client-side-routing`

## 흔한 오해

브라우저에 저장했으니 안전하다고 생각하기 쉽지만, 사용자가 개발자 도구로 직접 열어 고칠 수 있습니다. 로그인 여부나 권한처럼 신뢰가 필요한 값을 여기에만 두면 안 됩니다.
