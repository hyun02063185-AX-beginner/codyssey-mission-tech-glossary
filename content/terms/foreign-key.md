# 외래 키

## 한 줄 설명

외래 키는 한 테이블의 열이 다른 테이블의 기본 키(또는 UNIQUE 키)를 참조하게 해 두 테이블의 관계를 지키는 규칙입니다.

## 쉽게 설명하면

주문 테이블의 `user_id`가 사용자 테이블에 실제로 있는 사용자만 가리키게 만드는 장치입니다.

![PK와 FK: enrollment의 student_id 값이 student의 id 값을 가리킨다](assets/pk-fk-relationship.svg)

B6-1의 수강(`enrollment`) 표는 학생 이름을 다시 적지 않고 `student_id` 값만 담습니다. 이 값이 학생(`student`) 표의 `id`와 같아서 어느 학생의 수강인지 정확히 찾을 수 있습니다.

## 정확한 설명

외래 키 제약은 참조 대상이 없는 값을 넣는 일을 막아 참조 무결성을 돕습니다. 부모 행을 삭제하거나 키를 바꿀 때는 제한, 연쇄 삭제, NULL 설정 같은 동작을 선택할 수 있습니다. 어떤 방식을 쓸지는 데이터가 사라져도 되는지에 따라 신중하게 정해야 합니다.

## 이 미션에서는 왜 필요한가

B6-1에서는 학생(`student`)과 수강(`enrollment`) 테이블을 연결할 때, 수강 표의 `student_id`가 학생 표의 `id`를 참조하도록 외래 키로 관계를 설정합니다.

## 관련 용어

- primary-key
- join
- relational-database

## 주의할 점 / 경계 조건

- 외래 키 열이 NULL을 허용하면, 값이 비어 있는 행은 아무 행도 가리키지 않습니다. NULL을 막으려면 `NOT NULL`을 함께 씁니다.
- SQLite는 `PRAGMA foreign_keys = ON;`을 실행해야 외래 키를 검사합니다. 켜지 않으면 없는 값도 들어갑니다.
- 표 사이의 관계가 모두 외래 키 제약으로 만들어지는 것은 아닙니다. 제약이 없어도 같은 값으로 JOIN할 수는 있지만, 잘못된 값을 막아 주지는 않습니다.

## 흔한 오해

외래 키는 다른 테이블의 모든 열을 복사하는 기능이 아닙니다. 관계를 가리키고 유효성을 검사하는 제약입니다.
