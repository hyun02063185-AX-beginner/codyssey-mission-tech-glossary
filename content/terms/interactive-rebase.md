# git rebase -i

## 한 줄 설명

commit 순서·message·squash를 편집하며 history를 재작성하는 rebase.

## 쉽게 설명하면

여러 커밋의 순서를 바꾸거나 합치거나 메시지를 고치는 정리 도구입니다.

## 정확한 설명

지정한 범위의 커밋을 목록으로 열어 각각에 대해 유지·수정·합치기·삭제를 지정한 뒤 다시 만든다. 결과는 새 커밋들이므로 해시가 전부 달라지고, 이미 공유한 범위에 적용하면 다른 사람의 이력과 어긋난다.

## 이 미션에서는 왜 필요한가

이 회차에서 검토 요청을 열기 전에 개인 브랜치를 정리하는 데 씁니다. "오타 수정", "다시 수정" 같은 커밋이 여러 개 쌓였을 때 하나로 합치면 검토자가 읽기 훨씬 쉬워집니다.

## 코드 예

```bash
git rebase -i origin/main        # 갈라진 뒤 내 커밋만 정리한다

# 편집기가 열린다
# pick a1b2c3d 로그인 폼 추가
# squash b2c3d4e 오타 수정          ← 앞 커밋에 합친다
# squash c3d4e5f 다시 수정
# reword d4e5f6a 검증 추가          ← 메시지만 고친다

#  pick    그대로
#  squash  앞 커밋에 합치고 메시지도 합친다
#  fixup   앞 커밋에 합치고 메시지는 버린다
#  drop    버린다

git rebase --abort               # 중간에 되돌리기
```

## 주의할 점 / 경계 조건

공유한 범위에는 쓰지 않습니다. 개인 브랜치에서 아직 올리지 않았거나 혼자 쓰는 경우에만 안전합니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

이력을 편집하는 것이라 생각하기 쉽지만, 새로 만드는 것입니다. 모든 해시가 달라집니다.
