# Race Condition

## 한 줄 설명

여러 실행 흐름의 실행 순서에 따라 공유 상태의 결과가 달라지는 오류 조건입니다.

## 쉽게 설명하면

두 사람이 같은 마지막 좌석을 동시에 예약하려 해 결과가 순서에 따라 달라지는 상황입니다.

## 정확한 설명

Race condition은 읽기·수정·쓰기 같은 여러 단계가 원자적으로 보호되지 않아 interleaving에 따라 데이터가 손실되거나 불일치할 때 발생합니다.

## 이 미션에서는 왜 필요한가

M08에서 deadlock과 달리 작업은 진행될 수 있지만 결과가 틀릴 수 있는 동시성 문제를 구분합니다.

## 코드 예

```python
# 둘 다 balance=0을 읽고 1을 써서 기대값 2 대신 1이 될 수 있다
balance += 1
```

## 주의할 점 / 경계 조건

Lock이 유일한 해결책은 아닙니다. atomic operation, message passing, DB transaction 등 상황에 맞는 경계를 선택할 수 있습니다.

## 관련 용어

- `lock`
- `mutex`
- `deadlock`
- `transaction`

## 흔한 오해

Race condition은 항상 재현되는 버그가 아니어서 테스트 한 번 통과했다고 없다고 단정하기 어렵습니다.
