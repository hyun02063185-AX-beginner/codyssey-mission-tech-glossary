# BST

## 한 줄 설명

왼쪽에는 작은 키, 오른쪽에는 큰 키를 두는 이진 탐색 트리.

## 쉽게 설명하면

숫자 기준으로 작은 것은 왼쪽, 큰 것은 오른쪽으로 갈라 놓은 나무다.

## 정확한 설명

각 노드의 왼쪽 부분 트리는 더 작은 키, 오른쪽 부분 트리는 더 큰 키를 가진다. 균형이 유지되면 탐색·삽입·삭제는 O(log n)이다.

## 대표 사용

정렬된 순서로 범위 검색을 지원해야 할 때 사용한다.

## 주의할 점

한쪽으로만 기울면 연결 리스트처럼 O(n)이 된다.

## 이 미션에서는 왜 필요한가

해시맵은 "이 키"를 찾는 데는 빠르지만 "10과 20 사이의 키"처럼 범위를 묻는 질문에는 답하지 못합니다. 키를 크기 순으로 담는 이 구조가 그 차이를 보여 주며, 보너스 과제에서 해시맵 대신 무엇을 쓸 수 있는지 판단하는 기준이 됩니다.

## 코드 예

```text
해시맵    get("user:42")            빠름 (평균 O(1))
          10 <= key <= 20 전부      불가 — 전체를 훑어야 한다

BST       get(42)                   O(log n), 균형이 유지될 때
          10 <= key <= 20 전부      O(log n + 결과 수), 중위 순회로

범위 질문이 없다면 BST 를 쓸 이유가 없다
```
