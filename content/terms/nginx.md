# Nginx

## 한 줄 설명

HTTP 요청을 받아 정적 파일을 제공하거나 애플리케이션 서버로 전달할 수 있는 웹 서버와 리버스 프록시입니다.

## 쉽게 설명하면

건물 현관에서 방문자를 맞아 알맞은 부서로 안내하는 안내 데스크와 비슷합니다.

## 정확한 설명

Nginx는 클라이언트 연결을 처리하고 정적 콘텐츠를 직접 응답하거나, 경로·호스트 규칙에 따라 upstream 애플리케이션으로 요청을 프록시할 수 있습니다. 애플리케이션 프레임워크와는 별도 프로세스입니다.

## 동작 원리

1. 클라이언트 요청을 수신합니다.
2. 정적 응답 또는 location 규칙을 고릅니다.
3. 필요하면 upstream에 전달하고 응답을 다시 클라이언트에 보냅니다.

## 이 미션에서는 왜 필요한가

M05 배포에서 공개 HTTP 진입점과 실행 중인 웹 애플리케이션의 역할을 분리해 확인합니다.

## 코드 예

```nginx
location /api/ {
  proxy_pass http://127.0.0.1:8000;
}
```

## 주의할 점 / 경계 조건

Nginx 설정이 정상이어도 upstream 프로세스, DNS, TLS 인증서가 실패하면 서비스 전체가 정상이라는 뜻은 아닙니다.

## 관련 용어

- `http`
- `health-check`
- `deployment`

## 흔한 오해

Nginx가 Python/Node 애플리케이션 코드를 직접 실행하는 프레임워크라는 생각은 맞지 않습니다.
