# Scheduler

## 한 줄 설명

실행 가능한 job 중 다음에 CPU를 받을 대상을 고르는 운영체제 구성 요소.

## 쉽게 설명하면

실행할 준비가 된 작업 중에서 다음에 CPU를 쓸 것을 고르는 운영체제의 부분입니다. 코어 수보다 작업이 많을 때 필요합니다.

## 정확한 설명

실행 가능한 프로세스 목록에서 정책에 따라 다음 대상을 고르고, 정해진 시간이 지나거나 대기 상태가 되면 다른 것으로 바꾼다. 어떤 정책을 쓰느냐에 따라 전체 처리량과 개별 작업의 대기 시간이 달라지며, 둘을 동시에 최적화할 수는 없다.

## 이 미션에서는 왜 필요한가

이 회차의 스케줄링 보너스를 묶는 개념입니다. 여러 프로그램이 동시에 도는 것처럼 보이는 이유가 여기 있고, CPU 사용률이 높지 않은데도 응답이 느린 상황을 설명할 때 이 관점이 필요합니다.

## 코드 예

```bash
cat /proc/loadavg
# 3.42 2.10 1.85 2/431 12345
#  └1분 └5분 └15분   └ 실행중/전체

# 코어 수와 비교한다
nproc
# 부하 평균이 코어 수보다 크면 기다리는 작업이 있다는 뜻

# 무엇을 기다리는지 — D 상태는 디스크 대기다
ps -eo pid,stat,comm | awk '$2 ~ /^D/'
# CPU 사용률은 낮은데 D 가 많으면 CPU 가 아니라 디스크가 병목이다
```

## 주의할 점 / 경계 조건

사용률이 낮은데 느리다면 CPU를 기다리는 것이 아니라 디스크나 네트워크를 기다리는 중일 수 있습니다. 부하 평균과 함께 봐야 구분됩니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

여러 프로그램이 진짜 동시에 돈다고 생각하기 쉽지만, 코어 수만큼만 실제로 동시입니다. 나머지는 아주 빠르게 번갈아 도는 것입니다.
