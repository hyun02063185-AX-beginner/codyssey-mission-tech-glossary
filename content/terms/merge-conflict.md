# merge conflict

## 한 줄 설명

같은 변경 위치를 Git이 자동으로 합칠 수 없어 사람이 선택해야 하는 상태.

## 쉽게 설명하면

두 사람이 같은 자리를 다르게 고쳐서 컴퓨터가 어느 쪽이 맞는지 정할 수 없는 상태입니다.

## 정확한 설명

합치는 양쪽이 같은 줄 범위를 다르게 바꿨을 때 발생한다. 자동으로 고를 수 없으므로 파일에 양쪽 내용이 표시자와 함께 남고, 사람이 최종 내용을 정한 뒤 표시자를 지우고 해결됐음을 알려야 합치기가 진행된다.

## 동작 원리

공통 조상 시점과 양쪽의 현재 상태를 비교합니다. 한쪽만 바꾼 줄은 그 변경을 그대로 반영하고, 양쪽 모두 바꾼 줄은 판단하지 않고 두 내용을 파일 안에 나란히 남깁니다.

## 이 미션에서는 왜 필요한가

이 회차에서 여러 명이 같은 파일을 만지면 반드시 겪습니다. 오류가 아니라 정상적인 상태인데, 처음 만나면 무언가 망가진 것으로 느껴져 브랜치를 버리고 다시 만드는 일이 생깁니다.

## 코드 예

```bash
git merge origin/main
# CONFLICT (content): Merge conflict in src/app.py

# 파일 안에 이렇게 남는다
# <<<<<<< HEAD
#     timeout = 30          ← 내 변경
# =======
#     timeout = 60          ← 상대 변경
# >>>>>>> origin/main

# 표시자를 지우고 최종 내용을 정한 뒤
git add src/app.py            # 해결됐음을 알린다
git commit

git merge --abort             # 처음부터 다시 하고 싶으면
```

## 주의할 점 / 경계 조건

표시자를 지우는 것만으로는 끝나지 않습니다. 해결됐음을 알려야 합치기가 이어집니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

충돌이 나면 무언가 잘못한 것이라 생각하기 쉽지만, 같은 자리를 함께 고쳤다는 사실을 알려 주는 것뿐입니다. 자동으로 한쪽을 골랐다면 그것이 더 위험합니다.
