# process monitoring

## 한 줄 설명

process의 resource·상태·log를 관찰해 이상을 찾는 작업.

## 쉽게 설명하면

프로그램이 떠 있는지, 얼마나 쓰고 있는지를 지켜보는 일입니다. 떠 있다는 것과 일을 하고 있다는 것은 다릅니다.

## 정확한 설명

프로세스의 존재 여부, 자원 사용량, 상태를 주기적으로 확인한다. 존재 확인만으로는 멈춰 있는 프로세스를 걸러 낼 수 없어, 실제로 요청에 응답하는지를 함께 보는 편이 판정에 가깝다.

## 이 미션에서는 왜 필요한가

이 회차의 점검 대상 중 하나입니다. 프로세스 이름으로 찾는 방식은 이름이 비슷한 다른 프로세스나 검색 명령 자체를 함께 세는 실수를 부르므로, 무엇을 세고 있는지 확인해 보는 것이 첫 단계입니다.

## 코드 예

```bash
if pgrep -x nginx >/dev/null; then    # -x 로 이름 전체가 맞는 것만
    echo "nginx: 떠 있음"
else
    echo "nginx: 없음" >&2
fi

# ps | grep 은 grep 자신을 함께 센다
ps aux | grep nginx | grep -v grep | wc -l   # -v grep 이 필요한 이유

# 떠 있는 것과 일하는 것은 다르다
curl -fsS --max-time 3 http://localhost/healthz >/dev/null \
    && echo "응답함" || echo "응답 없음"
```

## 주의할 점 / 경계 조건

이름으로 찾으면 검색 명령 자신이 함께 잡힙니다. 전용 명령을 쓰거나 패턴을 다듬어야 합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

프로세스가 있으면 정상이라고 생각하기 쉽지만, 멈춘 채로 떠 있을 수 있습니다. 응답을 확인해야 살아 있는지 알 수 있습니다.
