# SSH

## 한 줄 설명

암호화된 원격 shell 접속과 파일 전송에 쓰는 프로토콜.

## 쉽게 설명하면

멀리 있는 컴퓨터의 명령창을 내 컴퓨터에서 여는 방법입니다. 오가는 내용이 암호화되고, 접속하는 쪽과 받는 쪽이 서로를 확인합니다.

## 정확한 설명

연결을 맺을 때 키를 교환해 암호화 통로를 만들고, 서버는 호스트 키로 자신을 증명하며 사용자는 비밀번호나 공개키로 자신을 증명한다. 공개키 인증은 공개키와 개인키가 한 쌍인 비대칭키 방식이다. 서버에는 공개키를 등록하고, 접속자는 개인키로 서명해 자신이 그 공개키의 소유자임을 증명한다. 검증에는 공개키만 쓰이므로 개인키 자체는 네트워크로 전송되지 않는다. 같은 통로로 파일 전송과 포트 포워딩도 할 수 있다.

## 동작 원리

처음 접속하면 서버의 호스트 키 지문을 보여 주고 사용자가 받아들이면 로컬에 기록합니다. 다음부터는 그 기록과 대조해 서버가 바뀌지 않았음을 확인합니다. 사용자 인증에서는 서버의 등록된 공개키가 개인키의 서명을 검증합니다. EC2에서는 Key Pair를 만들 때 공개키가 인스턴스에 등록되고, 접속자는 내려받아 안전하게 보관한 개인키로 서명합니다. 개인키 파일이나 그 내용은 서버로 보내지지 않습니다.

## 이 미션에서는 왜 필요한가

B3-1에서 EC2에 관리 접속하는 통로입니다. 인터넷에 열려 있는 문이므로 자동화된 접속 시도가 끊임없이 들어오고, 그래서 비밀번호 대신 EC2 Key Pair의 키 인증을 쓰고 SSH 22번 포트는 현재 공인 IP 하나(`/32`)로 제한합니다.

## 코드 예

```bash
ssh -i ./ec2-key.pem user@server-address    # 개인키로 서명해 접속한다

chmod 400 ./ec2-key.pem                     # 소유자만 읽을 수 있게 한다

# 처음 접속 때 보이는 지문은 서버가 바뀌었는지 확인하는 근거다.
# 나중에 지문이 달라졌다는 경고가 뜨면 그냥 지우지 말고 이유를 확인한다
```

## 주의할 점 / 경계 조건

개인키 파일의 권한이 느슨하면 클라이언트가 사용을 거부합니다. `chmod 400`은 소유자만 개인키를 읽을 수 있게 해 SSH 클라이언트가 안전한 키 파일이라고 판단하도록 하는 권한 설정입니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`
- `ssh-key`

## 흔한 오해

키를 쓰면 비밀번호를 안 쓰니 덜 안전하다고 생각하기 쉽지만 반대입니다. 추측으로 뚫을 수 있는 비밀번호와 달리 키는 추측이 사실상 불가능합니다.
