# SSH

## 한 줄 설명

암호화된 원격 shell 접속과 파일 전송에 쓰는 프로토콜.

## 쉽게 설명하면

멀리 있는 컴퓨터의 명령창을 내 컴퓨터에서 여는 방법입니다. 오가는 내용이 암호화되고, 접속하는 쪽과 받는 쪽이 서로를 확인합니다.

## 정확한 설명

연결을 맺을 때 키를 교환해 암호화 통로를 만들고, 서버는 호스트 키로 자신을 증명하며 사용자는 비밀번호나 공개키로 자신을 증명한다. 같은 통로로 파일 전송과 포트 포워딩도 할 수 있다.

## 동작 원리

처음 접속하면 서버의 호스트 키 지문을 보여 주고 사용자가 받아들이면 로컬에 기록합니다. 다음부터는 그 기록과 대조해 서버가 바뀌지 않았음을 확인하며, 사용자 인증은 공개키를 서버에 등록해 두고 개인키로 서명해 증명하는 방식이 기본입니다.

## 이 미션에서는 왜 필요한가

이 회차에서 클라우드 서버에 접속하는 유일한 통로입니다. 인터넷에 열려 있는 문이므로 자동화된 접속 시도가 끊임없이 들어오고, 그래서 비밀번호 대신 키를 쓰고 관리자 계정의 직접 접속을 막는 설정이 함께 요구됩니다.

## 코드 예

```bash
ssh-keygen -t ed25519 -C "codyssey"        # 키 한 쌍을 만든다
ssh-copy-id -i ~/.ssh/id_ed25519.pub ubuntu@서버주소

chmod 600 ~/.ssh/id_ed25519                # 권한이 느슨하면 거부된다
ssh -i ~/.ssh/id_ed25519 ubuntu@서버주소

# 처음 접속 때 보이는 지문은 서버가 바뀌었는지 확인하는 근거다.
# 나중에 지문이 달라졌다는 경고가 뜨면 그냥 지우지 말고 이유를 확인한다
```

## 주의할 점 / 경계 조건

개인키 파일의 권한이 느슨하면 클라이언트가 사용을 거부합니다. 본인만 읽을 수 있게(600) 두어야 합니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

키를 쓰면 비밀번호를 안 쓰니 덜 안전하다고 생각하기 쉽지만 반대입니다. 추측으로 뚫을 수 있는 비밀번호와 달리 키는 추측이 사실상 불가능합니다.
