# 원격 저장소

## 한 줄 설명

local repository와 연결된 다른 repository의 이름과 주소.

## 쉽게 설명하면

내 컴퓨터의 저장소와 연결해 둔 다른 저장소입니다. 이름을 붙여 두고 그 이름으로 주고받습니다.

## 정확한 설명

다른 저장소의 주소에 붙인 별칭이다. 여러 개를 등록할 수 있고, 가져오기와 보내기는 이름으로 대상을 지정한다. 원격의 상태는 가져올 때만 갱신되므로, 내가 보는 원격 브랜치 정보는 마지막으로 가져온 시점의 것이다.

## 동작 원리

등록된 이름마다 주소가 저장되어 있습니다. 가져오면 원격의 브랜치 상태가 내 저장소 안의 별도 이름으로 기록되고, 그것과 내 브랜치를 비교해 몇 개 앞서거나 뒤처졌는지가 계산됩니다.

## 이 미션에서는 왜 필요한가

이 회차에서 여러 명이 같은 저장소를 쓰는 전제가 이것입니다. 내가 보는 원격 정보가 실시간이 아니라 마지막으로 가져온 시점의 것이라는 점을 모르면, 팀원이 올린 변경이 왜 안 보이는지 설명하지 못합니다.

## 코드 예

```bash
git remote -v                     # 등록된 이름과 주소

git fetch origin                  # 원격 상태를 가져온다 (내 파일은 안 바뀐다)
git branch -r                     # 이제 팀원의 브랜치가 보인다

git status
# Your branch is behind 'origin/main' by 3 commits
#   ↑ 이 숫자는 마지막 fetch 시점 기준이다

git fetch --prune                 # 원격에서 지워진 브랜치를 내 쪽에서도 정리
```

## 주의할 점 / 경계 조건

history를 바꾸는 명령은 이미 공유된 commit에 영향을 줄 수 있습니다. 실행 전 branch, remote, collaborator와의 합의를 확인해야 합니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

원격 브랜치 목록이 항상 최신이라고 생각하기 쉽지만, 가져오기를 해야 갱신됩니다. 팀원이 만든 브랜치가 안 보이는 것은 대개 이 때문입니다.

## 동료평가 질문

팀원이 올린 브랜치가 내 목록에 안 보일 때 무엇을 해야 하는지와 그 이유를 설명할 수 있나요?
