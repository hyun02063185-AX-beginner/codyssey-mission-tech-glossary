# 리베이스

## 한 줄 설명

commit을 다른 base 위에 다시 적용해 history를 재구성하는 작업.

## 쉽게 설명하면

내 커밋들을 다른 지점 위에 옮겨 다시 붙이는 작업입니다. 기록이 한 줄로 정리됩니다.

## 정확한 설명

지정한 기준 위에 내 커밋들을 차례로 다시 적용한다. 각 커밋이 새로 만들어지므로 해시가 전부 달라지며, 합치기 커밋이 생기지 않아 기록이 직선으로 보인다. 이미 공유한 범위에 적용하면 다른 사람의 이력과 어긋난다.

## 이 미션에서는 왜 필요한가

예비 M02는 두 대의 PC에서 작업하는 상황을 다룹니다. 양쪽에서 각각 커밋이 쌓이면 이력이 갈라지는데, 리베이스는 그것을 한 줄로 다시 세워 읽기 쉽게 만듭니다. 다만 이미 공유한 커밋에는 쓰지 않는 것이 원칙입니다.

## 코드 예

```text
merge 한 결과                rebase 한 결과

  *   Merge branch...          * 로그인 검증 추가   ← 새 해시
  |\                           * 로그인 폼 추가     ← 새 해시
  | * 로그인 검증 추가          * README 수정
  | * 로그인 폼 추가            * 초기 커밋
  * | README 수정
  |/                           한 줄로 정리된다
  * 초기 커밋                   합친 시점의 기록은 사라진다

공유한 브랜치  → merge (이력을 건드리지 않는다)
내 브랜치      → rebase (올리기 전에 정리)
```

## 주의할 점 / 경계 조건

여러 커밋을 옮기면 각각에서 충돌이 날 수 있습니다. 합치기와 달리 충돌 해결이 여러 번 반복될 수 있습니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

합치기보다 깔끔하니 항상 낫다고 생각하기 쉽지만, 언제 합쳤는지에 대한 기록이 사라집니다. 공유 브랜치에서는 합치기가 맞습니다.
