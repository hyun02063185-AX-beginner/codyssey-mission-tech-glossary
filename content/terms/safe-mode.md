# safe-mode

## 한 줄 설명

문제 원인을 좁히기 위해 최소 기능·driver만으로 시작하는 진단 모드.

## 쉽게 설명하면

기능을 최소한만 켜고 동작시켜 문제의 원인을 좁히는 방식입니다.

## 정확한 설명

선택적인 기능과 확장을 끈 상태로 실행한다. 정상 동작하면 원인이 꺼 둔 쪽에 있다는 것이 좁혀지고, 그래도 실패하면 핵심 쪽 문제로 판단할 수 있다. 진단 수단이지 그 상태로 계속 운영하는 방식은 아니다.

## 이 미션에서는 왜 필요한가

이 회차에서 민감한 내용을 밖으로 보내지 않는 모드를 두는 데 쓰입니다. 변경 내용을 모델에 보내지 않고 사람이 직접 적게 하면, 도구는 계속 쓰면서도 외부로 나가는 것을 완전히 막을 수 있습니다.

## 코드 예

```python
import argparse

parser.add_argument('--safe', action='store_true',
                    help='변경 내용을 외부로 보내지 않습니다')

if args.safe:
    print('--- 아래 내용을 직접 요약해 주세요 ---')
    print(summary_of(diff))          # 밖으로 나가지 않는다
else:
    message = ask(build_prompt(mask(diff)))

# 이 모드로 정상 동작하면
#   원인은 외부 호출 쪽에 있다 (키, 네트워크, 응답 형식)
# 이 모드로도 실패하면
#   원인은 변경 수집이나 출력 쪽에 있다
```

## 주의할 점 / 경계 조건

진단용 상태입니다. 그대로 계속 쓰면 꺼 둔 기능이 필요할 때 왜 안 되는지 알기 어려워집니다.
