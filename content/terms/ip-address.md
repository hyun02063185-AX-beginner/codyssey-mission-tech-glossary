# IP 주소

## 한 줄 설명

IP 주소는 네트워크에서 데이터를 보낼 상대(정확히는 기기의 네트워크 인터페이스)를 찾아가기 위해 붙이는 번호입니다.

## 쉽게 설명하면

택배에 받는 사람의 주소가 있어야 배달할 수 있듯, 네트워크로 데이터를 보낼 때도 찾아갈 번호가 필요합니다. 그 번호가 IP 주소입니다. 비유는 여기까지입니다. 실제 IP 주소는 사람이 아니라 기기의 네트워크 연결 지점(인터페이스)에 붙고, 한 기기가 주소를 여러 개 가질 수 있습니다.

IPv4 주소는 `203.0.113.10`처럼 0~255 사이의 숫자 네 개를 점으로 이어 씁니다.

## 정확한 설명

IP(Internet Protocol)가 정한 주소 체계입니다. IPv4 주소는 32비트이며, 8비트씩 네 덩어리로 나눠 10진수로 적습니다. 주소가 부족해 128비트 주소를 쓰는 IPv6도 함께 쓰입니다. 이 설명과 B3-1 예시는 IPv4 기준입니다.

패킷의 IP 정보에는 출발지 IP 주소와 목적지 IP 주소가 들어 있고, 라우터는 목적지 주소를 보고 다음 경로를 고릅니다. 주소는 쓰이는 범위에 따라 인터넷 라우팅에 쓰는 공인 IP와 내부 네트워크에서 쓰는 사설 IP로 나뉩니다. 여러 주소를 묶은 범위는 CIDR(`10.0.0.0/16`)로 적습니다.

## 이 미션에서는 왜 필요한가

B3-1(M05)의 AWS 구성은 IP 주소를 여러 자리에서 다룹니다. VPC `10.0.0.0/16`과 Subnet `10.0.1.0/24`는 주소 범위이고, EC2의 네트워크 인터페이스(ENI)는 그 범위 안의 사설 IPv4를 받았으며, 외부 접속에는 자동 할당된 공인 IPv4를 썼습니다. Security Group 규칙의 출발지(`0.0.0.0/0`, `내 IP/32`)도 IP 주소 범위입니다. 무엇이 주소 하나이고 무엇이 범위인지 구분하면 설정 화면을 읽을 수 있습니다.

## 코드 예

```text
IPv4 주소 한 개 (문서용 예시 주소)
  203 . 0 . 113 . 10
  └── 0~255 숫자 4개 = 32비트

주소 하나와 범위
  10.0.1.149      주소 하나 (B3-1 당시 EC2의 사설 주소)
  10.0.1.0/24     범위: 10.0.1.0 ~ 10.0.1.255 (256개)
  0.0.0.0/0       모든 IPv4 주소

리눅스에서 내 인터페이스의 주소 보기
  ip addr show     # EC2 안에서는 사설 주소만 보인다
```

## 주의할 점 / 경계 조건

IP 주소만으로는 어느 프로그램과 통신할지 정해지지 않습니다. 같은 주소 안의 프로그램은 TCP·UDP의 포트 번호로 구분합니다. 또 주소를 안다고 통신이 되는 것은 아닙니다. 경로, 허용 규칙, 요청을 받는 프로그램이 함께 맞아야 합니다.

## 흔한 오해

"IP 주소는 컴퓨터마다 하나"라고 생각하기 쉽지만, 주소는 네트워크 인터페이스에 붙어서 한 기기가 여러 주소를 가질 수 있습니다. B3-1의 EC2도 운영체제 안에서는 사설 주소만 보이고, 밖에서 쓰는 공인 주소는 AWS의 인터넷 게이트웨이가 짝지어 줍니다.

## 비슷한 개념과의 차이

IP 주소는 기기(인터페이스)를, 포트는 그 기기 안에서 통신할 프로그램을 가리킵니다. 포트는 IP 정보가 아니라 TCP·UDP 정보에 들어 있습니다. IP 주소의 IP는 인터넷 프로토콜(Internet Protocol)이며, IP는 주소를 보고 패킷을 전달하는 약속이고 IP 주소는 그 약속이 쓰는 번호입니다. `example.com` 같은 도메인 이름은 사람이 읽기 쉬운 이름이고, DNS가 그 이름에 해당하는 IP 주소를 찾아 줍니다.
