# Shared Responsibility Model

## 한 줄 설명

cloud provider와 고객이 보안 책임을 나누는 모델.

## 쉽게 설명하면

클라우드에서 어디까지가 제공자의 몫이고 어디부터가 내 몫인지를 나눈 그림입니다. 경계를 모르면 아무도 안 하는 구간이 생깁니다.

## 정확한 설명

제공자는 물리 시설·하드웨어·가상화 계층을 책임지고, 이용자는 그 위에 올린 운영체제·설정·데이터·접근 권한을 책임진다. 서비스 종류에 따라 경계가 달라지므로, 쓰는 서비스마다 어디까지가 자기 몫인지 확인해야 한다.

## 이 미션에서는 왜 필요한가

이 회차에서 클라우드에 서버를 올릴 때, 제공자가 보안을 해 줄 것이라 생각하고 방화벽과 접속 설정을 그대로 두면 열린 채로 남습니다. 이 회차가 요구하는 설정들이 전부 이 그림의 "내 몫" 쪽에 있습니다.

## 코드 예

```text
가상 서버를 빌렸을 때

  제공자 몫                     내 몫
  데이터센터 물리 보안           운영체제 보안 갱신
  서버 하드웨어                  방화벽 규칙
  가상화 계층                    SSH 설정, 계정 관리
  네트워크 기반 시설             애플리케이션 코드
                                 데이터와 백업
                                 접근 권한 정책

관리형 데이터베이스를 쓰면 운영체제 갱신이 왼쪽으로 넘어간다.
서비스마다 경계가 다르므로 매번 확인한다.
```

## 주의할 점 / 경계 조건

같은 제공자라도 서비스 종류에 따라 경계가 달라집니다. 가상 서버를 빌리면 운영체제 갱신이 내 몫이지만 관리형 데이터베이스는 제공자 몫입니다.

## 관련 용어

- `authentication`

## 흔한 오해

큰 회사가 운영하니 안전하다고 생각하기 쉽지만, 방화벽을 열어 두거나 키를 공개 저장소에 올리는 것은 내 몫의 실수입니다. 제공자가 막아 주지 않습니다.
