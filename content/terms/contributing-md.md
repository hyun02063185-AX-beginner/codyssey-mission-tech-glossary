# CONTRIBUTING.md

## 한 줄 설명

repository에 기여하는 방법과 규칙을 설명하는 문서.

## 쉽게 설명하면

이 저장소에 기여하려면 무엇을 어떻게 해야 하는지 적어 둔 문서입니다.

## 정확한 설명

브랜치 이름 규칙, 커밋 메시지 형식, 검토 요청 절차, 실행과 테스트 방법을 적는다. 새로 합류한 사람이 물어보지 않고도 시작할 수 있게 하는 것이 목적이므로, 실제 규칙과 어긋나면 없는 것보다 나쁘다.

## 이 미션에서는 왜 필요한가

이 회차의 팀 협업 규칙을 적는 자리입니다. 규칙을 말로만 정하면 나중에 합류한 사람이 알 수 없고, 같은 질문이 반복됩니다. 적어 두면 그 질문이 한 번으로 끝납니다.

## 코드 예

```text
# CONTRIBUTING.md

## 시작하기
    pip install -r requirements.txt
    uvicorn main:app --reload

## 브랜치
    feature/<설명>   기능
    fix/<설명>       버그
    main 에 직접 push 하지 않습니다.

## 커밋 메시지
    <종류>(<범위>): <제목>
    종류: feat fix docs refactor test chore

## Pull Request
    1. 이슈를 만들고 번호를 받습니다
    2. 브랜치를 파고 작업합니다
    3. PR 본문에 Closes #번호 를 적습니다
    4. 승인 1명을 받으면 합칩니다
```

## 주의할 점 / 경계 조건

규칙이 바뀌었는데 문서를 안 고치면 잘못된 안내가 됩니다. 문서를 믿고 따른 사람이 틀리게 됩니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

길게 쓸수록 좋다고 생각하기 쉽지만, 길면 아무도 안 읽습니다. 실제로 지켜야 하는 것만 짧게 적는 편이 지켜집니다.

## 동료평가 질문

이 문서만 읽고 처음 온 사람이 첫 검토 요청을 열 수 있는지 확인해 볼 수 있나요?
