# column type

## 한 줄 설명

column에 저장할 값의 종류와 가능한 범위를 정하는 schema 속성.

## 쉽게 설명하면

한 칸에 어떤 종류의 값이 들어갈 수 있는지 정해 두는 것입니다. 숫자 칸에는 숫자만, 날짜 칸에는 날짜만 들어갑니다.

## 정확한 설명

저장 공간, 비교와 정렬 방식, 허용 범위가 자료형에 따라 정해진다. 문자열로 저장한 날짜는 사전식으로 비교되고 문자열로 저장한 숫자는 10이 2보다 앞서므로, 의미에 맞는 자료형을 고르는 것이 이후 조회의 정확성을 좌우한다.

## 이 미션에서는 왜 필요한가

이 회차는 의미에 맞는 자료형을 지정하도록 요구합니다. 전부 문자열로 만들면 처음에는 편하지만, 날짜 범위로 거르거나 금액을 합할 때 기대한 결과가 나오지 않습니다.

## 코드 예

```sql
-- 문자열로 두면 비교가 사전식이다
-- '2026-3-5' 와 '2026-03-05' 는 다른 값으로 취급된다
SELECT * FROM post WHERE created_at BETWEEN '2026-03-01' AND '2026-03-31';

-- 숫자를 문자열로 두면 정렬이 어긋난다
-- '10' < '2'  → 사전식이라 10 이 먼저 온다

CREATE TABLE payment (
    id       INTEGER PRIMARY KEY,
    amount   INTEGER NOT NULL,     -- 원 단위 정수. 실수로 두면 오차가 쌓인다
    paid_at  TEXT    NOT NULL      -- SQLite 는 ISO 8601 문자열을 쓴다
);
```

## 주의할 점 / 경계 조건

금액을 실수형으로 두면 더할 때 미세한 오차가 쌓입니다. 정수(원 단위)나 십진 자료형을 쓰는 편이 안전합니다.

## 흔한 오해

어차피 값이 들어가니 자료형은 형식일 뿐이라고 생각하기 쉽지만, 비교와 정렬 방식이 달라집니다. 같은 데이터에서 다른 답이 나옵니다.
