# UNIQUE

## 한 줄 설명

한 column 또는 column 조합의 중복 값을 막는 database 제약.

## 쉽게 설명하면

같은 값이 두 번 들어오지 못하게 막는 규칙입니다. 이메일처럼 한 사람당 하나여야 하는 값에 씁니다.

## 정확한 설명

지정한 열 또는 열 조합에 중복 값이 저장되는 것을 막는다. 대부분의 데이터베이스는 이 제약을 위해 색인을 만들므로 조회도 함께 빨라진다. NULL의 취급은 구현마다 달라, 여러 개의 NULL을 허용하는 경우가 많다.

## 동작 원리

값을 넣거나 고칠 때 데이터베이스가 색인을 확인해 같은 값이 이미 있는지 봅니다. 있으면 저장을 거부하고 오류를 돌려주며, 이 검사는 여러 요청이 동시에 들어와도 한 번에 하나씩 처리되므로 애플리케이션에서 먼저 조회해 확인하는 것보다 확실합니다.

## 이 미션에서는 왜 필요한가

이 회차는 중복을 막도록 요구합니다. 코드에서 "이미 있는지 조회한 뒤 없으면 넣기"로 처리하면 두 요청이 동시에 들어왔을 때 둘 다 통과할 수 있는데, 이 제약은 그 틈을 데이터베이스 안에서 막습니다.

## 코드 예

```sql
CREATE TABLE member (
    id    INTEGER PRIMARY KEY,
    email TEXT NOT NULL UNIQUE
);

-- 여러 열을 묶으면 조합이 같을 때만 막힌다
CREATE TABLE post_like (
    post_id   INTEGER NOT NULL,
    member_id INTEGER NOT NULL,
    UNIQUE (post_id, member_id)    -- 같은 사람이 같은 글에 두 번 못 누른다
);
-- 같은 사람이 다른 글에 누르는 것은 허용된다
```

## 주의할 점 / 경계 조건

여러 열을 묶어 이 제약을 걸면 조합이 같을 때만 막힙니다. 각 열이 따로 중복되는 것은 허용됩니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

코드에서 확인했으니 제약은 필요 없다고 생각하기 쉽지만, 확인과 저장 사이에 다른 요청이 끼어들 수 있습니다. 제약은 그 틈을 없앱니다.
