# Root Cause Analysis

## 한 줄 설명

문제의 표면 증상만 완화하지 않고, 재발을 만들 수 있는 근본 원인을 확인하는 조사 과정입니다.

## 쉽게 설명하면

바닥의 물을 닦는 데서 멈추지 않고 어디서 물이 새는지 찾는 일입니다.

## 정확한 설명

Root cause analysis는 로그·측정값·변경 이력·재현 절차를 바탕으로 원인 가설을 검증하고, 증상·직접 원인·시스템 원인을 구분합니다. 하나의 사건에 단일 원인이 항상 있는 것은 아닙니다.

## 이 미션에서는 왜 필요한가

M08에서 CPU 과점유나 lock 대기 문제를 임시 재시작으로 끝내지 않고 원인을 설명합니다.

## 코드 예

```text
증상: 응답 지연
증거: lock 대기 증가
원인 가설: 획득 순서 불일치
검증: 순서 통일 후 재현 테스트
```

## 주의할 점 / 경계 조건

상관관계가 있는 지표 하나만으로 원인을 확정하면 잘못된 workaround를 배포할 수 있습니다.

## 관련 용어

- `logging`
- `verification`
- `workaround`

## 흔한 오해

가장 최근에 변경한 코드가 항상 근본 원인이라는 생각은 위험합니다.
