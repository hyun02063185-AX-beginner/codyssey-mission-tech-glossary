# Round-Robin

## 한 줄 설명

ready queue의 job에 일정 time slice를 번갈아 주는 scheduling 방식.

## 쉽게 설명하면

작업마다 정해진 시간만큼 번갈아 CPU를 주는 방식입니다. 오래 걸리는 작업이 있어도 다른 작업이 기다리지 않습니다.

## 정확한 설명

각 작업에 동일한 시간 조각을 주고 다 쓰면 대기열 뒤로 보낸다. 조각이 짧으면 응답이 고르지만 전환 비용이 늘고, 길면 전환 비용은 줄지만 뒤에 선 작업의 대기 시간이 길어진다. 조각 길이가 곧 이 방식의 조절 손잡이다.

## 이 미션에서는 왜 필요한가

이 회차의 스케줄링 보너스에서 비교하는 방식 중 하나입니다. 짧은 작업이 긴 작업 뒤에 갇히지 않는다는 점이 다른 방식과의 핵심 차이이고, 대화형 프로그램이 멈춘 것처럼 느껴지지 않는 이유이기도 합니다.

## 코드 예

```text
작업 A(10초), B(1초), C(1초) 가 동시에 도착. 조각 = 1초

  A B C A C? ...   1초씩 번갈아
  B 완료 시점 2초,  C 완료 시점 3초,  A 완료 시점 12초

먼저 온 것부터 (FCFS) 라면
  A 완료 10초,  B 완료 11초,  C 완료 12초

전체가 끝나는 시점은 비슷하다.
달라지는 것은 짧은 작업이 언제 끝나느냐다.
```

## 주의할 점 / 경계 조건

시간 조각을 너무 짧게 하면 전환하는 데 쓰는 시간이 일하는 시간만큼 커집니다. 짧을수록 좋은 것이 아닙니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

번갈아 돌리니 전체가 빨라진다고 생각하기 쉽지만, 전체 처리 시간은 오히려 늘 수 있습니다. 나아지는 것은 개별 작업의 첫 응답 시간입니다.
