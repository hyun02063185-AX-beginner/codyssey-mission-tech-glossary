# Pull Request

## 한 줄 설명

branch의 변경을 검토·논의·병합하기 위해 여는 협업 요청.

## 쉽게 설명하면

내 작업 줄기를 중심 줄기에 합쳐 달라고 여는 요청입니다. 합치기 전에 논의하고 검토하는 자리이기도 합니다.

## 정확한 설명

두 브랜치 사이의 차이를 보여 주고 그 위에서 검토와 논의를 진행하는 단위다. 자동 검사 결과와 승인 상태를 함께 담으며, 합쳐지기 전까지는 대상 브랜치에 아무 영향을 주지 않는다. 뒤에 커밋을 더하면 차이도 함께 갱신된다.

## 이 미션에서는 왜 필요한가

이 회차에서 변경을 제안하는 단위입니다. 코드를 합치는 수단이면서 동시에 "왜 이렇게 바꿨는가"가 남는 기록이라, 나중에 이 변경을 다시 볼 때 커밋 메시지보다 더 많은 맥락을 줍니다.

## 코드 예

```text
읽기 좋은 요청의 조건

  제목    무엇을 바꿨는지 한 줄로
  본문    왜 바꿨는지 / 어떻게 확인했는지 / 무엇을 남겨 뒀는지
  크기    한 주제, 가능하면 400줄 이내
  연결    Closes #12 로 이슈와 이어 둔다

검토자가 10분 안에 다 읽을 수 없으면
대충 승인되거나 며칠 방치된다. 둘 다 나쁘다.
```

## 주의할 점 / 경계 조건

한 요청에 여러 주제를 담으면 검토가 어려워집니다. 검토자가 읽어야 할 양이 많아지면 대충 승인하게 됩니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

열면 바로 합쳐진다고 생각하기 쉽지만, 합치는 것은 별도 동작입니다. 열어 둔 상태에서는 대상 브랜치에 아무 영향이 없습니다.

## 동료평가 질문

한 요청에 담을 변경의 크기를 어떻게 정할지, 검토자 입장에서 설명할 수 있나요?
