# 303

## 한 줄 설명

POST 처리 뒤 다른 URL을 GET으로 보게 하는 HTTP redirect status.

## 쉽게 설명하면

"처리했으니 이 주소를 새로 열어 보라"는 응답입니다. 새로 열 때는 항상 조회 요청이 됩니다.

## 정확한 설명

처리 결과를 다른 주소에서 조회하라는 의미의 리다이렉트다. 원래 요청이 무엇이었든 새 요청은 조회 방식으로 바뀌는 것이 규정이라, 저장 요청 뒤에 쓰면 새로고침이 저장을 되풀이하지 않는다. 다른 리다이렉트 코드는 원래 방식을 유지하기도 한다.

## 이 미션에서는 왜 필요한가

이 회차에서 글을 등록한 뒤 목록으로 보낼 때 씁니다. 다른 리다이렉트 코드를 쓰면 브라우저가 저장 요청을 그대로 다시 보낼 수 있어 중복 등록이 생기는데, 이 코드는 그 문제를 규정 수준에서 막습니다.

## 코드 예

```text
코드   새 요청의 방식        쓰는 자리
301    GET 으로 바뀜(관행)   주소가 영구히 바뀌었을 때
302    브라우저마다 다름     쓰지 않는 편이 낫다
303    항상 GET             저장 뒤 결과 화면으로 (이번 회차)
307    원래 방식 유지        POST 를 그대로 다시 보내야 할 때
308    원래 방식 유지        영구 이동 + 방식 유지

POST /posts  →  303 + Location: /posts/7
             →  브라우저가 GET /posts/7 을 보낸다
             →  새로고침해도 GET 이라 중복 등록이 안 된다
```

## 주의할 점 / 경계 조건

`302`는 브라우저에 따라 원래 방식을 유지하기도 합니다. 저장 뒤 이동에는 이 코드를 쓰는 편이 확실합니다.

## 관련 용어

- `http-request-response`
- `redirectresponse`

## 흔한 오해

리다이렉트는 다 같다고 생각하기 쉽지만, 새 요청이 어떤 방식이 되는지가 코드마다 다릅니다. 그 차이가 중복 등록 여부를 가릅니다.
