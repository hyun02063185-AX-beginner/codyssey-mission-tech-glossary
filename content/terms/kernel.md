# 커널

## 한 줄 설명

hardware와 process·memory·device를 중재하는 operating system 핵심.

## 쉽게 설명하면

하드웨어와 프로그램 사이에서 중재하는 운영체제의 핵심입니다. 프로그램은 직접 하드웨어를 만지지 못하고 여기에 부탁합니다.

## 정확한 설명

프로세스·메모리·장치·파일 시스템을 관리하고, 프로그램의 요청을 받아 하드웨어 작업을 대신 수행한다. 컨테이너는 이것을 호스트와 함께 쓰기 때문에 가상 머신보다 가볍고, 같은 이유로 격리 수준이 낮다.

## 이 미션에서는 왜 필요한가

예비 M01에서 컨테이너 격리가 성립하는 근거입니다. 컨테이너는 별도의 운영체제를 띄우는 것이 아니라 호스트의 커널을 함께 쓰면서 보이는 범위만 나눈 것이라, 커널이 하는 일을 알아야 격리가 어디까지인지도 알 수 있습니다.

## 코드 예

```bash
uname -r                     # 호스트의 커널 버전
docker run --rm ubuntu uname -r    # 컨테이너 안에서도 같은 값이 나온다

# 컨테이너는 커널을 공유한다. 이미지는 그 위의 도구 묶음일 뿐이다

# 프로그램이 커널에 부탁하는 것을 들여다보기
strace -c ls 2>&1 | head
# openat, read, write, close ... 전부 커널에 넘기는 요청이다
```

## 주의할 점 / 경계 조건

컨테이너가 호스트와 이것을 공유하므로, 호스트와 다른 버전을 요구하는 프로그램은 컨테이너로도 해결되지 않습니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

컨테이너가 독립된 운영체제를 갖는다고 생각하기 쉽지만, 이 부분은 호스트의 것을 함께 씁니다. 격리되는 것은 그 위에서 보이는 범위입니다.
