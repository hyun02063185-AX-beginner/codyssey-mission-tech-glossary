# Resource Exhaustion

## 한 줄 설명

CPU·memory·disk·file descriptor 같은 resource가 부족해 기능이 실패하는 상태.

## 쉽게 설명하면

무언가가 바닥나서 기능이 실패하는 상태 전체를 가리킵니다. 메모리만이 아니라 디스크, 파일 개수, 연결 수도 바닥날 수 있습니다.

## 정확한 설명

한정된 자원이 소진되면 그 자원을 요구하는 동작이 실패한다. 증상은 비슷해 보이지만 자원마다 확인할 곳이 달라서, 무엇이 바닥났는지 먼저 정하지 않으면 엉뚱한 곳을 보게 된다. 메모리·디스크·파일 서술자·연결 수·프로세스 수가 흔한 후보다.

## 이 미션에서는 왜 필요한가

이 회차가 다루는 장애들을 하나로 묶는 개념입니다. 개별 증상을 따로 외우는 대신 "무엇이 바닥났는가"를 먼저 묻는 순서를 만들면, 처음 보는 장애에도 같은 방식으로 접근할 수 있습니다.

## 코드 예

```bash
# 무엇이 바닥났는지 차례로 확인한다
free -m                       # 메모리
df -h /                       # 디스크 용량
df -i /                       # 파일 개수
ulimit -n; lsof -p "$PID" | wc -l    # 열린 파일 수 / 한도
ss -s                         # 연결 수
ps -eLf | wc -l               # 스레드 수

# 한도 자체를 확인한다
cat /proc/$PID/limits | grep -E "open files|processes"
```

## 주의할 점 / 경계 조건

파일 서술자 고갈은 메모리나 디스크가 넉넉해도 생깁니다. 연결을 닫지 않는 코드가 흔한 원인입니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

메모리와 디스크만 확인하면 된다고 생각하기 쉽지만, 열 수 있는 파일 개수와 만들 수 있는 프로세스 수에도 한도가 있습니다. 그쪽이 먼저 걸릴 수 있습니다.

## 동료평가 질문

처음 보는 장애를 만났을 때 무엇이 바닥났는지 확인하는 순서를 만들어 설명할 수 있나요?
