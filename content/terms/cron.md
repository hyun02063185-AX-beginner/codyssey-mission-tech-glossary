# cron

## 한 줄 설명

정해진 시간이나 주기에 command를 실행하는 scheduler service.

## 쉽게 설명하면

정해진 시각마다 명령을 자동으로 실행해 주는 기능입니다. 사람이 안 보고 있어도 돕니다.

## 정확한 설명

등록된 일정과 현재 시각을 비교해 명령을 실행한다. 실행 환경이 로그인 셸과 달라 환경 변수와 경로가 거의 비어 있으므로, 직접 실행할 때 되던 명령이 여기서는 실패하는 일이 흔하다. 출력은 화면이 아니라 메일로 보내려 하므로 사라진 것처럼 보인다.

## 이 미션에서는 왜 필요한가

이 회차는 점검을 매분 자동 실행하도록 요구합니다. 직접 실행하면 잘 되는 스크립트가 여기서는 조용히 실패하는 경우가 많은데, 원인은 대부분 환경 변수와 경로이고 출력을 파일로 남겨야 그 사실이 보입니다.

## 코드 예

```bash
# 출력을 남기지 않으면 실패해도 보이지 않는다
* * * * * /home/agent/monitor.sh >> /var/log/monitor.log 2>&1

# 실행 환경이 다르다는 것을 직접 확인해 본다
* * * * * env > /tmp/cron-env.txt
# 로그인 셸의 env 와 비교하면 PATH 가 훨씬 짧다

# 그래서 절대 경로를 쓴다
* * * * * /usr/bin/python3 /home/agent/check.py

# 실행 기록 확인
grep CRON /var/log/syslog | tail
```

## 주의할 점 / 경계 조건

실행 환경의 경로가 짧아 명령을 찾지 못할 수 있습니다. 절대 경로를 쓰거나 스크립트 안에서 경로를 지정해야 합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

등록했는데 안 돈다고 생각하기 쉽지만, 대개 돌긴 돌고 실패한 것입니다. 출력을 파일로 남겨 보면 바로 드러납니다.
