# Browser Rendering

## 한 줄 설명

browser가 HTML·CSS·JavaScript를 해석해 픽셀 화면을 만드는 과정.

## 쉽게 설명하면

브라우저가 글자로 된 HTML과 CSS를 받아 실제 픽셀로 바꾸는 과정입니다. 한 번에 그리는 것이 아니라 구조를 세우고, 위치를 재고, 칠하는 단계를 거칩니다.

## 정확한 설명

DOM/CSSOM, style 계산, layout, paint, compositing이 변경 종류에 따라 이어진다.

## 이 미션에서는 왜 필요한가

이 회차에서 스타일을 바꿨는데 화면이 늦게 반응하거나 깜빡이는 이유를 설명해 줍니다. 무엇을 바꿨느냐에 따라 다시 하는 단계가 달라지는데, 위치를 바꾸면 전부 다시 재야 하고 색만 바꾸면 칠하기만 다시 합니다.

## 코드 예

```text
HTML  →  DOM  ┐
              ├→ 스타일 계산 → 배치(layout) → 칠하기(paint) → 합성
CSS   → CSSOM ┘

무엇을 바꾸면 어디부터 다시 하는가
  width, top, font-size   배치부터       ← 가장 비싸다
  color, background       칠하기부터
  transform, opacity      합성만         ← 가장 싸다

애니메이션은 아래쪽 속성으로 만드는 편이 부드럽다.
```

## 주의할 점 / 경계 조건

단계를 건너뛰게 만드는 속성이 따로 있습니다. `top`이나 `width`를 바꾸면 배치 계산부터 다시 하지만, `transform`과 `opacity`는 합성 단계만 다시 하므로 애니메이션에서 체감 차이가 큽니다.

## 관련 용어

- `dom-update`
- `css-cascade`
- `virtual-dom-rendering`

## 흔한 오해

JavaScript로 DOM을 고치는 순간 화면이 바뀐다고 생각하기 쉽지만, 브라우저는 변경을 모아 두었다가 다음 그리기 시점에 한꺼번에 반영합니다. 그래서 반복문 안에서 여러 번 고쳐도 중간 상태는 보이지 않습니다.
