# Trunk-based Development

## 한 줄 설명

짧은 branch와 잦은 main 통합을 중시하는 개발 방식.

## 쉽게 설명하면

브랜치를 아주 짧게 쓰고 중심 줄기에 매우 자주 합치는 방식입니다. 하루에 여러 번 합치기도 합니다.

## 정확한 설명

브랜치 수명을 길어야 하루 수준으로 유지하고 중심 브랜치에 계속 통합한다. 충돌이 작을 때 해결되는 대신 미완성 기능이 중심 브랜치에 들어가므로, 기능을 켜고 끄는 장치로 사용자에게 보이지 않게 하는 방법이 함께 필요하다.

## 이 미션에서는 왜 필요한가

이 회차의 협업 흐름과 비교할 수 있는 다른 전략입니다. 같은 문제(충돌과 통합)를 브랜치를 더 짧게 해서 푸는 방식인데, 그 대신 미완성 코드를 감추는 장치가 필요하다는 대가가 붙습니다.

## 코드 예

```text
                GitHub Flow          Trunk-based
브랜치 수명      며칠                 하루 이내
합치는 주기      기능 단위             하루에 여러 번
충돌             가끔 크게             자주 작게
미완성 코드      브랜치에 머문다       main 에 들어간다
필요한 장치      없음                 기능 스위치, 자동 테스트

미완성 기능을 감추는 방법
  if settings.FEATURE_NEW_EDITOR:
      return render('editor_new.html')
  return render('editor.html')

자동 테스트가 촘촘하지 않으면 이 방식은 위험하다.
```

## 주의할 점 / 경계 조건

미완성 기능이 중심 브랜치에 들어갑니다. 켜고 끄는 장치 없이 이 방식을 쓰면 사용자에게 미완성 화면이 보입니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

브랜치를 안 쓰는 방식이라고 생각하기 쉽지만, 쓰되 아주 짧게 씁니다. 사라지는 것은 브랜치가 아니라 브랜치의 수명입니다.
