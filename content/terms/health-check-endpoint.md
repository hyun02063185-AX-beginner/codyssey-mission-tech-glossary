# Health Check Endpoint

## 한 줄 설명

서비스 상태를 확인하도록 만든 HTTP endpoint.

## 쉽게 설명하면

서비스가 살아 있는지 물어보는 전용 주소입니다. 사람이 아니라 감시 도구가 주기적으로 두드립니다.

## 정확한 설명

liveness와 readiness 목적, 상태 코드, timeout, 의존성 검사 범위를 분명히 정한다.

## 이 미션에서는 왜 필요한가

이 회차에서 배포한 서비스가 외부에서 실제로 응답하는지 증명하는 데 씁니다. 첫 화면을 여는 것으로 확인하면 화면이 무거워 오래 걸리거나 로그인 때문에 막히므로, 가볍고 인증이 필요 없는 주소를 따로 둡니다.

## 코드 예

```python
@app.get('/healthz')            # 떠 있는가 — 가볍게, 의존성 확인 없이
def healthz():
    return {'status': 'ok'}

@app.get('/readyz')             # 일할 준비가 됐는가 — 의존성까지 확인
def readyz():
    try:
        db.execute('SELECT 1')
    except Exception:
        return JSONResponse({'status': 'db'}, status_code=503)
    return {'status': 'ok'}

# 인증을 걸지 않는다. 대신 내부 정보도 담지 않는다
```

## 주의할 점 / 경계 조건

살아 있는지와 요청을 받을 준비가 됐는지는 다른 질문입니다. 데이터베이스 연결이 아직 안 됐는데 200을 돌려주면 감시 도구는 정상으로 보고 요청을 보냅니다.

## 관련 용어

- `health-check`
- `http-status-code`

## 흔한 오해

200을 돌려주면 서비스가 정상이라고 생각하기 쉽지만, 확인한 것은 웹 서버가 응답했다는 것뿐입니다. 무엇까지 확인할지는 그 안에 직접 적어야 합니다.

## 동료평가 질문

이 주소가 200 을 돌려주는데도 실제 기능은 실패하는 상황을 하나 들고, 어떻게 보완할지 설명할 수 있나요?
