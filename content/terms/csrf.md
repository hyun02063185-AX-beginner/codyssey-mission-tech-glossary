# CSRF

## 한 줄 설명

사용자가 로그인한 browser를 악용해 의도하지 않은 요청을 보내게 하는 공격.

## 쉽게 설명하면

로그인해 둔 사용자의 브라우저를 빌려 본인이 의도하지 않은 요청을 보내게 만드는 공격입니다. 브라우저가 쿠키를 알아서 붙여 보낸다는 성질을 악용합니다.

## 정확한 설명

브라우저는 요청 대상 도메인의 쿠키를 출처와 무관하게 실어 보낸다. 따라서 공격자의 페이지에서 우리 서비스로 보낸 요청에도 세션 쿠키가 붙어, 서버는 정상 사용자의 요청으로 본다. 막는 방법은 쿠키만으로는 확인할 수 없는 값을 요청에 함께 요구하는 것이다.

## 이 미션에서는 왜 필요한가

이 회차의 인증을 세션 쿠키로 만들면 이 공격의 대상이 됩니다. 로그인 검사는 통과한 요청이므로 인증만으로는 막히지 않고, 폼마다 서버가 발급한 값을 함께 받아 확인하는 처리를 더해야 합니다.

## 코드 예

```html
<form method="post" action="/posts/7/delete">
  <input type="hidden" name="csrf_token" value="{{ csrf_token }}" />
  <button>삭제</button>
</form>

<!--
  서버는 세션에 저장한 값과 폼으로 온 값을 비교한다.
  공격자의 페이지는 우리 세션의 값을 읽을 수 없으므로 채워 넣지 못한다.

  함께 쓰는 방어
    쿠키에 SameSite=Lax  → 다른 사이트에서 온 POST 에 쿠키가 안 붙는다
    상태를 바꾸는 요청은 GET 으로 만들지 않는다
-->
```

## 주의할 점 / 경계 조건

토큰을 쿠키에만 담고 검사하면 막히지 않습니다. 쿠키는 자동으로 붙기 때문이며, 폼 필드나 헤더처럼 공격자가 채워 넣을 수 없는 자리에서 값을 받아 비교해야 합니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

HTTPS를 쓰면 막힌다고 생각하기 쉽지만, 이 공격은 통신을 엿듣는 것이 아닙니다. 정상 경로로 정상 형식의 요청을 보내는 것이라 암호화는 관계가 없습니다.

## 동료평가 질문
