# Composite Key

## 한 줄 설명

둘 이상의 column을 합쳐 row를 식별하는 key.

## 쉽게 설명하면

한 칸만으로는 행을 구분할 수 없을 때, 두 칸 이상을 묶어 식별자로 쓰는 것입니다.

## 정확한 설명

여러 열의 조합이 함께 유일성을 만든다. 조합에 속한 각 열은 개별적으로 중복될 수 있으며, 조합 전체가 같을 때만 중복으로 판정된다. 외래 키로 참조할 때는 조합 전체를 가져가야 하므로 참조하는 표가 복잡해진다.

## 이 미션에서는 왜 필요한가

이 회차의 키 설계 심화 부분입니다. 회원과 글을 잇는 중간 표처럼 두 쪽을 함께 봐야 행이 정해지는 경우가 있는데, 이때 별도의 번호를 새로 만들지 아니면 두 열을 묶을지가 선택지입니다.

## 코드 예

```sql
CREATE TABLE post_tag (
    post_id INTEGER NOT NULL REFERENCES post(id),
    tag_id  INTEGER NOT NULL REFERENCES tag(id),
    PRIMARY KEY (post_id, tag_id)
);

-- post_id 3 이 여러 번, tag_id 5 도 여러 번 나올 수 있다
-- (3, 5) 조합만 한 번뿐이다

-- 조합의 순서가 조회 성능에 영향을 준다
SELECT * FROM post_tag WHERE post_id = 3;   -- 앞 열이라 빠르다
SELECT * FROM post_tag WHERE tag_id  = 5;   -- 뒤 열만으로는 느릴 수 있다
```

## 주의할 점 / 경계 조건

조합의 열 순서는 색인 효율에 영향을 줍니다. 앞에 오는 열만으로 조회하는 것은 빠르지만 뒤쪽 열만으로 조회하는 것은 그렇지 않습니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

열을 여러 개 묶으면 각 열도 유일해진다고 생각하기 쉽지만, 유일해지는 것은 조합입니다. 각 열에는 같은 값이 여러 번 나올 수 있습니다.
