# CODEOWNERS

## 한 줄 설명

경로별 review 책임자를 지정하는 CODEOWNERS file.

## 쉽게 설명하면

어느 경로를 누가 검토할지 적어 두는 파일입니다. 적어 두면 검토 요청에 자동으로 지정됩니다.

## 정확한 설명

경로 패턴과 담당자를 줄 단위로 적는다. 아래에 적힌 규칙이 위를 덮어쓰므로 구체적인 경로일수록 아래에 두어야 하며, 보호 규칙과 연결하면 지정된 사람의 승인 없이는 합칠 수 없게 만들 수 있다.

## 이 미션에서는 왜 필요한가

이 회차에서 검토 책임을 설정으로 옮기는 수단입니다. 누구에게 검토를 부탁할지 매번 생각하지 않아도 되고, 빠뜨리는 일도 없어집니다.

## 코드 예

```text
# .github/CODEOWNERS

*                   @team/reviewers      # 기본값 — 맨 위에 둔다
/src/api/           @alice @bob
/src/web/           @carol
/infra/             @dave
*.md                @alice

# 아래 규칙이 위를 덮어쓴다.
# 위 순서를 뒤집어 * 를 맨 아래 두면
# 모든 파일이 @team/reviewers 로만 가고 나머지가 무시된다

# 보호 규칙에서
#   ☑ Require review from Code Owners
```

## 주의할 점 / 경계 조건

뒤에 적은 규칙이 앞을 덮어씁니다. 넓은 범위를 아래에 두면 위의 구체적인 지정이 무효가 됩니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

여러 규칙이 맞으면 모두 지정된다고 생각하기 쉽지만, 마지막으로 맞는 규칙 하나만 적용됩니다.

## 동료평가 질문

규칙의 순서를 잘못 적었을 때 무슨 일이 생기는지, 예를 들어 설명할 수 있나요?
