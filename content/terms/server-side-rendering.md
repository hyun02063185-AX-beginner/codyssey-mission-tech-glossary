# Server-Side Rendering

## 한 줄 설명

서버가 요청에 맞춰 HTML을 만들어 browser에 보내는 렌더링 방식.

## 쉽게 설명하면

브라우저가 아니라 서버가 HTML을 완성해서 보내는 방식입니다. 브라우저는 받은 것을 그대로 그리면 되므로 첫 화면이 바로 보입니다.

## 정확한 설명

초기 HTML을 서버에서 만들고 필요하면 client JavaScript가 hydration으로 상호작용을 연결한다.

## 동작 원리

요청이 들어오면 서버가 데이터베이스에서 값을 읽어 템플릿에 채우고, 완성된 HTML 문자열을 응답으로 보냅니다. 브라우저는 자바스크립트를 기다리지 않고 바로 그릴 수 있습니다.

## 이 미션에서는 왜 필요한가

이 회차의 게시판은 이 방식으로 만듭니다. 화면을 만드는 일이 서버에 있으므로 로그인 여부나 권한에 따라 아예 다른 HTML을 보낼 수 있고, 반대로 화면이 바뀔 때마다 서버에 다시 요청해야 합니다.

## 코드 예

```text
SSR (이번 회차)
  요청 → 서버가 DB 조회 → 템플릿에 채움 → 완성된 HTML 응답
  첫 화면이 빠르다 / 화면이 바뀔 때마다 서버에 간다

SPA
  요청 → 빈 HTML + JS → JS 가 API 호출 → 브라우저가 그림
  첫 화면이 느리다 / 이후 이동이 빠르다

어느 쪽이든 권한 확인은 서버에서 해야 한다.
화면에서 버튼을 감추는 것은 안내이지 방어가 아니다.
```

## 주의할 점 / 경계 조건

화면을 만드는 데 필요한 데이터 조회가 모두 끝나야 응답이 나갑니다. 목록 하나를 그리려고 항목마다 따로 조회하면 응답 시간이 항목 수에 비례해 늘어납니다.

## 관련 용어

- `templateresponse`
- `browser-rendering`
- `single-page-application`

## 흔한 오해

서버가 HTML을 만들었으니 안전하다고 생각하기 쉽지만, 화면에서 버튼을 감추는 것과 그 경로를 막는 것은 다른 일입니다. 주소를 직접 입력하면 화면과 무관하게 요청이 들어옵니다.

## 동료평가 질문

권한이 없는 사용자에게 수정 버튼을 감추는 것만으로 충분하지 않은 이유와, 무엇을 더 해야 하는지 설명할 수 있나요?
