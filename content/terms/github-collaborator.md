# Collaborator

## 한 줄 설명

repository 권한을 받은 GitHub 사용자.

## 쉽게 설명하면

저장소에 권한을 받아 참여하는 사람입니다. 권한 등급에 따라 할 수 있는 일이 다릅니다.

## 정확한 설명

저장소 단위로 권한을 부여받은 계정이다. 읽기·분류·쓰기·관리·소유의 등급이 있고, 브랜치 보호 규칙은 쓰기 권한이 있어도 적용되므로 권한과 규칙은 별개로 작동한다.

## 이 미션에서는 왜 필요한가

이 회차에서 팀원을 저장소에 참여시키는 방식입니다. 개인 저장소에서 협업할 때 쓰는 가장 단순한 방법인데, 사람마다 따로 초대해야 하므로 인원이 늘면 관리가 번거로워집니다.

## 코드 예

```text
권한 등급

  Read      보기, 이슈 작성
  Triage    이슈·PR 분류 (코드 수정 불가)
  Write     push, 브랜치 생성, PR 병합   ← 팀원에게 보통 이것
  Maintain  설정 일부 변경
  Admin     모든 설정, 삭제

주의
  Write 가 있어도 보호된 main 에는 직접 push 할 수 없다.
  권한과 브랜치 보호는 따로 작동한다.

초대 → 상대가 수락 → 참여 완료
```

## 주의할 점 / 경계 조건

초대를 보내면 상대가 수락해야 참여가 완료됩니다. 초대만 보내 두고 되는 줄 아는 경우가 있습니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

쓰기 권한이 있으면 무엇이든 할 수 있다고 생각하기 쉽지만, 브랜치 보호 규칙은 권한과 별개로 적용됩니다.
