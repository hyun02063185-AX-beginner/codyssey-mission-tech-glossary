# 인증 오류

## 한 줄 설명

인증 정보가 없거나 유효하지 않아 요청을 처리할 수 없다는 실패 상태.

## 쉽게 설명하면

누구인지 확인되지 않아 요청이 거절된 상태입니다. 권한이 없어 거절된 것과는 다릅니다.

## 정확한 설명

자격 증명이 없거나 유효하지 않을 때의 실패다. 누구인지 확인되지 않은 경우와, 확인은 됐지만 그 동작이 허용되지 않은 경우는 다른 상태 코드로 구분되며, 재시도가 의미 있는지도 다르다. 앞쪽은 자격 증명을 고치면 되지만 뒤쪽은 다시 보내도 같은 결과다.

## 이 미션에서는 왜 필요한가

이 회차에서 모델 호출이 실패할 때 원인을 나누는 기준입니다. 키가 잘못된 것인지, 권한이 없는 것인지, 사용량을 넘긴 것인지에 따라 사용자에게 할 안내가 달라집니다.

## 코드 예

```python
try:
    r = httpx.post(URL, headers={'Authorization': f'Bearer {key}'}, json=payload)
    r.raise_for_status()
except httpx.HTTPStatusError as e:
    code = e.response.status_code
    if code == 401:
        raise RuntimeError('API 키가 올바르지 않습니다. 설정을 확인하세요.')
    if code == 403:
        raise RuntimeError('이 키로는 허용되지 않는 요청입니다.')
    if code == 429:
        raise RuntimeError('요청이 너무 잦습니다. 잠시 뒤 다시 시도하세요.')
    raise

# 메시지에 키 값을 넣지 않는다
```

## 주의할 점 / 경계 조건

실패 메시지에 자격 증명 값을 담으면 안 됩니다. 오류 보고서나 로그를 통해 그대로 새어 나갑니다.

## 관련 용어

- `authentication`

## 흔한 오해

401과 403이 같은 뜻이라고 생각하기 쉽지만, 앞은 "누구인지 모르겠다"이고 뒤는 "알지만 안 된다"입니다. 대응이 다릅니다.
