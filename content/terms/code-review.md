# code review

## 한 줄 설명

변경을 병합하기 전에 동료가 정확성·설계·위험을 검토하는 과정.

## 쉽게 설명하면

합치기 전에 동료가 변경을 읽어 보는 과정입니다. 틀린 곳을 찾는 것만이 목적은 아닙니다.

## 정확한 설명

정확성뿐 아니라 설계와 위험, 읽기 쉬움을 함께 본다. 검토를 거치면 변경 내용을 아는 사람이 둘 이상이 되므로 지식이 한 사람에게 몰리는 것을 막는 효과도 있다. 자동 검사가 잡는 것과 사람이 봐야 하는 것은 다르다.

## 이 미션에서는 왜 필요한가

이 회차가 요구하는 협업 활동입니다. 오류를 찾는 것보다 실질적인 효과는 그 코드를 아는 사람이 둘이 된다는 것인데, 팀원이 빠졌을 때 작업이 멈추지 않는 이유가 여기 있습니다.

## 코드 예

```text
도구에 맡길 것            사람이 볼 것
  들여쓰기, 줄바꿈          이 설계가 맞는가
  안 쓰는 변수              빠진 경우가 있는가
  타입 오류                 이름이 하는 일을 말하는가
  테스트 통과 여부          테스트가 맞는 것을 검사하는가
                            이 변경이 다른 곳에 미치는 영향

의견을 적을 때
  "이거 틀렸어요"                  → 무엇이 왜 틀렸는지가 없다
  "입력이 빈 문자열이면 어떻게 되나요?"  → 확인할 지점이 분명하다
```

## 주의할 점 / 경계 조건

형식이나 줄바꿈처럼 자동 도구가 잡을 수 있는 것에 시간을 쓰면 정작 봐야 할 설계를 놓칩니다. 그런 것은 도구에 맡깁니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

잘못을 지적하는 자리라고 생각하기 쉽지만, 묻는 것도 검토입니다. "이 경우에는 어떻게 되나요"라는 질문이 오류를 찾아내는 일이 많습니다.

## 동료평가 질문
