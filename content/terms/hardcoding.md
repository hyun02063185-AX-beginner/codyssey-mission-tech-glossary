# 하드코딩

## 한 줄 설명

변경 가능한 값·비밀값을 source code에 직접 고정하는 방식.

## 쉽게 설명하면

바뀔 수 있는 값이나 비밀 값을 코드 안에 직접 적어 두는 것입니다. 바꾸려면 코드를 고쳐야 합니다.

## 정확한 설명

값이 코드에 붙어 있으면 환경마다 다른 값을 쓸 수 없고, 저장소를 공유하는 순간 그 값도 함께 공유된다. 비밀값은 물론이고 주소·경로·한도처럼 환경에 따라 달라지는 값도 밖으로 빼는 것이 원칙이다.

## 이 미션에서는 왜 필요한가

이 회차는 모델 호출 키를 코드에 넣지 않도록 명시합니다. 개인 저장소라도 올리는 순간 되돌릴 수 없고, 한 번 이력에 들어간 값은 파일을 지워도 남기 때문입니다.

## 코드 예

```python
# 이렇게 하지 않는다
API_KEY = 'sk-abc123...'
DB_URL = 'postgresql://user:pass@prod-db:5432/app'
# API_KEY = 'sk-old456...'      ← 주석도 파일에 남는다

# 밖에서 받는다
import os
API_KEY = os.environ['API_KEY']        # 없으면 시작할 때 바로 실패한다
DB_URL = os.environ.get('DB_URL', 'sqlite:///dev.db')

# 올리기 전에 훑어본다
# git diff --staged | grep -iE 'api[_-]?key|secret|password|token'
```

## 주의할 점 / 경계 조건

주석에 적어 둔 값도 마찬가지입니다. 실행되지 않을 뿐 파일에는 그대로 있습니다.

## 관련 용어

- `authentication`

## 흔한 오해

개인 저장소라 괜찮다고 생각하기 쉽지만, 공개로 바꾸는 순간 과거 이력까지 전부 공개됩니다. 처음부터 넣지 않는 것이 유일한 방법입니다.
