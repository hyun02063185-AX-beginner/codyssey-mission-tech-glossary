# Inbound / Outbound Rule

## 한 줄 설명

resource로 들어오는 traffic과 나가는 traffic을 각각 제한하는 network rule.

## 쉽게 설명하면

들어오는 통신과 나가는 통신을 따로 정하는 규칙입니다. 방향이 다르면 다른 규칙이 적용됩니다.

## 정확한 설명

들어오는 규칙은 어디서 온 요청을 받을지를, 나가는 규칙은 어디로 요청을 보낼 수 있는지를 정한다. 상태를 기억하는 방화벽에서는 한쪽을 허용하면 그에 대한 응답이 자동으로 통과하지만, 상태를 기억하지 않는 방화벽에서는 양쪽을 모두 적어야 한다.

## 이 미션에서는 왜 필요한가

이 회차의 방화벽 설정이 이 두 방향으로 나뉩니다. 대부분 들어오는 쪽만 신경 쓰면 되지만, 서버가 외부 API를 호출해야 하는데 나가는 쪽이 막혀 있으면 원인을 찾기 어려운 실패가 생깁니다.

## 코드 예

```text
        인터넷 ──── 들어오는(inbound) ───▶ 서버
               ◀─── 나가는(outbound) ────

웹 서버로 쓸 때
  들어오는   80, 443 을 누구에게나 / 22 는 내 IP 에만
  나가는     기본 전체 허용 (패키지 설치, 외부 API 호출)

더 좁히려면
  나가는 것도 필요한 대상만 남긴다.
  대신 패키지 설치가 막히므로 무엇이 필요한지 먼저 확인한다.
```

## 주의할 점 / 경계 조건

들어오는 쪽을 열었는데도 안 되면 방향이 아니라 응답 경로를 봐야 합니다. 상태를 기억하지 않는 계층이 중간에 있으면 응답이 따로 막힐 수 있습니다.

## 관련 용어

- `authentication`

## 흔한 오해

나가는 쪽은 열어 둬도 상관없다고 생각하기 쉽지만, 서버가 뚫렸을 때 밖으로 데이터를 보내는 통로가 됩니다. 제한하면 그 경로가 좁아집니다.
