# ERD

## 한 줄 설명

entity와 attribute, relationship을 그림으로 나타낸 설계도.

## 쉽게 설명하면

표와 표 사이의 관계를 그림으로 그린 설계도입니다. SQL을 쓰기 전에 무엇을 어떻게 나눌지 확인하는 용도입니다.

## 정확한 설명

개체와 속성, 개체 사이의 관계와 개수를 기호로 표현한다. 실제 표 구조와 일대일로 대응하지는 않으며, 여럿 대 여럿 관계는 그림에서는 선 하나로 그려도 표로 옮길 때는 중간 표가 생긴다.

![ERD 읽기: 상자는 표, 선은 관계, 선 끝 기호는 최소·최대 개수](assets/erd-basics.svg)

선 끝 기호는 안쪽이 최대, 바깥쪽이 최소 개수입니다. 한쪽 표에서 출발해 반대쪽 끝의 기호를 읽습니다. 그림에서 학생 1명은 수강 기록을 0건 이상 가지고, 수강 기록 1건은 학생 정확히 1명에 속합니다.

## 이 미션에서는 왜 필요한가

이 회차의 선택 제출물이지만, 표를 네 개 이상 만들 때 관계를 머릿속으로만 잡으면 외래 키의 방향을 헷갈리기 쉽습니다. 그려 놓으면 어느 쪽에 키를 둘지가 그림에서 바로 보입니다.

B6-1 사례에서는 공부방 데이터베이스의 표 6개와 관계를 ERD로 그렸고, 가운데 수강(`enrollment`) 표가 학생과 수업의 여럿 대 여럿 관계를 잇습니다.

## 코드 예

```text
student ||────o< enrollment >o────|| course

선 끝 기호 (상자 쪽 = 최대, 바깥쪽 = 최소)
  ||          반드시 하나   (최소 1 · 최대 1)
  o<  >o      0개 이상 여럿 (최소 0 · 최대 여럿)
              세 갈래(< >)가 상자 쪽, 동그라미(o)가 바깥쪽

읽기: 한쪽 표에서 출발해 반대쪽 끝의 기호를 읽는다
  학생 1명 → 수강 기록 0건 이상     (enrollment 쪽 o<)
  수강 1건 → 학생 정확히 1명         (student 쪽 ||)
  수업 1개 → 수강 기록 0건 이상     (enrollment 쪽 >o)
  수강 1건 → 수업 정확히 1개         (course 쪽 ||)

여럿 쪽 표(enrollment)에 외래 키를 둔다.
enrollment.student_id,  enrollment.course_id
```

## 주의할 점 / 경계 조건

그림과 실제 표가 달라지면 그림이 잘못된 정보를 주게 됩니다. 설계를 바꿨으면 그림도 함께 고치거나, 고치지 않을 것이면 만든 시점을 적어 둡니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

그림을 그리면 표가 자동으로 정해진다고 생각하기 쉽지만, 여럿 대 여럿 관계처럼 그림과 표가 다른 경우가 있습니다. 옮기는 단계에 판단이 들어갑니다.
