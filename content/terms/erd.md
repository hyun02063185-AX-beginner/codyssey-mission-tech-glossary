# ERD

## 한 줄 설명

entity와 attribute, relationship을 그림으로 나타낸 설계도.

## 쉽게 설명하면

표와 표 사이의 관계를 그림으로 그린 설계도입니다. SQL을 쓰기 전에 무엇을 어떻게 나눌지 확인하는 용도입니다.

## 정확한 설명

개체와 속성, 개체 사이의 관계와 개수를 기호로 표현한다. 실제 표 구조와 일대일로 대응하지는 않으며, 여럿 대 여럿 관계는 그림에서는 선 하나로 그려도 표로 옮길 때는 중간 표가 생긴다.

## 이 미션에서는 왜 필요한가

이 회차의 선택 제출물이지만, 표를 네 개 이상 만들 때 관계를 머릿속으로만 잡으면 외래 키의 방향을 헷갈리기 쉽습니다. 그려 놓으면 어느 쪽에 키를 둘지가 그림에서 바로 보입니다.

## 코드 예

```text
member ──1────< post ──1────< comment
   │                              │
   └──────────1───────────────────┘
                (작성자)

기호
  1      한 개
  <      여러 개 (까마귀 발)
  ○      0 개여도 된다

그림에서 "여러 개" 쪽 끝에 외래 키를 둔다.
post.author_id,  comment.post_id,  comment.author_id
```

## 주의할 점 / 경계 조건

그림과 실제 표가 달라지면 그림이 잘못된 정보를 주게 됩니다. 설계를 바꿨으면 그림도 함께 고치거나, 고치지 않을 것이면 만든 시점을 적어 둡니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

그림을 그리면 표가 자동으로 정해진다고 생각하기 쉽지만, 여럿 대 여럿 관계처럼 그림과 표가 다른 경우가 있습니다. 옮기는 단계에 판단이 들어갑니다.

## 동료평가 질문

그린 그림과 실제 만든 표가 어긋나는 부분이 있는지 확인하고, 있다면 왜 그런지 설명할 수 있나요?
