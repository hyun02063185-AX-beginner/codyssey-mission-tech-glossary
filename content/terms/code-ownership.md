# Code Ownership

## 한 줄 설명

code 영역의 유지보수 책임과 review 책임을 정하는 운영 방식.

## 쉽게 설명하면

코드의 어느 부분을 누가 책임지고 볼지 정해 두는 운영 방식입니다.

## 정확한 설명

영역별로 유지보수와 검토의 책임자를 정한다. 검토 요청이 왔을 때 누구에게 물어야 하는지가 분명해지지만, 한 사람만 지정하면 그 사람이 없을 때 막히고 책임이 한곳에 몰려 지식이 퍼지지 않는다.

## 이 미션에서는 왜 필요한가

이 회차에서 검토 책임을 정하는 개념입니다. 아무도 책임지지 않으면 검토 요청이 며칠 방치되고, 한 사람이 다 책임지면 그 사람이 없을 때 팀 전체가 막힙니다. 둘 사이를 정하는 것이 이 결정입니다.

## 코드 예

```text
정할 것

  범위     어느 경로를 누가 보는가
  인원     한 영역에 최소 2명 (한 명이면 막힌다)
  기한     검토를 며칠 안에 하기로 하는가
  대안     책임자가 없을 때 누가 대신 보는가

4~5명 팀이라면
  프런트엔드   A, B
  백엔드       C, D
  배포·인프라  D, E

겹치게 두면 한 명이 빠져도 멈추지 않는다.
```

## 주의할 점 / 경계 조건

한 영역에 한 명만 두면 그 사람이 휴가일 때 아무도 합치지 못합니다. 최소 두 명을 두는 편이 낫습니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

책임자를 정하면 그 사람만 그 코드를 고쳐야 한다고 생각하기 쉽지만, 검토 책임이지 수정 독점권이 아닙니다.

## 동료평가 질문

책임자를 한 명만 둘 때와 여러 명 둘 때의 맞바꿈을 설명할 수 있나요?
