# Resource Cleanup

## 한 줄 설명

더 이상 쓰지 않는 cloud resource와 data를 제거해 비용·위험을 줄이는 작업.

## 쉽게 설명하면

실습이 끝난 뒤 만든 것들을 지우는 일입니다. 지우지 않으면 요금이 계속 나갑니다.

## 정확한 설명

자원마다 과금 기준과 삭제 순서가 다르고, 다른 자원이 참조하고 있으면 삭제가 거부되기도 한다. 만들 때의 역순으로 지우는 것이 대체로 맞으며, 무엇을 만들었는지 기록해 두지 않으면 목록을 다시 찾는 일 자체가 어려워진다.

## 이 미션에서는 왜 필요한가

이 회차 이후 과금을 막는 운영 작업입니다. 실습은 끝났는데 자원이 남아 몇 달 뒤 요금이 청구되는 일이 흔하므로, 만들면서 목록을 적어 두는 것이 정리의 실제 준비가 됩니다.

## 코드 예

```text
만든 순서
  VPC → 서브넷 → IGW → 경로표 → 보안그룹 → 인스턴스 → Elastic IP

지우는 순서 (역순)
  1. Elastic IP 연결 해제 후 반납
  2. 인스턴스 종료
  3. 남은 EBS 볼륨과 스냅샷 삭제
  4. 보안그룹 삭제 (쓰는 인스턴스가 있으면 거부된다)
  5. 경로표 연결 해제 후 삭제
  6. IGW 분리 후 삭제
  7. 서브넷 삭제
  8. VPC 삭제

마지막으로 요금 대시보드에서 다음 날 사용량이 0 인지 확인한다.
```

## 주의할 점 / 경계 조건

참조하는 자원이 있으면 삭제가 거부됩니다. 붙어 있는 것부터 떼어 낸 뒤 상위 자원을 지워야 합니다.

## 관련 용어

- `http`
- `tcp`

## 흔한 오해

콘솔에서 인스턴스를 지우면 다 끝난다고 생각하기 쉽지만, 저장 장치와 주소, 네트워크 자원은 따로 남습니다. 각각 확인해야 합니다.
