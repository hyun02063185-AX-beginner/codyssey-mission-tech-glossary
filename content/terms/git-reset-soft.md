# git reset --soft

## 한 줄 설명

HEAD만 이전 commit으로 옮기고 index와 working tree는 유지하는 reset.

## 쉽게 설명하면

마지막 커밋을 취소하되 바꾼 내용은 그대로 두는 명령입니다. 커밋만 없던 일이 됩니다.

## 정확한 설명

브랜치가 가리키는 위치만 앞으로 옮기고 스테이지와 작업 디렉터리는 건드리지 않는다. 취소된 커밋의 내용은 스테이지에 올라간 상태로 남으므로 그대로 다시 커밋하거나 나눠 커밋할 수 있다. 파일을 지우는 옵션과는 결과가 완전히 다르다.

## 이 미션에서는 왜 필요한가

이 회차의 트러블슈팅 항목 중 하나입니다. 커밋을 너무 크게 만들었거나 잘못 묶었을 때 되돌리는 방법인데, 옵션 하나만 잘못 쓰면 작업 내용이 사라지므로 차이를 정확히 알아야 합니다.

## 코드 예

```text
git reset --soft HEAD~1
  브랜치 위치    ← 옮긴다
  스테이지       그대로 (커밋하려던 내용이 남아 있다)
  작업 파일      그대로
  → 커밋만 취소. 바로 다시 커밋할 수 있다

git reset --mixed HEAD~1   (기본값)
  스테이지       비운다
  작업 파일      그대로
  → 다시 add 부터 해야 한다

git reset --hard HEAD~1
  작업 파일      되돌린다         ← 작업한 내용이 사라진다
  → 되돌릴 수 없다. 쓰기 전에 한 번 더 생각한다
```

## 주의할 점 / 경계 조건

다른 옵션을 쓰면 작업 내용까지 지워집니다. 이름이 비슷해 헷갈리기 쉬운데 결과는 완전히 다릅니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

되돌리는 명령이니 안전하다고 생각하기 쉽지만, 어느 옵션을 쓰느냐에 따라 파일이 통째로 사라질 수 있습니다.
