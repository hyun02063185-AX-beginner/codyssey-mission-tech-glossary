# cascade / 부모 삭제 정책

## 한 줄 설명

부모 record 삭제 때 연결된 child record를 어떻게 처리할지 정하는 정책.

## 쉽게 설명하면

부모를 지울 때 딸린 자식을 어떻게 할지 정해 두는 규칙입니다. 정하지 않으면 기본값이 적용됩니다.

## 정확한 설명

부모 삭제 시 자식을 함께 지울지, 참조를 비울지, 삭제 자체를 거부할지를 정한다. 데이터베이스 쪽 제약과 ORM 쪽 설정이 따로 있어 둘이 어긋날 수 있으며, ORM이 자식을 먼저 지우면 데이터베이스 제약은 발동하지 않는다.

## 동작 원리

ORM 쪽 설정이 있으면 확정할 때 자식을 먼저 지우는 명령을 내보냅니다. 없으면 부모만 지우려 하고, 그때 데이터베이스 제약이 거부하거나 자식을 함께 지웁니다.

## 이 미션에서는 왜 필요한가

이 회차에서 회원이나 글을 지울 때 딸린 것을 어떻게 할지 정하는 자리입니다. 정하지 않고 두면 지우기가 거부되거나 가리키는 대상이 없는 자식이 남는데, 어느 쪽인지는 설정에 달려 있습니다.

## 코드 예

```python
class Post(Base):
    comments: Mapped[list['Comment']] = relationship(
        back_populates='post',
        cascade='all, delete-orphan',    # ORM 쪽: 자식을 먼저 지운다
    )

class Comment(Base):
    post_id: Mapped[int] = mapped_column(
        ForeignKey('post.id', ondelete='CASCADE')    # DB 쪽
    )

# 둘이 어긋나면
#   session.delete(post)          ORM 설정이 동작한다
#   DELETE FROM post WHERE ...    DB 설정이 동작한다
# 접근 경로에 따라 결과가 달라진다
```

## 주의할 점 / 경계 조건

데이터베이스 쪽 설정과 ORM 쪽 설정이 다를 수 있습니다. ORM으로 지울 때와 SQL로 직접 지울 때 결과가 달라집니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

한쪽만 설정하면 된다고 생각하기 쉽지만, 접근 경로에 따라 다른 쪽이 동작합니다. 둘을 맞춰 두는 편이 안전합니다.
