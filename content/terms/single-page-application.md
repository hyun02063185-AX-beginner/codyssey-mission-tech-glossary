# Single Page Application

## 한 줄 설명

초기 document 뒤 JavaScript가 화면 일부를 갱신하며 여러 route를 제공하는 웹 앱.

## 쉽게 설명하면

주소가 바뀌어도 문서를 새로 받아 오지 않고, 이미 떠 있는 화면의 일부만 갈아 끼우는 방식의 웹 앱입니다. 그래서 화면이 깜빡이지 않고 바뀝니다.

## 정확한 설명

client router가 URL과 화면을 연결하고 API data를 받아 같은 document 안의 UI를 바꾼다.

## 동작 원리

첫 요청에서 거의 빈 HTML과 자바스크립트 묶음을 받습니다. 그 자바스크립트가 실행되면서 주소를 읽고 그에 맞는 화면을 그리며, 이후의 이동은 서버에 문서를 다시 요청하지 않고 주소 표시줄만 바꾼 뒤 화면을 교체합니다.

## 이 미션에서는 왜 필요한가

이 회차가 만드는 구조 자체입니다. 화면 전환이 부드러운 대신 서버가 하던 일 — 주소에 맞는 화면 고르기, 없는 주소 처리, 첫 화면이 준비될 때까지의 표시 — 을 전부 앱이 맡게 되므로, 그 일들이 새로 할 일 목록이 됩니다.

## 코드 예

```text
여러 화면 페이지 (기존 방식)
  /        → 서버가 HTML 을 만들어 보냄 → 브라우저가 처음부터 그림
  /about   → 서버가 HTML 을 만들어 보냄 → 다시 처음부터 (깜빡임)

SPA
  /        → 거의 빈 HTML + app.js  → JS 가 화면을 그림
  /about   → 요청 없음. JS 가 주소만 바꾸고 화면을 교체
  새로고침 → 서버가 /about 을 모르면 404. 서버 설정이 따로 필요하다
```

## 주의할 점 / 경계 조건

첫 화면이 보이기까지 자바스크립트를 받아 실행해야 하므로, 여러 화면 페이지보다 처음이 느릴 수 있습니다. 반대로 두 번째 이동부터는 빠릅니다.

## 관련 용어

- `client-side-routing`
- `react-router`
- `server-side-rendering`

## 흔한 오해

서버가 필요 없어졌다고 생각하기 쉽지만, 데이터는 여전히 서버에서 옵니다. 사라진 것은 화면을 만드는 일이지 서버가 아닙니다.

## 동료평가 질문
