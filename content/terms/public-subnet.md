# Public Subnet

## 한 줄 설명

Public Subnet은 연결된 Route Table에 인터넷 게이트웨이로 가는 직접 경로가 있는 AWS Subnet입니다.

## 쉽게 설명하면

인터넷으로 나가는 길이 경로 표에 적힌 구획입니다. 여기 둔 서버가 공인 주소를 가지고 허용 규칙도 맞으면 밖에서 접속할 수 있습니다.

## 정확한 설명

경로 표에 인터넷 게이트웨이로 가는 기본 경로가 있는 서브넷이다. 설정 항목에 이런 이름의 값이 따로 있는 것이 아니라, 붙은 경로 표의 내용으로 성격이 정해진다. 그래서 경로 표를 바꾸면 같은 서브넷의 성격이 달라진다. 이 서브넷 안의 자원도 사설 IP를 가지며, IPv4로 인터넷과 직접 주고받으려면 공인 IPv4가 따로 있어야 한다.

## 이 미션에서는 왜 필요한가

B3-1(M05)에서 웹 서버 EC2를 둔 Subnet `10.0.1.0/24`가 Public Subnet입니다. Route Table에 `0.0.0.0/0 → IGW`를 적고 그 표를 이 Subnet에 연결해 Public Subnet이 되었습니다. B3-1에는 Private Subnet이나 데이터베이스가 없지만, 일반적인 설계에서는 밖에서 접근할 필요가 없는 서버를 Private Subnet에 두어 노출 범위를 줄입니다. 무엇을 어디에 둘지가 곧 노출 범위를 정하는 결정입니다.

## 코드 예

```text
무엇으로 판정하는가
  이름이 "public-subnet" 이다        → 아무 의미 없다
  붙은 경로 표에 0.0.0.0/0 → IGW    → 이것이 판정 기준

B3-1 (2026-10-14 배포 기록)
  Subnet 10.0.1.0/24    Route Table: 0.0.0.0/0 → IGW
  EC2    ENI의 Private IPv4 + 자동 할당 Public IPv4

일반적인 두 구획 설계 (B3-1에는 없음)
  public   웹 서버        밖에서 접속해야 한다
  private  데이터베이스   웹 서버에서만 접속하면 된다
```

## 주의할 점 / 경계 조건

여기 있어도 공인 IP가 없으면 밖에서 접속할 수 없습니다. 반대로 공인 IP가 있어도 경로가 없으면 나가지 못합니다. 공인 IP와 경로가 모두 있어도 Security Group이 허용하지 않거나 서버가 그 포트에서 요청을 받지 않으면 접속되지 않습니다.

## 흔한 오해

이름으로 정해지는 성질이라고 생각하기 쉽지만, 붙은 경로 표가 정합니다. 이름을 그렇게 지어도 경로가 없으면 아닙니다. 또 Public Subnet 안의 서버는 공인 IP만 가진다고 생각하기 쉽지만, 사설 IP도 함께 가집니다.

## 비슷한 개념과의 차이

공인 IP는 주소의 종류이고 Public Subnet은 경로의 기준이므로, 공인 IP가 있다는 것과 Public Subnet에 있다는 것은 다른 말입니다. 일반 기업망의 DMZ는 공개 서비스와 내부망을 나누는 설계 개념이고, Public Subnet은 인터넷 게이트웨이 경로가 있는 Subnet이라는 AWS의 경로 기준이라 같은 것이 아닙니다.
