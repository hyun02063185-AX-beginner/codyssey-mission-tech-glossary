# 파일시스템

## 한 줄 설명

file·directory·metadata를 storage에 조직하는 방식.

## 쉽게 설명하면

저장 장치 위에 파일과 폴더를 어떤 방식으로 배치할지 정한 규칙입니다. 같은 디스크도 방식에 따라 다르게 다뤄집니다.

## 정확한 설명

파일의 내용과 이름, 권한·시각 같은 메타데이터를 저장 장치에 배치하는 방식이다. 방식마다 파일 이름의 대소문자 구분, 한 파일의 최대 크기, 갑작스러운 정전에서의 복구 방식이 다르다. 저장 공간을 붙이는 일은 이 구조를 디렉터리 한 곳에 이어 붙이는 것이다.

## 이 미션에서는 왜 필요한가

예비 M01에서 볼륨과 마운트를 다루기 전에 전제가 되는 개념입니다. 저장 장치가 어떤 규칙으로 파일과 디렉터리를 담는지 알아야, 마운트가 "다른 저장 공간을 이 경로에 붙인다"는 뜻으로 읽힙니다.

## 코드 예

```bash
df -Th                       # 어느 방식으로 붙어 있는지
# /dev/nvme0n1p1  ext4   50G  12G  36G  25% /

# 대소문자 구분 여부를 직접 확인한다
touch Test.txt
ls test.txt        # 리눅스(ext4)에서는 "No such file"
                   # 맥(APFS 기본)에서는 찾아진다

mount | head -3              # 어디에 무엇이 붙어 있는지
```

## 주의할 점 / 경계 조건

방식에 따라 파일 이름의 대소문자를 구분하지 않기도 합니다. 맥에서 잘 되던 코드가 리눅스 서버에서 파일을 못 찾는 흔한 원인입니다.

## 관련 용어

- `kernel`
- `directory`

## 흔한 오해

디스크에 파일이 그냥 저장된다고 생각하기 쉽지만, 어떤 방식으로 배치할지 정한 구조가 먼저 있어야 합니다.

## 동료평가 질문

맥에서 되던 코드가 리눅스 서버에서 파일을 못 찾는 경우의 원인을 설명할 수 있나요?
