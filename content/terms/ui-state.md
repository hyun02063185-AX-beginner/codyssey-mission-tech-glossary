# UI 상태

## 한 줄 설명

UI 상태는 로딩·성공·오류·빈 결과처럼 현재 상황에 따라 같은 화면이 다르게 보이는 경우입니다.

## 쉽게 설명하면

데이터를 기다릴 때, 데이터를 받았을 때, 실패했을 때를 모두 같은 빈 화면으로 두지 않고 사용자에게 현재 상황을 알려 주는 것입니다.

## 정확한 설명

UI는 요청 시작, 성공, 실패, 데이터 없음처럼 서로 배타적인 상태를 가질 수 있습니다. 상태 값을 먼저 정하고 그 값에 따라 렌더링 조건을 나누면 이전 성공 데이터를 오류 상태에 남기는 혼란을 줄입니다.

M01의 GitHub API 영역은 loading·success·error·empty를 구분합니다. 오류 상태는 개발자 콘솔이 아니라 사용자 화면에서 다음 행동을 판단할 수 있는 문구로 보여야 합니다.

## 이 미션에서는 왜 필요한가

API 요청의 진행과 결과를 사용자가 오해하지 않도록 표현합니다.

## 관련 용어

- fetch-api
- async-await
- github-api
- http-status-code-403

## 흔한 오해

성공 화면만 만든 뒤 나머지를 빈 화면으로 처리하면 사용자는 고장과 데이터 없음을 구분할 수 없습니다.
