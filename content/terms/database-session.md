# Database Session

## 한 줄 설명

Database Session은 애플리케이션이 데이터베이스 작업을 수행하는 동안 연결·변경 추적·트랜잭션 경계를 관리하는 작업 단위입니다.

## 쉽게 설명하면

데이터베이스에 일을 맡기는 동안 변경 내용을 모으고, 모두 성공하면 확정하거나 실패하면 되돌리는 작업 공간입니다.

## 정확한 설명

ORM에서 session은 객체 상태와 데이터베이스 작업을 연결하고 query, flush, commit, rollback을 조율합니다. session이 항상 물리적 데이터베이스 연결 하나와 같은 것은 아니며, 연결 풀에서 연결을 빌려 사용할 수 있습니다. 요청마다 session의 수명과 예외 시 rollback·close 책임을 분명히 해야 데이터와 자원을 안전하게 관리할 수 있습니다.

## 이 미션에서는 왜 필요한가

M12에서 요청 처리 중 데이터 조회·변경을 수행하고, 오류가 나도 트랜잭션과 연결이 남지 않도록 관리합니다.

## 관련 용어

- `request-response-cycle`
- `sqlalchemy`
- `transaction`
- `data-integrity`

## 흔한 오해

session을 오래 전역으로 하나만 두면 편하다고 생각할 수 있지만, 동시 요청과 실패 상태가 섞일 수 있습니다. 수명 범위를 요청이나 작업 단위에 맞춰야 합니다.

## 동료평가 질문

데이터베이스 변경 중 예외가 발생했을 때 rollback과 session 정리가 필요한 이유는 무엇인가요?
