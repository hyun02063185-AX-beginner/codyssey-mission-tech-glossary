# Transaction

## 한 줄 설명

여러 database 작업을 하나의 성공 또는 실패 단위로 묶는 처리.

## 쉽게 설명하면

여러 작업을 하나로 묶어 전부 되거나 전부 안 되게 하는 단위입니다. 중간까지만 반영되는 상태를 막습니다.

## 정확한 설명

시작과 확정 사이의 변경은 다른 연결에서 보이지 않으며, 취소하면 시작 시점으로 되돌아간다. 어디까지 다른 트랜잭션의 중간 상태가 보이는지는 격리 수준이 정하고, 같은 조건을 두 번 조회했을 때 결과가 달라질 수 있는지도 여기서 갈린다.

## 동작 원리

시작을 선언하면 이후의 변경이 임시로 쌓입니다. 확정하면 한꺼번에 반영되고 취소하면 전부 버려지며, 도중에 연결이 끊기면 확정되지 않은 것은 자동으로 버려집니다.

## 이 미션에서는 왜 필요한가

이 회차에서 여러 명령이 하나의 작업을 이룰 때 필요합니다. 글을 지우면서 댓글도 지워야 하는데 중간에 실패하면, 묶어 두지 않은 경우 글은 없는데 댓글만 남는 상태가 됩니다.

## 코드 예

```python
conn = sqlite3.connect('app.db')
try:
    conn.execute('DELETE FROM comment WHERE post_id = ?', (pid,))
    conn.execute('DELETE FROM post WHERE id = ?', (pid,))
    conn.commit()          # 여기서 한꺼번에 반영된다
except Exception:
    conn.rollback()        # 둘 다 없던 일이 된다
    raise

# commit 전에는 다른 연결에서 이 변경이 보이지 않는다
```

## 주의할 점 / 경계 조건

한 query가 성공했다고 data model 전체가 안전한 것은 아닙니다. NULL, 중복, foreign key, 동시 변경, transaction 범위를 함께 확인해야 합니다.

## 관련 용어

- `data-integrity`
- `relational-database`

## 흔한 오해

명령 하나하나가 성공했으니 안전하다고 생각하기 쉽지만, 여러 명령이 하나의 의미를 이룰 때는 그중 하나만 실패해도 데이터가 어긋납니다. 묶는 단위는 명령이 아니라 의미입니다.
