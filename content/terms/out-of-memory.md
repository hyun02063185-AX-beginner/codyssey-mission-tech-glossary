# OOM

## 한 줄 설명

사용할 memory를 확보하지 못해 process가 실패하거나 종료되는 상태.

## 쉽게 설명하면

메모리를 더 못 얻어서 프로그램이 실패하거나 강제로 종료되는 상태입니다. 예고 없이 사라진 것처럼 보입니다.

## 정확한 설명

할당 요청이 실패하거나, 시스템 전체가 부족해지면 커널이 프로세스 하나를 골라 강제 종료한다. 종료된 쪽에는 아무 기록이 남지 않으므로, 애플리케이션 로그만 보면 원인이 없는 갑작스러운 중단으로 보인다. 커널 로그를 봐야 선택된 이유가 나온다.

## 이 미션에서는 왜 필요한가

이 회차가 다루는 장애 중 하나입니다. 프로그램 로그에 아무것도 없이 멈췄다면 이것을 의심해야 하는데, 어디를 봐야 하는지 모르면 원인 불명으로 남습니다. 확인할 자리가 따로 있다는 것이 핵심입니다.

## 코드 예

```bash
dmesg -T | grep -i "killed process"
# [Mon Sep 22 10:31:02] Out of memory: Killed process 4211 (python)
#   total-vm:8203400kB, anon-rss:7891200kB

journalctl -k --since "1 hour ago" | grep -i oom

# 컨테이너라면 한도에 걸린 것일 수 있다
docker inspect --format="{{.State.OOMKilled}}" <컨테이너>

# 커널이 누구를 고를지 점수로 정한다
cat /proc/$PID/oom_score
```

## 주의할 점 / 경계 조건

강제 종료된 프로세스가 반드시 메모리를 가장 많이 쓴 것은 아닙니다. 커널은 점수를 매겨 고르며 그 기준은 사용량만이 아닙니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

로그에 아무것도 없으니 프로그램 문제가 아니라고 생각하기 쉽지만, 종료당한 쪽은 기록을 남길 틈이 없습니다. 기록은 커널 쪽에 있습니다.
