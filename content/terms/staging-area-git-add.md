# 스테이징

## 한 줄 설명

다음 commit에 넣을 변경 snapshot을 선택하는 Git index.

## 쉽게 설명하면

다음 커밋에 담을 것을 미리 골라 두는 자리입니다. 고쳐 놓고 담지 않은 것은 커밋되지 않습니다.

## 정확한 설명

작업 디렉터리와 커밋 사이의 중간 단계다. 파일 단위뿐 아니라 파일 안의 일부 변경만 골라 담을 수 있어, 한 번에 여러 가지를 고쳤을 때 주제별로 나눠 커밋할 수 있다. 담은 뒤 파일을 또 고치면 그 변경은 담기지 않은 상태로 따로 남는다.

## 이 미션에서는 왜 필요한가

예비 M02에서 커밋을 남기려면 그 전에 무엇을 담을지 고르는 단계를 지나야 합니다. 고친 파일이 여러 개일 때 전부 한 커밋에 넣지 않고 일부만 고를 수 있는 것이 이 단계 덕분입니다.

## 코드 예

```bash
git add -p src/app.py      # 변경 덩어리마다 담을지 묻는다
#  y 담는다  n 건너뛴다  s 더 잘게 나눈다  q 그만

git diff                   # 안 담은 변경
git diff --staged          # 담은 변경 (이것이 커밋된다)

# 담은 뒤 또 고치면 둘이 따로 존재한다
git add src/app.py
echo "# 메모" >> src/app.py
git status                 # 같은 파일이 양쪽에 다 나온다

git restore --staged src/app.py    # 담은 것을 내린다
```

## 주의할 점 / 경계 조건

담은 뒤에 같은 파일을 또 고치면 담은 내용과 고친 내용이 따로 존재합니다. 커밋되는 것은 담았던 쪽입니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

파일 단위로만 고를 수 있다고 생각하기 쉽지만, 파일 안의 일부 변경만 담을 수도 있습니다. 주제가 섞였을 때 나누는 수단이 됩니다.

## 동료평가 질문

한 파일에 두 가지를 고쳤을 때 하나만 커밋하려면 어떻게 하겠습니까?
