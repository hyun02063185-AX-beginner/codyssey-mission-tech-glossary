# OAuth2

## 한 줄 설명

사용자 password를 앱에 주지 않고 제한된 access token을 위임하는 authorization framework.

## 쉽게 설명하면

다른 서비스의 계정으로 로그인할 때, 우리 서비스에 그쪽 비밀번호를 주지 않고도 확인이 되게 하는 방식입니다. 비밀번호 대신 제한된 권한의 표식만 건네받습니다.

## 정확한 설명

자원 소유자(사용자), 클라이언트(우리 서비스), 인가 서버, 자원 서버의 네 역할로 나눈다. 사용자가 인가 서버에서 직접 동의하면 클라이언트는 범위가 제한된 접근 토큰을 받는다. 클라이언트는 사용자의 비밀번호를 보지 않는다.

## 이 미션에서는 왜 필요한가

이 회차의 소셜 로그인 보너스가 이 방식입니다. 우리가 비밀번호를 받지 않아도 된다는 점이 가장 큰 이점인데, 대신 흐름이 여러 단계로 나뉘고 각 단계에서 무엇을 확인해야 하는지가 늘어납니다.

## 코드 예

```text
사용자          우리 서비스          제공자(구글 등)
   │  로그인 누름   │                      │
   │──────────────▶ │  이쪽으로 가세요 ───▶ │
   │◀───────────────┼──── 동의 화면 ────── │
   │  동의          │                      │
   │                │ ◀── code 전달 ────── │
   │                │ ─── code + secret ─▶ │
   │                │ ◀── access token ─── │

우리 서비스는 사용자의 비밀번호를 끝까지 보지 않는다.
```

## 주의할 점 / 경계 조건

요청할 권한 범위(scope)를 넓게 잡으면 사용자가 동의 화면에서 물러납니다. 로그인만 필요하면 신원 확인 범위만 요청합니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

OAuth가 로그인 방식이라고 생각하기 쉽지만, 본래 목적은 권한 위임입니다. "누구인지"를 알려면 그 위에 얹은 OpenID Connect 쪽을 써야 정확합니다.
