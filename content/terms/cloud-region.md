# Cloud Region

## 한 줄 설명

cloud provider가 resource를 운영하는 지리적 location 단위.

## 쉽게 설명하면

서버가 실제로 놓이는 지역입니다. 어느 지역을 고르느냐에 따라 응답 속도와 요금이 달라집니다.

## 정확한 설명

지리적으로 떨어진 독립 운영 단위이며, 지역마다 요금과 제공 서비스가 다를 수 있다. 자원은 지역에 묶여 있어 다른 지역의 콘솔 화면에서는 보이지 않고, 지역 사이 데이터 전송에는 별도 요금이 붙는다.

## 이 미션에서는 왜 필요한가

이 회차에서 서울 지역을 고르는 이유가 여기 있습니다. 사용자와 가까울수록 응답이 빠르기 때문인데, 더 실질적인 이유는 다른 지역에 만든 자원이 콘솔에 보이지 않아 정리할 때 빠뜨리게 된다는 점입니다.

## 코드 예

```text
지역을 고를 때 보는 것

  응답 속도   사용자와 가까울수록 빠르다 (서울 ap-northeast-2)
  요금        지역마다 다르다
  서비스      새 서비스는 일부 지역에만 먼저 열린다
  법·규정     데이터를 국내에 둬야 하는 경우가 있다

실습에서 더 중요한 것
  자원은 지역에 묶여 있다.
  콘솔 오른쪽 위의 지역이 다르면 만든 자원이 보이지 않는다.
  "분명히 지웠는데 요금이 나온다" 의 흔한 원인이다.
```

## 주의할 점 / 경계 조건

콘솔 화면은 선택한 지역의 자원만 보여 줍니다. 실수로 다른 지역에 만든 자원은 목록에 나타나지 않습니다.

## 관련 용어

- `http`
- `tcp`

## 흔한 오해

계정 단위로 자원이 관리된다고 생각하기 쉽지만, 대부분 지역 단위입니다. 지역을 바꾸면 목록이 통째로 달라집니다.
