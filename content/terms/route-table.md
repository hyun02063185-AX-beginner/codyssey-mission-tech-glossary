# Route Table

## 한 줄 설명

Route Table은 목적지 IP 주소 범위마다 다음으로 보낼 대상을 적어 둔 경로 규칙표입니다.

## 쉽게 설명하면

어디로 가는 통신을 어느 통로로 보낼지 적어 둔 표입니다. AWS에서는 서브넷마다 하나씩 연결됩니다. 길을 정할 뿐, 누가 들어와도 되는지는 정하지 않습니다.

## 정확한 설명

목적지 범위와 다음 경유지의 짝을 나열한다. 여러 경로가 맞을 때는 범위가 좁은 쪽이 우선하므로, 넓은 기본 경로가 있어도 좁은 경로가 따로 있으면 그쪽이 선택된다. 같은 범위의 로컬 경로는 지울 수 없다. 패킷이 지나가는 장비가 아니라 서브넷에 연결된 설정이며, 서브넷에서 나가는 트래픽의 다음 대상을 정한다. 통신을 허용하거나 막지는 않는다. 허용 여부는 Security Group 같은 규칙이 따로 판단한다.

## 이 미션에서는 왜 필요한가

이 회차에서 서버가 인터넷과 통신할 수 있게 만드는 설정입니다. B3-1(M05)에서는 Route Table에 `0.0.0.0/0 → IGW`를 적고 Subnet `10.0.1.0/24`에 명시적으로 연결했습니다. 이 경로가 응답이 VPC 밖으로 나갈 다음 대상을 정합니다. 게이트웨이를 만들어 두어도 이 표에 경로를 적지 않으면 연결되지 않는데, 이 둘을 한 단계로 생각하면 왜 안 되는지 알 수 없게 됩니다.

## 코드 예

```text
경로 표 (public-rt)
  대상            다음 경유지
  10.0.0.0/16     local          ← 지울 수 없다. VPC 내부 통신
  0.0.0.0/0       igw-abc123     ← 이 줄이 없으면 인터넷에 못 나간다

연결된 서브넷: 10.0.1.0/24

확인할 것이 둘이다
  1. 표에 경로가 적혀 있는가
  2. 그 표가 내 서브넷에 붙어 있는가

범위가 좁은 쪽이 우선한다
  0.0.0.0/0 → IGW 와 203.0.113.0/24 → NAT 가 함께 있으면
  203.0.113.x 로 가는 통신은 NAT 로 간다

경로와 허용은 다른 표
  Route Table      어디로 보낼까   (목적지 IP → 다음 대상)
  Security Group   통과시킬까      (출발지 IP · 프로토콜 · 포트)
```

## 주의할 점 / 경계 조건

표는 서브넷에 붙습니다. 경로를 추가해도 그 표가 대상 서브넷에 붙어 있지 않으면 적용되지 않습니다.

## 관련 용어

- `internet-gateway`
- `default-route-any-ipv4`
- `subnet`
- `public-subnet`
- `cidr`
- `security-group`

## 흔한 오해

게이트웨이를 만들면 연결된다고 생각하기 쉽지만, 통로를 만든 것과 그 통로로 보내라고 적는 것은 다른 일입니다. 두 단계가 모두 필요합니다. 또 경로가 있으면 접속도 허용된다고 생각하기 쉽지만, 경로는 길만 정하고 통과 허용은 Security Group이 따로 판단합니다.

## 비슷한 개념과의 차이

Route Table은 목적지 IP 주소를 보고 다음 대상을 정하는 경로 규칙이고, Security Group은 출발지 IP·프로토콜·포트를 보고 통과를 허용하는 규칙입니다. 일반 기업망의 라우터 경로표와 하는 일이 비슷하지만, AWS의 Route Table은 장비가 아니라 서브넷에 연결하는 설정입니다.
