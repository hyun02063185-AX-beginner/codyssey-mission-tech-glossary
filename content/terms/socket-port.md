# Socket / Port

## 한 줄 설명

transport protocol에서 process endpoint를 구분하는 port 번호.

## 쉽게 설명하면

한 컴퓨터 안에서 어느 프로그램이 통신을 받을지 구분하는 번호입니다. 주소가 건물이면 번호는 호실입니다.

## 정확한 설명

주소와 번호의 조합으로 통신 상대를 특정한다. 한 번호는 한 프로세스만 받을 수 있어, 이미 쓰고 있으면 새 프로세스가 뜨지 못한다. 어느 주소에 묶였는지에 따라 같은 기계에서만 닿을지 밖에서도 닿을지가 갈린다.

## 이 미션에서는 왜 필요한가

본과정 M07에서 15034 포트의 상태 점검이 동작하는지 확인하려면 먼저 그 포트에서 무언가 듣고 있어야 합니다. LISTEN 상태가 무슨 뜻인지 알아야 "포트를 열었다"와 "프로그램이 받고 있다"를 구분할 수 있습니다.

## 코드 예

```bash
ss -tlnp | grep :8000
# LISTEN 0.0.0.0:8000  users:(("python",pid=4211,fd=3))
#        │                          └ 누가 잡고 있는지
#        └ 0.0.0.0 밖에서도 닿는다 / 127.0.0.1 이 기계에서만

# 이미 쓰고 있다는 오류가 날 때
lsof -i :8000
kill 4211

# 끝난 직후 잠시 잡혀 있기도 하다 (TIME_WAIT)
ss -tan | grep :8000
```

## 주의할 점 / 경계 조건

프로세스가 끝나도 번호가 잠시 잡혀 있을 수 있습니다. 바로 다시 띄우면 이미 쓰고 있다는 오류가 납니다.

## 관련 용어

- `http`
- `tcp`

## 흔한 오해

번호만 맞으면 통한다고 생각하기 쉽지만, 어느 주소에 묶였는지도 함께 봐야 합니다. 로컬에만 묶여 있으면 밖에서는 닿지 않습니다.

## 동료평가 질문

서비스를 띄우려는데 이미 쓰고 있다는 오류가 날 때 어떻게 확인하겠습니까?
