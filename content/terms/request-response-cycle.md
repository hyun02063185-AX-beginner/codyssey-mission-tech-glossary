# Request / Response Cycle

## 한 줄 설명

Request / Response Cycle은 서버가 요청을 받아 라우팅·처리하고 응답을 돌려줄 때까지의 애플리케이션 처리 흐름입니다.

## 쉽게 설명하면

문 앞에 도착한 주문이 담당자를 찾아가 처리된 뒤 결과를 들고 다시 나오는 전체 과정입니다.

## 정확한 설명

HTTP 메시지 교환 자체보다 넓은 서버 내부 흐름입니다. 서버는 요청을 라우터에 매칭하고, 인증·검증 같은 전처리와 핸들러·서비스·데이터 접근을 거쳐 response를 만듭니다. 예외가 나면 적절한 오류 response로 변환해야 하며, 처리 중 공유 상태와 트랜잭션 경계도 설계 대상입니다.

## 동작 원리

- 서버가 HTTP request를 수신하고 경로와 method를 찾습니다.
- 필요한 검증과 애플리케이션 로직을 실행합니다.
- 성공 또는 오류 결과를 HTTP response로 직렬화해 반환합니다.

## 이 미션에서는 왜 필요한가

M12에서 FastAPI 요청이 라우팅과 로직을 거쳐 응답이 되는 구조를 설명할 때 사용합니다.

## 관련 용어

- `http-request-response`
- `fastapi`
- `dependency-injection`
- `database-session`

## 흔한 오해

Request / Response Cycle은 단순히 네트워크 왕복 시간만 뜻하지 않습니다. 서버 내부의 처리와 오류 변환도 이 흐름에 포함됩니다.
