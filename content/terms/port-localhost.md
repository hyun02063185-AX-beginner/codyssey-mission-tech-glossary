# 포트 / localhost

## 한 줄 설명

local host에서 process를 구분하는 port와 loopback 주소의 조합.

## 쉽게 설명하면

내 컴퓨터 자신을 가리키는 주소와 프로그램을 구분하는 번호를 함께 쓰는 표현입니다.

## 정확한 설명

되돌림 주소와 번호의 조합이다. 이 조합으로 보낸 통신은 네트워크 장치를 거치지 않고 같은 기계 안에서 끝나므로, 방화벽과 무관하게 동작하는 대신 밖에서는 닿지 않는다. 컨테이너 안의 이 주소는 컨테이너 자신을 가리키지 호스트가 아니다.

## 이 미션에서는 왜 필요한가

예비 M01에서 포트 매핑을 이해하기 위한 전제입니다. 컨테이너 안의 80번과 내 컴퓨터의 8080번이 다른 자리라는 것을 알아야, `-p 8080:80`이 무엇과 무엇을 잇는 설정인지 읽힙니다.

## 코드 예

```bash
docker run -d -p 8080:80 nginx
#              │    └ 컨테이너 안의 80
#              └ 호스트의 8080

curl http://localhost:8080        # 호스트에서 — 닿는다
docker exec <컨테이너> curl http://localhost:8080
# 닿지 않는다. 컨테이너 안의 localhost 는 컨테이너 자신이다

# 컨테이너에서 호스트로 가려면
# host.docker.internal (맥·윈도우)
# --network host 또는 호스트의 실제 IP (리눅스)
```

## 주의할 점 / 경계 조건

컨테이너 안에서 이 주소를 쓰면 컨테이너 자신을 가리킵니다. 호스트의 서비스에 닿으려면 다른 이름을 써야 합니다.

## 관련 용어

- `http`
- `tcp`

## 흔한 오해

포트를 열어 뒀으니 밖에서 접속된다고 생각하기 쉽지만, 이 주소에 묶여 있으면 같은 기계에서만 닿습니다. 포트 매핑이 필요한 이유입니다.

## 동료평가 질문

컨테이너 안에서 호스트의 데이터베이스에 접속하려면 무엇을 써야 하는지 설명할 수 있나요?
