# 로그인

## 한 줄 설명

사용자가 자격 증명을 제시해 session이나 token을 받는 인증 시작 절차.

## 쉽게 설명하면

아이디와 비밀번호가 맞는지 확인한 뒤, 다음 요청부터는 다시 묻지 않도록 표식을 하나 쥐여 주는 절차입니다. 표식이 없으면 매 요청마다 비밀번호를 보내야 합니다.

## 정확한 설명

제시된 자격 증명을 저장된 값과 대조하고, 통과하면 세션 식별자나 토큰을 발급해 응답에 실어 보낸다. 대조에 쓰는 저장값은 비밀번호 원문이 아니라 해시이며, 발급한 표식의 수명과 폐기 방법을 함께 정해야 한다.

## 이 미션에서는 왜 필요한가

이 회차의 인증 흐름이 시작되는 지점입니다. 여기서 발급한 표식의 형태가 이후 모든 결정을 좌우합니다. 세션으로 하면 서버가 상태를 들고 있어야 하고 토큰으로 하면 폐기가 어려워지므로, 로그아웃과 만료 처리가 이 선택에 따라 달라집니다.

## 코드 예

```python
@app.post('/login')
def login(form: LoginForm):
    user = repo.find_by_email(form.email)
    # 아이디가 없을 때와 비밀번호가 틀릴 때를 구분해 알려 주지 않는다
    if user is None or not verify(form.password, user.password_hash):
        raise HTTPException(401, '아이디 또는 비밀번호가 올바르지 않습니다')

    request.session.clear()          # 기존 세션을 버리고 새로 만든다
    request.session['user_id'] = user.id
    return RedirectResponse('/', status_code=303)
```

## 주의할 점 / 경계 조건

정상 응답이나 한 번의 로그인 성공만으로 전체 보안이 보장되지는 않습니다. 만료, 철회, 최소 권한, 감사 기록을 함께 확인합니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

아이디가 없을 때와 비밀번호가 틀릴 때 다른 메시지를 주면 친절하다고 생각하기 쉽지만, 그러면 어떤 아이디가 가입돼 있는지 알려 주는 셈이 됩니다. 실패 메시지는 두 경우에 같아야 합니다.
