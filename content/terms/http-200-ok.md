# HTTP 200

## 한 줄 설명

HTTP request가 성공적으로 처리됐음을 나타내는 200 status.

## 쉽게 설명하면

요청이 정상적으로 처리됐다는 응답 번호입니다. 서버가 답했다는 뜻이지 답의 내용이 맞다는 뜻은 아닙니다.

## 정확한 설명

요청이 성공했음을 나타내는 상태 코드다. 서버가 응답을 만들어 보냈다는 것까지를 의미하며, 그 안에 오류 메시지가 담겨 있어도 이 코드가 나갈 수 있다. 따라서 자동 확인에서는 코드와 함께 본문의 내용도 봐야 판정이 된다.

## 이 미션에서는 왜 필요한가

이 회차에서 배포가 성공했다는 증거로 씁니다. 다만 서버가 오류 페이지를 이 코드로 돌려주는 경우도 있어, 코드만 확인하면 잘못된 화면이 떠 있는 것을 놓칠 수 있습니다.

## 코드 예

```bash
curl -I http://<공인IP>/
# HTTP/1.1 200 OK

# 코드와 내용을 함께 확인한다
curl -fsS http://<공인IP>/ | grep -q "내 이름" && echo "정상" || echo "내용 이상"

#  -f  4xx/5xx 일 때 실패로 끝낸다 (종료 상태로 이어진다)
#  -s  진행 표시를 끈다
#  -S  그래도 오류는 보여 준다

# 배포 증거로 남길 때
curl -sS -o /dev/null -w "%{http_code} %{time_total}s\n" http://<공인IP>/
```

## 주의할 점 / 경계 조건

오류 화면을 이 코드로 돌려주는 서버가 많습니다. 코드만 보고 정상으로 판단하면 잘못된 화면을 놓칩니다.

## 관련 용어

- `http-request-response`
- `redirectresponse`

## 흔한 오해

이 코드가 나오면 기능이 정상이라고 생각하기 쉽지만, 확인한 것은 요청이 처리됐다는 것뿐입니다. 안에 무엇이 담겼는지는 따로 봐야 합니다.
