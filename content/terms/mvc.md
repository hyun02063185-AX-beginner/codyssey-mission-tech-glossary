# MVC

## 한 줄 설명

Model·View·Controller로 화면과 상태, 입력 처리를 나누는 구조.

## 쉽게 설명하면

데이터, 화면, 사용자 요청의 책임을 나눠 정리하는 방식이다.

## 정확한 설명

Model은 도메인 상태, View는 표현, Controller는 입력을 받아 흐름을 조정한다. 웹 프레임워크마다 경계는 조금씩 다르다.

## 언제 쓰나

폼 요청을 controller가 받고 model을 바꾼 뒤 view를 렌더링한다.

## 기억할 경계

MVC는 파일 개수 규칙이 아니라 책임 분리 원칙이다.

## 이 미션에서는 왜 필요한가

이 회차는 서버가 HTML을 만들어 내려보내는 구조로 게시판을 만듭니다. 요청을 받는 자리, 데이터를 다루는 자리, 화면을 그리는 자리를 나눠 두면 "글이 안 보인다"는 문제가 셋 중 어디서 났는지 좁힐 수 있습니다. 파일을 몇 개로 나누느냐가 아니라 책임을 나누는 것이 요점입니다.

## 코드 예

```text
요청 POST /posts
  ↓
Controller  입력을 받아 형식을 확인하고 어디로 보낼지 정한다
  ↓
Model       글을 저장하고 규칙을 적용한다
  ↓
View        저장 결과를 HTML 로 그린다

"목록이 비어 보인다" 는 문제는
  Controller 가 조회를 안 불렀거나 / Model 이 빈 결과를 주었거나 /
  View 가 변수 이름을 틀렸거나 — 셋 중 하나다.
```
