# 프로세스 / PID 1

## 한 줄 설명

container 또는 system namespace에서 종료·signal 처리 책임이 특별한 첫 process.

## 쉽게 설명하면

컨테이너 안에서 가장 먼저 뜨는 프로세스입니다. 이것이 끝나면 컨테이너도 함께 끝납니다.

## 정확한 설명

해당 범위에서 최초로 실행되는 프로세스이며, 이것이 종료되면 그 범위 전체가 정리된다. 또 부모를 잃은 프로세스를 거둬들이고 종료 신호를 처리할 책임을 지므로, 신호를 처리하지 않는 프로그램을 여기에 두면 멈추라는 요청을 무시한다.

## 이 미션에서는 왜 필요한가

예비 M01에서 `docker run ubuntu`가 아무 일도 안 하고 즉시 끝나는 이유입니다. 컨테이너는 1번 프로세스가 살아 있는 동안만 살아 있고, 그 프로세스가 종료 신호를 받아 처리할 책임도 함께 집니다.

## 코드 예

```bash
docker run ubuntu            # 즉시 끝난다
docker ps -a                 # STATUS: Exited (0)
# bash 가 1번으로 떴는데 입력이 없어 바로 끝났다. 오류가 아니다

docker run -d ubuntu sleep 300    # 상주하는 명령을 주면 떠 있는다
docker exec <컨테이너> ps -ef
# PID 1  sleep 300

# 신호를 처리하지 않으면 종료가 느리다
docker stop <컨테이너>       # 10초 기다렸다 강제 종료된다
```

## 주의할 점 / 경계 조건

신호를 처리하지 않는 프로그램을 여기에 두면 정상 종료 요청을 무시하고 강제 종료될 때까지 버팁니다. 종료가 10초쯤 걸린다면 이 경우입니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

컨테이너가 바로 꺼지면 오류라고 생각하기 쉽지만, 이 프로세스가 할 일을 마치면 정상적으로 끝난 것입니다. 계속 떠 있으려면 상주하는 프로그램이어야 합니다.
