# useEffect

## 한 줄 설명

렌더링 뒤 네트워크·구독 같은 외부 시스템과 동기화하는 React Hook.

## 쉽게 설명하면

화면을 그린 뒤에 해야 할 바깥일 — 데이터 요청, 타이머 시작, 이벤트 구독 — 을 적는 자리입니다. 그리는 일과 바깥일을 섞지 않기 위해 따로 둡니다.

## 정확한 설명

dependency 변경 뒤 effect를 실행하고 cleanup으로 timer·subscription·request를 정리할 수 있다.

## 동작 원리

컴포넌트가 화면에 반영된 뒤 실행됩니다. 두 번째 인자로 준 값들 중 하나라도 이전과 달라지면 다시 실행되며, 다시 실행하기 전과 화면에서 사라질 때 앞서 돌려준 정리 함수가 먼저 불립니다.

## 이 미션에서는 왜 필요한가

이 회차에서 서버 데이터를 가져오거나 타이머를 다루는 코드가 여기 들어갑니다. 정리 함수를 돌려주지 않으면 화면이 사라진 뒤에도 타이머와 요청이 계속 살아 있어, 없는 화면에 값을 넣으려다 오류가 납니다.

## 코드 예

```jsx
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/posts/${id}`, { signal: controller.signal })
    .then(r => r.json())
    .then(setPost)
    .catch(e => { if (e.name !== 'AbortError') setError(e); });

  return () => controller.abort();   // 화면을 떠나거나 id 가 바뀌면 취소
}, [id]);                            // id 가 바뀔 때마다 다시 실행

// 두 번째 인자를 빼면 매 렌더링마다 실행되고,
// 안에서 setState 를 하면 무한 반복이 된다
```

## 주의할 점 / 경계 조건

두 번째 인자를 아예 생략하면 렌더링할 때마다 실행됩니다. 그 안에서 상태를 바꾸면 다시 렌더링되고 또 실행되어 무한히 반복됩니다.

## 관련 용어

- `asynchronous-data-fetching`
- `react-state`
- `custom-hook`

## 흔한 오해

화면이 그려지기 전에 실행된다고 생각하기 쉽지만, 그려진 뒤에 실행됩니다. 그래서 첫 화면에는 데이터가 없는 상태가 반드시 한 번 나타나며, 그 상태의 화면을 따로 정해 두어야 합니다.

## 동료평가 질문

요청 중에 사용자가 다른 화면으로 이동했을 때 무슨 일이 생기는지와, 정리 함수로 어떻게 막는지 설명할 수 있나요?
