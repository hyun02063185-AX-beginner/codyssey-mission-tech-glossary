# Internet Gateway

## 한 줄 설명

인터넷 게이트웨이(IGW)는 VPC를 인터넷과 연결하는 AWS 구성요소로, IPv4에서는 인스턴스의 사설 주소와 공인 주소를 1:1로 바꿔 줍니다.

## 쉽게 설명하면

VPC와 인터넷을 잇는 출입구입니다. 만들어서 VPC에 붙이고, Route Table에 "인터넷으로 가는 것은 이 출입구로"라고 적어야 쓰입니다.

## 정확한 설명

VPC와 외부 사이의 공인 IP 통신을 중계한다. 대역폭 제한이나 가용성 문제가 없고 별도 과금도 없지만, VPC에 붙이는 것과 경로 표에 등록하는 것이 별개의 단계라 하나만 해서는 동작하지 않는다. IPv4에서는 공인 IPv4가 있는 인스턴스로 들어오는 트래픽의 목적지를 사설 IPv4로, 나가는 트래픽의 출발지를 공인 IPv4로 바꾼다(AWS 문서의 one-to-one NAT). 경로를 고르는 장비가 아니고 허용·차단도 하지 않는다. 경로는 Route Table이, 허용은 Security Group이 정한다.

## 이 미션에서는 왜 필요한가

이 회차에서 서버를 인터넷에 노출하는 데 필요합니다. B3-1(M05)에서는 IGW를 VPC에 붙이고 Route Table에 `0.0.0.0/0 → IGW`를 적었으며, 별도의 NAT Gateway는 만들지 않았습니다. 만들기만 하고 경로를 등록하지 않아 접속이 안 되는 경우가 흔한데, 두 단계가 따로라는 것을 알면 어디가 빠졌는지 바로 찾을 수 있습니다.

## 코드 예

```text
IPv4 인터넷 접속에 필요한 것

  1. 게이트웨이를 만들어 VPC 에 붙인다
  2. Subnet 의 Route Table 에  0.0.0.0/0 → 그 게이트웨이  를 적는다
  3. 자원에 공인 IP 가 붙어 있다
  4. Security Group 이 그 포트를 허용한다
  5. 서버 프로그램이 그 포트에서 요청을 받고 있다

하나만 빠져도 접속되지 않는다.
증상(시간 초과, 연결 거부)만으로는 어디가 빠졌는지 알기 어렵다.

요청이 지나가는 것과 설정을 나눠 보기
  지나감   인터넷 → IGW → EC2 의 ENI → Nginx
  설정     Route Table (Subnet 에 연결) · Security Group (ENI 에 적용)
           ← 패킷이 통과하는 장비가 아니다

IGW 의 1:1 변환 (IPv4)
  들어올 때  목적지  Public IPv4  → ENI 의 Private IPv4
  나갈 때    출발지  Private IPv4 → Public IPv4
```

## 주의할 점 / 경계 조건

이것이 있어도 자원에 공인 IP가 없으면 밖에서 접속할 수 없습니다. 통로와 주소는 다른 조건입니다.

## 관련 용어

- `virtual-private-cloud`
- `route-table`
- `public-ip`
- `private-ip`
- `nat-gateway`
- `default-route-any-ipv4`

## 흔한 오해

붙이면 바로 통한다고 생각하기 쉽지만, 경로 표에 목적지를 적어야 합니다. 통로가 있다는 것과 그리로 보내는 것은 다릅니다. 또 IGW가 주소를 바꾸니 NAT Gateway와 같다고 생각하기 쉽지만, 둘은 다른 자원입니다.

## 비슷한 개념과의 차이

IGW의 1:1 변환은 공인 IPv4를 가진 자원 하나에 공인 주소 하나를 짝짓고, 밖에서 먼저 시작한 연결과 안에서 나가는 연결을 모두 지원합니다. NAT Gateway는 따로 만드는 유료 서비스로, 공인 IP가 없는 Private Subnet 자원이 밖으로 나가는 연결을 시작할 수 있게 출발지 주소를 바꾸며, 밖에서 먼저 시작한 연결은 받지 않습니다. Route Table은 IGW 쪽으로 보내라고 적는 표이고, IGW는 그 출입구입니다. 일반 기업망의 경계 라우터와 비슷한 자리에 있지만 같은 장비가 아닙니다.
