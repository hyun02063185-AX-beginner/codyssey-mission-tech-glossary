# CSS Cascade

## 한 줄 설명

여러 CSS 규칙이 같은 요소를 가리킬 때 최종 선언을 고르는 우선순위 규칙.

## 쉽게 설명하면

같은 요소를 가리키는 CSS 규칙이 여러 개일 때 무엇을 적용할지 정하는 규칙입니다. 나중에 쓴 것이 이긴다는 것은 조건이 같을 때만 맞습니다.

## 정확한 설명

origin, importance, specificity, source order를 고려해 선언을 선택한다.

## 이 미션에서는 왜 필요한가

이 회차에서 스타일을 분명히 적었는데 적용되지 않는 일이 생기면 대부분 이 순위 때문입니다. `!important`를 붙여 해결하고 넘어가면 다음에 또 같은 일이 생기고, 그때는 덮을 방법이 없어집니다.

## 코드 예

```css
/* 구체성: ID(100) > 클래스·속성·가상클래스(10) > 태그(1) */

#header .nav a   { color: navy;  }   /* 100 + 10 + 1 = 111 */
.nav-link        { color: red;   }   /*             10      */
a                { color: green; }   /*              1      */

/* 파일 순서와 무관하게 navy 가 적용된다 */

/* 해결 방법은 !important 가 아니라 구체성을 맞추는 것 */
#header .nav a.nav-link { color: red; }
```

## 주의할 점 / 경계 조건

선택자가 구체적일수록 이깁니다. `#nav a` 는 `.nav-link` 보다 강하므로, 클래스로 만든 스타일이 ID 선택자에 밀려 적용되지 않을 수 있습니다.

## 관련 용어

- `css`
- `inline-style`
- `browser-rendering`

## 흔한 오해

나중에 쓴 규칙이 항상 이긴다고 생각하기 쉽지만, 순서는 구체성이 같을 때만 따집니다. 파일 아래쪽에 쓴 `.btn` 은 위쪽에 쓴 `#header .btn` 을 이기지 못합니다.

## 동료평가 질문

적용되지 않는 스타일을 만났을 때 `!important` 를 붙이기 전에 무엇을 먼저 확인해야 하는지 설명할 수 있나요?
