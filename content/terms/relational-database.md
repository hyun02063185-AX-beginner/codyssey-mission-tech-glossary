# relational database

## 한 줄 설명

table, row, column과 관계 제약으로 데이터를 관리하는 database.

## 쉽게 설명하면

데이터를 표로 나눠 담고 표 사이를 서로 가리키게 해서 관리하는 방식입니다. 같은 값을 여러 곳에 적지 않는 것이 핵심입니다.

## 정확한 설명

행과 열로 이뤄진 표에 데이터를 담고, 표 사이의 연결을 키로 표현한다. 제약으로 데이터가 지켜야 할 규칙을 데이터베이스 안에 적어 두므로, 어떤 프로그램이 접근하든 같은 규칙이 적용된다. 여러 작업을 한 단위로 묶는 트랜잭션도 이 모델의 일부다.

## 동작 원리

중복되는 값을 별도의 표로 빼고 원래 표에는 그 표를 가리키는 키만 남깁니다. 값을 고칠 일이 생기면 한 군데만 고치면 되고, 필요할 때는 연결로 다시 합쳐 봅니다.

## 이 미션에서는 왜 필요한가

이 회차가 사용하는 데이터 모델입니다. 파일에 저장하던 것과 가장 크게 달라지는 점은 규칙을 데이터베이스가 지켜 준다는 것인데, 애플리케이션 코드가 실수해도 잘못된 데이터가 들어가지 않습니다.

## 코드 예

```text
파일 하나에 다 담으면
  post.csv
    1, 첫 글, kim, kim@ex.com
    2, 둘째 글, kim, kim@ex.com     ← 이메일이 반복된다
  kim 의 이메일이 바뀌면 모든 줄을 고쳐야 한다.
  한 줄만 빠뜨리면 같은 사람의 이메일이 두 개가 된다.

표로 나누면
  member(id, name, email)      1, kim, kim@ex.com
  post(id, title, author_id)   1, 첫 글, 1
                               2, 둘째 글, 1
  이메일은 한 곳에만 있다. 고칠 곳도 한 곳이다.
```

## 주의할 점 / 경계 조건

모든 데이터가 이 모델에 맞는 것은 아닙니다. 구조가 자주 바뀌거나 관계가 없는 로그성 데이터는 다른 저장 방식이 더 맞을 수 있습니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

표로 나누면 항상 좋다고 생각하기 쉽지만, 지나치게 나누면 하나를 보려고 연결을 여러 번 해야 합니다. 나누는 정도에도 판단이 필요합니다.
