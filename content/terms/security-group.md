# Security Group

## 한 줄 설명

cloud resource의 inbound·outbound traffic을 제어하는 가상 방화벽 규칙.

## 쉽게 설명하면

클라우드 서버 앞에 두는 방화벽 규칙입니다. 어떤 포트로 누가 들어올 수 있는지 정합니다.

## 정확한 설명

인스턴스 단위로 붙는 상태 저장 방화벽이다. 들어오는 연결을 허용하면 그에 대한 응답은 규칙 없이도 나가므로, 나가는 규칙을 따로 열 필요가 없다. 허용 규칙만 적을 수 있고 적지 않은 것은 모두 막힌다.

## 이 미션에서는 왜 필요한가

이 회차에서 배포한 서버에 외부에서 접속할 수 있게 만드는 설정입니다. 웹 포트를 열지 않으면 서버가 정상 동작해도 밖에서 보이지 않고, 반대로 필요 이상으로 열면 열어 둔 만큼 노출됩니다.

## 코드 예

```text
인바운드 규칙 (들어오는 것만 적는다)

  유형    포트   출처              이유
  SSH     22     내 IP/32          관리 접속. 0.0.0.0/0 로 열지 않는다
  HTTP    80     0.0.0.0/0         누구나 접속해야 한다
  HTTPS   443    0.0.0.0/0         같음

아웃바운드는 기본값 그대로 둔다.
들어온 연결의 응답은 규칙 없이도 나간다.

접속이 안 될 때 확인 순서
  1. 여기 규칙   2. 서버 안 방화벽(ufw)   3. 서비스가 떠 있는지
```

## 주의할 점 / 경계 조건

접속이 안 될 때 원인이 여기일 수도 서버 안의 방화벽일 수도 있습니다. 두 겹이 모두 열려야 통하므로 한쪽만 보고 판단하면 안 됩니다.

## 관련 용어

- `authentication`
- `authorization`

## 흔한 오해

나가는 규칙도 함께 열어야 한다고 생각하기 쉽지만, 들어온 연결에 대한 응답은 자동으로 나갑니다. 상태를 기억하기 때문입니다.

## 동료평가 질문

접속이 안 될 때 클라우드 방화벽과 서버 안 방화벽 중 어디가 원인인지 어떻게 구분하겠습니까?
