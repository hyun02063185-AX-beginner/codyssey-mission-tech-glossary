# 네트워크 프로토콜

## 한 줄 설명

네트워크 프로토콜은 통신하는 양쪽이 데이터를 어떤 형식과 절차로 주고받을지 미리 정해 둔 약속입니다.

## 쉽게 설명하면

편지를 보낼 때 봉투에 주소를 쓰는 규칙, 등기로 받았는지 확인하는 규칙, 편지 내용을 쓰는 형식이 따로 있는 것과 비슷합니다. 네트워크도 한 번의 통신에 역할이 다른 약속을 여러 개 겹쳐 씁니다. 비유는 여기까지입니다.

## 정확한 설명

웹 요청 하나에는 역할이 다른 프로토콜이 함께 쓰입니다. IP는 출발지·목적지 IP 주소를 보고 패킷을 네트워크 사이로 전달하며, 도착을 보장하지는 않습니다. TCP는 포트로 통신할 프로그램을 구분하고, 연결을 맺어 빠진 데이터는 다시 보내고 순서를 맞춰 전달합니다. HTTP는 무엇을 요청하고 어떻게 응답할지(메서드, 경로, 상태 코드)를 정합니다.

아래쪽 프로토콜이 위쪽 프로토콜의 데이터를 담아 옮깁니다. 그래서 셋은 같은 일을 하는 경쟁자가 아니라 역할을 나눈 층입니다. 조합은 고정되어 있지 않습니다. HTTPS는 TCP 위에 TLS 암호화를 더하고, HTTP/3는 TCP 대신 UDP 기반의 QUIC를 씁니다.

## 이 미션에서는 왜 필요한가

B3-1(M05)의 Security Group 규칙 "HTTP · TCP · 80"에는 프로토콜 이름이 두 개 나옵니다. TCP는 규칙이 검사하는 전송 프로토콜이고, 80은 TCP 포트이며, HTTP는 그 포트로 Nginx가 주고받은 웹 요청·응답의 형식입니다. 콘솔의 유형 "HTTP"는 TCP 80을 고르는 편의 이름일 뿐이고, Security Group이 HTTP 내용을 검사하지는 않습니다. 미션 스토리의 일반 기업망 예시는 HTTPS 443, B3-1 배포 기록은 HTTP 80이어서 같은 웹 접속이라도 프로토콜 조합이 다를 수 있습니다.

## 코드 예

```text
한 번의 웹 요청에서 겹쳐 쓰는 약속 (B3-1 · HTTP 80 · 문서용 주소)

  HTTP   GET /  →  200 OK                 무엇을 요청하고 응답하나
  TCP    포트 51514 → 80                   어느 프로그램 · 빠짐없이 순서대로
  IP     198.51.100.25 → 203.0.113.10     어느 기기까지

Security Group 규칙 읽기
  유형 HTTP  =  프로토콜 TCP + 포트 80 을 고르는 콘솔의 편의 이름
  Security Group은 프로토콜 · 포트 · 출발지를 보고, HTTP 내용은 검사하지 않는다
```

## 주의할 점 / 경계 조건

아래 층이 성공했다고 위 층이 성공한 것은 아닙니다. TCP로 데이터가 빠짐없이 전달되어도 서버는 HTTP 404나 500으로 응답할 수 있습니다. 또 "HTTP는 항상 TCP를 쓴다"고 외우면 HTTP/3를 설명할 수 없습니다.

## 흔한 오해

"IP·TCP·HTTP 중 하나를 골라 통신한다"고 생각하기 쉽지만, 한 번의 웹 요청에 셋이 함께 쓰입니다. 각자 맡은 정보와 역할이 다릅니다.

## 비슷한 개념과의 차이

프로토콜은 통신 약속 전체를 부르는 말이고, IP(Internet Protocol)는 그중 주소로 패킷을 전달하는 특정 프로토콜입니다. 포트는 TCP·UDP가 쓰는 번호이며 프로토콜이 아닙니다. 80번은 HTTP가 관례적으로 쓰는 번호일 뿐, 다른 포트에서 HTTP를 쓸 수도 있습니다.
