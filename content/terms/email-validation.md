# 이메일 검증

## 한 줄 설명

입력값이 서비스가 허용하는 이메일 형식과 정책을 만족하는지 확인하는 과정.

## 쉽게 설명하면

입력된 값이 이메일 주소처럼 생겼는지 확인하는 일입니다. 생긴 것을 확인할 뿐이고, 그 주소가 실제로 있는지는 알 수 없습니다.

## 정확한 설명

형식 검사는 소유·수신 가능성을 보장하지 않으므로 인증 메일과 구분한다.

## 이 미션에서는 왜 필요한가

이 회차의 폼 검증에 쓰입니다. 정규식을 아주 촘촘하게 쓰면 실제로 쓰이는 정상 주소까지 거절하게 되므로, 형식 검사는 느슨하게 하고 진짜 확인은 확인 메일로 미루는 편이 낫습니다.

## 코드 예

```javascript
// 너무 촘촘한 정규식은 정상 주소를 거절한다
// 최소 조건만 본다: @ 가 하나, 앞뒤에 값, 점 뒤에 글자
const LOOSE = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validate(value) {
  const email = value.trim();
  if (!email) return '이메일을 입력해 주세요.';
  if (!LOOSE.test(email)) return '예: name@example.com 형식으로 입력해 주세요.';
  return null;
}

// 실제로 받을 수 있는 주소인지는 확인 메일로만 알 수 있다
```

## 주의할 점 / 경계 조건

완벽한 이메일 정규식은 사실상 만들 수 없습니다. 표준이 허용하는 형식이 넓어서, 엄격하게 만들수록 정상 사용자를 막을 확률이 올라갑니다.

## 관련 용어

## 흔한 오해

형식 검사를 통과하면 보낼 수 있는 주소라고 생각하기 쉽지만, 오타로 만들어진 존재하지 않는 주소도 형식은 맞습니다. 받을 수 있는 주소인지는 실제로 보내 봐야 압니다.
