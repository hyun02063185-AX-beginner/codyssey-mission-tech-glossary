# Access Control

## 한 줄 설명

누가 어떤 resource에 어떤 작업을 할 수 있는지 결정·집행하는 보안 통제.

## 쉽게 설명하면

누가 무엇을 할 수 있는지 정하고 실제로 그렇게 되게 막는 일입니다. 정하는 것과 막는 것은 다른 일이며, 둘 다 있어야 합니다.

## 정확한 설명

정책(무엇을 허용할지)과 집행(요청마다 그 정책을 확인할지)으로 나뉜다. 집행 지점이 한 군데로 모여 있어야 새 경로를 추가할 때 빠뜨리지 않으며, 흩어져 있으면 같은 규칙이 곳곳에서 조금씩 다르게 적용된다.

## 이 미션에서는 왜 필요한가

이 회차에서 공개 경로와 보호 경로를 나누는 일의 상위 개념입니다. 경로마다 따로 검사를 넣으면 새 경로를 만들 때마다 기억해서 넣어야 하는데, 검사를 한 곳으로 모아 두면 잊어버려도 기본이 막힘으로 동작합니다.

## 코드 예

```text
두 가지를 따로 묻는다

  인증 (authentication)   당신은 누구입니까
  인가 (authorization)    그 사람이 이것을 해도 됩니까

요청 하나에 대해
  /posts/7/edit  →  로그인했는가?        아니면 로그인 화면으로
                 →  7번 글의 작성자인가?  아니면 403

두 번째를 빠뜨리면 로그인한 아무나 남의 글을 고칠 수 있다.
```

## 주의할 점 / 경계 조건

권한 확인을 화면을 그리는 코드에 두면, 같은 데이터를 다른 경로로 내보낼 때 검사가 빠집니다. 데이터를 꺼내는 쪽에 두는 편이 새는 곳이 적습니다.

## 관련 용어

- `authentication`

## 흔한 오해

로그인 검사를 했으면 접근 통제를 한 것이라 생각하기 쉽지만, 확인한 것은 "누구인가"뿐입니다. "이 사람이 이 자원에 이 동작을 해도 되는가"는 별개의 질문입니다.

## 동료평가 질문

남의 글 수정 화면 주소를 직접 입력했을 때 무엇이 막아 주는지, 그 검사가 어디에 있는지 보여 줄 수 있나요?
