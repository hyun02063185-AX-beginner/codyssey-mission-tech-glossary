# Virtual DOM Rendering

## 한 줄 설명

React가 새 UI 설명을 비교해 필요한 실제 DOM 변경을 반영하는 흐름.

## 쉽게 설명하면

화면을 바로 고치지 않고, 새로 그려야 할 모습을 먼저 메모리에 만든 뒤 이전 것과 비교해 달라진 부분만 실제로 고치는 방식입니다.

## 정확한 설명

reconciliation은 key와 component identity를 바탕으로 DOM mutation을 결정한다.

## 이 미션에서는 왜 필요한가

이 회차에서 상태를 바꾸면 화면이 따라 바뀌는 이유가 이것입니다. 목록에 `key`를 제대로 주지 않으면 비교가 어긋나 엉뚱한 항목이 남거나 입력 중이던 값이 다른 줄로 옮겨 가는데, 그 원인이 이 비교 방식에 있습니다.

## 코드 예

```jsx
// index 를 key 로 쓰면 중간 삽입 때 비교가 어긋난다
{items.map((item, i) => <Row key={i} item={item} />)}

// 항목마다 변하지 않는 값을 준다
{items.map(item => <Row key={item.id} item={item} />)}

/*
  [A, B, C] 의 맨 앞에 Z 를 넣으면
    key={index}  0:A→Z, 1:B→A, 2:C→B, 3:새로 C  → 전부 다른 것으로 본다
    key={id}     Z 만 새로 만들고 A·B·C 는 그대로 옮긴다
  입력 중이던 값은 "그대로 옮긴" 쪽에서만 남는다
*/
```

## 주의할 점 / 경계 조건

`key`에 배열 인덱스를 쓰면 중간에 항목을 넣고 뺄 때 비교가 어긋납니다. 항목마다 변하지 않는 고유한 값을 줘야 합니다.

## 관련 용어

- `react-state`
- `dom-update`
- `browser-rendering`

## 흔한 오해

가상 DOM이 있어서 항상 빠르다고 생각하기 쉽지만, 비교 자체에도 비용이 듭니다. 빨라지는 것이 목적이라기보다, 화면을 직접 고치지 않고 상태만 다루게 해 주는 것이 본래 이점입니다.
