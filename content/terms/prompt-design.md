# prompt design

## 한 줄 설명

원하는 작업과 제약을 모델에 명확히 전달하도록 입력을 설계하는 일.

## 쉽게 설명하면

모델이 무엇을, 어떤 기준과 형식으로 답할지 안내문을 쓰는 작업이다.

## 정확한 설명

역할·입력 경계·출력 형식·예시·평가 기준을 명시하고 실제 실패 사례로 반복 개선한다.

## 대표 사용

요약 요청에 대상 독자와 최대 길이, JSON 형식을 함께 지정한다.

## 주의할 점

긴 prompt가 항상 좋은 것은 아니며 상충하는 지시는 결과를 불안정하게 만든다.

## 이 미션에서는 왜 필요한가

이 회차의 출력 품질은 대부분 여기서 결정됩니다. 모델을 바꾸는 것보다 "무엇을, 어떤 형식으로, 무엇을 하지 말고"를 명확히 적는 쪽이 효과가 큰 경우가 많고, 고칠 때는 실제로 잘못 나온 사례를 근거로 고쳐야 합니다.

## 코드 예

```text
모호한 지시
  "이 변경사항으로 커밋 메시지를 써 줘"

경계를 정한 지시
  역할    너는 커밋 메시지를 쓰는 도구다
  입력    아래는 git diff 다 (--- 로 구분)
  형식    첫 줄 50자 이내 요약, 빈 줄, 본문은 왜 바꿨는지
  금지    파일 이름을 나열하지 마라, 추측한 의도를 쓰지 마라
  예시    fix(auth): 만료된 토큰으로도 로그인되던 문제

고칠 때는 실제로 잘못 나온 출력 하나를 근거로 한 줄씩 더한다.
```
