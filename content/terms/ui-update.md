# UI Update

## 한 줄 설명

상태나 data 변화가 사용자가 보는 화면에 반영되는 일.

## 쉽게 설명하면

데이터가 바뀌었을 때 사람이 보는 화면도 따라 바뀌게 하는 일입니다. 둘을 따로 관리하면 데이터는 바뀌었는데 화면은 그대로인 상태가 생깁니다.

## 정확한 설명

state 계산 뒤 DOM 또는 component tree가 새 view를 렌더링한 결과다.

## 이 미션에서는 왜 필요한가

이 회차에서 버튼을 눌러 상태를 바꾼 뒤 화면이 그대로라면, 상태를 안 바꾼 것인지 화면을 안 그린 것인지 나눠 봐야 합니다. 상태를 바꾸는 자리와 화면을 그리는 자리를 분리해 두면 이 확인이 쉬워집니다.

## 코드 예

```javascript
// 상태와 그리기를 섞으면 어디가 문제인지 알기 어렵다
button.addEventListener('click', () => {
  count += 1;
  label.textContent = count;        // 여기저기 흩어지면 순서 문제가 생긴다
});

// 상태를 바꾸는 자리와 그리는 자리를 나눈다
let state = { count: 0 };

function render() {
  label.textContent = state.count;
}

button.addEventListener('click', () => {
  state = { ...state, count: state.count + 1 };
  render();                         // 그리는 곳은 한 군데
});
```

## 주의할 점 / 경계 조건

여러 곳에서 각자 화면을 고치면 어느 쪽이 마지막에 실행됐는지에 따라 결과가 달라집니다. 화면을 그리는 자리를 하나로 모아 두면 순서에 흔들리지 않습니다.

## 관련 용어

- `state-change`
- `dom-update`
- `virtual-dom-rendering`

## 흔한 오해

화면이 안 바뀌면 그리기 코드가 잘못됐다고 보기 쉽지만, 상태를 바꾸면서 새 객체를 만들지 않아 "바뀌지 않았다"고 판단됐을 수도 있습니다. 먼저 상태 값을 찍어 확인해야 합니다.
