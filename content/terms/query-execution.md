# Query Execution

## 한 줄 설명

database가 SQL을 parse, plan, 실행해 결과를 만드는 과정.

## 쉽게 설명하면

적어 낸 SQL을 데이터베이스가 실제로 어떻게 처리했는지를 말합니다. 같은 답을 내는 방법이 여러 가지라 그중 하나를 고릅니다.

## 정확한 설명

문장을 해석해 여러 실행 계획 후보를 만들고, 통계를 바탕으로 비용이 가장 낮은 것을 골라 실행한다. 같은 SQL이라도 데이터 양과 색인 유무에 따라 다른 계획이 선택되므로, 느린 쿼리는 문장이 아니라 계획을 봐야 원인이 보인다.

## 이 미션에서는 왜 필요한가

이 회차에서 조회가 느릴 때 SQL을 이리저리 고쳐 보는 대신 무엇이 일어나는지 먼저 보게 해 줍니다. 대부분의 원인은 색인을 타지 못해 표 전체를 읽는 것이고, 그 사실은 계획을 출력해 보면 바로 드러납니다.

## 코드 예

```sql
EXPLAIN QUERY PLAN
SELECT * FROM post WHERE author_id = 3;

-- SCAN post                       ← 표 전체를 읽고 있다
-- SEARCH post USING INDEX ...     ← 색인을 타고 있다

CREATE INDEX idx_post_author ON post(author_id);
-- 만든 뒤 같은 명령을 다시 실행해 계획이 바뀌었는지 확인한다

-- 데이터가 적으면 색인이 무시될 수 있다. 실제 규모로 실험한다
```

## 주의할 점 / 경계 조건

데이터가 적을 때는 표 전체를 읽는 편이 오히려 빨라서 색인이 무시될 수 있습니다. 성능 실험은 실제 규모에 가까운 데이터로 해야 합니다.

## 관련 용어

- `sql`
- `table`

## 흔한 오해

SQL을 더 복잡하게 쓰면 느려진다고 생각하기 쉽지만, 문장의 길이와 실행 비용은 관계가 없습니다. 어떤 계획이 선택되느냐가 정합니다.
