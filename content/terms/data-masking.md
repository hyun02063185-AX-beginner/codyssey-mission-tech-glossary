# 데이터 마스킹

## 한 줄 설명

원본 민감값을 숨기거나 일부만 보이게 바꿔 노출 위험을 줄이는 처리.

## 쉽게 설명하면

민감한 값을 별표로 가리거나 일부만 보이게 바꾸는 처리입니다. 지우는 것과는 다릅니다.

## 정확한 설명

값을 보여 주되 원본을 알 수 없게 바꾼다. 앞뒤 몇 글자만 남기면 사람이 어느 값인지 구분하면서도 전체를 알 수 없고, 로그와 오류 메시지처럼 사람이 읽는 출력에 주로 적용한다. 저장된 원본까지 바꾸는 것은 아니다.

## 동작 원리

요청 또는 접속이 들어오면 자격 증명과 정책을 확인하고, 허용된 범위에서만 작업을 수행한 뒤 기록·만료·회수 조건을 적용합니다.

## 이 미션에서는 왜 필요한가

이 회차에서 변경 내용을 모델에 보내기 전에 적용해야 하는 처리입니다. 코드 변경분에 키나 토큰이 섞여 있을 수 있는데, 그대로 보내면 외부 서비스에 그 값이 남습니다.

## 코드 예

```python
import re

PATTERNS = [
    (re.compile(r'sk-[A-Za-z0-9]{20,}'), 'sk-****'),
    (re.compile(r'gh[pous]_[A-Za-z0-9]{20,}'), 'ghp_****'),
    (re.compile(r'(?i)(password|secret|token)\s*[=:]\s*\S+'), r'\1=****'),
    (re.compile(r'[\w.+-]+@[\w-]+\.[\w.]+'), '****@****'),
]

def mask(text):
    for pattern, replacement in PATTERNS:
        text = pattern.sub(replacement, text)
    return text

# 보내기 전에 한 번 더 눈으로 확인한다.
# 정규식이 모든 형태를 잡지는 못한다
```

## 주의할 점 / 경계 조건

앞뒤를 너무 많이 남기면 추측할 수 있습니다. 짧은 값은 아예 전부 가리는 편이 낫습니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

가렸으니 안전하다고 생각하기 쉽지만, 저장된 원본은 그대로입니다. 새어 나간 값은 가리는 것이 아니라 무효화해야 합니다.
