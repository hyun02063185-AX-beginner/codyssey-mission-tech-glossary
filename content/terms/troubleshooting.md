# 트러블슈팅

## 한 줄 설명

증상에서 원인을 좁혀 확인·완화·재발 방지를 진행하는 문제 해결 과정.

## 쉽게 설명하면

문제가 생겼을 때 추측부터 하지 않고 증거를 모아 원인을 좁히는 절차다.

## 정확한 설명

재현, 관측, 가설, 검증, 완화, 회고 순으로 진행하며 변경 이력과 영향 범위를 함께 확인한다.

## 대표 사용

컨테이너가 기동하지 않을 때 logs와 설정을 비교한다.

## 주의할 점

가장 최근 변경이 항상 원인이라는 가정은 위험하다.

## 이 미션에서는 왜 필요한가

예비 M01은 문제 해결 기록을 두 건 이상 남기라고 요구합니다. 결과만 적으면 다음에 같은 일이 생겼을 때 쓸 수 없으므로, 문제 → 가설 → 확인 → 해결의 네 칸을 채우는 구조로 적습니다.

## 코드 예

```text
문제   docker run 후 컨테이너가 즉시 종료됨
가설   1번 프로세스가 바로 끝나는 이미지라서
확인   docker ps -a 의 STATUS 가 Exited (0)
해결   sleep 또는 상주 프로세스를 CMD 로 지정
```

## 관련 용어

- `docker-logs`
- `observability`
