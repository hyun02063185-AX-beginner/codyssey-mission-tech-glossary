# 인증 토큰

## 한 줄 설명

인증이 끝난 뒤 클라이언트가 자신을 증명할 때 제시하는 자격 증명 값.

## 쉽게 설명하면

로그인했다는 사실을 증명하는 표식입니다. 이것을 가진 쪽이 그 사용자로 취급되므로, 사실상 열쇠와 같습니다.

## 정확한 설명

서버가 발급하고 서명해 위조를 막는다. JWT는 내용과 만료 시각을 토큰 자체에 담고 서명으로 무결성을 보장하므로, 서버가 저장소를 조회하지 않고도 검증할 수 있다. 대신 발급 뒤에는 만료 전까지 회수하기 어렵다.

## 동작 원리

서버가 사용자 식별자와 만료 시각을 담아 비밀 키로 서명합니다. 클라이언트는 이후 요청마다 이 값을 헤더나 쿠키에 실어 보내고, 서버는 서명을 검증해 내용이 바뀌지 않았음을 확인한 뒤 만료 여부를 봅니다.

## 이 미션에서는 왜 필요한가

이 회차의 인증을 토큰으로 만들 때 쓰는 값입니다. 서버가 상태를 들고 있지 않아도 된다는 점이 장점이지만, 그 대가로 로그아웃과 권한 회수가 즉시 반영되지 않습니다. 이 맞바꿈을 알고 골라야 합니다.

## 코드 예

```python
import jwt, datetime

def issue(user_id: int) -> str:
    now = datetime.datetime.now(datetime.UTC)
    return jwt.encode(
        {'sub': str(user_id), 'iat': now, 'exp': now + datetime.timedelta(minutes=15)},
        SECRET, algorithm='HS256',
    )

# 본문은 누구나 열어 볼 수 있다 — 비밀을 담지 않는다
# jwt.decode(token, options={'verify_signature': False})

# 검증할 때 알고리즘을 명시한다. 생략하면 위조된 alg 를 따를 수 있다
jwt.decode(token, SECRET, algorithms=['HS256'])
```

## 주의할 점 / 경계 조건

서명은 내용이 바뀌지 않았음을 보장할 뿐 내용을 감추지는 않습니다. JWT의 본문은 누구나 열어 볼 수 있으므로 비밀을 담으면 안 됩니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

토큰이 암호화되어 있다고 생각하기 쉽지만, 기본 JWT는 그냥 인코딩된 것입니다. 붙여 넣으면 안의 값이 그대로 보입니다.
