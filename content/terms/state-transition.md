# State Transition

## 한 줄 설명

상태가 허용된 규칙에 따라 한 상태에서 다른 상태로 이동하는 것입니다.

## 쉽게 설명하면

배송이 ‘결제 대기 → 결제 완료 → 발송됨’ 순서로만 바뀌는 표지판과 비슷합니다.

## 정확한 설명

State transition은 상태 집합과 전이 규칙으로 현재 상태에서 가능한 다음 상태를 제한합니다. 단순 값 변경보다, 어떤 이벤트가 어떤 변경을 허용하는지까지 포함합니다.

## 동작 원리

1. 현재 상태와 가능한 이벤트를 정의합니다.
2. 이벤트가 허용되는지 검사합니다.
3. 새 상태를 기록하고 필요한 후속 작업을 수행합니다.

## 이 미션에서는 왜 필요한가

M13의 인증·보호 기능처럼 요청 처리 단계와 비즈니스 상태의 유효한 순서를 설계할 때 필요합니다.

## 코드 예

```text
PENDING --approve--> APPROVED
PENDING --reject--> REJECTED
```

## 주의할 점 / 경계 조건

이미 종료된 상태를 다시 승인하는 전이를 허용할지는 도메인 규칙이며, 상태 이름만으로 자동 결정되지 않습니다.

## 관련 용어

- `state-change`
- `ui-state`
- `verification`
- `business-logic`

## 흔한 오해

모든 state change가 의미 있는 state transition은 아닙니다. 전이에는 허용 규칙이 필요합니다.
