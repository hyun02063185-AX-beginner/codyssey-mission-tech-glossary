# CPU

## 한 줄 설명

process 또는 system이 CPU 시간을 사용한 비율.

## 쉽게 설명하면

프로세서가 일한 시간의 비율입니다. 순간 값 하나로는 판단할 수 없고 평소와 비교해야 의미가 생깁니다.

## 정확한 설명

누적된 CPU 시간의 차이를 경과 시간으로 나눈 값이다. 따라서 한 시점을 찍어서는 계산할 수 없고 두 시점이 필요하며, 코어가 여러 개면 프로세스 단위 값이 100%를 넘을 수 있다.

## 이 미션에서는 왜 필요한가

이 회차의 점검 스크립트가 수집하는 값 중 하나입니다. 한 번 찍은 값만 기록하면 나중에 "높다"고 판단할 기준이 없으므로, 평소 값을 함께 쌓아 두는 것이 수집의 목적입니다.

## 코드 예

```bash
# 두 시점의 차이로 계산된다 — 첫 호출은 부팅 이후 평균이라 의미가 적다
top -bn2 -d1 | grep '^%Cpu' | tail -1

# 코어 수를 함께 기록해 둔다
nproc

# 프로세스별 값은 코어 수만큼 넘을 수 있다
ps -eo pid,pcpu,comm --sort=-pcpu | head -5
# %CPU 가 380 이면 4코어 중 거의 전부를 쓰고 있다는 뜻
```

## 주의할 점 / 경계 조건

코어가 4개면 한 프로세스가 400%까지 나올 수 있습니다. 100%를 상한으로 보고 경보를 걸면 오작동합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

높으면 문제라고 생각하기 쉽지만, 일을 하고 있다는 뜻이기도 합니다. 문제인지는 응답 시간이나 대기 중인 작업 수와 함께 봐야 알 수 있습니다.
