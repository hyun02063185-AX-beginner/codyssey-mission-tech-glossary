# CPU Spike

## 한 줄 설명

짧은 시간에 CPU 사용률이 급격히 올라가는 현상.

## 쉽게 설명하면

짧은 시간에 CPU 사용률이 확 치솟는 현상입니다. 잠깐이면 정상이고 계속되면 문제입니다.

## 정확한 설명

짧은 상승은 배치 작업이나 요청 몰림처럼 정상적인 이유로도 생긴다. 문제로 판단하려면 지속 시간과 그 사이의 응답 시간을 함께 봐야 하며, 순간을 놓치면 원인을 잡을 수 없으므로 기록을 미리 쌓아 두는 것이 조사 조건이다.

## 이 미션에서는 왜 필요한가

이 회차가 다루는 장애 유형 중 하나입니다. 발생한 뒤에 들여다보면 이미 지나가 있는 경우가 많으므로, 앞선 회차에서 만든 점검 기록이 여기서 증거가 됩니다. 기록이 없으면 추측밖에 할 수 없습니다.

## 코드 예

```bash
# 지난 기록에서 언제 치솟았는지 찾는다
sar -u 1 1 2>/dev/null || top -bn2 -d1 | grep "^%Cpu" | tail -1

# 주기적으로 오르내린다면 정해진 작업을 의심한다
crontab -l; ls /etc/cron.*

# 지금 치솟고 있다면 범인부터 좁힌다
ps -eo pid,pcpu,etime,comm --sort=-pcpu | head -5
#            └ 사용률   └ 떠 있던 시간
# 방금 뜬 프로세스가 높으면 시작 비용일 수 있다
```

## 주의할 점 / 경계 조건

무한 반복이 원인이면 사용률이 내려오지 않습니다. 반대로 주기적으로 오르내리면 정해진 시각에 도는 작업을 의심해야 합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

치솟았으니 문제라고 생각하기 쉽지만, 일을 처리하고 있는 것일 수도 있습니다. 같은 시간대에 응답이 느려졌는지를 함께 봐야 판단이 됩니다.
