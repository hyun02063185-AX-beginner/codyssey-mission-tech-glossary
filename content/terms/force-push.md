# force push

## 한 줄 설명

remote branch history를 강제로 바꾸는 push 방식.

## 쉽게 설명하면

원격의 기록을 내 쪽 기록으로 덮어쓰는 방식입니다. 남이 올린 것이 사라질 수 있습니다.

## 정확한 설명

원격 브랜치가 내 이력의 조상이 아니어도 밀어 넣는다. 그 사이에 다른 사람이 올린 커밋이 있으면 참조를 잃게 되며, 안전 장치가 붙은 형태를 쓰면 내가 마지막으로 본 상태와 다를 때 거부된다.

## 이 미션에서는 왜 필요한가

이 회차에서 개인 브랜치의 이력을 정리한 뒤 반영할 때 필요합니다. 필요한 경우가 분명히 있지만 공유 브랜치에서 쓰면 팀원의 작업이 사라지므로, 어디에 쓰는지가 이 명령의 전부입니다.

## 코드 예

```bash
# 위험한 형태 — 그 사이 누가 올렸어도 덮어쓴다
git push --force origin feature/login

# 안전한 형태 — 내가 마지막으로 본 상태와 다르면 거부된다
git push --force-with-lease origin feature/login

# 실수로 날렸을 때 되찾기
git reflog                     # 최근에 HEAD 가 있던 자리들
git reset --hard HEAD@{3}
# 다른 사람 쪽에서는 못 찾는다. 자기 저장소에만 남는다
```

## 주의할 점 / 경계 조건

안전 장치가 붙은 형태를 쓰면 그 사이 누군가 올렸을 때 거부됩니다. 습관적으로 그쪽을 쓰는 편이 낫습니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

내 브랜치니까 괜찮다고 생각하기 쉽지만, 다른 사람이 그 브랜치를 보고 있을 수도 있습니다. 혼자 쓰는 브랜치인지 확인해야 합니다.

## 동료평가 질문

이 명령을 써도 되는 브랜치와 그러면 안 되는 브랜치를 구분하고, 안전한 형태를 설명할 수 있나요?
