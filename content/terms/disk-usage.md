# DISK

## 한 줄 설명

file과 directory가 storage에서 차지하는 용량.

## 쉽게 설명하면

저장 공간을 얼마나 썼는지입니다. 용량이 남았는데도 파일을 못 만드는 경우가 있어 두 가지를 함께 봐야 합니다.

## 정확한 설명

용량과 별개로 파일 수를 담는 자료 구조에도 한도가 있어, 작은 파일이 아주 많으면 용량이 남아도 파일 생성이 실패한다. 또 지워진 파일이라도 프로세스가 열고 있으면 공간이 반환되지 않아, 목록에서 사라졌는데 사용량이 줄지 않는 상황이 생긴다.

## 이 미션에서는 왜 필요한가

이 회차의 점검 스크립트가 수집하는 값입니다. 서버가 멈추는 흔한 원인이 로그 파일로 디스크가 차는 것인데, 이 값을 쌓아 두면 언제부터 늘기 시작했는지를 나중에 되짚을 수 있습니다.

## 코드 예

```bash
df -h /              # 용량
df -i /              # 파일 수 한도 — 이쪽이 먼저 찰 수 있다

# 지웠는데 공간이 안 돌아올 때
sudo lsof +L1        # 링크 수가 0 인데 열려 있는 파일

# 어디가 차지하는지 좁혀 간다
sudo du -h --max-depth=1 /var | sort -rh | head
```

## 주의할 점 / 경계 조건

지운 파일이 프로세스에 열려 있으면 공간이 돌아오지 않습니다. 지웠는데 사용량이 그대로면 이 경우를 의심해야 합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

용량이 남으면 파일을 만들 수 있다고 생각하기 쉽지만, 파일 수 한도에 먼저 걸릴 수 있습니다. 두 가지를 함께 확인해야 합니다.

## 동료평가 질문

용량이 남았는데도 파일 생성이 실패하는 두 가지 경우를 들고, 각각 어떻게 확인할지 설명할 수 있나요?
