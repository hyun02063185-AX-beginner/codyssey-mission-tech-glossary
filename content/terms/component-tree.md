# Component Tree

## 한 줄 설명

UI framework에서 component가 부모·자식 관계로 구성된 구조.

## 쉽게 설명하면

화면을 이루는 조각들이 부모와 자식으로 이어진 구조입니다. 값은 위에서 아래로만 내려가므로, 형제 사이에 값을 주고받으려면 공통 부모를 거쳐야 합니다.

## 정확한 설명

props가 아래로 흐르고 context가 provider 아래로 전달되는 경계를 보여 준다.

## 이 미션에서는 왜 필요한가

값을 어느 조각에 둘지 정할 때의 기준이 됩니다. 두 조각이 같은 값을 봐야 한다면 그 값은 둘의 공통 부모에 있어야 하고, 이 구조를 그려 보지 않으면 값을 잘못된 자리에 두고 여러 곳에서 따로 관리하게 됩니다.

## 코드 예

```text
App                    ← 검색어는 여기 있어야 한다
 ├ SearchBar           ← 검색어를 바꾼다
 └ ResultList          ← 검색어를 읽는다
    └ ResultItem

SearchBar 안에 검색어를 두면 ResultList 가 읽을 수 없다.
둘 다 필요한 값은 둘의 공통 부모로 올린다.

부모가 깊어져 값이 여러 단계를 그냥 통과하기만 하면,
그때가 Context 같은 다른 방법을 볼 시점이다.
```
