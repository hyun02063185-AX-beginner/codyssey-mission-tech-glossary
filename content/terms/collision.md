# Collision

## 한 줄 설명

서로 다른 키가 같은 해시 값 또는 버킷에 배정되는 현상.

## 쉽게 설명하면

다른 이름표 두 개가 같은 서랍 번호를 받는 일이다.

## 정확한 설명

해시 공간은 유한하므로 충돌은 피할 수 없다. 체이닝이나 open addressing으로 키를 다시 비교해 구분한다.

## 작은 사례

해시맵 조회 결과가 잘못 섞이지 않도록 충돌 처리를 구현한다.

## 주의할 점

충돌은 해시 함수가 고장 났다는 뜻이 아니라 설계상 예상되는 상황이다.

## 이 미션에서는 왜 필요한가

서로 다른 키가 같은 칸을 받는 일은 저장소를 만들면 반드시 생깁니다. 이것을 고장으로 오해하면 해시 함수를 계속 바꾸며 시간을 씁니다. 충돌은 없애는 대상이 아니라 처리하는 대상이며, 그래서 다음 단계로 체이닝이 나옵니다.

## 코드 예

```python
# 키가 달라도 버킷 번호는 같을 수 있다
for key in ['apple', 'grape', 'melon', 'peach']:
    print(f'{key:>6} -> bucket {hash(key) % 4}')

# 그래서 버킷 안에서 키를 한 번 더 비교해야 한다
# bucket = [('apple', 1), ('melon', 9)]  <- 같은 칸, 다른 키
```

## 관련 용어

- `hash-function`
- `separate-chaining`
