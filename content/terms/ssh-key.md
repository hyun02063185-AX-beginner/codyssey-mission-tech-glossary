# SSH 키

## 한 줄 설명

SSH에서 password 대신 공개키 암호로 사용자를 증명하는 key pair.

## 쉽게 설명하면

비밀번호 대신 쓰는 한 쌍의 열쇠입니다. 공개키를 서버에 올려 두고 개인키로 자신을 증명합니다.

## 정확한 설명

공개키와 개인키가 한 쌍으로 만들어지는 비대칭키 인증 방식이다. 서버에는 공개키를 등록하고, 접속자는 개인키로 서명해 자신이 그 키 쌍의 소유자임을 증명한다. 서버는 등록된 공개키로 서명을 검증하므로 개인키 자체는 네트워크를 지나가지 않는다.

## 이 미션에서는 왜 필요한가

B3-1에서는 EC2 Key Pair를 만들어 EC2 인스턴스에 접속할 때 사용합니다. EC2에는 공개키가 등록되고, 접속자가 보관한 개인키는 외부에 공유하지 않습니다. 키 인증은 매번 비밀번호를 입력하지 않으면서도 추측 공격에 강한 관리 접속 방식을 제공합니다.

## 코드 예

```bash
EC2 Key Pair
공개키  → EC2 인스턴스에 등록
개인키  → 접속자가 안전하게 보관하고 서명에 사용

chmod 400 ./ec2-key.pem       # 소유자만 읽을 수 있게 한다
ssh -i ./ec2-key.pem user@server-address

# 개인키는 네트워크를 지나가지 않는다.
# 서버가 보낸 값에 서명해 돌려줄 뿐이다
```

## 주의할 점 / 경계 조건

개인키 파일의 권한이 느슨하면 사용이 거부됩니다. `chmod 400`은 소유자만 개인키를 읽을 수 있게 하여 SSH 클라이언트가 안전하다고 판단하도록 하는 권한 설정입니다. 개인키 내용은 복사·공유·저장소 커밋을 하지 않습니다.

## 관련 용어

- `authentication`
- `ssh`
- `security-group`

## 흔한 오해

두 파일 중 어느 것을 올려도 된다고 생각하기 쉽지만, `.pub`이 붙은 쪽만 올립니다. 개인키를 올리면 누구나 나인 척할 수 있습니다.
