# Semantic / Conventional Commits

## 한 줄 설명

변경 의미를 type과 scope로 표현하는 commit message 관례.

## 쉽게 설명하면

커밋 메시지 앞에 `fix:`나 `feat:` 같은 표시를 붙여 종류를 나타내는 관례입니다.

## 정확한 설명

변경의 종류와 영향 범위를 제목 앞부분에 정해진 형식으로 적는다. 형식이 기계가 읽을 수 있게 되어 있어 변경 기록 자동 생성이나 버전 번호 결정에 쓸 수 있으며, 사람에게는 기록을 훑을 때 분류 기준이 된다.

## 이 미션에서는 왜 필요한가

이 회차의 커밋 규칙을 확장한 형태입니다. 표시를 붙이는 것 자체가 목적이 아니라 종류를 먼저 생각하게 만드는 효과가 있는데, 하나의 커밋에 여러 종류가 섞였다면 나눠야 한다는 신호가 됩니다.

## 코드 예

```text
형식   <종류>(<범위>): <제목>

  feat(auth): 소셜 로그인 추가
  fix(post): 제목이 비어도 저장되던 문제 수정
  docs(readme): 실행 방법 보완
  refactor(db): 조회 코드를 리포지토리로 분리
  test(post): 빈 제목 검증 테스트 추가
  chore(deps): fastapi 0.115 로 올림

종류를 못 정하겠다면 커밋이 너무 큰 것이다.
feat 과 fix 가 섞여 있으면 나눈다.
```

## 주의할 점 / 경계 조건

종류를 붙였다고 커밋이 잘 나뉜 것은 아닙니다. 기능 추가와 버그 수정이 한 커밋에 있으면 어느 표시를 붙여도 정확하지 않습니다.

## 관련 용어

- `git`
- `commit`

## 흔한 오해

형식만 맞추면 된다고 생각하기 쉽지만, 형식이 맞아도 제목이 "수정"이면 아무 정보가 없습니다. 표시는 분류이고 내용은 여전히 사람이 써야 합니다.

## 동료평가 질문

어떤 표시를 붙일지 정하기 어려운 커밋이 있다면, 그것이 무엇을 뜻하는지 설명할 수 있나요?
