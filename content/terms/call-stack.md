# Call Stack

## 한 줄 설명
함수 호출이 시작된 순서대로 실행 정보를 쌓고, 반환할 때 가장 최근 호출부터 꺼내는 실행 구조입니다.

## 쉽게 설명하면
함수를 부른 순서를 적은 접시 더미와 같습니다. 새 함수를 부르면 맨 위에 한 장이 놓이고, 일이 끝나면 맨 위 장부터 치웁니다.

## 정확한 설명
Call Stack은 실행 중인 함수마다 반환할 위치, 매개변수, 지역 변수 같은 호출 프레임을 LIFO 순서로 보관합니다. 자료구조 일반인 `stack`과 달리, 함수 실행을 추적하는 runtime 구조를 뜻합니다.

## 동작 원리
1. 함수 호출 시 프레임을 push합니다.
2. 함수 본문을 실행합니다.
3. 반환 시 결과와 다음 위치를 남기고 프레임을 pop합니다.
4. 재귀 호출이 깊거나 반환하지 않으면 제한을 넘어 stack overflow가 날 수 있습니다.

## 이 미션에서는 왜 필요한가
M01에서는 현재 실행이 끝난 뒤 event loop가 다음 작업을 처리한다는 흐름을, M10에서는 재귀·탐색 함수가 호출 후 되돌아오는 순서를 설명하는 기준이 됩니다.

## 코드 예
```js
function inner() { return 'done'; }
function outer() { return inner(); }
outer(); // outer 프레임 → inner 프레임 → inner 반환 → outer 반환
```

## 주의할 점 / 경계 조건
비동기 callback이 등록되었다고 즉시 call stack에 실행되는 것은 아닙니다. 현재 stack이 비워진 뒤에야 다음 작업이 실행될 수 있습니다.

## 관련 용어
- `stack`
- `function`
- `recursion`
- `event-loop`
- `stack-trace`

## 흔한 오해
Call Stack은 프로그램 전체의 모든 메모리나 모든 비동기 작업을 저장하는 곳이 아닙니다.
