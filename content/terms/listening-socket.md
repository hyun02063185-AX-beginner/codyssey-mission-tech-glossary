# LISTEN

## 한 줄 설명

network connection을 받을 준비가 된 server socket.

## 쉽게 설명하면

서비스가 연결을 받을 준비를 하고 열어 둔 창구입니다. 이것이 열려 있어야 밖에서 접속할 수 있습니다.

## 정확한 설명

어떤 주소와 포트에 묶여 연결 요청을 기다리는 상태다. `127.0.0.1`에 묶으면 같은 기계에서만 닿고 `0.0.0.0`에 묶어야 밖에서 닿으므로, 접속이 안 될 때 포트가 열렸는지와 어느 주소에 묶였는지는 다른 질문이다.

## 이 미션에서는 왜 필요한가

이 회차의 포트 상태 확인이 이것입니다. 서비스가 떠 있는데 접속이 안 되는 경우, 대부분 방화벽이 아니라 로컬 주소에만 묶여 있어서입니다. 묶인 주소를 보면 바로 구분됩니다.

## 코드 예

```bash
ss -tlnp
# State  Local Address:Port   Process
# LISTEN 127.0.0.1:8000       python      ← 이 기계에서만 닿는다
# LISTEN 0.0.0.0:80           nginx       ← 밖에서도 닿는다

# 포트를 누가 잡고 있는지
sudo ss -tlnp | grep :8000

# 실제로 닿는지 확인
curl -fsS --max-time 3 http://localhost:8000/ >/dev/null && echo ok
```

## 주의할 점 / 경계 조건

같은 포트를 두 프로세스가 쓸 수 없습니다. 서비스가 뜨지 않으면 이전 프로세스가 아직 붙잡고 있는지 확인해야 합니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

포트가 열려 있으면 밖에서 접속된다고 생각하기 쉽지만, 어느 주소에 묶였는지가 함께 정합니다. 로컬에만 묶여 있으면 방화벽과 무관하게 막힙니다.

## 동료평가 질문

서비스는 떠 있는데 밖에서 접속이 안 될 때, 묶인 주소로 원인을 구분하는 방법을 설명할 수 있나요?
