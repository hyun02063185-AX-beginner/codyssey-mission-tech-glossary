# 이미지 레이어

## 한 줄 설명

컨테이너 이미지 변경을 겹쳐 만든 읽기 전용 파일시스템 층.

## 쉽게 설명하면

이미지는 한 덩어리보다 여러 투명 필름을 포개 놓은 구조에 가깝다.

## 정확한 설명

Dockerfile 각 단계가 layer를 만들 수 있고, container 실행 시 writable layer가 그 위에 추가된다. cache 재사용과 이미지 크기에 영향을 준다.

## 언제 쓰나

변경이 적은 의존성 설치를 앞 단계에 둬 build cache를 활용한다.

## 기억할 경계

명령 하나가 항상 layer 하나라는 보장은 빌더와 설정에 따라 다르다.

## 이 미션에서는 왜 필요한가

예비 M01에서 Dockerfile 을 고쳤는데 빌드가 빨리 끝나는 이유이자, 반대로 한 줄만 고쳤는데 전부 다시 빌드되는 이유입니다. 각 줄이 층으로 쌓이고 바뀐 줄부터 다시 만들기 때문입니다.

## 코드 예

```text
FROM ubuntu:24.04          ← 층 1
RUN apt-get install -y ...  ← 층 2  (자주 안 바뀜 → 위에 둔다)
COPY ./site /var/www        ← 층 3  (자주 바뀜 → 아래에 둔다)

자주 바뀌는 줄을 위에 두면 아래 층이 매번 다시 만들어진다
```

## 관련 용어

- `docker-hub`
- `containerd-runc`
