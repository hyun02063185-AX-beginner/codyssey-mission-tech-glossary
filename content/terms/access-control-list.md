# ACL

## 한 줄 설명

주체별로 resource에 허용·거부할 작업을 나열한 권한 규칙.

## 쉽게 설명하면

주인·모임·나머지 세 부류만으로 나눌 수 없을 때, 특정 사용자 한 명에게만 따로 권한을 주는 목록입니다.

## 정확한 설명

기본 권한 비트 위에 사용자별·그룹별 규칙을 추가로 얹는다. 규칙이 있으면 `ls -l`의 권한 표시 끝에 `+`가 붙으며, 실제 허용 범위는 mask 값에 의해 더 좁아질 수 있어 표시된 규칙만 보고 판단하면 어긋난다.

## 이 미션에서는 왜 필요한가

이 회차에서 로그 파일을 특정 사용자 한 명에게만 열어 주고 싶을 때 쓸 수 있습니다. 그 사람을 위해 모임을 새로 만들지 않아도 되지만, 권한이 두 군데(기본 비트와 이 목록)에 나뉘어 있어 나중에 확인하기 어려워지는 대가가 있습니다.

## 코드 예

```bash
setfacl -m u:alice:r-- report.log    # alice 에게만 읽기 허용

ls -l report.log
# -rw-r-----+ 1 ubuntu ops ...        ← 끝의 + 가 추가 규칙이 있다는 표시

getfacl report.log
# user::rw-
# user:alice:r--
# mask::r--                           ← 실제 상한. 이보다 넓게는 못 준다

setfacl -b report.log                # 추가 규칙을 모두 지운다
```

## 주의할 점 / 경계 조건

기본 권한만 보면 실제 접근 가능 범위를 알 수 없습니다. `+` 표시가 있으면 전용 명령으로 따로 확인해야 합니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

여기에 허용으로 적으면 반드시 허용된다고 생각하기 쉽지만, mask 값이 그보다 좁으면 좁은 쪽이 적용됩니다. 규칙 목록과 실제 권한이 다를 수 있습니다.

## 동료평가 질문

파일 권한을 확인할 때 `ls -l` 만으로 부족한 경우가 언제인지, 그리고 그때 무엇을 더 보는지 설명할 수 있나요?
