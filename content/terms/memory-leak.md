# Memory Leak

## 한 줄 설명

더 이상 필요하지 않은 memory가 해제되지 않아 process 사용량이 계속 늘어나는 문제.

## 쉽게 설명하면

더 이상 안 쓰는 메모리를 돌려주지 않아 사용량이 계속 늘어나는 문제입니다. 늘기만 하고 줄지 않는 것이 특징입니다.

## 정확한 설명

참조가 남아 있어 회수되지 않는 메모리가 쌓인다. 정상적인 캐시 증가와 겉보기가 비슷하므로, 부하가 없는 구간에서도 사용량이 내려오지 않는지를 오래 관찰해야 구분된다. 한 번 찍은 값으로는 판정할 수 없다.

## 동작 원리

할당·참조·해제의 흐름을 따라 memory가 반환되지 않는 지점을 찾고, 사용량 추세와 process 종료 조건을 함께 관찰합니다.

## 이 미션에서는 왜 필요한가

이 회차가 다루는 메모리 고갈 장애의 원인 중 하나입니다. 사용량이 높다는 사실만으로는 이것인지 알 수 없고, 시간에 따른 변화를 봐야 하므로 점검 기록이 여기서도 판정 근거가 됩니다.

## 코드 예

```bash
# 한 시점의 값으로는 판정할 수 없다. 변화를 본다
while true; do
    date +%H:%M:%S
    ps -p "$PID" -o rss=,vsz=
    sleep 60
done >> /var/log/mem-trace.log

# 읽는 법
#   부하가 있을 때만 오르고 끝나면 내려온다  → 정상
#   부하가 없어도 계속 오르기만 한다          → 누수를 의심
#   톱니 모양으로 오르내린다                  → 가비지 컬렉션이 도는 중
```

## 주의할 점 / 경계 조건

재시작하면 증상이 사라지므로 해결된 것처럼 보입니다. 원인을 찾지 않으면 같은 주기로 반복됩니다.

## 관련 용어

- `process`
- `linux`

## 흔한 오해

메모리 사용량이 늘면 이 문제라고 생각하기 쉽지만, 캐시가 커지는 것일 수 있습니다. 캐시는 필요할 때 회수되지만 이 문제는 회수되지 않습니다.

## 동료평가 질문

캐시가 늘어난 것과 이 문제를 구분하려면 무엇을 얼마나 오래 관찰해야 하는지 설명할 수 있나요?
