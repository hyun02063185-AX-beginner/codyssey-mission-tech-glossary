# Refresh Token

## 한 줄 설명

짧은 access token이 만료된 뒤 새 access token을 받는 데 쓰는 장기 자격 증명.

## 쉽게 설명하면

수명이 짧은 표식이 만료됐을 때 새것을 받아 오는 데 쓰는 긴 수명의 표식입니다. 자주 쓰이지 않고 한곳에만 보관됩니다.

## 정확한 설명

짧은 접근 토큰과 짝으로 쓴다. 접근 토큰이 만료되면 이것을 제시해 새 접근 토큰을 받으며, 이 과정에서 서버가 저장소를 조회하므로 폐기가 가능하다. 사용할 때마다 새것으로 교체하면(rotation) 탈취된 것이 재사용될 때 탐지할 수 있다.

## 이 미션에서는 왜 필요한가

이 회차에서 토큰 인증을 쓸 때, 접근 토큰의 수명을 짧게 잡으면 사용자가 자주 다시 로그인해야 하는 문제가 생깁니다. 그 불편을 없애면서도 탈취된 토큰의 유효 기간을 짧게 유지하는 방법이 이 구조입니다.

## 코드 예

```text
접근 토큰 (access)          재발급 토큰 (refresh)
  수명   15분 안팎                 2주 안팎
  용도   매 요청에 실어 보낸다      만료됐을 때만 쓴다
  보관   메모리                     HttpOnly 쿠키
  폐기   불가 (만료를 기다린다)     서버 저장소에서 지운다

재발급 때마다 새것으로 바꿔 준다.
이미 쓴 것이 다시 들어오면 탈취를 의심하고 전부 폐기한다.
```

## 주의할 점 / 경계 조건

이 값이 새어 나가면 접근 토큰을 계속 새로 발급받을 수 있습니다. 접근 토큰보다 더 엄하게 보관해야 하며, JavaScript가 읽지 못하는 쿠키에 두는 것이 일반적입니다.

## 관련 용어

- `authentication`
- `authorization`
- `security-group`

## 흔한 오해

두 개를 쓰니 더 안전하다고 생각하기 쉽지만, 긴 수명의 값을 하나 더 만드는 일이기도 합니다. 안전해지는 것은 이 값을 접근 토큰보다 잘 지켰을 때뿐입니다.
