# HTTP 80

## 한 줄 설명

암호화하지 않은 HTTP service가 관례적으로 사용하는 TCP port 80.

## 쉽게 설명하면

암호화하지 않은 웹 접속에 쓰는 번호입니다. 주소창에 포트를 안 적으면 이 번호로 갑니다.

## 정확한 설명

암호화되지 않은 웹 서비스의 기본 포트다. 브라우저가 이 포트로 보낼 때 주소창에는 번호가 표시되지 않으며, 오가는 내용이 평문이라 중간에서 읽힐 수 있다. 실제 서비스에서는 여기로 온 요청을 암호화된 포트로 넘기는 용도로만 쓰는 것이 보통이다.

## 이 미션에서는 왜 필요한가

이 회차에서 브라우저로 접속하려면 열어야 하는 문입니다. 접속 포트와 달리 이쪽은 누구나 들어올 수 있어야 하므로 전체에 여는 것이 맞는데, 그 차이가 방화벽 규칙을 판단하는 기준이 됩니다.

## 코드 예

```bash
# 서비스가 실제로 그 포트에 묶여 있는지 먼저 확인한다
ss -tlnp | grep :80

# 밖에서 닿는지 확인
curl -I http://<공인IP>/
# HTTP/1.1 200 OK        ← 방화벽과 서비스가 모두 정상
# (응답 없음)            ← 방화벽 또는 경로 문제
# Connection refused     ← 방화벽은 통과했는데 서비스가 없다

# 실제 서비스에서는 여기로 온 것을 443 으로 넘긴다
# return 301 https://$host$request_uri;
```

## 주의할 점 / 경계 조건

여기로 오간 내용은 암호화되지 않습니다. 로그인 폼을 이 포트로만 열어 두면 비밀번호가 평문으로 지나갑니다.

## 관련 용어

- `http`
- `tcp`

## 흔한 오해

80번을 열었는데 접속이 안 되면 방화벽 문제라고 생각하기 쉽지만, 서비스가 그 포트에 묶여 있는지도 확인해야 합니다. 열린 문과 그 안에 사람이 있는 것은 다릅니다.
