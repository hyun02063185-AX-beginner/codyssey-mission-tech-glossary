# TTL

## 한 줄 설명

cache나 record가 유효한 것으로 취급되는 제한 시간.

## 쉽게 설명하면

값이 유효한 시간의 길이입니다. 그 시간이 지나면 더는 쓰지 않습니다.

## 정확한 설명

값에 부여하는 유효 기간이다. 기간이 지났다고 즉시 지워지는 것은 아니고, 꺼내 볼 때 확인하거나 주기적으로 훑어 치우는 방식이 쓰인다. 그래서 지난 값이 아직 메모리에 남아 사용량에 잡히는 상태가 존재한다.

## 동작 원리

값을 넣을 때 만료 시각을 함께 적어 두고, 꺼낼 때 지금 시각과 견주어 지났으면 없는 것으로 처리합니다. 실제 저장소는 여기에 더해 주기적으로 훑어 만료된 것을 치우기도 하는데, 그래서 "지났다"와 "지워졌다"가 같은 순간이 아닙니다.

## 이 미션에서는 왜 필요한가

본과정 M09에서 저장한 키를 일정 시간 뒤에 스스로 사라지게 하는 기능입니다. 캐시에 둔 값은 언젠가 낡으므로 지울 시점을 미리 정해 두는 것이고, 만료 처리를 직접 구현할 때는 이 값을 무엇으로 관리할지가 설계 문제가 됩니다.

## 코드 예

```python
store[key] = (value, time.time() + ttl_seconds)

def get(key):
    value, expires_at = store[key]
    if time.time() >= expires_at:
        del store[key]
        return None          # 만료된 것은 없는 것과 같다
    return value
```

## 주의할 점 / 경계 조건

기간이 지난 것과 지워진 것은 다릅니다. 사용량을 볼 때 이 차이를 모르면 숫자를 잘못 읽습니다.

## 관련 용어

- `cache`
- `expiration-timestamp`

## 흔한 오해

만료 시간이 지나면 그 순간 사라진다고 생각하기 쉽지만, 대부분의 구현은 꺼내 볼 때 또는 주기적으로 확인할 때 치웁니다. 지났다는 것과 지워졌다는 것은 다릅니다.
