## 기존 문제와 변경

기존에는 기초 보강, 정적 상세 구조도, 패킷 애니메이션이 한 장면에 모여 강사가 설명의 순서를 잡기 어려웠다. 이제 한 번에 하나의 주제를 설명하고 이전·다음 버튼으로 넘긴다. 기존 장면 ID와 URL, 용어 링크 및 개념지도 복귀를 유지하기 위해 AWS 대응과 마무리를 각각 별도 장면으로 남겨 총 8장으로 구성했다.

1. **왜 네트워크를 다시 배우나** — B3-1의 목적과 학습 목표
2. **네트워크 기초** — IP, 공인·사설 IP, 네트워크와 서브넷
3. **패킷과 프로토콜** — 출발지·목적지, 포트, IP·TCP·HTTP와 연결선의 의미
4. **전체 연결망** — PC, 공유기, 인터넷 라우터, DNS, 회사 경계, 방화벽/NAT, 웹 서버의 위치
5. **패킷의 여행** — 기존 26단계 애니메이션 직접 시연
6. **AWS에서 다시 보기** — VPC, Subnet, Route Table, IGW의 역할
7. **AWS 접근 조건** — Security Group과 EC2 + Nginx의 역할
8. **내 말로 설명하기** — 확인 질문과 개념지도 연결

전체 연결망은 기존 애니메이션과 같은 노드·연결 데이터를 사용한 개요로 표시한다. 기존 웹 요청·응답 상세 구조도와 원본 전체망·AWS 그림은 필요한 경우 펼치는 보충 자료로 축소했다. 따라서 기본 강의에서는 상세 흐름을 정적 그림과 애니메이션으로 중복 설명하지 않는다. 기존 SVG 원본과 AWS 비교의 핵심 설명은 보존한다.

패킷 애니메이션을 독립 슬라이드의 중심에 두어 강사가 한 단계씩 라우터의 목적지 IP 기반 경로 선택, NAT 전후 주소 변화, DNS와 HTTP의 차이를 설명할 수 있다. 처음에는 자동 재생하지 않으며, 기존 기업망 보강 자료에서도 같은 `PacketJourney`를 독립적으로 사용할 수 있다. 장면 이동 시 컴포넌트가 해제되어 재생 타이머가 정리된다.

## 강의 진행

목적과 주소·서브넷을 짧게 소개한 다음 패킷과 프로토콜을 설명한다. 전체 연결망에서 장비 위치를 확인하고, 다섯 번째 장면에서 직접 단계를 진행하며 DNS 요청·응답, NAT, 라우팅과 HTTP 흐름을 살펴본다. 이어서 일반 네트워크 원리를 AWS 구성과 접근 조건에 대응시키고 마지막 질문으로 학습자가 자신의 말로 정리한다. 상세 근거는 각 장면의 보충 자료, 용어 링크, 강사용 안내에서 확인할 수 있다.

## 검증 결과

- `PYTHONUTF8=1 npm test`: 41개 파일, 509개 테스트 통과.
- `PYTHONUTF8=1 npm run build`: TypeScript와 프로덕션 빌드 통과. 기존 Vite 청크 크기 경고는 남아 있다.
- Playwright: 프로덕션 빌드에서 슬라이드, 메인·기업망 가이드의 패킷 여행 관련 21개 테스트 통과. 26단계, 라우팅·NAT, 한 단계 진행, 재생·일시정지, 초기화, 장면 이탈과 reduced motion을 확인했다. 이후 마무리 슬라이드의 지도 링크를 추가하고 최종 빌드에서 슬라이드 5개 테스트를 다시 통과했다.
- PC 1280px과 모바일 390px, Light/Dark에서 순서와 왕복 이동, 기존 주소, 개요 요소, 가로 넘침 및 최초 정지 상태를 확인했다. 기존 SVG·기초 카드·테마 관련 추가 회귀 6개와 기존 스토리·지도 왕복 회귀 4개도 통과했다.
- `npm run mission:ui-check`: 12개 상태, 156개 검사 통과. `git diff --check` 통과.
- 기존 PacketJourney 구현, 기업망 가이드, 원본 SVG와 개념지도 데이터는 선행 구현 기준으로 변경하지 않았다.

슬라이드 5는 1280px과 390px 모두 세로 스크롤이 필요하며, 스크롤 후에도 다음 장면으로 이동할 수 있도록 하단 탐색을 제공한다. 실제 수강자 대상 학습 효과, 실기기 모바일, Safari/Firefox, 스크린리더 및 배포 환경은 이번 검증 범위에 포함되지 않았다. 독립 GPT 검토와 Owner의 강의 화면 확인은 남아 있다.
