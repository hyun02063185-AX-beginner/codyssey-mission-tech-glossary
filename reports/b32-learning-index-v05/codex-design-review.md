## 제안

- **판별 진입점과 회귀 경계.** `b32-v05` 조건의 지연 로딩에서 Story·Lab·용어 복귀에 같은 v0.5 lesson을 넘긴다. v0.4용 판별 플래그는 유지하고 SVG와 Lab 렌더링처럼 두 통합판이 공유하는 동작만 별도 조건이나 기존 props로 활성화한다. 공개 앱의 공용 컴포넌트에는 새 원고·JSON·CSS를 정적으로 import하지 않는다. Vite 빌드 검증은 해당 판의 파서로 실행한다. Playwright는 v0.5 기본 포트 4176, 기존 서버 재사용 끄기, 명시한 `PLAYWRIGHT_PORT` 우선으로 등록한다. [라우트 선택](../../src/App.tsx#L55) · [Vite 설정](../../vite.config.ts#L9) · [Playwright 설정](../../playwright.config.ts#L1)

- **파서와 주소.** Markdown AST 읽기는 재사용하고 판별 프로필 또는 별도 진입 함수로 제목·Scene 표·화면 수·ID 검사·도식 상태만 분리한다. v0.4의 연속 번호 검사와 I1–I10 타입 및 허용 상태를 보존한다. v0.5는 제목에서 문자열 ID를 읽고 Scene 일치, 중복, 번호의 수치 순서, 기본 화면 뒤 연속 접미사 구간을 검증한다. 화면 위치는 배열 인덱스로 계산한다. `screenHref`·`readStoryState`·통합 Lab 함수에는 활성 판의 화면 목록을 전달한다. v0.3 전용 숫자 검사와 K 매핑은 유지한다. S4-5a(S4-5b도 같은 방식)의 용어 링크에서 `b32-story` 왕복을 확인하고, `?from=S4-5b` → Lab → `from-lab` 및 Lab → 용어사전 → Lab의 `b32-lab` 왕복도 확인한다. `screen=5c`는 기존 복구 함수대로 S4-1이고, v0.4에서는 `5a`·`5b`도 복구 대상이다. [설계 §7](../../content/mission-stories/main-m06/design-v0.5.md#7-scene-4-흐름과-주소-호환-작업-d) · [기존 Lab 계약](../../content/mission-stories/main-m06/handover-v0.4.md#5-lab-연동)

- **도식과 근거 데이터.** 기존 I3 및 I5의 `git/http/program`은 기존의 증거 자료로 렌더링한다. v0.5의 I4 분기와 S3-5의 I5 `git-cases`, I11, I12만 판별 도식에서 처리한다. I4는 파싱된 S3-4 실습 결과에서 ①·②를, R11에서 ③과 PIPE 동등성을 읽는다. I5는 S3-5의 결과 블록을 네 사례로 읽고 `returncode`·`stdout`·`stderr` 및 명령의 네 필드를 검증한다. `''`와 이스케이프된 줄바꿈은 원문 표기를 보존한다. I11은 GFM 표 AST로 후보와 1.0 열을 읽고 0.2·2.0 열은 기대값으로 사용한다. I12는 JSON의 `total_units`와 조각 끝 오프셋으로 잘린 글을 계산하고 `results[n]`과 R9 P4·P5의 기존 판정 문구를 사용한다. 정적 표·실습 블록은 각 원고의 보조 자료로 같은 데이터에서 렌더링한다. 인덱스·로드맵·위치 띠도 파싱된 Scene·화면 목록, 순서, 주소를 함께 사용한다. 로드맵과 공통 Scene 카드의 목적지와 제목을 일치시키고 6개 질문·목표의 별도 `dl`을 제거한다. [인수인계 §4–5](../../content/mission-stories/main-m06/handover-v0.5.md#4-학습-인덱스-구현) · [R9 기존 판정 추출](../../src/b32Story/integratedEvidence.ts#L53)

- **레이아웃과 상태.** 왼쪽 인덱스를 `.b32-deck` 바깥의 형제로 두고, v0.5를 표시하는 바깥 요소의 `data-*` 상태로 열 크기와 배치를 바꾼다. 덱 안의 P 배치는 기존 규칙을 재사용한다. 닫혔을 때 바깥 래퍼에 남는 열·간격을 없애고, 1240px 이상에서는 56px 레일 또는 전체 열만 차지하게 한다. 레일 위 오버레이와 drawer는 문서 폭을 늘리지 않게 하고 P와 학습자료 메뉴의 쌓임 순서를 확인한다. 슬라이드 쪽은 `minmax(0,1fr)` 및 실제 가용 폭에 따른 버튼 줄바꿈·도식 내부 1열 전환을 적용한다. I5 비교·I11 비교·I12 결과는 좁은 공간에서 순서대로 쌓고 긴 로그와 표는 이름 있는 내부 스크롤로 처리한다. 한 번 배치한 `.b32-integrated-material`과 `.b32-review`의 부모·요소 타입·`screen.id` 키를 유지한다. 열림 상태·화면 폭·`location.key`를 이 키에 섞지 않는다. I7 값과 JSON 변화, 실습·정답 펼침, I11 비교 상태, I12 값과 재생 중 상태를 같은 화면에서 확인하고 다른 ID로 이동했을 때 초기화를 확인한다. [기존 본문 트리](../../src/b32Story/B32Story.tsx#L206) · [도식·표 CSS](../../src/b32Story/b32Integrated.css#L48)

- **초점과 키보드.** 지속되는 데스크톱 열·레일과 일시적으로 열리는 모바일 모달 상태를 구분한다. 데스크톱 열림만 저장하고, 폭 전환·위치 변경으로 drawer가 닫힐 때 저장값을 건드리지 않는다. drawer는 발표 변수의 상속 범위 안에서 네이티브 `dialog.showModal()`을 쓰거나 동등하게 초점 가두기·뒤 UI 비활성화·배경 스크롤 차단을 제공한다. 제목은 `tabIndex={-1}`로 열릴 때 초점을 받고, 닫기·배경·Esc는 실제 열기 버튼으로 돌려보낸다(레일 오버레이는 레일 버튼). 이동이나 뒤로 가기에서는 drawer를 닫고 새 화면 제목에 초점을 둔다. 현재 화면 링크를 골라도 모달을 닫고 제목으로 이동한다. P와 Esc는 한 이벤트에서 한 패널만 처리한다. drawer 동안 P를 무시하고, 인덱스에 초점이 있는 Esc는 인덱스를 닫으며, 나머지 P 동작은 기존 규칙을 따른다. 패널 스크롤만 조정하고 화면 전체의 `scrollIntoView`는 피한다. Scene별 고유 `aria-controls`·현재 화면 텍스트와 `aria-current`·44px 목표 크기·두 테마의 키보드 초점 표시를 확인한다. [설계 §3.2](../../content/mission-stories/main-m06/design-v0.5.md#32-상시-학습-인덱스-패널-a-4)

- **재생과 음성 안내.** I12는 재생 전 한도·추론 가정에 해당하는 결과를 보여 주고, 재생 중 한도나 가정을 바꾸면 타이머를 취소하고 새 결과를 표시한다. `n=0`이나 축소 동작 설정에서는 즉시 결과를 표시하고, 화면 이동·언마운트 시 타이머를 정리한다. 공용 `Diagram`에는 선택형 도식 본문 전체를 읽는 live 영역이 있으므로, I11·I12는 요약 한 곳만 알리도록 v0.5 렌더링에서 범위를 조정한다. I12의 40ms 간격 텍스트는 시각적으로만 갱신하고 시작과 최종 상태를 요약한다. ## 질문

1. **S3-4 출력 상속.** “출력 통로를 따로 지정하지 않으면 Git이 Python의 통로에 직접 쓰고, `a.stdout`·`a.stderr`는 `None`이며 `a.returncode`는 남는다”는 뜻으로 핵심 메시지·해설·이해 확인을 맞출 수 있을까? v0.5 도식의 R6 발췌에서도 해당 주석을 같은 뜻으로 표현하고, ③은 stdout 리다이렉션만 설명하는 것을 제안한다.
2. **I12 추론과 결과 단계.** 가정값 30은 안내에 남기고, 막대의 실제 가정 소비량은 `min(한도, 30)`, 보이는 글은 `min(total_units, max(0, 한도 − 30))`로 표시해도 될까? 한도 57(추론 끔)은 “답변 완성 · 한도와 같은 양”, 한도 30 이하(추론 켬)의 `results[0]`은 “응답 처리에서 거부 · PR 형식 검사 전”으로 제안한다. 확인 사례는 한도 20·30·31·80(추론 켬)과 57·80(추론 끔)이다.
3. **I12의 50자 권장.** 두 제한 표의 Python 검사 칸은 72자·80자·섹션·불릿으로 구성하고, 커밋 제목 50자는 프롬프트 권장이라는 별도 주석으로 표시하도록 해설과 설계 §5를 맞출 수 있을까?
4. **1280×720 위치 띠.** 기존 관점 띠의 자리를 유지하면서 위치 요약 한 행과 인덱스 버튼에 필요한 높이를 허용할까? 인덱스나 P를 열어 본문이 좁아질 때는 뷰포트가 900px 이상이어도 본문 폭에 따라 위치 띠를 번호 중심으로 접고 요약 텍스트는 줄바꿈하는 것을 제안한다.
5. **인트로 로드맵 테마.** 로드맵은 공통 인트로와 같은 사이트 변수, 강의 중 인덱스·위치 띠는 발표 변수를 쓰도록 설계 §3.4의 적용 범위를 정리할 수 있을까?
