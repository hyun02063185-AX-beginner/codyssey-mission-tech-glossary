## 3. 렌더링을 눈으로 확인

미리보기: `preview/desktop-1280.png`, `preview/desktop-900.png`, `preview/mobile-390.png`, `preview/mobile-360.png`(2배), 검토 페이지 `preview/index.html`.

| 확인 항목 | 결과 |
| --- | --- |
| 핵심 흐름이 가장 두드러지는가 | 요청(초록 실선)과 응답(갈색 점선)이 맨 위 한 줄에 모여 있다. 이번에 쓰지 않는 구역은 흐리게 처리했다 |
| 요청·응답 구별 | 색, 선 모양(실선/점선), 표식 모양(동그라미/네모), 글자(A/R) 네 가지로 구별된다 |
| 장비·경계와 화살표의 겹침 | 없음. 응답 차선은 회색 선 아래 22단위(노트북) / 왼쪽 18단위(휴대전화) |
| 구름 접촉 | A1·A2·R4·R5와 회색 선이 구름 외곽에 닿는다(자동 검사 + 화면 확인) |

| 4·5 순서 단정 금지 | 방화벽 안에 "4·5의 처리 순서는 장비·정책마다 다름"이 있고, 두 단계 사이에 화살표가 없다 |
| 휴대전화용 길이 | 390px 화면에서 약 2,620px(화면 약 3.5장). 범례 1장, 그림 2장, 카드·각주 1장 |
| 색만으로 구별하지 않는가 | 구역(번호·이름), 흐름(선 모양·표식 모양·글자), 흐림(범례 설명) |

## 4. 교육·기술 품질 — **사용자 검증 대기**

실제 교육생 시험은 하지 않았다. 아래는 근거가 그림 어디에 있는지만 확인한 것이다.

| 학습 질문 | 그림 속 근거 | 결과 |
| --- | --- | --- |
| 라우터가 필요한 이유는? | 단계 3, 카드 "도착 주소로 다음 길 선택", 경로표 예 | 사용자 검증 대기 |
| 방화벽이 있어도 경로 설정이 필요한 이유는? | 카드 3 "허용 여부는 판단 안 함" ↔ 카드 4. 방화벽에도 "구역 사이 길 안내" 이름표 | 사용자 검증 대기 |
| NAT와 보안 정책은 어떻게 다른가? | 카드 5 "허용·차단은 안 함" ↔ 카드 4 | 사용자 검증 대기 |
