## 2. 단계별 검증

| 단계 | 그림의 표현 | 판정 |
| --- | --- | --- |
| 1 요청 시작 | 브라우저가 공개 주소(203.0.113.10)로 HTTPS 443 요청. 주소는 이미 앎(DNS 생략) | 정확. 지시서 §3대로 DNS 생략을 표시했다 |
| 2 회사 경계 도착 | 인터넷을 지나 경계 라우터 | 정확. 인터넷 안 경로는 구름 하나로 단순화했다 |
| 3 경로 선택 | 도착 주소로 다음 길 선택. 경로표 예 `203.0.113.0/24 → 방화벽 쪽`. 방화벽도 구역 사이 길 안내. "허용 여부는 판단 안 함" | 정확. 경로 선택과 허용 판단을 분리했다(§5-1·2). 경로표 한 줄은 설명용 예시이며 실제 구성(전용 연결 구간, 정적·동적 경로)은 기업마다 다르다 |
| 4 허용 판단 | 규칙: 인터넷 → 웹 서버, HTTPS 443 허용. 맞으면 통과·연결 기록, 없으면 차단 | 정확(§2.1.2 상태 추적). "연결 기록"은 상태표 항목 추가를 쉬운 말로 옮긴 것이다 |
| 5 주소 변환 | 미리 설정한 규칙대로. 요청 도착 `203.0.113.10 → 172.16.10.10`, 응답 출발 `172.16.10.10 → 203.0.113.10`. 허용·차단은 안 함 | 정확. 외부에서 사설 주소의 서버로 가는 것은 사전 설정 규칙을 전제로 했다(§5-4). NAT가 접근 정책을 대신하지 않는다고 적었다(§5-3) |
| 4·5의 순서 | 방화벽 안 "4·5의 처리 순서는 장비·정책마다 다름". 두 단계 사이에 화살표 없음 | 정확(§3). 번호는 설명 순서라고 그림·목록·각주 세 곳에 적었다 |
| 6 웹 서버로 전달 | 방화벽 DMZ 쪽 → 스위치 → 웹 서버(A4·A5) | 정확 |
| 7 응답 만들기 | 웹 서버가 홈페이지 내용을 응답 | 정확. DB 조회는 다른 장면이라고 각주에 적어 기본 경로와 구분했다(§5-9) |
| 8 방문자에게 | R1~R5. 허용된 연결의 응답이라 통과. NAT가 출발 주소를 되돌림. 웹 서버가 새 연결을 먼저 시작할 수 있다는 뜻이 아님. 돌아가는 경로는 기업망마다 다를 수 있음 | 정확(§5-7·8). 이 예시는 경계 장비가 하나라 요청과 같은 장비를 거꾸로 지난다 |

## 3. 지시서 §5 기술 조건 점검

| 조건 | 결과 |
| --- | --- |
| 방화벽과 라우터 역할 혼동 금지 | 지켰다. 라우터에는 "경로 선택"만, 방화벽에는 "허용·차단 판단"과 "구역 사이 길 안내"를 두었다 |
| 경로 선택 ≠ 연결 허용 | 지켰다. 카드 3 "허용 여부는 판단 안 함", 카드 4는 별도 |
| NAT ≠ 접근 정책 | 지켰다 |
| 사설 IP 서버로의 외부 연결은 사전 설정 규칙 전제 | 지켰다 |
| 라우터·방화벽·NAT는 복합 장비일 수 있음 | 지켰다. NAT를 방화벽 장비의 기능 이름표로 그렸다(Scene 01 각주 계승). Scene 02 그림에는 이 각주를 반복하지 않았다(Owner 판단 사항) |
| 연결선 ≠ 통신 허용선 | 지켰다. 회색 선 "통신 허용 아님" |
| 상태 추적 응답 ≠ 양쪽 자유 연결 | 지켰다(각주, 휴대전화 카드 8) |
| 왕복 경로 동일 단정 금지 | 지켰다 |
| DB 조회·직원 게시와 구분 | 지켰다. 해당 구역을 흐리게 하고 각주를 달았다 |
| 일반 기업망 예시이며 B3-1과 다름 | 지켰다. 부제·각주와 HTTPS 443 / HTTP 80 구분 |

## 4. 단순화한 부분

| 단순화 | 드러나는 곳 |
| --- | --- |
| DNS 생략 | 단계 1, 각주 |
| 인터넷 = 구름 하나 | 관례적 표현(표시 없음) |
| 경로표 한 줄 | "경로표 예" |
| 4·5 순서 | 방화벽 안 문구, 각주 |
| TLS가 어디서 끝나는지, 포트 번호 변환(출발 포트) | 표시하지 않음. 출발 포트 변환은 이 흐름(목적지 주소 변환)과 다른 경우다 |
| 응답 경로가 요청과 같은 장비를 지남 | 단계 8 "기업망마다 다를 수 있음" |
