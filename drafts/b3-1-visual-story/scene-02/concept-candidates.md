# Scene 02 개념지도 후보 — 핵심 개념과 관계

> 개념지도 자체는 만들지 않았다. Scene 01·02 그림에 **실제로 등장한** 개념과 관계만 후보로 적었다. 기존 지식지도·용어사전 데이터는 읽기만 했고 수정하지 않았다.

## 관계 유형 사용 기준

| 유형 | 이 문서에서의 뜻 | 쓰지 않는 경우 |
| --- | --- | --- |
| 포함 | A 안에 B가 놓인다(구역 ⊃ 장비, 회사망 ⊃ 구역) | 기능의 포함은 "역할"로 쓴다 |
| 선행 | **학습상** A를 먼저 이해해야 B를 이해하기 쉽다 | 패킷이 먼저 지나가는 동작 순서는 "흐름"으로 쓴다 |
| 역할 | 장비 A가 기능 B를 맡는다 | — |
| 흐름 | 통신이 A에서 B로 이동한다(요청·응답) | 학습 순서는 "선행" |
| 대응 | 서로 다른 체계의 A와 B가 같은 자리를 맡는다(공인 ↔ 사설 주소, 일반망 ↔ AWS) | 단순 비교·대조 |
| 연관 | 위 다섯이 아니지만 함께 이해해야 하는 관계(판단 기준, 구분해야 하는 짝) | — |

확인 여부: **확인** = 근거 자료(NIST SP 800-41 Rev.1 등)와 대조함. **설명용** = 이 예시의 설정값이며 일반 사실이 아님. **제안** = 학습 설계상의 판단이며 기술 사실 확인 대상이 아님.

## 3. 넣지 않은 관계와 이유

| 후보 | 이유 |
| --- | --- |
| DNS → 요청 시작 | 그림에서 생략했다. 넣는다면 학습상 "선행"이 아니라 동작상 "흐름"(이름 → 주소 → 요청)이다 |
| 경계 라우터 → 방화벽 → 웹 서버를 "선행"으로 표시 | 패킷이 지나는 순서는 흐름이지 학습 선행이 아니다 |
| 방화벽 → NAT 순서 | 처리 순서는 장비마다 다르다. 순서 관계로 고정하지 않는다 |
| 일반 장비 ↔ AWS 자원(라우터 ↔ Route Table, NAT ↔ IGW, 방화벽 ↔ Security Group) | 이번 장면에 그리지 않았다. AWS 비교 장면에서 "대응"으로 다시 검토한다 |
| HTTP 80(B3-1) ↔ HTTPS 443(예시) | 대응이 아니라 **사례 구분**이다. 개념 관계로 넣지 않는다 |
| 웹 서버 → DB 조회 | 이번 장면의 흐름이 아니다(Scene 03 후보) |
