## 2. 03-A 구조·역할 비교

**질문:** 일반 기업망에서 하던 일을 AWS에서는 무엇이 맡을까?

| 남긴 것 | 줄인 것 |
| --- | --- |
| 일반망 구역 1~5와 주요 장비(Scene 01 요약), B3-1 AWS 구조(리전 ⊃ VPC ⊃ Public Subnet ⊃ EC2, EC2에 연결된 ENI와 EC2에서 실행한 Nginx, VPC 경계의 IGW, VPC 안의 Route Table·SG). ENI를 EC2 상자 안에 그린 것은 "EC2의 네트워크 카드"를 보여 주는 단순화이며 포함 관계가 아니다(개념지도 AW03: 연결) | 구역 4·5의 장비 상자와 스위치 → 머리글 한 줄과 장비 이름 한 줄(흐림) |
| 비교선 6개와 "≈" 알약 | 1차의 "VPC와 인터넷 연결" 라벨, IGW 설명 줄 → 짧게 |
| 주의 카드 4장 | 비교선마다 붙던 주의 문장(휴대전화 카드) → 주의 카드로 모음 |
| B3-1에서 구현하지 않음 상자 | 웹 접속 흐름·조건표 → 03-B로 이동 |

**비교선 6개 (`COMPARE_R1`).**
- 회사 네트워크 ≈ VPC (네트워크 영역)
- 방화벽의 NAT ≈ IGW의 1:1 IPv4 변환 (주소 변환)
- 구역 사이 길 안내 ≈ Route Table (경로 결정)
- 허용·차단 판단 ≈ Security Group (접근 통제)
- 공개 웹 서버 ≈ EC2 + Nginx (웹 서버)
- 구역마다 서브넷 ≈ Subnet (주소 구역 분리)

노트북용에서 "구역마다 서브넷"은 구역 3~5 오른쪽의 **보라 괄호 막대**로 표시했다. 구역 3~5 머리글에 서브넷 주소를 적어, 막대가 무엇을 가리키는지 보이게 했다. 웹 서버 비교선이 지나는 자리는 막대를 비워 선끼리 겹치지 않는다.

**직접 비교선에서 뺀 관계.**
- 경계 라우터 ↔ IGW: 경계 라우터에서는 비교선이 나가지 않는다. 주의 카드 "경계 라우터 ≠ IGW"가 IGW는 연결 구성요소이고 경로는 Route Table이 정한다고 설명한다.
- DMZ ↔ Public Subnet: DMZ 구역에서는 비교선이 나가지 않는다. 주의 카드 "DMZ ≠ Public Subnet"이 두 정의를 나란히 적는다.

**주의 카드 4장 (`CAUTIONS`):** 경계 라우터 ≠ IGW · DMZ ≠ Public Subnet · Route Table ≠ Security Group · 1:1 변환 ≠ NAT Gateway(IGW가 Public IPv4 ↔ ENI의 Private IPv4를 1:1로 바꿈, NAT Gateway는 별도 AWS 서비스).

**휴대전화용:** 맨 위에 "일반 기업 네트워크 전체 구조(구역 1~5)는 Scene 01 그림에서 봅니다"를 두고, 그다음 AWS 구성 → 미구현 상자 → 비교 카드 6장 → 주의 카드 4장 순서로 읽는다.

## 3. 03-B 웹 접속 조건

**질문:** B3-1에서는 어떤 설정이 함께 있어야 방문자가 웹사이트에 접속할 수 있을까?

| 표현 | 뜻 |
| --- | --- |
| 초록 화살표 W1~W4 | 요청이 실제로 이동하는 길: 방문자 → 인터넷 → IGW → EC2의 ENI → Nginx. 식별자 W는 Scene 02의 응답 R1~R5와 겹치지 않게 정했다. 1차 통합형 B 부분의 B3-1 요청 W1~W4와 같은 뜻이다 |
| 회색 점선 | 설정이 연결·적용된 곳: Route Table → Public Subnet(연결), Security Group → ENI(적용) |
| 숫자 원 ①~⑥ | 필요한 설정. 그림의 해당 요소 모서리와 아래 카드에 같은 번호 |

- **Route Table과 SG는 요청 경로 위에 놓지 않았다.** 둘 다 VPC 안 위쪽의 설정 카드이며, 초록 화살표는 그 카드를 지나지 않는다(검사기 확인). SG는 "ENI에 적용", Route Table은 "Subnet에 연결" 점선으로만 이어진다.
- IGW는 VPC 경계선 위에 걸쳐 그렸다. 요청은 실제로 IGW를 거쳐 VPC로 들어오므로 화살표가 IGW를 지난다(AWS 문서: IGW가 목적지 주소를 Private IPv4로 바꿔 VPC로 전달).
- 필요한 설정 ①~⑥은 지시서 §3의 1~6에 맞췄다: ① 요청 ② IGW 연결 ③ 경로와 Subnet 연결 ④ Public·Private IPv4 ⑤ SG를 ENI에 적용 ⑥ Nginx HTTP 80.
- 일반망 요청·응답 흐름은 그리지 않았다. "응답은 같은 연결의 반대 방향(Scene 02)", "B3-1은 HTTP 80만, 일반망 예시는 HTTPS 443"을 각주 한 줄씩으로 남겼다.
