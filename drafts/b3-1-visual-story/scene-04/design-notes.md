# Scene 04 설계 노트 — 핵심 개념지도

> 미션 스토리맵 · B3-1 · 마지막 장면. 상태: **시안(Owner 시각 검토 전)**. 기준: Scene 03 정합성 패치 `fd4af2b`. 원본 데이터는 `concept-map.json` 한 파일이며, SVG 두 장은 이 데이터를 읽어 생성한다.

## 1. 질문과 중심 개념

**질문:** B3-1에서 내가 만든 웹사이트는 어떤 기술들이 서로 연결되었기 때문에 인터넷에서 열릴 수 있었을까?

**중심:** VPC 안의 배치(영역 A)와, 그 배치에 인터넷 요청이 닿게 하는 연결·설정(영역 B)이다. 일반망에서 배운 세 역할(영역 C)은 왼쪽 비교 영역에서 이어 본다.

## 2. 노드·관계 최종 선정

| | Scene 03 후보(`fd4af2b`) | Scene 04 |
| --- | --- | --- |
| 노드 | 14 | **14(변경 없음)**. 인터넷은 노드가 아니라 C12 흐름 경로의 표시(`@internet`)로만 둔다 |
| 관계 | 15(포함 3 · 연관 8 · 흐름 1 · 대응 3) | **15(변경 없음)**. 끝점·유형·설명 문장이 후보와 글자 그대로 같다(`_tools/check_data.py`로 대조) |
| 학습 순서 | L1~L3 | 관계 그래프 밖의 `learningOrder`로 따로 둔다. 그림에서는 C 영역 아래 "학습 순서(지도 밖)" 상자 |

화면 표시용 이름(label)만 새로 정했다. 예를 들어 C3는 "연결", C7은 "경로 대상", C11은 "1:1 짝"이다. 관계 설명(description)은 바꾸지 않았다.

## 3. 영역 배치

| 영역 | 노드 | 그림에서 |
| --- | --- | --- |
| **A 네트워크 안에 무엇이 있나** | VPC, Subnet, EC2, ENI, Nginx, Private IPv4 | VPC 영역 ⊃ Subnet 영역 ⊃ EC2 영역 ⊃ Nginx. ENI·Private IPv4는 Subnet 안의 노드 |
| **B 인터넷에서 어떻게 닿나** | 외부 방문자, IGW, Public IPv4, Route Table, Security Group | 방문자·Public IPv4는 VPC 밖 위쪽. IGW는 VPC 경계에 걸침. Route Table·SG는 VPC 안 왼쪽의 "설정" 노드 |
| **C 일반망에서 배운 역할** | 경로 선택, 접근 통제, 주소 변환 | 왼쪽 별도 영역. 각 역할이 대응하는 AWS 노드와 같은 높이에 있어 대응선이 짧고 수평이다 |

Route Table·Security Group은 B(접속을 가능하게 하는 설정)에 속하지만 그림에서는 VPC 영역 안에 놓았다. 둘 다 VPC에 속한 설정이기 때문이다(Scene 03-B와 같음). 대신 노드 색을 "설정(규칙)"으로 구분했다.

## 4. 관계 시각화

| 유형 | 표현 | 이유 |
| --- | --- | --- |
| 포함 (C1·C2·C4) | **영역 겹침** + "VPC 안에 포함" 같은 표식 | "영역에 속하는 관계"를 그대로 보여 준다. 선으로 그리면 선이 늘고 방향이 모호해진다 |
| 연관 (C3·C5~C11) | 회색 긴 점선 + 관계 이름(연결·적용·할당·경로 대상·주소 변환·1:1 짝). C5(IGW–VPC)는 IGW를 VPC 경계에 걸치고 "VPC에 연결" 표식 | 연관은 종류가 많아 선마다 이름을 붙였다 |
| 흐름 (C12) | 초록 실선 화살표 3구간: 방문자 →(인터넷 경유)→ IGW → ENI →(HTTP 80 요청)→ Nginx | Scene 03-B의 W1~W4와 같은 설명용 흐름이다. 방문자가 IGW·ENI를 건너뛰고 Nginx에 바로 닿는 것처럼 보이지 않게 했다 |
| 대응 (C13~C15) | 보라 점선 + 양끝 마름모 + "≈" | Scene 03과 같은 비교선이다. 화살촉이 없다 |

- **선 교차 0개**(검사기가 선분 교차를 계산해 확인).
- **Route Table은 요청 경로 위에 없다.** "Subnet에 연결"·"경로 대상" 점선으로만 이어진다.
- **Security Group은 VPC 경계가 아니라 ENI에 "적용" 점선으로 이어진다.**
- **Public IPv4 ↔ Private IPv4는 "1:1 짝"이다.** 비교선(대응)이 아니라 연관 점선이며, 변환 주체 IGW와 "주소 변환" 점선으로 이어진다.

## 5. 구조도와의 차이(6.4)

Scene 01~03은 네트워크 구조와 통신 과정의 그림이다. Scene 04는 다음 점에서 다르다.
- 장비 아이콘을 쓰지 않았다. 모든 개념을 같은 모양의 상자(이름 + 짧은 설명)로 그리고, 종류는 테두리·바탕으로 구분한다.
- 모든 선에 관계 이름이 붙는다.
- 일반망 역할이 장비가 아니라 **역할 노드**로 나온다.
- 학습 순서를 지도 밖에 따로 둔다.

영역 겹침은 포함 관계를 보여 주는 데만 썼다.

## 7. 노트북용과 휴대전화용

| | 노트북용 1280×990 | 휴대전화용 360×1768 |
| --- | --- | --- |
| 구성 | 한 장에 A·B·C | A(포함 구조) → B(접속 관계) → C(역할 비교) 순서로 아래로 이어 읽음 |
| 노드 중복 | 없음 | B·C에서 A·B 노드를 다시 가리킬 때 **점선 참조 상자**를 씀(예: ENI ↑ A). 데이터상 노드는 하나다 |
| 관계 | 15개 모두 한 번씩 | 15개 모두 한 번씩(같은 관계를 두 번 그리지 않음) |
| 최소 글자 | 16단위(최소 12px 이상이 되는 표시 폭 960px) | 14단위(360 화면 12.8px) |

휴대전화용 B 영역은 오른쪽 열에 흐름(방문자 → IGW → ENI → Nginx)을, 왼쪽 열에 설정과 주소(Subnet↑, Route Table, Public IPv4, Private IPv4↑, Security Group)를 둔다. 관계 이름을 단 선으로 오른쪽 열과 잇는다. 선 교차는 0개다.

## 8. 편집 방법

- 노드·관계·문구는 `concept-map.json`을 고친다. 그다음 `python3 -I _tools/check_data.py`(데이터 검사), `python3 -I _tools/build.py`(생성), `node _tools/check.cjs`(그림 검사) 순서로 실행한다.
- 좌표는 `_tools/build.py`에 있다. 노드를 더하거나 빼면 좌표도 함께 손봐야 한다.
