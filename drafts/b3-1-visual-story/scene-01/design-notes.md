## 1. 기존 그림 평가 — 판단: **부분 수정(구조 유지, 흐름 축소·기능 표시 보강, 모바일판 신규)**

검토 대상은 `content/mission-guides/main-m05/supplement/assets/00-enterprise-network-overview.svg`(그림 0, 1144×848)와 `01-network-zones.svg`(그림 1, 360×1308)다. 작업 지시서에 적힌 그림 0은 로컬 작업 브랜치(`d8b9ecc`)에는 없고 `origin/main`에만 있다. 로컬 브랜치가 원격보다 뒤처져 있었기 때문이다.

| 회사 안·밖 구분 | 인터넷 구역과 내부 업무망이 **같은 색**(`soft`)이다. 회사 경계선이 따로 없다. | **수정.** 회사 밖은 회색으로 바꾸고, 회사 네트워크를 굵은 테두리로 둘렀다(학습 질문 1). |
| 모바일 | 390px에 맞추면 최소 글자가 5.0px다(기존 QA 기록). 웹에서는 가로 스크롤로 보여 준다. | **신규.** 세로형 모바일판을 따로 만들었다. 최소 글자는 13단위(358px 표시에서 12.9px)다. |
| 그림 1(세로형 구역도) | 허용·차단 알약이 많고 연결은 하나의 줄기 선에서 갈라진다. 장비 사이 실제 연결을 나타내지 않는다. | 그림 1은 "구역별 허용·차단"을 보는 자료로 **그대로 유지**한다. 이번 모바일판은 장비 연결을 데스크톱과 똑같이 보여 줘야 하므로 그림 1을 재사용하지 않았다. |

결론: 그림 0의 사실 관계는 그대로 쓸 수 있다. 다만 **첫 출발점 그림**으로 쓰기에는 정보가 과하고, 라우팅·NAT의 위치가 부정확하게 읽힐 수 있으며, 모바일판이 없다. 새 SVG 두 장은 그림 0의 배치를 이어받은 부분 수정본이며, 처음부터 다시 그린 것이 아니다.

## 2. 정보 우선순위

1. **안과 밖**: 회사 밖(회색) / 회사 네트워크(굵은 테두리)
2. **구역 다섯 개**: 번호 1~5, 색 면, 이름, 한 줄 성격("외부에 공개하는 서버만", "외부 공개 안 함")
3. **방문자 → 공개 웹 서버**: 그림에서 유일한 초록 화살표. 데스크톱에서는 맨 위 가로 한 줄, 모바일에서는 오른쪽 세로 한 줄
4. **장비의 위치와 기능**: 장비 상자 + 기능 이름표(경로 선택, NAT, 허용·차단 판단, 구역 사이 길 안내)
5. **세부**: NAT 조건, 방화벽 규칙 예시, 단순화 안내(카드와 각주)

일부러 넣지 않은 것: 응답, 직원 게시(B), 웹 서버의 DB 조회(C), 기본 게이트웨이·경로표 순서, 포트 번호 목록, AWS 대응. 이 내용은 기존 그림 1~4와 후속 장면의 몫이다.

## 4. 노트북용과 휴대전화용

| | 노트북용 `enterprise-network-desktop.svg` | 휴대전화용 `enterprise-network-mobile.svg` |
| --- | --- | --- |
| 크기 | 1280 × 852 단위, 가로형 | 360 × 2274 단위, 세로형(휴대전화 화면 약 3장) |
| 방문자 흐름 | 맨 위 가로 한 줄(A1~A5) | 오른쪽 세로 한 줄(A1~A5) |
| 회사 안 세 구역의 연결 | 방화벽의 오른쪽 연결 지점에서 각 구역 스위치로 | DMZ는 방화벽 아래로 바로, 저장·업무망은 **왼쪽 여백의 두 선**으로 각 구역 스위치에 연결(구역 면을 지나지 않음) |
| 범례 | 왼쪽 열 | 제목 바로 아래(먼저 읽기) |
| NAT·규칙 | 경계 구역 안 카드 | 회사 테두리 아래 "자세히" 카드(같은 이름표로 짝을 맞춤) |
| 최소 글자 | 15단위(본문 16) | 13단위(본문 14~15) |

**같은 사실에서 만들었다.** `_tools/build.py`의 장비·연결·흐름 정의 한 벌로 두 SVG를 생성한다. 각 요소에는 `data-node`, `data-link`, `data-flow` 속성을 붙였고, `_tools/check.cjs`가 두 그림의 장비 12개, 연결 11개, 흐름 5개, 구역 6개가 같은지 비교한다(결과는 [visual-qa.md](visual-qa.md)).

**전체 → 구역별 세부로 이어 보는 방안(제안, 미구현).**

- 웹 페이지에서는 900px 이상이면 노트북용, 그보다 좁으면 휴대전화용을 보여 준다(`<picture>`의 `media` 또는 CSS). 두 그림이 같은 사실을 담으므로 어느 쪽을 봐도 질문 1~4에 답할 수 있다.
- 모바일에서는 그림 위에 구역 바로가기 칩 `1 밖 · 2 경계 · 3 DMZ · 4 저장 · 5 업무망`을 두고, 누르면 해당 구역 위치로 이동한다. 각 구역 아래에는 후속 장면(방문자 요청·응답, 직원 게시, DB 조회)으로 가는 링크를 둔다.
- NAT·규칙 카드는 SVG 안에 있지만, 웹 통합 때 HTML 본문으로 옮기면 화면 낭독기와 글자 크기 조절에 더 유리하다. 웹 담당(Codex)이 판단할 사항이다.

## 6. 편집 방법

- 글자만 고칠 때는 SVG의 `<text>`를 직접 편집하면 된다. 생성기 없이도 편집할 수 있다.
- 배치를 바꾸거나 두 그림을 함께 바꿀 때는 `_tools/build.py`를 수정하고 `python3 -I _tools/build.py`를 실행한 뒤 `_tools/check.cjs`로 검사한다. `_tools`는 시안 단계용 도구이므로 서비스에 반영할 때는 제외해도 된다.
