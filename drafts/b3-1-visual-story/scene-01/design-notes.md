## 2. 정보 우선순위

1. **안과 밖**: 회사 밖(회색) / 회사 네트워크(굵은 테두리)
2. **구역 다섯 개**: 번호 1~5, 색 면, 이름, 한 줄 성격
3. **방문자 → 공개 웹 서버**: 그림의 유일한 초록 화살표 A1~A5
4. **장비의 위치와 기능**: 장비 상자 + 기능 이름표
5. **세부**: NAT 조건, 방화벽 규칙 예시, 단순화 안내

일부러 넣지 않은 것은 응답, 직원 게시(B), 웹 서버의 DB 조회(C), 기본 게이트웨이·경로표 순서, AWS 대응이다.

## 4. NAT와 차단 규칙의 문구(2차 수정)

| 항목 | 1차 | 2차 |
| --- | --- | --- |
| 동작 조건 | "방화벽의 인터넷 쪽에서" | "**미리 설정한 (변환) 규칙대로**, 방화벽의 인터넷 쪽에서" |
| 내부 구역 사이 | "내부 구역끼리는 변환 없음" | "**이 예시에서는** 내부 구역 사이 주소를 바꾸지 않음". 내부에서 NAT를 쓰는 구성도 있으므로 범위를 한정했다 |
| 차단 규칙 | "차단: 인터넷 → 저장 …" | "차단 · **먼저 연결 시작 차단**: 인터넷 → 저장 구역, 인터넷 → 업무망, DMZ → 업무망" |

## 5. 노트북용과 휴대전화용

| | 노트북용 `enterprise-network-desktop.svg` | 휴대전화용 `enterprise-network-mobile.svg` |
| --- | --- | --- |
| 크기 | 1280 × 1096 단위, 가로형 | 360 × 2410 단위, 세로형 |
| 글자 | 설명·카드·각주 18, 그 밖 최소 17(1차: 15~16) | 본문 14~15, 최소 13(서브넷 주소) |
| 방문자 흐름 | 맨 위 가로 한 줄 | 오른쪽 세로 한 줄 |
| 회사 안 세 구역의 연결 | 방화벽의 오른쪽 연결 지점에서 연결 | DMZ는 아래로 바로 연결하고, 저장·업무망은 왼쪽 여백의 두 선으로 연결 |
| 범례 | 왼쪽 열. 실제 연결 ≠ 통신 허용, 응답 생략, 스위치 포함 | 제목 바로 아래. **2차에 같은 세 항목을 추가했다** |
| NAT·규칙 | 경계 구역 안 카드 | 회사 테두리 아래 "자세히" 카드 |

**같은 사실에서 만들었다.** `_tools/build.py`의 정의 한 벌에서 두 SVG를 생성하고, `_tools/check.cjs`가 두 그림의 장비 12, 연결 11, 흐름 5, 구역 6이 같은지 비교한다.

**노트북·휴대전화 전환 제안(측정 결과 기준).** 근거는 [visual-qa.md](visual-qa.md) 2절이다.

| 그림이 표시될 폭 | 보여 줄 그림 | 측정값 |
| --- | --- | --- |
| **904px 이상** | 노트북용 | 최소 글자 12.0px 이상. 900px에서 최소 12.0, 설명·각주 12.7. 1000px에서 13.3 / 14.1 |
| **904px 미만** | 휴대전화용, 최대 폭 420px로 가운데 정렬 | 420px에서 최소 15.2, 358px에서 12.9, 328px(360 화면)에서 11.8 |

- 기준은 화면(viewport) 폭이 아니라 **그림이 실제로 놓이는 칸의 폭**이다. 사이드바가 있는 가이드 본문은 화면이 넓어도 칸이 904px보다 좁을 수 있다. 그래서 CSS 컨테이너 쿼리나 칸 폭 측정으로 전환하는 방식을 권한다. 단순한 `<picture media>`는 화면 폭 기준이므로 부정확할 수 있다.
- 1차 제안("900px 이상이면 노트북용")은 당시 900px에서 최소 10.5px였으므로 측정과 맞지 않았다. 이번에 기준을 904px로 고쳤다.
- 노트북용을 904px보다 좁은 칸에 억지로 넣지 않는다. 기존 그림 0처럼 가로 스크롤로 보여 주는 방식은 휴대전화용이 있으므로 권하지 않는다.
- 모바일에서 구역 바로가기 칩(1~5)을 두고, 각 구역에서 후속 장면으로 연결하는 방안은 1차 제안을 유지한다(미구현).
- NAT·규칙 카드를 웹 본문 HTML로 옮길지는 웹 담당이 판단한다.

## 6. 기존 자산·원고와의 차이

| 기존(그림 0 / 보강 README 장면 0) | 이번 시안 |
| --- | --- |
| 경로 A가 **A1~A4**: 방문자 → 경계 라우터 → 방화벽·NAT → DMZ 스위치 → 공개 웹 서버 | **A1~A5**: 방문자 → **인터넷** → 경계 라우터 → 방화벽 → DMZ 스위치 → 공개 웹 서버. 인터넷이 별도 요소가 되어 구간이 하나 늘었다 |
| 경로 **B(직원 게시, B1~B7)·C(웹 서버의 자료 조회, C1~C4)** | **생략.** 그림 2·3과 후속 장면의 몫이다 |

| 관리 화면 서버 | 내부 관리 서버 (보조 설명: 게시 관리 화면) |
| DB | DB 서버 |
| 인터넷 (기업망 밖) | 회사 밖 · 인터넷 |

보강 README의 장면 0 본문(경로 표, 대체 설명, 확인 질문 6개)은 A·B·C와 A1~A4를 전제로 쓰여 있다. 이번 시안을 장면 0에 쓰려면 원고 수정이 필요하다. 이번 작업에서는 본문을 수정하지 않았다. 자세한 내용은 [handover.md](handover.md)에 있다.

## 7. 편집 방법

- 글자만 고칠 때는 SVG의 `<text>`를 직접 편집하면 된다.
- 배치를 바꿀 때는 `_tools/build.py`를 수정하고 실행한 뒤 `_tools/check.cjs`로 검사한다. 구름과 선이 만나는 점은 생성기가 곡선을 계산해 정하므로, 구름의 위치나 크기를 바꿔도 접촉점이 따라간다.
- `_tools`는 시안 단계용 도구이며 서비스 반영 때는 제외해도 된다.
