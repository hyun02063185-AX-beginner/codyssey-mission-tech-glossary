# Scene 01 용어·역할·연결 검증

> 범위: 두 시안 SVG(2차)에 나오는 구역, 장비, 기능 이름표, 주소. 새 용어는 등록하지 않았다(용어 목록·지식 지도 변경 없음).

## 1. 근거 자료

| 자료 | 확인 방법 | 사용한 내용 |
| --- | --- | --- |
| NIST SP 800-41 Rev.1, *Guidelines on Firewalls and Firewall Policy* | PDF 본문 텍스트를 직접 추출해 대조했다(1차 작업 때) | §2.1 NAT는 방화벽 기술이 아니라 "routing technology"이다. · §3.1 방화벽이 WAN과 LAN 사이에서 "acts as a router"한다. DMZ는 "interfaces on a routing firewall"이다. "NAT is not part of the security functionality of a firewall." · §3.1 내부에서 연결을 시작하면 NAT가 출발 포트를 대응시키고, 특정 목적지 포트를 내부 호스트로 보내도록 **설정할 수 있다**(pinholing). · §5 "Because firewalls usually act as routers…" |
| NIST CSRC 용어집 *demilitarized zone* | 기존 보강 자료 README의 인용을 재사용했다 | DMZ 정의가 여러 개이므로 하나의 배치를 표준으로 단정하지 않는다 |
| RFC 1918, RFC 5737 | 기존 보강 자료와 같은 주소를 썼다(원문 재대조 안 함) | 사설 대역, 문서용 `203.0.113.0/24`, `198.51.100.0/24` |
| AWS 공식 문서 | 사용하지 않았다(AWS 요소 없음) | — |

## 2. 장비·기능별 검증

| 그림의 표기 | 위치 | 역할 | 연결(회색 선) | 판정·근거 |
| --- | --- | --- | --- | --- |
| 외부 방문자 (PC·스마트폰) | 1 회사 밖 | 요청 시작 | 인터넷 | 정확 |
| 인터넷 | 1 회사 밖 | 여러 통신망의 연결 | 방문자, 경계 라우터 | 단순화(구름 하나). 2차에서 선의 끝을 구름 외곽에 실제로 닿게 했다 |
| 경계 라우터 | 2 경계 | 인터넷과 회사망 연결, 경로 선택 | 인터넷, 방화벽 | 정확. 허용·차단 기능은 붙이지 않았다 |
| 방화벽 | 2 경계 | 허용·차단 판단, 구역 사이 길 안내 | 라우터, 세 구역 스위치 | 정확. 이 예시는 라우팅 방화벽이다(SP 800-41 §3.1) |
| NAT (이름표) | 방화벽의 인터넷 쪽 | **미리 설정한 변환 규칙대로** 주소를 바꾼다. 들어올 때 `203.0.113.10 → 172.16.10.10`, 나갈 때 직원 PC 주소 → 회사 공인 주소. **이 예시에서는** 내부 구역 사이 주소를 바꾸지 않는다 | — | 정확. 허용·차단을 하지 않는다고 명시했다(§2.1·§3.1). 들어오는 쪽 변환은 미리 설정된 대응이 있어야 동작한다는 점을 반영했다(§3.1 pinholing 설명). 내부 구역 사이 무변환은 이 예시의 선택으로 한정했다 |
| 규칙 예시 | 방화벽 규칙 카드 | 허용: 인터넷 → 웹 서버, 웹 80·443만. **먼저 연결 시작 차단**: 인터넷 → 저장 구역, 인터넷 → 업무망, DMZ → 업무망 | — | 정확. 기존 그림 0·1의 정책과 같다. 차단이 "연결을 먼저 시작하는 방향"에 대한 것임을 2차에서 명시했다(기존 README의 "허용·차단 알약은 그 방향으로 연결을 먼저 시작할 수 있는가" 설명과 일치) |
| 스위치(구역마다 1대) | 3·4·5 | 같은 구역 안 장비 연결 | 방화벽의 해당 연결 지점, 구역 안 장비 | 단순화. VLAN 구성은 각주로 밝혔다. 모바일 범례에도 2차에 추가했다 |
| 공개 웹 서버 `172.16.10.10` | 3 DMZ | 요청을 받음 | DMZ 스위치 | 정확 |
| DB 서버 / 파일 저장소 | 4 저장 | 글·게시 상태 / 이미지 저장 | 저장 구역 스위치 | 정확. 인터넷과 직접 연결된 선이 없다 |
| 내부 관리 서버 / 직원 PC | 5 업무망 | 게시 관리 화면 / 업무용 | 업무망 스위치 | 정확. 명칭 변경은 [handover.md](handover.md)에 기록했다 |

## 3. 작업 지시서 §5 제약 점검

| 제약 | 결과 |
| --- | --- |
| 라우터의 경로 선택 ≠ 방화벽의 허용·차단 | 지켰다 |
| NAT ≠ 방화벽 보안 기능 | 지켰다. "허용·차단은 하지 않음"을 적었고, 동작 조건(미리 설정한 규칙)도 명시했다 |
| 장비가 물리적으로 분리됐다고 단정하지 않음 | 지켰다(각주) |
| DMZ ≠ 인터넷에 공개된 모든 서버 | 지켰다 |
| 업무망·저장 구역의 인터넷 직접 노출 금지 | 지켰다. 자동 검사에서 선이 다른 장비를 지나는 곳 0건, 외곽 접촉 오류 0건 |
| 허용 정책을 벗어나는 통신 선 금지 | 지켰다. 화살표는 A 하나뿐이다. 회색 선은 "통신 허용을 뜻하지 않음"이라고 두 판의 범례에 적었다 |
| 모든 기업이 같은 구성이라고 말하지 않음 | 지켰다 |
| AWS 요소와 동일시 금지 | 해당 없음 |
| B3-1에 없는 구성을 있었던 것처럼 표현 금지 | 지켰다(각주) |
| IP는 문서용·사설 주소이며 예시임을 밝힘 | 지켰다 |
