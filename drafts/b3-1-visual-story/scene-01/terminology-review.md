## 2. 장비·기능별 검증

| 그림의 표기 | 위치 | 그림에서 맡긴 역할 | 연결(회색 선) | 판정·근거 |
| --- | --- | --- | --- | --- |
| 외부 방문자 (PC·스마트폰) | 1 회사 밖 | 요청을 시작함 | 인터넷 | 정확. 회사 밖에 있다(학습 질문 1). |
| 인터넷 | 1 회사 밖 | 여러 통신망의 연결 | 방문자, 경계 라우터 | 단순화. 통신사 망과 회선을 구름 하나로 묶어 그렸다. |
| 경계 라우터 | 2 경계 | 인터넷과 회사망을 잇고 경로를 선택함 | 인터넷, 방화벽 | 정확. 허용·차단 이름표를 붙이지 않았다(라우터와 방화벽을 혼동하지 않게). |
| 방화벽 | 2 경계 | **허용·차단 판단**, **구역 사이 길 안내** | 경계 라우터, DMZ·저장·업무망 스위치 | 정확. 이 예시에서는 라우팅 방화벽이다(SP 800-41 §3.1). "구역 사이 연결은 모두 방화벽을 거칩니다"라고 적었다. |
| NAT (이름표) | 방화벽의 **인터넷 쪽** | 주소 바꾸기. 들어올 때 `203.0.113.10 → 172.16.10.10`, 나갈 때 직원 PC 주소 → 회사 공인 주소. 내부 구역끼리는 바꾸지 않음 | — | 정확. **허용·차단은 하지 않는다**고 명시했다(SP 800-41 §2.1·§3.1). 방화벽에 붙은 이름표로 그렸으므로 "NAT = 방화벽"이 아니라 "이 예시에서 방화벽 장비가 함께 맡는 기능"으로 읽힌다. 라우터가 NAT를 맡는 구성도 있다는 점은 각주에 적었다. |
| 규칙 예시(허용·차단) | 방화벽 규칙 카드 | 인터넷→웹 서버 80·443만 허용. 인터넷→저장 구역, 인터넷→업무망, DMZ→업무망 차단 | — | 정확. 기존 그림 0·1의 정책과 같다. "필요한 다른 연결은 이후 그림"이라고 적어, 저장 구역이 아무 연결도 받지 않는다는 오해를 막았다. |
| 스위치(구역마다 1대) | 3·4·5 | 같은 구역 안 장비를 연결 | 방화벽의 해당 연결 지점, 구역 안 장비 | 단순화. 스위치 한 대를 구역별로 나눠 쓰는 구성(VLAN)도 각주에 적었다. 용어 "VLAN"은 그림에 넣지 않았다. |
| 공개 웹 서버 `172.16.10.10` | 3 DMZ | 방문자의 요청을 받음 | DMZ 스위치 | 정확. 사설 주소이며, 밖에서는 NAT 카드의 공인 주소로 보인다. |
| DB 서버 | 4 저장 | 글·게시 상태 저장 | 저장 구역 스위치 | 정확. 인터넷과 직접 연결된 선이 없다. |
| 파일 저장소 | 4 저장 | 이미지 파일 저장 | 저장 구역 스위치 | 정확. |
| 내부 관리 서버 | 5 업무망 | 게시 관리 화면 | 업무망 스위치 | 정확. 기존 그림의 "관리 화면 서버"와 같은 장비다(용어 선택은 Owner 판단). |
| 직원 PC | 5 업무망 | 업무용 | 업무망 스위치 | 정확. |

## 3. 작업 지시서 §5 제약 점검

| 제약 | 결과 |
| --- | --- |
| 라우터의 경로 선택 ≠ 방화벽의 허용·차단 | 지킴. 서로 다른 이름표를 썼고, 라우터에는 허용 기능을 붙이지 않았다. 방화벽의 "길 안내"는 구역 **사이** 경로로 한정했다. |
| NAT ≠ 방화벽 보안 기능 | 지킴. NAT 카드에 "허용·차단은 하지 않음"을 적었다. 차단 규칙은 별도 카드에 있다. |
| 장비가 물리적으로 분리됐다고 단정하지 않음 | 지킴. 각주에 "라우터·방화벽·NAT를 한 장비가 맡기도 하고, 스위치 한 대를 나눠 쓰기도 함"을 적었다. |
| DMZ ≠ 인터넷에 공개된 모든 서버 | 지킴. DMZ는 방화벽의 한 연결 지점에 붙은 별도 구역이고 업무망으로 먼저 연결하는 것이 차단된다. "외부에 공개하는 서버만 둠"은 이 예시의 배치 원칙을 말하며, "공개 서버라면 모두 DMZ에 있다"는 정의로 쓰지 않았다. |
| 업무망·저장 구역의 인터넷 직접 노출 금지 | 지킴. 두 구역의 선은 방화벽의 자기 연결 지점에만 닿는다(자동 검사: 선이 다른 장비를 지나는 곳 0건). |
| 허용 정책을 벗어나는 통신 선 금지 | 지킴. 화살표는 허용된 A(인터넷→웹 80·443) 하나뿐이다. 회색 선은 "실제 연결이며 통신 허용은 방화벽 규칙이 따로 정한다"고 범례에 적었다. |
| 모든 기업이 같은 구성이라고 말하지 않음 | 지킴. 부제와 각주 두 곳에 적었다. |
| AWS VPC·Public Subnet·Security Group과 동일시 금지 | 해당 없음. AWS 요소를 넣지 않았다. |
| B3-1에 직원망·DB·DMZ가 있었던 것처럼 표현 금지 | 지킴. 각주에 "실제 B3-1(AWS) 구성이 아닙니다"를 적었다. |
| IP는 문서용·사설 주소, 예시임을 밝힘 | 지킴. 공인 `203.0.113.10`(RFC 5737), 사설 `172.16/10.20/192.168` 대역, 각주에 예시 주소임을 적었다. |
