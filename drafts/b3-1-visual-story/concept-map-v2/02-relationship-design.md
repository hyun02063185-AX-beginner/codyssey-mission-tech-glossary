> 근거 기호: `b31-record` B3-1 배포 기록(c689299) · `aws-*` AWS 공식 문서 · `nist-800-41` NIST SP 800-41 Rev.1 · `nist-dmz` NIST CSRC DMZ 정의 · `rfc1918` · `scene-example` Scene 01·02의 설명용 예시값(일반 사실이 아님).

## 1. 설계 원칙

| 원칙 | 적용 |
| --- | --- |
| 관계 유형은 여섯 가지 | 포함 · 선행 · 역할 · 흐름 · 대응 · 연관. **선행은 그래프에 쓰지 않고** `learningOrder`(L1~L4)로 둔다. '연관'의 구체적 뜻(연결·적용·할당·경로 대상·변환·분리·판단 기준·구분)은 `label`·`description` 첫 낱말에 적는다 |
| 범위(scope) 네 가지 | `general` 일반망 내부 · `aws` AWS 내부 · `cross` 교차 · `shared` 공통 노드끼리. 검사기가 끝점 domain과 맞는지 확인한다 |
| 대응은 교차에서만 | 대응 7개 모두 일반망 노드 → AWS 노드 방향이다. **장비(device) 노드는 대응의 끝점이 되지 않는다.** 경계 라우터·방화벽·스위치에서는 AWS로 가는 선이 없다 |
| 같지 않은 것은 선 대신 카드 | 경계 라우터 ≠ IGW, DMZ ≠ Public Subnet 등 6개는 `contrasts`. 검사기가 카드의 두 노드가 관계선으로 이어지지 않았음을 확인한다 |
| 장비 안의 처리 순서를 확정하지 않음 | 방화벽의 허용 판단·NAT 사이에는 관계를 두지 않았다(Scene 02 "4·5의 처리 순서는 장비·정책마다 다름"). 흐름 GF01의 경로는 **장비를 지나는 순서**이며 장비 안 기능의 순서가 아니다 |
| 흐름은 Scene 경로와 같게 | GF01 = Scene 01·02 A1~A5, GF02 = Scene 02 R1~R5, AF01 = Scene 03-B W1~W4. `pathStepIds`에 장면의 표식을 그대로 적었다 |
| 설명용 값과 일반 사실을 나눔 | 203.0.113.10, 172.16.10.0/24, "웹 80·443만" 같은 값은 근거를 `scene-example`로 표시했다. B3-1 값(10.0.0.0/16 등)은 `b31-record` |

## 2. 일반망 내부 관계 (33)

### 2-1. 질문별로 따라가기

| 질문 | 따라갈 관계 | 답 |
| --- | --- | --- |
| 1. 인터넷 요청은 어떤 역할을 거쳐 웹 서버에 닿나 | GF01 → GN12 · GN13 · GN14 · GN16·GN17 · GN20 → GN22 | 방문자 → 인터넷 → 경계 라우터(경로 선택) → 방화벽(구역 사이 길 안내 · 허용·차단 판단 · NAT 주소 변환, **순서는 장비마다 다름**) → DMZ 스위치(같은 구역 안 연결) → 공개 웹 서버(웹 서비스 제공) |
| 2. 라우터와 방화벽의 역할 구별 | GN12 · GN13 · GN14 · 카드 CT03 | 둘 다 경로 선택을 맡지만(라우터: 인터넷 ↔ 회사망, 방화벽: 구역 사이), 허용·차단 판단은 방화벽만 한다. 라우터는 허용 여부를 판단하지 않는다 |
| 3. NAT와 IP 주소 | GN16 · GN17 · GN18 · GN19 · SH01 · 카드 CT05 | NAT는 기술, 주소 변환은 역할. 공인 203.0.113.10 ↔ 사설 172.16.10.10을 미리 설정한 규칙대로 짝짓는다. 허용·차단은 하지 않는다 |
| 4. DMZ는 무엇을 위한 영역인가 | GN02 · GN07 · GN23 · GN24 | 외부 공개용 서버만 두고(GN07), 인터넷에서는 웹 요청만 DMZ까지 들어오게 하며(GN23), DMZ에서 내부 업무망으로 먼저 연결을 시작하지 못하게 해 공개 서비스와 내부망을 나눈다(GN24) |
| 5. 스위치의 역할 | GN20 · GN21 | 같은 구역 안의 장비를 잇는다. 구역 사이로 가는 길은 방화벽이 안내한다 |
| 6. 공개 웹 서버 · DB 서버 · 파일 저장소의 구별 | GN07 · GN08 · GN09 · GN25 · GN27 | 놓인 구역이 다르다(DMZ / 자료 저장 구역). 인터넷에서 자료 저장 구역으로 먼저 시작하는 연결은 차단되고, 웹 서버의 DB 조회처럼 필요한 연결만 규칙으로 따로 허용한다 |
| 7. 내부 업무망과 공개 서비스 영역의 차이 | GN04 · GN10 · GN11 · GN24 · GN26 | 업무망은 직원 전용이며 인터넷·DMZ에서 먼저 시작하는 연결을 차단한다. DMZ는 외부 방문자를 위한 공개 영역이다 |

### 2-3. 일반망에서 의도적으로 두지 않은 관계

| 후보 | 이유 |

**왜 역할 노드에서 출발하나.** 지시서의 직접 대응 네 가지(경로 선택 ↔ Route Table, 접근 통제 ↔ SG, 주소 변환 ↔ IGW, 웹 서버 역할 ↔ Nginx)는 모두 '역할'과 AWS 구현의 대응이다. 장비(경계 라우터·방화벽)에서 AWS 자원으로 바로 선을 그으면 "AWS에서 방화벽 = SG", "라우터 = IGW"처럼 장비끼리 같은 것으로 읽힌다. 그래서 일반망 장비는 역할 노드까지만 잇고(GN12~GN17·GN22), AWS 쪽은 역할 노드에서 받는다. 회사 네트워크 ≈ VPC(CR05)와 구역별 주소 범위 ≈ Subnet(CR06)은 영역·주소 범위끼리의 대응이며 Scene 03-A 비교선 6개 중 두 개를 그대로 옮겼다.

**IGW와 NAT에 대해.** AWS 문서는 IGW의 변환을 "one-to-one NAT"라고 부른다. 그래서 '같은 주소 변환 기술'이라는 점은 숨기지 않고 CR03 공통점에 적었다. 다만 IGW → NAT를 '역할'로 잇지 않은 것은 이전 Scene 03 판단을 따른 것이다: 일반망 NAT 노드와 IGW를 직접 이으면 IGW가 "일반망 NAT 장비의 한 종류"처럼 보인다. 이 판단은 Owner 확인 사항으로 남긴다(handover.md).

| CT01 | 경계 라우터 ≠ IGW | 경계 라우터 · IGW (인터넷 게이트웨이) | 선을 그으면 IGW가 라우터 장비처럼 읽힌다. | IGW는 VPC를 인터넷과 연결하는 VPC 구성요소이고 IPv4 1:1 변환을 한다. 다음 길을 고르는 규칙은 Route Table이 정한다. 경로 선택이라는 역할의 비교는 CR01(경로 선택 ≈ Route Table)이 맡는다. |
| CT02 | DMZ ≠ Public Subnet | DMZ (공개 서비스 구역) · Public Subnet | 서로 다른 개념이다. | DMZ는 공개 서비스와 내부망을 나누는 설계 개념이다. Public Subnet은 IGW 경로가 있는 Route Table에 연결된 Subnet이라는 AWS의 경로 기준이다. B3-1에는 지킬 내부망이 따로 없고 별도 DMZ도 만들지 않았다. 주소 범위 비교는 CR06이 맡는다. |
| CT03 | 경로 선택 ≠ 접근 통제 | 경로 선택 · 접근 통제 | 서로 다른 판단이므로 관계선 대신 구분 카드로 둔다. | 경로 선택은 '어디로 보낼지', 접근 통제는 '들어와도 되는지'를 판단한다. 길을 알아도 허용되지 않으면 통과하지 못한다. 경계 라우터는 허용 여부를 판단하지 않는다. |
| CT04 | Route Table ≠ Security Group | Route Table · Security Group | 둘 다 설정이지만 역할이 다르다. | Route Table은 어디로 보낼지(경로)를 Subnet 단위로, Security Group은 들어와도 되는지(허용)를 ENI 단위로 정한다. B3-1 접속에는 둘이 모두 필요했다(03-B ③·⑤). |
| CT05 | NAT ≠ 접근 통제 | NAT · 접근 통제 | 같은 장비가 맡아도 다른 기능이다. | NAT는 주소를 바꿀 뿐 허용·차단을 하지 않는다. NAT가 접근 정책을 대신하지 않는다(NIST SP 800-41 §3.1). |
| CT06 | IGW의 1:1 변환 ≠ NAT Gateway | IGW (인터넷 게이트웨이) · NAT · NAT Gateway(B3-1에 없음) | NAT Gateway는 B3-1에 없다. | B3-1의 주소 변환은 IGW가 Public IPv4가 있는 인스턴스마다 1:1로 했다. NAT Gateway는 사설 Subnet 자원이 밖으로 나갈 때 출발 주소를 바꾸는 별도 AWS 서비스이며 B3-1은 만들지 않았다. 일반망의 NAT 노드를 용어사전 nat-gateway에 연결하지 않는다. |

CT01·CT02·CT04·CT06은 Scene 03-A 주의 카드 4장과 같은 내용이다. CT03·CT05는 Scene 02 후보 #13·#14(서로 다른 판단·기능)를 카드로 옮겼다.
