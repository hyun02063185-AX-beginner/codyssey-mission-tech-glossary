## 이전 Scene 04 대비 주요 변화

1. **일반망이 독립된 기술 관계망이 되었다.** 역할 노드 3개뿐이던 일반망이 구역 6 · 장비 3 · 서버·단말 5 · 기술 1 · 역할 6 노드와 내부 관계 33개가 되었다. Scene 01·02에서 배운 것만으로 질문 1~7에 답할 수 있다.
2. **한 원본, 세 보기.** 전체·일반망·AWS 보기를 `views` 정의로 파생한다. 노드·관계 목록을 보기마다 적지 않는다.
3. **공통 노드.** 외부 방문자·인터넷·공인 IP·사설 IP·포트를 두 체계가 함께 쓴다. 이전의 Public IPv4·Private IPv4는 공인·사설 IP로 합쳤고(같은 주소 개념의 중복 방지), 이전 C11 '1:1 짝'은 공통 관계 SH01이 되었다. 인터넷은 경로 표시에서 노드로 올렸다.
4. **교차 관계는 역할·영역 수준.** 이전 대응 3개(C13~C15) + 03-A 비교선 중 3개(웹 서버·네트워크 영역·주소 구역 분리) + 상태 추적 ≈ SG. 장비에서 AWS로 가는 선은 없다.
5. **같지 않은 것은 비교 카드.** 03-A 주의 카드 4장 + 경로 선택 ≠ 접근 통제, NAT ≠ 접근 통제.
6. **AWS 쪽 보충 노드 2개, 보충 관계 5개 추가.** 서울 리전, 기본 경로 0.0.0.0/0. 이전 관계 C1~C10·C12·C13~C15는 설명 문장을 그대로 이어받았다.
7. **정적 SVG가 아니라 인터랙티브 계약.** 핵심·보충, 관계별 '왜', 공통점·차이점, 딥링크, 모바일 하단 시트까지 데이터와 명세로 정했다. 새 SVG는 만들지 않았다.

## Owner 승인 필요 사항

1. **노드 범위와 핵심·보충 구분** — 36개(핵심 23). 전체 보기 첫 화면 23개가 많은지
2. **공통 주소 노드** — 공인·사설 IP를 일반망·AWS가 함께 쓰는 방식(대안: 체계별로 따로 두고 대응으로 잇기)
3. **웹 서버 비교 방식** — 공개 웹 서버 → '웹 서비스 제공'(역할) ≈ Nginx. 03-A의 "공개 웹 서버 ≈ EC2 + Nginx" 직접선과 다르다
4. **IGW와 NAT** — AWS 문서의 "one-to-one NAT" 표현을 적되, NAT와는 역할 노드를 거친 대응으로만 잇는 것
5. **새로 넣은 노드** — 인터넷(노드로 올림), 서울 리전·기본 경로·포트(보충), 역할 '상태 추적'·'같은 구역 안 연결'·'웹 서비스 제공'
6. **Public Subnet** — 표시 이름 'Subnet' → 'Public Subnet', 용어사전 링크 순서 `public-subnet` 먼저(이전 Scene 04 승인 대기 4번의 후속)
7. **접근 통제의 용어사전 연결** — `access-control`(M13 맥락)을 연결하지 않음
8. **비교 카드 6개 문구**, 특히 새 카드 CT03·CT05
9. **엔진 1단계 추출**(기존 `TechnologyFieldMap.tsx` 동작 보존 리팩터링, Owner Gate) 또는 복제 방식
10. **모바일 첫 화면을 일반망 보기로** 하는 제안과 목록 보기 추가
11. **주소** — `/missions/main-M05/story-map/concepts`와 매개변수 `view·node·rel·flow·more·term`, 장면 링크 `?scene=` 방식(공개 route 계약)
