# 03 · 상호작용 명세 — 기존 기술 지도와 같은 사용성

> 이번 단계에서는 구현하지 않는다. 주소·화면 구조는 후속 웹 통합을 위한 설계 계약이며, 공개 route 계약은 Owner Gate다. 기존 기술 지도의 실제 동작은 `src/TechnologyFieldMap.tsx`, `src/styles.css`(5~10·27행), `src/repair.css`(19~41행), `playwright/technology-field-map.spec.ts`, `playwright/map-immersive-workspace.spec.ts`를 읽고 정리했다(기준 `f829c8e`, `origin/main` `57462a9`와 이 파일들이 같다).

## 2. 화면 구성

```
┌ 머리 ───────────────────────────────────────────────────────────────┐
│ B3-1 스토리맵 · 마지막 장면  [제목]                    [전체 지도 보기] │
├ 도구 줄 ────────────────────────────────────────────────────────────┤
│ 보기: [전체 관계] [일반 네트워크] [AWS 네트워크]   □ 보충 개념 함께 보기 │
│ 흐름: [일반망 요청 A1~A5] [일반망 응답 R1~R5] [B3-1 요청 W1~W4]          │
│ 지도에서 찾기 [________]            [−][+][읽기 크기][전체 보기]          │
├ 작업공간 ───────────────────────────────────────────────────────────┤
│ ┌ 일반망 · 구역 ┐┌ 일반망 · 장비 ┐┌ 일반망 · 역할 ┐┌ 공통 ┐┌ AWS 설정 ┐┌ AWS 자원 ┐ ┌ 설명 패널 ┐ │
│ │   ...        ││    ...       ││    ...       ││ ... ││   ...   ││   ...   │ │  (선택 시) │ │
│ └──────────────┘└──────────────┘└──────────────┘└─────┘└─────────┘└─────────┘ └───────────┘ │
│ 끌어서 이동 · 읽기 크기 · 전체 보기 · Tab과 Enter로 노드 선택                    │
├ 범례 · 앞 장면으로 ───────────────────────────────────────────────────┤
└─────────────────────────────────────────────────────────────────────┘
```

- 영역(region)은 데이터의 `regions` 순서대로 왼쪽 → 오른쪽에 놓는다: 일반망 구역 · 일반망 장비와 서버 · 일반망 기술과 역할 · 공통 · AWS 설정 · AWS 영역과 자원. 일반망 역할과 AWS 설정·자원이 가까워 **교차 대응선이 짧다.** 공통 영역이 가운데에 있어 두 체계의 요청 흐름이 모두 지난다.
- 영역 안의 노드 순서는 `order`를 따른다(기존 엔진은 이름순으로 정렬한다. 04-engine-reuse-review.md 3절).
- 보기마다 보이지 않는 영역은 자리를 비우지 않고 빼서 다시 배치한다(일반망 보기 = 영역 4개, AWS 보기 = 영역 3개).

## 3. 보기 세 가지 — 한 원본에서 파생

보기는 데이터의 `views` 정의(노드 domain·관계 scope의 목록)만으로 계산한다. 노드·관계 목록을 보기마다 따로 적지 않는다.

| 보기 | 보이는 노드 | 보이는 관계 | 첫 화면 | 노드 수 (핵심 / 전체) | 관계 수 (핵심 / 전체) |
| --- | --- | --- | --- | --- | --- |
| **전체 관계** (기본) | general · common · aws | general · aws · cross · shared | 핵심 노드·핵심 관계만 | 23 / 36 | 31 / 57 |
| **일반 네트워크** | general · common | general · shared | 핵심 + 보충 | 15 / 26 | 15 / 34 |
| **AWS 네트워크** | aws · common | aws · shared | 핵심 + 보충 | 12 / 15 | 12 / 17 |

- 관계는 **양 끝 노드가 모두 보일 때만** 그린다. 흐름 관계는 경로 노드 가운데 보이는 것끼리만 이어 그린다(숨은 스위치는 건너뛰고 방화벽 → 공개 웹 서버로 이음). 그때 패널 경로 목록에는 숨은 노드도 흐리게 적는다.
- 모든 보기·모든 표시 수준에서 고립 노드가 없음을 검사기가 확인했다(05-content-qa.md 3절).
- 일반망 보기와 AWS 보기는 그 체계만 보고 이해할 수 있어야 하므로 **보충 노드까지 처음부터 보인다.** 전체 보기는 노드가 36개라 첫 화면에서는 핵심 23개만 보인다.
- 교차 관계(대응 7개)는 전체 보기에서만 보인다. 일반망·AWS 보기에서는 패널에 "AWS에서는 / 일반망에서는" 항목으로 글로만 보여 준다(7-1).

## 4. 핵심과 보충

| 상황 | 동작 |
| --- | --- |
| 전체 보기, 선택 없음 | 핵심 노드 23개 + 핵심 관계 31개. "보충 개념 함께 보기"가 꺼져 있다. 양 끝이 핵심이어도 보충 관계(예: 응답 흐름 GF02)는 숨긴다 |
| "보충 개념 함께 보기" 켬 | 보충 노드 13개와 그 관계가 나타난다. 보충 노드는 점선 테두리 + 표지 '보충'(기존 지도 `foundation` 표지 모양을 재사용) |
| 핵심 노드 선택(토글 꺼짐) | 그 노드와 이어진 **보충 이웃도 그 선택 동안 나타나** 강조된다. 선택을 풀면 다시 숨는다. 예: 방화벽 선택 → 상태 추적·경계 구역이 잠시 보임 |
| 패널에서 보충 이웃을 선택 | 그 노드를 선택한다. 토글 상태는 바꾸지 않는다 |
| 보충 노드 딥링크 | 토글이 꺼져 있어도 그 노드와 이웃이 나타난다 |
| 일반망·AWS 보기 | 토글을 숨기거나 켜진 상태로 고정한다(모두 보이므로) |

관계에도 `importance`가 있다. 핵심 관계는 양 끝이 모두 핵심 노드다(검사기 확인, 흐름 제외). 보충 관계는 위 규칙으로 끝점이 나타날 때만 보인다.

## 5. 선택과 강조

### 5-1. 노드 선택

1. 선택 노드 `is-selected`. 이어진 관계 `is-highlighted`, 양 끝 노드 `is-highlighted`.
2. 그 노드를 지나는 흐름 관계(예: 방화벽 → GF01·GF02)는 **흐름 전체가 아니라 그 노드에 닿는 두 구간만** 강조한다. 흐름 전체는 칩으로 본다.
3. 비교 카드(`contrasts`)에 이 노드가 있으면 상대 노드를 **주황 점선 테두리**로 표시한다(관계선은 긋지 않는다). 예: DMZ 선택 → Public Subnet에 "≠" 표시.
4. 나머지는 기존 `has-focus` 규칙으로 흐리게 한다.
5. 패널을 연다(7절). URL `node=`를 바꾼다(8절).
6. 시점은 옮기지 않는다(기존 `keepView`). 딥링크로 들어왔을 때만 노드를 화면 가운데로 맞춘다.

### 5-2. 관계 선택 (새 기능)

기존 지도는 관계에 `<title>` 툴팁만 있고 관계를 고를 수 없다. 개념지도는 "왜 연결되는지"가 핵심이므로 관계 선택을 더한다.

- 패널의 "연결 관계" 목록 항목, 또는 캔버스의 관계선(두꺼운 투명 hit 영역)을 누르면 그 관계를 선택한다.
- 관계와 양 끝 노드만 강조하고 나머지는 흐리게 한다. 패널은 관계 상세(7-2)로 바뀌고, "← ○○로 돌아가기"로 직전 노드 패널에 돌아간다.
- URL에 `rel=`을 더한다. 키보드: 패널 목록 항목이 버튼이므로 Tab·Enter로 고를 수 있다. 캔버스의 관계선은 키보드 초점 대상으로 만들지 않는다(초점 순서가 너무 길어진다).

### 5-3. 흐름 칩

| 칩 | 관계 | 보이는 보기 | 강조 |
| --- | --- | --- | --- |
| 일반망 요청 A1~A5 | GF01 | 전체 · 일반망 | 방문자 → 인터넷 → 경계 라우터 → 방화벽 → 스위치 → 공개 웹 서버. 구간마다 A1~A5 표식 |
| 일반망 응답 R1~R5 | GF02 | 전체(보충 켬) · 일반망 | 반대 방향. 응답임을 선 모양(점선)으로도 구분 |
| B3-1 요청 W1~W4 | AF01 | 전체 · AWS | 방문자 → 인터넷 → IGW → ENI → Nginx. **Route Table·Security Group은 강조하지 않고**, 패널에 "이 길을 가능하게 한 설정: Route Table(AW06·AW07), Security Group(AW08)"을 적는다 |

기존 `RouteDetail`(경로 이름·설명·만나는 기술 목록)을 그대로 쓰고, 목록 항목에 장면 표식(A1…)을 붙인다. 칩은 기존처럼 다시 누르면 해제된다.

## 6. 보기 전환 정책

| 전환할 때 상태 | 동작 |
| --- | --- |
| 선택 노드가 새 보기에도 있음 | **선택 유지**, 패널 유지. 강조는 새 보기에서 보이는 관계로 다시 계산 |
| 선택 노드가 새 보기에 없음 (예: 방화벽 선택 중 AWS 보기) | 선택을 풀고 안내 한 줄: "'방화벽'은 AWS 네트워크 보기에 없는 일반망 노드라 선택을 해제했습니다. 전체 관계 보기에서 비교를 볼 수 있습니다." 그 노드의 대응 상대가 있으면(방화벽 → 없음, 접근 통제 → Security Group) 안내에 "AWS에서 비슷한 역할: Security Group" 링크를 단다 |
| 선택 관계가 새 보기에서 사라짐 (예: 교차 관계 선택 중 일반망 보기) | 관계 선택을 풀고, 그 관계의 일반망 쪽 끝 노드가 보이면 그 노드를 선택한다 |
| 흐름 칩이 새 보기에 없음 | 칩 선택을 푼다 |
| 시점 | 보기 전환 뒤 그 보기의 **전체 보기(Fit)**로 맞춘다. 선택이 유지되면 선택 노드를 가운데에 둔 읽기 크기로 맞춘다 |
| URL | `view=`만 바꾸고 남은 `node`·`rel`·`flow`는 위 규칙대로 지운다(뒤로 가기로 이전 보기에 돌아갈 수 있게 `replace` 대신 `push`) |

## 7. 설명 패널

데스크톱은 기존 오른쪽 겹침 패널, 모바일(700px 이하)은 기존 하단 시트 CSS를 그대로 쓴다. 머리(선택 상태 · 닫기)는 기존 `map-detail-panel-header`를 쓴다.

### 7-1. 노드 패널 — 순서

| 순서 | 항목 | 데이터 | 비고 |
| --- | --- | --- | --- |
| 1 | 표지: 체계 · 종류 · 구현 상태 | `domain` · `conceptType` · `implementationStatus` | 예: "일반망 · 장비 · 설명용 예시(B3-1에 없음)", "B3-1 AWS · 설정 · 실제 구성(2026-10-14 기록)". 색만으로 구분하지 않고 글자로 적는다 |
| 2 | 이름 · 한 줄 설명 | `label` · `summary` | 기존 `map-detail-summary` |
| 3 | 자세한 설명(정의와 기술적 역할) | `description` | |
| 4 | B3-1에서는 | `b31Note` | 일반망 노드만. 회색 상자 |
| 5 | 비교: 공통점 · 차이점 | 이 노드에 닿는 교차 관계의 `comparisonNote` + 이 노드가 든 비교 카드 | 일반망·AWS 보기에서는 교차 관계가 캔버스에 없어도 이 항목은 보인다. "AWS에서는 → Security Group"처럼 상대 노드를 누르면 **전체 보기로 바꾸고** 그 노드를 선택한다 |
| 6 | 연결 관계 | 이 노드의 관계(보이는 보기 기준) | 유형별로 묶는다: 포함 → 역할 → 흐름 → 연관 → 대응. 각 항목 = "→ 역할 · 경로 선택" + 상대 노드 + `description`. 기존 패널은 관계 키(`uses` 등)를 그대로 보여 주지만, 여기서는 한국어 유형과 `label`을 보인다 |
| 7 | 함께 보면 좋은 순서 | `learningOrder` 중 이 노드의 관계·카드를 참조하는 항목 | 예: 접근 통제 → L3 |
| 8 | 관련 장면 | `storyScenes` | "Scene 02 · 웹사이트 요청·응답 흐름 →" 링크(9절) |
| 9 | 용어사전 | `termIds`(+ 포트의 `relatedTermIds`) | 첫 ID는 기존 "상세 사전에서 보기 →" 단추, 나머지는 작은 링크. 없으면 "용어사전 항목 없음 — 이 지도 설명이 기준입니다" |
| 10 | 관련 개념 연결 | `linkPolicy.conceptConnection` | 그 연결의 `terms`에 이 노드의 termId가 있을 때만(기존 `connectionsForTerm`) |

### 7-2. 관계 패널

이름(`label`) · 유형 · 범위("일반망 내부" 등) · 양 끝 노드(누르면 그 노드 선택) · 연결 이유(`description`) · 근거(`source`의 `label`) · 공통점·차이점(교차) · 체계별 설명(`perSystem`, SH01) · 경로(흐름) · 관련 장면 · 관련 용어(`relatedTermIds`).

### 7-3. 비교 카드 패널

노드 패널 5번에서 카드 제목을 누르면 카드 내용(`explanation`, `noLineReason`)을 패널 안에서 펼친다. 카드는 별도 선택 상태나 URL을 두지 않는다.

## 8. 딥링크

| 매개변수 | 값 | 예 |
| --- | --- | --- |
| `view` | `all`(생략 시) · `general` · `aws` | `?view=aws` |
| `node` | 노드 ID | `?node=gen:firewall` |
| `rel` | 관계 ID | `?rel=CR02` |
| `flow` | 흐름 관계 ID | `?flow=AF01` |
| `more` | `1`이면 보충 개념 표시 | `?more=1` |
| `term` | 용어사전 ID. 그 ID를 `termIds`에 가진 첫 노드를 선택 | `?term=security-group` → `aws:security-group` |

- 전체 주소 예: `/#/missions/main-M05/story-map/concepts?view=general&node=gen:dmz` (HashRouter, 기존 앱과 같음).
- 우선순위: `rel` > `flow` > `node` > `term`. 함께 오면 앞의 것만 쓰고 나머지는 지운다.
- `node`가 그 보기에 없으면 `view=all`로 바꿔 선택한다. 없는 ID면 기존 지도처럼 "찾으려는 지도 개념을 찾지 못해 전체 지도를 표시합니다" 안내.
- 같은 termId를 가진 노드가 둘 이상이면 `term`은 첫 노드를 고른다. 현재 데이터에서는 겹치는 termId가 없다(검사로 확인 가능).
- 스토리맵 마지막 장면 안에 넣을 때와 바로가기 주소로 열 때 같은 컴포넌트·같은 매개변수를 쓴다.

## 10. 시각 표현 약속

Scene 01~03의 약속을 지도에도 이어 쓴다. **색만으로 구분하지 않는다**(선 모양·표지 글자를 함께).

| 의미 | 표현 | Scene 근거 |
| --- | --- | --- |
| 체계 | 영역 위치 + 노드 아래 줄 글자("일반망 · 장비", "B3-1 · 설정", "공통 · 주소") | 03-A 왼쪽 일반망 / 오른쪽 AWS |
| 핵심 / 보충 | 실선 테두리 + 표지 '핵심' / 점선 테두리 + 표지 '보충' | 기존 지도 `core`·`foundation` 모양 |
| 설명용 예시(B3-1에 없음) | 노드 아래 줄 끝에 "예시" | 03-A "점선 상자 = B3-1에서 구현하지 않음" |
| 포함 | 가는 실선, 화살촉 없음 | — |
| 역할 | 실선 + 작은 화살촉(장비 → 역할) | Scene 01 "이름표 = 장비가 맡는 기능" |
| 흐름(요청) | 초록 실선 + 화살촉, 구간 표식 A·W | Scene 01·02·03-B |
| 흐름(응답) | 갈색 점선 + 화살촉, 표식 R | Scene 02 |
| 대응 | **보라 점선 + 양끝 마름모 + ≈**, 화살촉 없음 | 03-A "≈는 비슷한 역할일 뿐, 같은 장비·서비스가 아닙니다" |
| 연관 | 회색 점선, 화살촉 없음, 이름표 | 03-A·03-B "회색 점선 = 설정이 연결·적용된 곳" |
| ≠ 비교 카드 상대 | 주황 점선 테두리 + "≠" (선택 중일 때만) | 03-A 주의 카드 |

범례에는 다음 두 문장을 고정으로 둔다: "선은 관계이며 통신이 허용된다는 뜻이 아닙니다." "≈는 비슷한 역할일 뿐 같은 장비·서비스가 아닙니다."
