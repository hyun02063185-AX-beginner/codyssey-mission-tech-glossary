## 3. AWS 내부 관계 (16)

이전 Scene 04의 C1~C10·C12는 끝점(새 ID)·유형·설명이 같다. 바뀐 것은 다음뿐이다.

- C9·C10의 끝점이 공통 주소 노드(`com:private-ip`, `com:public-ip`)로 바뀌었다. 설명 문장은 그대로다.
- C12(AF01)의 경로에서 인터넷이 경로 표시 `@internet`이 아니라 노드 `com:internet`이 되었다. 설명에 "Route Table과 Security Group은 이 길 위의 장비가 아니라 길을 가능하게 하는 설정"을 더했다.
- 보충 관계 5개를 더했다: 리전 ⊃ VPC(AW11), Route Table ⊃ 기본 경로(AW12), SG — 포트(AW13), Nginx — 포트(AW14), ENI — 공인 IP 할당(AW15). AW15는 Scene 03 후보에서 보충으로 남겼던 관계이며 AWS ENI 문서("When you launch an instance, the IP address is assigned to the primary network interface")로 다시 확인했다.

## 4. 교차 관계 (7) · 공통 관계 (1) · 비교 카드 (6)

### 4-1. 교차 대응

교차 관계는 모두 `대응`이며, 연결선이 있다고 두 노드가 같은 개념이라는 뜻이 아니다. 각 관계에 `comparisonNote`(공통점·차이점·주의)를 붙여 설명 패널에 그대로 보여 준다.

| ID | 공통점 | 차이점 | 주의 |
| --- | --- | --- | --- |
{{cross_notes}}

**왜 역할 노드에서 출발하나.** 지시서의 직접 대응 네 가지(경로 선택 ↔ Route Table, 접근 통제 ↔ SG, 주소 변환 ↔ IGW, 웹 서버 역할 ↔ Nginx)는 모두 '역할'과 AWS 구현의 대응이다. 장비(경계 라우터·방화벽)에서 AWS 자원으로 바로 선을 그으면 "AWS에서 방화벽 = SG", "라우터 = IGW"처럼 장비끼리 같은 것으로 읽힌다. 그래서 일반망 장비는 역할 노드까지만 잇고(GN12~GN17·GN22), AWS 쪽은 역할 노드에서 받는다. 회사 네트워크 ≈ VPC(CR05)와 구역별 주소 범위 ≈ Subnet(CR06)은 영역·주소 범위끼리의 대응이며 Scene 03-A 비교선 6개 중 두 개를 그대로 옮겼다.

**IGW와 NAT에 대해.** AWS 문서는 IGW의 변환을 "one-to-one NAT"라고 부른다. 그래서 '같은 주소 변환 기술'이라는 점은 숨기지 않고 CR03 공통점에 적었다. 다만 IGW → NAT를 '역할'로 잇지 않은 것은 이전 Scene 03 판단을 따른 것이다: 일반망 NAT 노드와 IGW를 직접 이으면 IGW가 "일반망 NAT 장비의 한 종류"처럼 보인다. 이 판단은 Owner 확인 사항으로 남긴다(handover.md).
