## 1. 핵심 시각화 두 가지

| 그림 | 질문 | 구성 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** 데이터가 바뀌는 과정 | CRUD 동작을 하면 목록의 무엇이 바뀌고, 검색·요약은 무엇을 만들까? | 행 표시 범례 · A-0 처음 상태(4건)와 '데이터를 담는 모양'(한 행 = 딕셔너리, 전체 = 리스트, id) · A-1 **C·R·U·D 카드 4장**(각 카드 = 그 동작 바로 뒤의 목록, 바뀐 행 표시) · A-2 Read/검색/요약 비교 카드, **같은 원본**에서 만든 검색 결과 2개와 요약 값, '원본 4건 그대로' 띠 | 데이터 상태 비교. **화살표 없음**(데이터 변화는 선이 아니라 행 표시로) |
| **B** 하나의 기능을 처리하는 책임 | 수정(Update) 한 번을 할 때 어디서 규칙을 판단하고, 어디서 값이 바뀌고, 어디서 출력할까? | 설계 예시 안내 띠 · B-1 **가로 책임 띠(swimlane) 위의 실제 호출 흐름** ①~⑨ + return 3개 + 실행 결과 · B-2 역할 카드 4장(규칙 판단·데이터 변경·출력·데이터의 모양)과 실패 두 경우 · B-3 **기능별 책임 표**(번호 없음) · B-4 다음 질문(메모리 ≠ 파일 저장) | B-1 = **호출**(실선·번호)과 **return**(회색) / B-3 = 책임(표, 순서 아님) |

그림의 데이터 상태·검색 결과·요약 값·호출 순서·부른 쪽·return·실행 결과는 모두 `_tools/demo/`를 실제로 실행하고 호출을 추적(`sys.setprofile`)해 얻었다. `verify_demo.py`가 매번 다시 대조한다.

**예제 선택.** 지시서 권장대로 수입·지출 거래 4건(→ 추가로 5건 → 삭제로 4건)을 썼다. Scene 01~03-A의 가상 패키지 `todo`(할 일)는 거래 데이터와 맞지 않아, 같은 원리의 학습용 가상 패키지 **`cashbook`**을 새로 만들었다. 공식 권장 이름 `budget_app`과 구현 사례 이름 `ledger`는 정답처럼 보일 수 있어 쓰지 않았다(Owner 확인 요청 §7).

**숫자 선택.** 처음 지출 3건의 합계 15000·평균 5000.0이 나누어떨어지게 했다. 삭제 대상은 목록 **가운데**(id 3)로 골라 "위치는 당겨지지만 ID는 그대로"가 보이게 했다. 검색·요약은 CRUD 뒤의 상태가 아니라 **처음 4건**에 적용해 `cashbook`의 CLI `summary`·`search` 출력(매 실행 처음 4건에서 시작)과 숫자가 같게 했다.

## 2. 시각 약속 (Scene 03-A 확정 약속 유지 + 데이터 변경 표시 추가)

| 표현 | 뜻 | 출처 |
| --- | --- | --- |
| 진한 실선 + 채운 화살촉 + 검은 번호 원 | **실제 호출 순서** | Scene 01·02·03-A와 같음 |
| 회색 가는 실선 + 빈 화살촉 + 'return' 글자, 번호 없음 | **return 결과** | Scene 03-A와 같음 |
| 파란 파선 + 빈 꺾쇠 화살촉 | import 의존 | 03-A와 같음. **이번 그림에는 import 지도를 그리지 않았다**(03-A에서 확정한 '호출 ≠ import'를 반복하지 않고, 원고 6절의 모듈 코드로 대신) |
| 회색 띠(가로) | 책임 영역(설계상의 묶음) | 03-A의 세로 열을 **가로 띠**로 바꿈. 순서가 아니다 |
| 회색 막대 `main()` | 처음부터 끝까지 실행 중인 함수. 다른 호출이 이 막대에서 나간다 | **이번에 추가** |
| 초록 실선 테두리 + `+ 추가` | 새로 생긴 행 | **이번에 추가** |
| 파란 굵은 테두리 + `읽음`(·변화 없음) | 찾아서 돌려준 행. 데이터는 그대로 | **이번에 추가** |
| 갈색 테두리 + 이전 값 취소선 → 새 값 + `값 변경` | 값이 바뀐 행 | **이번에 추가** |
| 빨간 **파선** 테두리 + 행 취소선 + `− 삭제` | 목록에서 빠진 행(자리에 남겨 보여 줌) | **이번에 추가** |
| 검은 글자 상자 C·R·U·D | 동작 이름표. **번호가 아니다** | **이번에 추가** |

- 색만으로 구분하지 않는다: 행 표시는 색 + 테두리 모양(실선·굵은 실선·파선) + 글자 표시 + 취소선. 검사기가 바뀐 행마다 글자 표시가 있는지, 삭제 행이 파선·취소선인지, 값 변경 행에 이전 값(`data-old`)·취소선이 있는지 확인한다.
- **번호를 붙이지 않은 곳:** 그림 A의 카드(실행 차례대로 놓았지만 그림 B의 호출 번호와 섞이지 않게 C·R·U·D 글자만), B-2 역할 카드, B-3 책임 표. 검사기가 이 영역 안에 번호 원이 없는지 확인한다.
- 호출 선은 실선·채운 화살촉, return 선은 회색 실선·빈 화살촉이고 16px 안에 번호 원이 없는지 검사한다(03-A와 같은 기준).

## 3. Scene 03-A·B3-1과 다른 점

- 03-A 그림 B-2는 **계층을 세로 열**로 세우고 위→아래로 호출을 그렸다. 03-B의 B-1은 **계층을 가로 띠**로 눕히고 시간을 **왼쪽 → 오른쪽**으로 흐르게 했으며, `main()`을 띠 전체 길이의 **실행 막대**로 그렸다. 아래 띠로 내려가는 화살표 = 안쪽 책임으로 들어가는 호출, 위로 올라가는 회색 선 = return.
- 03-A의 2×2 import 상자와 차이 카드 배치는 쓰지 않았다. 대신 **기능 × 책임 표**(B-3)와 **실패 경우**(B-2)를 새로 넣었다.
- 그림 A의 '상태 카드' 구성은 이전 장면에 없던 새 배치다. B3-1 네트워크 그림(구역 중첩·≈ 비교선)은 쓰지 않았다.
- 그리기 도구는 03-A 생성기를 불러 썼다(그 안의 02·01 도구 포함). 세 생성기 파일은 바꾸지 않았다.

## 4. 노트북용과 휴대전화용

| 항목 | 노트북용 `1280×3984` | 휴대전화용 `360×6780` |
| --- | --- | --- |
| A-0 | 처음 상태 표(왼쪽) + 데이터 모양(오른쪽) | 위아래 |
| A-1 CRUD | 2×2 카드, 행 표시 글자 `읽음 · 변화 없음`·`값 변경` | 세로 4장, 표시 글자 `읽음`·`변경`(뜻은 카드 설명 줄에), 긴 코드는 두 줄 |

| B-1 호출 흐름 | 가로 책임 띠 4개, `main()` 가로 막대, 아래로 내려가는 호출·위로 오르는 return | **세로**: `main()` 머리 상자 + 왼쪽 세로 막대, 책임 영역은 들여쓰기 + 상자 오른쪽 위 글자, return은 오른쪽 바깥 통로(x=340·352)와 막대로 |

| 길이 | 1280px 화면(높이 약 900px)에서 약 4.4화면(그림 A 약 2.1 + 그림 B 약 2.3) | 390px 화면(칸 358px, 높이 약 800px)에서 약 8.4화면(그림 A 약 4.1 + 그림 B 약 4.3) |

휴대전화용이 길다. CRUD 네 카드가 각각 전체 목록을 보여 줘야 '변경 전후 비교'가 되고, 책임 표·실패 경우·다음 질문까지 한 그림에 담았기 때문이다. 웹에서는 **그림 A/B 탭(I1)**으로 나누면 한 탭이 약 4화면이 된다. 정적 SVG에서 더 줄이려면 B-4 다음 질문을 원고로만 옮기는 방안이 있다(Owner 판단 요청 §7).

**저장 오해 방지(필수).** I2·I3·I6은 **화면의 학습용 표시 상태만 바꾼다.** 파일·서버·브라우저 저장소에 기록하지 않으며, 화면에 "학습용 표시 · 실제 파일에 저장되지 않음"을 늘 보인다. I6 버튼 이름은 '처음 상태로'로 하고 '저장'·'불러오기' 같은 말을 쓰지 않는다. 그림 B-4(메모리 ≠ 파일 저장)와 연결해, 웹에서 바꾼 표시가 새로고침하면 처음으로 돌아가는 것이 **의도된 동작**임을 안내한다.

공통: 키보드 탐색, `aria-pressed`/`aria-live`, `prefers-reduced-motion` 존중, 강조는 색과 함께 굵은 테두리·글자로도 표시.

## 7. Owner·독립 검토 확인 요청

1. 가상 예시를 `todo`에서 거래용 `cashbook`으로 바꾼 것(Scene 03-B부터)
2. 그림 A의 행 표시 약속(추가·읽음·값 변경·삭제)과 카드에 번호 대신 C·R·U·D 글자를 쓴 것
3. 그림 B-1의 가로 책임 띠 + `main()` 실행 막대 배치, import 지도를 생략한 것
4. 휴대전화 길이 약 8.4화면 — I1 탭으로 해결할지, B-4를 원고로만 옮길지
5. 단일 파일 함수 예제(`crud_basics.py`)와 책임별 패키지(`cashbook`)를 둘 다 두는 분량
