## 1. 핵심 시각화 두 가지

| 그림 | 질문 | 구성 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** 패키지와 실행 시작점 | `python -m todo list --limit 3`을 실행하면 어느 파일부터, 어떤 순서로 실행될까? | A-1 폴더 구조와 파일 역할 · A-2 **실제 실행 순서 ①~⑧**(불러올 때 ①~④ / 호출될 때 ⑤~⑧) · A-3 실행 방식 비교표(`-m 패키지`·`-m 모듈`·파일 직접 실행) · A-4 비교 카드 2장(`__main__.py` ≠ `if __name__ == "__main__":`, `__init__.py` ≠ `__init__()`) | A-2만 **실행 순서**(번호·실선). 나머지는 구조·비교 |
| **B** 같은 소스, 두 개의 지도 | 파일이 연결되어 있다는 것과 함수가 실행된다는 것은 어떻게 다른가? | B-1 **모듈 의존 관계(import 지도)** · B-2 **함수 실행 흐름(호출 지도)** · 아래에 두 지도를 겹쳐 본 차이 카드 3장 | B-1 = **사용(import)**, 번호 없음 / B-2 = **호출**, 번호 있음 |

그림 A-2의 순서와 그림 B의 import·호출은 모두 `_tools/demo/`를 실제로 실행하고 소스를 분석해 얻었다. `verify_demo.py`가 매번 다시 대조한다.

## 2. 두 경로의 시각 구분 (지시서 §3-D)

**같은 화살표나 같은 순서 번호로 표시하지 않는다.**

| | 모듈 의존 관계 (B-1) | 함수 실행 흐름 (A-2, B-2) |
| --- | --- | --- |
| 선 | 파란 **파선**(`9 6`) | 진한 **실선** |
| 화살촉 | **빈** 꺾쇠(`>`) | **채운** 삼각형 |
| 번호 | **없음** | 검은 번호 원 ①~⑧. B-2는 그림 A와 **같은 번호**(⑤~⑧)를 써서 같은 사건임을 보인다 |
| 글자 | 선 옆에 `import`, 상자 안에 실제 `import` 줄(파란 고정폭) | 상자 안에 함수 이름(고정폭)과 그 함수가 있는 파일 |
| 표준 라이브러리 | 화살표를 그리지 않고 import 줄 옆 **회색 칩**("표준 라이브러리", 휴대전화 "표준") | 표준 라이브러리 함수도 호출이면 그린다(⑦ `parse_args()`) |

검사기(`check.cjs`)가 import 선은 파선·빈 화살촉이고 30px 안에 번호 원이 없는지, 실행·호출 선은 실선·채운 화살촉인지 확인한다. 색만으로 나누지 않으며(선 모양·화살촉·번호 유무·글자) 흑백에서도 구별된다.

**'불러올 때'와 '호출될 때'의 구분(그림 A-2):** 두 단계 상자를 다른 테두리(파선 파랑 / 실선 초록)와 머리글 글자로 나눴다. 불러올 때 단계의 설명에 "def는 함수를 만들기만 합니다"를 넣어 함수 정의 시점과 호출 시점의 차이를 그림에서 바로 읽게 했다.

## 3. Scene 01·B3-1과의 관계

- Scene 01의 그리기 도구(`Svg`, 글꼴, 번호 원, 실행 화살표, 범례 상자)를 **불러 써서** 같은 시각 언어를 유지했다. Scene 01 파일은 바꾸지 않았다.
- Scene 01의 "실선·번호 = 실제 처리 순서"를 그대로 쓰고, Scene 02에서 **import 연결(파선·빈 화살촉·번호 없음)**과 **표준 라이브러리 칩**을 새로 더했다.
- B3-1과 같은 품질 기준(노트북·휴대전화 두 판, 최소 글자, 색에만 의존하지 않기, 대체 설명, 자동 검사)을 따르고, 네트워크 구성도 레이아웃(좌우 비교·구역 중첩·≈ 비교선)은 쓰지 않았다.

## 4. 노트북용과 휴대전화용

| 항목 | 노트북용 `1280×2290` | 휴대전화용 `360×4130` |
| --- | --- | --- |
| A 폴더 구조 + 실행 순서 | 좌우 두 카드 | 위아래. 역할 설명은 `·` 앞부분만 남겨 짧게 |
| 실행 순서 화살표 | 단계 상자 왼쪽의 **전용 통로(x=582)**로 돌아 다음 상자로 들어감 → 단계 머리글·글자 위를 지나지 않음 | 같은 방식, 통로 x=26 |
| 실행 방식 비교 | 4열 표 | 명령별 카드 3장 |
| 비교 카드 | 가로 2장 | 세로 2장, 제목을 `≠` 기준 두 줄 |
| B-1 / B-2 | 좌우 두 패널 | 위아래. 호출 지도는 `main()`에서 내려오는 줄기에서 ⑥⑦⑧ 가지 |
| 최소 글자 | 16단위 → 960px 칸 12.0px | 14단위 → 328px 칸 12.8px |
| 길이 | 1280px 화면(높이 약 900px)에서 약 2.5화면 | 390px 화면(칸 358px, 높이 약 800px)에서 약 5.1화면 |

휴대전화용이 길다(약 5.1화면). 그림이 둘이고, 실행 순서 8단계와 비교표·카드를 줄이지 않았기 때문이다. 웹에서는 그림 A·B를 **탭 또는 장면 내부 단계로 나누는 방안**을 인터랙션 명세(I1)에 둔다. 글자를 14단위 아래로 줄이지 않았다.

## 5. 추후 인터랙션 명세 (Codex 구현용 · 이번에 구현하지 않음)

| 속성 | 붙은 곳 | 값 |
| --- | --- | --- |
| `data-file` | 폴더 구조의 파일 묶음 | `main.py`, `todo/`, `__init__.py`, `__main__.py`, `cli.py`, `actions.py`, `실습 폴더/` |
| `data-step` · `data-phase` · `data-out` | 실행 순서 단계 | `1`~`8` · `load`/`call` · 데모 출력 표식(예: `todo/cli.py`, `cli.main()`) |
| `data-flow` | 실행 순서 화살표 | `1>2` … `7>8` |
| `data-runmode` | 실행 방식 비교 행 | 명령 3개 |
| `data-card` · `data-contrast` | 비교 카드 · 차이 카드 | `name-guard`, `init` · `import-not-call`, `call-only`, `order` |
| `data-module` · `data-import` | import 지도 상자 · import 선과 표준 라이브러리 칩 | `__main__`, `cli`, `actions` · `__main__>cli`, `__main__>sys`, `cli>actions`, `cli>argparse` |
| `data-callnode` · `data-call` | 호출 지도 상자 · 호출 선 | `entry`, `main`, `build`, `parse`, `show` · `entry>main@5`, `main>build@6`, `main>parse@7`, `main>show@8` |

**교육적 필요성 검토** (지시서 §5)

| # | 상호작용 | 필요성 판단 | 동작 |
| --- | --- | --- | --- |
| I1 | **그림 A/B 전환(휴대전화)** | **필요.** 휴대전화 길이 약 5.1화면을 줄이고, 강의에서 한 그림씩 설명하기 쉽다 | 장면 안의 'A 실행 시작점 / B 두 지도' 탭. 키보드·URL로 선택 상태 유지 |
| I2 | **단계별 실행 강조** | **필요(핵심).** 강사가 ①~⑧을 한 단계씩 짚을 때 실제 출력 줄과 짝지어 보여 줄 수 있다 | '다음 단계' 버튼. 현재 단계 강조 + 그 단계의 실제 출력 한 줄을 패널에 표시(데모 출력 그대로). ⑤ 이후에는 B-2의 같은 번호도 함께 강조. 자동 재생 없음 |
| I3 | **import 지도 / 호출 지도 보기 전환** | **필요.** 두 지도를 겹치면 오히려 헷갈리므로, 한쪽을 강조하고 다른 쪽을 흐리게(0.3 안팎) 해 대조한다 | 'import 지도 보기'·'호출 지도 보기'·'둘 다' 세 상태. 선 모양 구분은 유지 |
| I4 | **파일 선택** | **유용(강의 후 탐색).** 파일을 고르면 그 파일의 역할·import 줄·그 파일에서 일어나는 실행 단계(예: `cli.py` → ③, ⑤, ⑥)를 보여 준다 | 폴더 구조·import 지도의 파일 상자 선택 → 설명 패널. 데모 코드 보기(원고 2절 코드와 같은 내용) |
| I5 | **실행 방식 바꿔 보기** | **유용.** `-m todo` / `-m todo.cli` / `main.py` / `-h` / `import만` 다섯 보기에서 실행 순서가 어떻게 달라지는지 비교 | 미리 정한 보기만(자유 입력 없음). 결과는 `verify_demo.py`로 확인한 원고의 출력만 사용 |
| I6 | 호출 지도에서 함수 정의로 이동 | **보류.** 학습자 자기 코드 탐색은 편집기에서 하는 활동이며, 웹에서 코드 편집기를 흉내 낼 필요는 낮다 | 구현하지 않음. 원고 10절 활동으로 대신 |

공통: 키보드 탐색, `aria-pressed`/`aria-live` 상태 알림, `prefers-reduced-motion` 존중, 강조는 색과 함께 굵은 테두리로도 표시. 개념지도 연결은 [개념지도 개요](../concept-map-outline.md) §7의 Scene 02 탐색 후보(`__main__.py`, R10·R12, C07, C08)를 쓴다.

## 6. 편집 방법

`_tools/build.py`의 `TREE`·`STEPS`·`RUNMODES`·`CARDS`·`MODULES`·`CALL_NODES`·`CALLS`·`CONTRASTS`를 고치면 두 판에 함께 반영된다. 데모(`_tools/demo/`)를 바꾸면 원고 코드 블록과 그림이 달라지므로 반드시 `verify_demo.py`로 대조한다. 원고의 코드 블록은 `<!-- demo:경로 -->`, 실행 출력 블록은 `<!-- run: 명령 | exit=N -->` 표식으로 대조 대상이 된다.

```bash
python -I drafts/b2-1-story-map/scene-02/_tools/build.py
python -I drafts/b2-1-story-map/scene-02/_tools/verify_demo.py   # 원고·데모·그림 대조(데모는 python으로 실제 실행)
node drafts/b2-1-story-map/scene-02/_tools/check.cjs             # 저장소의 node_modules/playwright 사용
node drafts/b2-1-story-map/scene-02/_tools/preview.cjs           # preview/*.png
```
