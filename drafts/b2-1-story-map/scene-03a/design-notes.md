| 그림 | 질문 | 구성 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** 함수와 클래스 문법 | 정의와 호출, 클래스와 객체는 무엇이 다를까? | A-1 함수: 코드 4줄(정의·`return`·호출)과 부분별 뜻, `price ← 1000` 연결 · A-2 클래스: 클래스 코드, 객체 생성 코드, **객체 카드 a·b**(각자의 데이터) · A-3 비교 카드 3장(함수≠메서드, `__init__()`≠일반 메서드, Parameter≠전달값) · `basics.py` 실행 결과 띠 | 구조·비교. **화살표 없음**(문법 장면에서 흐름 기호를 쓰지 않음) |

## 2. 시각 약속 (Scene 02 승인 후보 재사용 + 추가 1가지)

| 표현 | 뜻 | 출처 |
| --- | --- | --- |
| 진한 실선 + 채운 화살촉 + 검은 번호 원 | **실제 호출 순서** | Scene 01·02와 같음 |
| 파란 파선 + 빈 꺾쇠 화살촉, 번호 없음 | **import 의존** | Scene 02와 같음 |
| 회색 칩 | 표준 라이브러리 import | Scene 02와 같음 |
| **회색 가는 실선 + 빈 화살촉 + 'return' 글자, 번호 없음** | **return 결과**(부른 쪽으로 돌아가는 값) | **이번에 추가.** 지시서 §5-B "요청·결과 흐름은 실제 호출일 때만 실행 화살표"에 따라 return을 호출 화살표와 다른 모양으로 그렸다 |
| 코드 안 초록 굵은 글자 + **밑줄** | Parameter(받는 자리) | 이번에 추가. 색 + 밑줄로 구분 |
| 코드 안 갈색 굵은 글자 | 전달값(Argument) | 이번에 추가. 밑줄 없음으로 Parameter와 구분 |
| 갈색 테두리 카드 | 객체(인스턴스)와 그 데이터 | 이번에 추가 |
| 회색 열(레인) | 책임 계층(CLI·서비스·저장소·모델) | 이번에 추가. 레인은 **설계상의 묶음**이며 호출 순서가 아니다 |

검사기가 호출 선은 실선·채운 화살촉, import 선은 파선·빈 화살촉이고 30px 안에 번호 원이 없는지, return 선은 회색 실선·빈 화살촉이고 16px 안에 번호 원이 없는지 확인한다. 색만으로 구분하지 않는다(선 모양·화살촉·번호 유무·밑줄·글자).

**① 표시:** `main()`은 그림 밖(`__main__.py`)에서 불리므로 화살표 없이 번호 ①만 붙였다. ②~⑦은 부른 쪽에서 화살표가 나간다.

## 3. B3-1·Scene 02와 다른 점

- Scene 02의 파일 트리와 좌우 두 지도 배치를 복제하지 않았다. 03-A의 B-2는 **계층을 열(레인)로 세우고** 그 위에 호출을 그리는 새 배치이며, import 의존(B-3)은 아래에 2×2 상자로 따로 두었다.
- B3-1 네트워크 그림(구역 중첩·≈ 비교선)의 레이아웃은 쓰지 않았다.
- 그리기 도구(Scene 01·02 생성기)는 불러 써서 글꼴·번호 원·화살표 모양을 유지했다. 두 생성기 파일은 바꾸지 않았다.

## 4. 노트북용과 휴대전화용

| 항목 | 노트북용 `1280×2314` | 휴대전화용 `360×4694` |
| --- | --- | --- |
| A-1·A-2 | 좌우 두 카드. A-2는 코드(왼쪽)와 객체 카드(오른쪽) | 위아래. 객체 카드는 코드 아래 |
| 비교 카드 | 가로 3장 | 세로 3장 |
| B-1 책임 | 가로 4장 | 세로 4장 |
| B-2 호출 흐름 | 계층 4열 위에 노드. `main()`에서 내려오는 통로(rail)로 ②③⑤⑥, ③→④, ⑥→⑦은 옆으로 | **들여쓰기 트리**: 부른 쪽 아래로 한 칸 들여 씀. 계층은 상자 오른쪽 위 글자. return은 상자 오른쪽 바깥 통로(x=340) |
| B-3 import | 2×2 상자, 가로·세로 화살표 | 세로 4상자, `cli → repository`는 오른쪽 통로로 `services` 상자를 비켜 감. 긴 import 줄은 `import …`로 줄임(원고에 전체) |
| 최소 글자 | 16단위 → 960px 칸 12.0px | 14단위 → 328px 칸 12.8px |
| 길이 | 1280px 화면(높이 약 900px)에서 약 2.6화면 | 390px 화면(칸 358px, 높이 약 800px)에서 약 5.8화면 |

휴대전화용이 길다(약 5.8화면). 그림이 둘이고 문법 장면이라 코드를 줄이지 않았다. 웹에서는 그림 A·B를 탭으로 나누는 방안(I1)을 둔다.

## 5. 추후 인터랙션 명세 (Codex 구현용 · 이번에 구현하지 않음)

| 속성 | 붙은 곳 | 값 |
| --- | --- | --- |
| `data-part` | 함수 부분 설명 | `func-1`~`func-4` |
| `data-object` | 객체 카드 | `a`, `b` |
| `data-card` · `data-contrast` | 비교 카드 · 차이 카드 | `func-method`, `init-method`, `param-arg` · `call-no-import`, `not-a-chain`, `module-vs-layer` |
| `data-out` | 실행 결과 줄 | `basics.py` 출력 3줄 |
| `data-layer` | 책임 카드, 호출 노드 | `cli`, `service`, `repo`, `model` |
| `data-callnode` · `data-call` · `data-return` | 호출 노드 · 호출 선 · return 선 | `main`…`all`, `show` · `main>build@2` … `list>all@7` · `all>list`, `list>show` |
| `data-module` · `data-import` | import 상자 · 선·칩 | `cli`, `service`, `repo`, `model` · `cli>argparse`, `cli>repo`, `cli>service`, `repo>model` |

| # | 상호작용 | 교육적 필요성 | 동작 |
| --- | --- | --- | --- |
| I1 | 그림 A/B 탭(휴대전화) | **필요.** 약 5.8화면을 줄이고 문법과 구조를 따로 설명 | 장면 안 탭, 선택 상태 유지 |
| I2 | **코드 부분 선택(그림 A)** | **필요(핵심).** `def`·Parameter·전달값·`return`·`self`를 하나씩 짚을 때 코드 속 해당 글자와 설명을 함께 강조 | 부분 설명(`data-part`)이나 코드 글자를 고르면 둘 다 강조. 키보드로 차례 이동 |
| I3 | **객체 상태 따라가기** | **유용.** `a = Task(…)` → `b = Task(…)` → `a.complete()`를 한 줄씩 실행하며 객체 카드의 값이 바뀌는 것을 본다 | '다음 줄' 버튼. 카드 값은 `verify_demo.py`가 확인한 실제 상태만 사용. 자동 재생 없음 |
| I4 | **호출 단계 강조(그림 B-2)** | **필요.** ①~⑦과 return 두 개를 한 단계씩 짚고, 그 단계가 어느 계층의 책임인지 B-1 카드와 함께 강조 | '다음 단계'. ⑦ 뒤에 return 두 단계, 마지막에 '결과 표시'. 자동 재생 없음 |
| I5 | **호출 흐름 / import 의존 겹쳐 보기** | **유용.** "호출은 있지만 import는 없다"(서비스→저장소), "CLI가 저장소를 import해 직접 만든다"를 한 화면에서 대조 | 두 그림의 같은 모듈을 함께 강조, 다른 쪽은 흐리게. 선 모양 구분은 유지 |
| I6 | 내 코드 표 만들기 | **보류.** 학습자 코드 입력은 저장·보안 문제가 있고, 원고 9절의 종이·편집기 활동으로 충분 | 구현하지 않음 |

공통: 키보드 탐색, `aria-pressed`/`aria-live`, `prefers-reduced-motion` 존중, 강조는 색과 함께 굵은 테두리로도 표시.
