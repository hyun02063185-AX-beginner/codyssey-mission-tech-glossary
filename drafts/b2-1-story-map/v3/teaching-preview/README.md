# B2-1 Story v3.4 — Scene 01~04 강의 미리보기

2026-10-24 · v3.3 승인 디자인 `18a0fcb` 위에 Scene 03·04를 추가 · **Scene 03·04 Owner 검토 대기**

v3 교육 원고([Scene 01](../scene-01/storyboard.md), [Scene 02](../scene-02/storyboard.md), [Scene 03](../scene-03/storyboard.md), [Scene 04](../scene-04/storyboard.md))를 v3.3에서 승인된 디자인과 조작 체계로 보여 주는 **대면 강의용 화면**이다. 독립 HTML 한 파일이며 React·운영 서비스에 등록하지 않았다.

Scene 01·02의 원고·그림·강의 순서·조작·주소(`#1-…`, `#2-…`)는 v3.3과 같다. 바뀐 곳은 Scene 02 마지막 단계(`#2-17`) 하나로, `Scene 03으로 ›` 버튼이 생기고 강사 대본의 ‘Scene 03은 아직 제작 전’ 문장을 ‘Scene 03으로 넘어갑니다’로 고쳤다. 자동 회귀 검사로 확인한다([qa.md](qa.md)).

## 여는 방법

서버·인터넷·Python이 필요 없다. 외부 글꼴·스크립트 요청도 없다.

**Windows** (저장소 루트, PowerShell):

```powershell
Start-Process .\drafts\b2-1-story-map\v3\teaching-preview\index.html
```

**Mac** (저장소 루트, 터미널):

```bash
open drafts/b2-1-story-map/v3/teaching-preview/index.html
```

특정 단계로 바로 열려면 주소 끝에 `#3-1`(Scene 03 첫 단계)처럼 붙인다. 탐색기/Finder에서 더블클릭해도 된다. 발표 화면은 1280×720 이상 또는 전체 화면(F11 / ⌃⌘F).

## 조작 (v3.3과 같음)

| 하고 싶은 것 | 방법 |
| --- | --- |
| 다음·이전 설명 | `→`/`←` (또는 `PageDown`/`PageUp`, 프레젠터 리모컨), 아래 `다음 ›`·`‹ 이전`. 장면 끝에서 다음 장면으로 이어짐 |
| 장면 처음·끝 | `Home`/`End` |
| 그림의 특정 영역 설명 | 명령의 부분, 역할, 파일, 상황, **CRUD 동작, 검색·요약 결과, 메모리·파일 칸, 저장 흐름 상자, JSONL 줄, CSV 첫 줄**을 클릭 (Tab → Enter/Space) |
| 전체 구조로 돌아가기 | 선택된 영역을 다시 클릭하거나 `전체 구조` |
| 현재 위치 | 아래 `Scene 03 · 4 / 12 · 수정 Update`와 진행 막대 |
| 강사 대본·노트·심화 | `강사 노트` — 이 단계 대본, (확인 단계) 기대 답과 흔한 오답, 정확성 경계, 선택형 심화 |
| 전체 개념 한눈에 / 장면 이동 | `목차` — 4개 장면 56단계의 제목과 화면 한 문장 |
| 패널 닫기 | `Esc` 또는 `닫기` |
| 확인 질문의 답 | 확인·적용 단계의 `답 보기` |

강사 노트는 같은 화면에 열리므로 발표 화면을 나누지 않으면 학습자에게도 보인다.

## 강의 단계

Scene 01(13단계)·Scene 02(17단계)는 v3.3과 같다. 단계표는 각 원고와 v3.3 기록을 따른다.

**Scene 03 — 기록을 다루는 기본 동작에는 어떤 것이 있을까? (12단계, 학습용 가상 기록)**

가운데 같은 기록 묶음(4개)을 두고 둘레의 동작을 바꿔 가며 설명한다. 구조도에는 번호·화살표가 없다.

| 단계 | 그림 | 내용 |
| --- | --- | --- |
| 1 | F1 구조 | 기록 묶음 + 네 동작, ‘순서가 아닙니다’ |
| 2–5 | F1 구조 (같은 자리 변화) | 추가: #5 ‘새로 추가’ · 조회: ‘그대로’ · 수정: #3 2,000원 취소선 → 2,500원 ‘수정됨’ · 삭제: #2 점선·취소선 ‘삭제됨’ |
| 6 | F2 비교 | 추가·수정·삭제 ‘원본이 바뀜’ / 조회 ‘원본 그대로’ |
| 7–9 | F3 비교 | 검색(간식 → #1·#3) · 요약(합계 14,500원, 분류별) · 둘 다 원본 4개 그대로 |
| 10 | 이해 확인 | 질문 3개 |
| 11 | F4 적용 | 요청 6개를 동작으로 분류 |
| 12 | 정리 | 바꾸는 일·꺼내 보는 일·고르는 일·계산하는 일 + Scene 04 질문 |

**Scene 04 — 프로그램을 종료해도 기록이 남으려면 무엇이 필요할까? (14단계, 학습용 가상 기록 + 실제 사례 1단계)**

| 단계 | 그림 | 내용 |
| --- | --- | --- |
| 1–3 | F1 비교 | 메모리(5개, #5 아직 파일에 없음) / 파일(4개) → 저장 없이 종료하면 #5 ‘남지 않음’ |
| 4–5 | F2 흐름 | 사용자 요청 → 프로그램의 처리 → 파일에 저장 (이 장면 유일한 화살표). 파일에 #5 ‘저장됨’ → Service·Repository 이름표, 종료 후에도 5개 남음 |
| 6–7 | F3 구조 | `records.jsonl` 5줄, 줄 번호, 한 줄 = 기록 하나 → 1번 줄의 항목 이름·값 |
| 8–9 | F4 구조 | `records.csv` 원문 + 같은 내용의 표 → 첫 줄 = 열 이름 |
| 10–11 | F5 비교 | JSONL·CSV의 모양과 잘 맞는 곳 → **실제 사례**: 기록 저장 `data/transactions.jsonl` / CSV 가져오기·내보내기 |
| 12–13 | 이해 확인·적용 | 질문 3개 + 상황 3개 |
| 14 | 정리 | 메모리·파일 저장·JSONL·CSV + Scene 05 질문 (Scene 05는 제작 전, 연결 버튼 없음) |
