## 1. 강의용 그림 5개

### 그림 F1 — Type Hint: 기대하는 값 표시 (구조)

큰 안내판에 `amount: int`. 아래 두 이름표: **amount — 이름 (금액)**, **int — 기대하는 형 (정수)**.

| 단계 | 추가 표시 |
| --- | --- |
| 2 | 안내판을 읽는 쪽 두 카드: **사람** ‘코드를 읽을 때 기대를 안다’ · **검사 도구** ‘실행하기 전에 맞지 않는 곳을 찾아 줄 수 있다’ |
| 3 | 안내판 옆을 지나가는 값 세 개 `1000` · `"1000"` · `-5`, 모두 ‘그대로 지나감’. 표시: **안내판은 문이 아닙니다 — 실행 중에 값을 막지 않음** |

안내판을 문·검사대처럼 그리지 않는다. 함수 전체 코드는 넣지 않는다.

### 그림 F2 — 표시와 실제 검사의 차이 (비교)

| 값 | 왼쪽: Type Hint · 기대하는 형 표시 (`amount: int`) | 오른쪽: 값 검증 · 실제 값 확인 (금액 규칙: 0보다 큰 정수) |
| --- | --- | --- |
| `1000` | ✓ int와 맞음 | ✓ 0보다 큰 정수 — 통과 |
| `"1000"` | 글자 — int와 다름 (그래도 막지는 않음) | 글자 그대로는 정수가 아님 — 먼저 바꿔야 함 (다음 그림) |
| `-5` | ✓ int와 맞음 | ✕ 0보다 크지 않음 — 거부 |

줄은 단계마다 하나씩 채운다.

### 그림 F3 — 변환과 검증 (흐름)

머리줄 `입력 → 정수로 변환 → 금액 규칙 검사 → 사용`은 실제 처리 흐름이므로 화살표를 쓴다. 그 아래 값별 줄.

| 입력 | 정수로 변환 | 금액 규칙 검사 | 결과 |
| --- | --- | --- | --- |
| `"1000"` | ✓ 1000 | ✓ 0보다 큼 | 사용 |
| `"abc"` | ✕ 정수로 바꿀 수 없음 | — | 변환 단계에서 멈춤 |
| `"-5"` | ✓ -5 | ✕ 0보다 크지 않음 | 규칙 단계에서 거부 |

그림 아래 작은 글씨: ‘이 순서는 이 예시의 처리 흐름입니다. 모든 프로그램이 같은 곳에서 같은 순서로 하는 것은 아닙니다.’

### 강사 설명 대본

**단계 1**
> “앞 장면 끝에서 물었죠. 금액에 정수라고 형을 적어 두면 잘못된 값도 막아 줄까요? 먼저 ‘형을 적어 둔다’는 게 뭔지 봅시다. amount: int는 ‘amount라는 이름의 자리에는 int, 곧 정수를 기대한다’는 표시예요. 이런 표시를 Type Hint라고 합니다.”

**단계 2**
> “이 표시는 누가 읽을까요? 먼저 사람입니다. 코드를 읽는 사람이 ‘아, 여기엔 정수가 와야 하는구나’ 하고 알 수 있죠. 그리고 검사 도구가 있어요. 실행하기 전에 코드를 훑어서 기대와 맞지 않는 곳을 찾아 줄 수 있습니다.”

**단계 3**
> “그럼 실행 중에는 어떨까요?” (답을 들은 뒤) “Python은 Type Hint만 보고 값을 막지 않습니다. 안내판은 문이 아니에요. 1000도, 글자 "1000"도, -5도 안내판 옆을 그대로 지나갑니다. 그래서 정말 막고 싶은 값이 있으면 따로 확인하는 코드가 필요해요.”

**단계 4**
> “그래서 두 가지를 나눠 봅니다. 왼쪽은 Type Hint, 기대하는 형을 표시만 합니다. 오른쪽은 값 검증, 실제 값이 규칙에 맞는지 확인합니다. 우리 금액 규칙은 ‘0보다 큰 정수’라고 합시다.”

**단계 5**
> “1000은 정수이고 0보다 크죠. 표시와도 맞고 규칙도 통과합니다.”

**단계 6**
> “따옴표가 붙은 "1000"은 숫자처럼 보여도 글자, 문자열입니다. int라는 기대와 다르지만, Type Hint가 이 값을 막아 주지는 않아요. 그리고 글자 그대로는 정수가 아니니까, 쓰려면 먼저 정수로 바꿔야 합니다. 그건 다음 그림에서 볼게요.”

**단계 7**
> “-5는 어떨까요?” (답을 들은 뒤) “-5는 정수입니다. int라는 기대에는 맞아요. 하지만 금액은 0보다 커야 한다는 규칙에는 맞지 않죠. ‘정수인가’와 ‘금액으로 쓸 수 있는가’는 다른 질문입니다.”

**단계 8**
> “실제로 사용자 입력은 대부분 글자로 들어옵니다. 그래서 두 단계를 나눠 생각해요. 먼저 글자를 정수로 바꾸는 자료형 변환, 그다음 바뀐 값이 규칙에 맞는지 보는 값 검증입니다. 이 화살표는 이 예시의 처리 흐름이에요.”

**단계 9**
> “"1000"은 정수 1000으로 바뀌고, 0보다 크니 규칙도 통과합니다. 이제 사용할 수 있어요.”

**단계 10**
> “"abc"는 정수로 바꿀 수가 없죠. 그래서 변환 단계에서 멈춥니다. 규칙 검사까지 가지도 않아요.”

**단계 11**
> “"-5"는 정수 -5로 잘 바뀝니다. 변환은 성공했어요. 하지만 금액 규칙 검사에서 거부됩니다. 변환이 된다고 해서 쓸 수 있는 값이 되는 건 아닙니다.”

**단계 12**
> “실제 용돈 기입장은 어떻게 할까요? 기록의 금액은 정수라고 Type Hint로 표시해 두었습니다. 명령줄에서 --amount로 받은 글자는 Scene 01에서 본 argparse가 type=int 규칙으로 정수로 바꾸고, 대화형 입력이나 CSV처럼 글자로 들어온 금액은 validate_amount()라는 검사 함수가 정수로 바꿉니다. 그리고 그 validate_amount()가 정수인지, 0보다 큰지 실제로 확인해요. 맞지 않으면 금액 오류를 일으키고, Scene 06의 공통 처리가 ‘[오류] 금액은 0보다 큰 정수여야 합니다’라고 알려 줍니다.”

## 4. 강사 노트 — 정확성 경계

- **런타임 비강제:** Python은 Type Hint를 보관하지만 실행 중에 그것만으로 값을 검사·변환·거부하지 않는다. 맞지 않는 값이 들어와 그 값을 쓰는 코드가 실패하면 그때 평소 규칙대로 오류가 날 수는 있다. ‘아무 일도 일어나지 않는다’가 아니라 ‘힌트가 막아 주지는 않는다’로 말한다.
- **검사 도구:** 정적 타입 검사기나 편집기가 실행 전에 맞지 않는 곳을 알려 줄 수 있다. 설치·설정은 다루지 않는다. ledger는 이런 검사기를 실행한 기록을 원고 근거로 쓰지 않았다.
- **변환과 검증의 순서:** F3의 순서는 이 예시의 흐름이다. 실제 ledger에서는 `validate_amount()` 한 함수 안에서 글자를 정수로 바꾼 뒤 검사하고, `--amount` 같은 명령줄 입력은 argparse가 먼저 정수로 바꿔 둔다. 모든 입력 경로가 같은 곳에서 같은 순서로 처리한다는 일반 규칙으로 말하지 않는다.
- **argparse의 변환 실패:** 명령줄에서 `--amount abc`처럼 정수로 바꿀 수 없으면 argparse가 사용법과 오류를 보여 주고 멈춘다(종료 코드 2). 이것은 Scene 06의 `handle_errors`가 아니라 argparse가 처리한다.
- **실제 `validate_amount()` (`d14e812`):** 글자면 앞뒤 공백을 지우고 `int()`로 바꾸며, 바꿀 수 없으면 금액 오류(`InvalidAmountError`). 정수가 아니거나 `bool`이면 금액 오류. 0 이하이면 금액 오류. 통과하면 정수를 돌려준다. 이 오류는 `LedgerError` 계열이라 Scene 06의 `handle_errors`가 ‘[오류] 금액은 0보다 큰 정수여야 합니다.’ ‘[힌트] 예: 15000’으로 알린다.
- **실제 타입 표시:** `models.py`의 기록 필드 `amount: int`, `validators.py`의 `validate_amount(value: int | str) -> int`. dataclass 필드의 Type Hint도 실행 중에 값을 검사하지 않으므로 별도 검증 함수가 있다.
- **개념 예시:** F1~F3·F5의 값과 규칙은 개념 예시다. ledger를 실행한 결과가 아니다.

## 5. 선택형 심화

1. **`bool`과 `int`** — Python에서 `bool`은 `int`의 하위 형이라 `True`도 int 표시에 맞는다. 그래서 ledger는 `bool`을 따로 막는다.
2. **정적 타입 검사기** — 실행 전에 Type Hint와 맞지 않는 코드를 찾는 도구
3. **Parameter와 Argument** — 함수 정의의 자리 이름과 호출 때 넣는 실제 값의 차이
4. **여러 형을 받는 표시** — `int | str`, `str | None`
5. **`None`과 기본값** — 값이 없을 수 있음을 표시하고 처리 코드를 함께 쓰기
6. **argparse `type=int`와 Type Hint의 차이** — 하나는 실제로 변환하고, 하나는 표시만 한다
