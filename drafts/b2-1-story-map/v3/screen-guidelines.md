# v3.2 대면 설명용 콘텐츠 기준

2026-10-24 · 교육 콘텐츠를 만들고 검토할 때의 기준이다. 화면 디자인은 승인된 콘텐츠를 기준으로 별도로 진행한다. 실제 강의 시간·학습 효과는 시범 수업 전 미검증이다.

## 1. 한 화면에 기본으로 보이는 것

1. **핵심 질문** — 장면 내내 같은 질문 하나
2. **큰 그림** — 지금 설명하는 개념을 보여 주는 그림 하나. 화면에서 가장 큰 영역
3. **화면 한 문장** — 지금 설명 중인 개념의 짧은 문장 하나. 길어도 두 줄 이내

이 밖의 설명은 강사가 말로 한다. 고정 요점 목록, 긴 설명 패널, 코드, 실행 로그는 기본 화면에 두지 않는다.

**확인 질문과 정리는 설명을 모두 마친 뒤에** 제시한다. 설명 도중에 미리 보이지 않게 한다. 답은 학습자가 먼저 말해 본 뒤 공개한다.

## 2. 그림의 종류와 규칙

모든 그림에 종류를 하나 정해 원고에 표시한다. 하나의 그림에 여러 개념을 넣지 않는다.

| 종류 | 보여 주는 것 | 규칙 | 예 |
| --- | --- | --- | --- |
| **흐름** | 실제로 일어나는 순서 | 순서 화살표 사용 가능. 화살표마다 무엇이 넘어가는지 짧게 적는다 | 01-F4 argparse, 02-F6 `__main__.py` 시작 |
| **구조** | 무엇이 무엇으로 이루어지는가, 누가 무엇을 맡는가 | **번호·순서 화살표 금지.** 같은 수준의 요소는 같은 크기 | 01-F2 명령 네 부분, 02-F2 네 역할 |
| **비교** | 두 가지의 같은 점과 차이 | 좌우 또는 위아래로 나란히, 같은 크기. 사이에 화살표 없음 | 01-F1 GUI·CLI, 02-F3 먼저 볼 곳 |
| **관계** | 개념 사이의 연결(포함·사용·역할 등) | 선에 관계 이름을 적는다. 실행 순서가 아님을 표시할 수 있다. 처음에는 선 하나만 | 02-F1 부탁 뒤의 여러 일, 02-F5 import |

- 실행 순서가 아닌 그림에 번호나 화살표를 억지로 넣지 않는다. 강의 진행 번호는 그림 밖 원고에만 둔다.
- **같은 구조는 같은 자리에.** 한 장면에서 같은 요소가 다시 나오면 위치·크기를 유지한다(예: Scene 02 F2·F4·F7의 2×2 자리, Scene 01 F2·F3의 명령 줄).
- 설명 중인 요소만 테두리·색으로 강조한다. 나머지를 흐리게 지워 읽을 수 없게 만들지 않는다. 색만으로 의미를 구분하지 않는다.
- 가상 예시와 실제 사례는 그림 위 작은 라벨로 구분한다(‘가상 todo 예시’ / ‘실제 사례 · ledger’).
- 가짜 실행 결과나 지어낸 데이터를 그리지 않는다.

## 3. 용어와 문장

- **일상 설명이 먼저, 기술 용어는 뒤에.** “기록의 모양을 정하는 부분을 Model이라고 합니다”처럼 연결한다.
- 한 단계에 새 기술 용어는 하나. 장면 전체의 새 용어 수를 원고 첫머리에 적는다.
- 화면 한 문장은 입문자가 소리 내어 읽어도 자연스러운 말로 쓴다. 주어가 사람·도구·프로그램 중 무엇인지 분명히 한다(예: “python은 Python으로 만든 프로그램을 실행해 주는 도구입니다”).
- 같은 단어가 장면마다 다른 뜻으로 쓰이면 명시한다(예: CLI — 조작 방식 / 프로그램의 부분).
- ‘반드시’, ‘항상’ 같은 단정은 사실일 때만 쓴다. 설계 선택은 “~로 나눌 수 있습니다”, Python 규칙은 “~합니다”로 구분한다.

## 4. 기본·강사 노트·선택형 심화의 분리

| 층 | 무엇을 넣나 | 어디에 |
| --- | --- | --- |
| 기본 | 핵심 질문, 그림, 화면 한 문장, 확인 질문, 한 문장 정리 | 학습자 화면 |
| 강사 대본 | 가리킬 순서, 말할 내용, 첫 질문, 비유 | 강사용 원고 |
| 강사 노트 | 정확성 경계, 예외, 설계 선택과 Python 규칙의 구분, 흔한 혼동 | 강사용 원고. 질문이 나올 때 사용 |
| 선택형 심화 | 기술 용어 대응, 내부 동작, 코드·실행, 기존 v2 자료 | 펼침 자료·용어사전·학습가이드 |

예외와 기술적 주의사항은 삭제하지 않는다. 사실 정확성을 유지한 채 강사 노트나 심화로 옮긴다.

## 5. 확인 질문 작성 기준

- 장면마다 **기본**(방금 배운 구분을 다시 말하기)과 **적용**(새 상황에 옮기기)을 최소 하나씩 둔다. 앞 장면과의 **연결** 질문을 하나 더할 수 있다.
- 적용 질문은 설명에서 쓴 예와 겹치지 않는 새 상황으로 만든다.
- 질문마다 기대 답, 흔한 오답, 강사 대응(어느 그림을 다시 가리킬지)을 적는다.
- 가상 예시에 없는 기능을 질문에 쓸 때는 ‘가상 확장 예시’임을 밝힌다.

## 6. 시간

장면 시간을 3~5분에 억지로 맞추지 않는다. 설명 시간과 질문·답 시간을 나누어 추정하고, 시범 수업 전에는 **추정**이라고 적는다. 시범 수업 후 실제 시간으로 고친다.

## 7. 디자인 단계로 넘길 참고 사항

아래는 v3.1 HTML 시안에서 확인한 화면 기준이다. 새 디자인 작업에서 다시 검토하며, 이번 v3.2에서 새로 검증하지 않았다.

- PC 1280×720에서 기본 단계가 한 화면에 들어오고 가로 넘침이 없을 것. 그림이 폭 대부분을 쓰고 화면 한 문장은 그림 아래.
- 모바일 390/360px에서는 그림을 작게 줄이지 않고 재배치한다(명령 2×2, 역할 세로 등). 명령·파일 이름이 중간에 끊기지 않을 것. 누를 영역 최소 44px.
- 실제 button, 보이는 초점 표시, 키보드 이동, 현재 문장의 스크린리더 안내. 자동 재생·장식 애니메이션·외부 요청 없음.
- 실물 프로젝터·휴대전화·스크린리더·200% 확대 확인은 아직 하지 않았다.

## 8. 강의 주소 (v3.7 추가)

- 강의 미리보기의 단계 주소는 `#장면-번호`(예: `#7-3`)가 기본이다.
- 장면의 교수 순서를 다시 짜서 단계가 바뀌는 경우, 그 장면은 **단계 ID 주소**(예: `#5-pause`)로 바꾸고 이전 숫자 주소를 의미가 대응하는 새 단계로 옮기는 대응표를 원고에 둔다(v3.7의 Scene 05·06). 다른 장면의 주소는 바꾸지 않는다.
- 개념지도의 복습 버튼은 이 주소로 이동하고, ‘개념지도로 돌아가기’와 브라우저 ‘뒤로’로 떠났던 단계에 돌아온다.
