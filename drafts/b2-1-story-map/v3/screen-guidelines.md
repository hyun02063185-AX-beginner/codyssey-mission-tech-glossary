# v3 강의 화면 기준

## 공통 구조

한 화면은 학습 질문 1개, 핵심 그림 1개, 핵심 포인트 최대 3개, 확인 질문 1~2개, 한 문장 정리, 선택 심화로 구성한다. 같은 장면의 그림을 바꿀 때도 질문은 유지한다. 장면 전체 설명 시간 목표는 3~5분이다.

Scene 01은 ‘명령 네 블록’과 ‘argparse 역할’, Scene 02는 ‘네 역할’과 ‘파일·패키지’ 두 화면으로 나눈다. 그림을 바꾸는 탭과 그림 안 강조를 바꾸는 이전/다음 버튼은 기능이 다르며 라벨을 명확히 한다. 마지막 단계에서는 ‘다음’이 비활성화된다. 장면·화면 이동은 위쪽의 실제 버튼으로 가능하다.

## PC 강의

- 기준 viewport 1280×720. 기본 화면(심화 닫힘)에 질문·그림·설명·확인·정리·조작이 보여야 한다. 기본 강의를 긴 세로 스크롤로 진행하지 않는다. 작은 노트북·브라우저 확대에서는 자연스러운 문서 스크롤을 허용하며 내용을 자르지 않는다.
- 전체 폭 최대 1184px, 제목 약 30px, 명령 30px, 역할 제목 24px, 설명 18px를 기본값으로 쓴다. 화면 설명은 오른쪽, 큰 그림은 왼쪽에 두어 가리키기 쉽게 한다.
- 밝은 바탕·짙은 글자. 선택 항목은 굵은 테두리·번호·‘선택’ 표시와 색을 함께 사용한다. 비선택 항목도 읽을 수 있도록 투명도를 낮추지 않는다.
- 명령 네 블록의 가로 배치는 명령을 읽는 순서다. 네 역할 사이에는 호출 화살표를 그리지 않는다. argparse 그림의 화살표만 입력→해석→요청이라는 개념 흐름을 나타낸다.

## 모바일 복습

- 390px·360px에서 실제 브라우저로 검사한다. 네 명령 블록은 2×2, 역할 블록은 세로 카드, 패키지 모듈은 2×2로 재배치한다. PC 그림을 통째로 줄이지 않는다.
- 본문 최소 16px, 누를 영역 최소 높이 44px. 파일 이름은 공간에 따라 줄바꿈하고 페이지 가로 넘침을 만들지 않는다.
- 각 블록의 명칭·역할·선택 설명은 PC와 동일하다. 모바일에서 삭제하는 학습 정보는 없다. 긴 심화·강사 노트는 native details로 접는다. 모바일은 복습용으로 자연스러운 세로 스크롤을 허용한다.

## 조작과 접근성

- 실제 HTML button을 사용한다. Tab/Shift+Tab으로 모든 버튼, Enter/Space로 선택한다. 그림 블록은 자유롭게 선택할 수 있고 이전/다음 버튼으로 순서대로 설명할 수 있다.
- 좌/우 방향키는 현재 그림의 단계, Home/End는 첫/마지막 단계다. Tab·Enter·Space의 기본 조작과 충돌하지 않는다. modifier 조합과 입력 요소에는 단축키를 적용하지 않는다. 방향키는 기본 강의 영역 안에서만 적용하고 심화·강사 노트의 문서 읽기에는 관여하지 않는다.
- `aria-pressed`·화면/단계 상태 텍스트·`aria-live=polite` 설명을 제공한다. 단계 전환 때 초점을 빼앗지 않는다. 화면 전환은 새 질문 제목에 초점을 둔다. `:focus-visible`에 3px 테두리를 제공한다.
- 자동 재생·장식 애니메이션 없음. 외부 글꼴·스크립트·API 요청 없음. Python 입력창·가짜 터미널 실행 결과 없음. argparse의 해석 카드는 고정된 **개념 설명**이며 실행 출력이 아니다.
- 심화 펼침과 강사 노트는 실제 내용이 있다. 서비스로 연결되지 않은 버튼은 만들지 않는다. 정적 문서 링크는 같은 저장소의 기존 자료를 가리키며 `file://`로 열어도 읽을 수 있다.

## 강사 보조와 평가

각 storyboard에 시작 질문, 그림을 가리킬 순서, 꼭 설명할 세 문장, 혼동 지점, 다음 화면 연결을 적는다. HTML에도 화면별 보조 노트를 접어 둔다. 기본 강의에는 긴 코드·API 목록·호출/import 추적·장문의 표를 넣지 않는다.

이해 확인 답은 펼치기 안에 제공한다. 강사가 학습자의 답을 먼저 듣고 연다. 개념 설명의 성공을 미션 완료로 판정하지 않는다. 프로젝터, 실물 휴대전화, 화면 낭독기, 실제 3~5분 수업 진행과 학습 효과는 별도 현장 검증 대상이다.
