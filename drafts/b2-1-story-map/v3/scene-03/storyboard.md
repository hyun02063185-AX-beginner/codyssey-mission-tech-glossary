## 1. 강의용 그림 4개

### 그림 F1 — CRUD 핵심 구조 (구조)

가운데 **기록 묶음**(기록 카드 4장), 둘레에 네 동작을 둔다. 위 추가, 오른쪽 조회, 아래 수정, 왼쪽 삭제. **번호·화살표 없음.** 오른쪽 아래 빈칸에 ‘네 동작의 분류 — 순서가 아닙니다’.

| 동작 | 큰 글씨 | 작은 글씨 | 선택하면 기록 묶음의 변화 (같은 자리) |
| --- | --- | --- | --- |
| 추가 | 추가 | Create · 새 기록을 더함 | 아래에 #5 카드가 ‘새로 추가’ 표시와 함께 나타남. 머리: 기록 4개에서 5개로 |
| 조회 | 조회 | Read · 기록을 꺼내 봄 | 카드 4장 그대로, ‘원본 그대로’ 표시. 머리: 기록 4개 그대로 |
| 수정 | 수정 | Update · 있는 기록을 바꿈 | #3 카드 금액 2,000원에 취소선, 옆에 2,500원, ‘수정됨’. 머리: 기록 4개 · 1곳 바뀜 |
| 삭제 | 삭제 | Delete · 있는 기록을 없앰 | #2 카드가 점선·취소선 빈자리로 바뀌고 ‘삭제됨’. 머리: 기록 4개에서 3개로 |

변화는 색만이 아니라 표시 글자(‘새로 추가’·‘수정됨’·‘삭제됨’), 취소선, 점선으로도 구분한다. 구조도 안에는 화살표 기호도 쓰지 않는다(머리의 개수 변화도 글로 적음).

### 그림 F2 — 데이터 변화 비교 (비교)

F1과 같은 배치에서 네 동작을 두 무리로 표시한다. 추가·수정·삭제에 **‘원본이 바뀜’**, 조회에 **‘원본 그대로’**. 가운데 기록 묶음은 처음 4개.

### 그림 F3 — 검색과 요약 (비교)

가운데 같은 기록 묶음, 왼쪽 검색 결과, 오른쪽 요약 결과.

| 위치 | 표시 문구 |
| --- | --- |
| 왼쪽 | **검색** · 조건: 분류가 간식 → #1 떡볶이 3,000원, #3 아이스크림 2,000원 · ‘조건에 맞는 기록 2개’ |
| 가운데 | 기록 4개. 검색 단계에서는 #1·#3에 ‘✓ 간식’ 표시 |
| 오른쪽 | **요약** · 계산: 금액 합계 → **14,500원** · 간식 5,000원 / 교통 1,500원 / 책 8,000원 · ‘기록 4개를 계산한 결과’ |
| 마지막 단계 | 가운데 머리에 ‘원본 4개 그대로’ |

### 그림 F4 — 적용: 이 요청은 어떤 동작일까? (확인)

새 요청 카드 6개. ‘답 보기’를 누르면 동작 이름이 나타난다(3절 표).

### 강사 설명 대본

**단계 1**
> “앞 장면에서 Service는 요청한 일을 처리하는 부분이었죠. 그럼 용돈 기입장에 들어오는 ‘요청한 일’에는 어떤 것들이 있을까요?” (답을 들은 뒤) “기록을 새로 적고, 보고, 고치고, 지우는 일이 있겠죠. 기록을 다루는 이 네 가지 기본 동작을 영어 머리글자를 따서 CRUD라고 부릅니다. 이 그림은 네 동작의 종류이지, 이 순서대로 실행된다는 뜻이 아닙니다.”

**단계 2 — 추가**
> “10월 6일에 지하철을 타서 1,500원을 썼다고 해 봅시다. 이 기록을 새로 적는 것이 추가, Create입니다. 기록이 4개에서 5개가 되었죠.”

**단계 3 — 조회**
> “기록을 꺼내 보는 것은 조회, Read입니다. 보기만 했으니 기록은 그대로 4개, 내용도 그대로예요.”

**단계 4 — 수정**
> “아이스크림 값을 잘못 적어서 2,500원으로 고친다면 수정, Update입니다. 기록 수는 그대로지만 내용 한 곳이 바뀌었습니다.”

**단계 5 — 삭제**
> “버스 기록을 잘못 넣어서 지운다면 삭제, Delete입니다. 기록이 3개로 줄었습니다.”

**단계 6 — 변화 비교**
> “네 동작을 원본 기록이 바뀌는지로 나눠 봅시다. 추가·수정·삭제는 원본이 바뀌고, 조회는 그대로입니다. 지금 보는 기록 묶음이 처음 4개 그대로인 것도 확인해 주세요. 앞의 세 변화는 같은 처음 기록에서 따로 비교한 것입니다.”

**단계 7 — 검색**
> “간식에 쓴 기록만 보고 싶다면요? 분류가 간식인 기록만 골라 보는 것을 검색이라고 합니다. 떡볶이와 아이스크림, 2개가 골라졌죠.”

**단계 8 — 요약**
> “이번엔 지금까지 모두 얼마를 썼는지 알고 싶다면요? 네 기록의 금액을 더하면 14,500원입니다. 분류별로 묶어서 더할 수도 있어요. 여러 기록을 계산해 하나의 결과를 얻는 것을 요약이라고 합니다.”

**단계 9 — 원본 유지**
> “검색 결과는 고른 기록들이고, 요약 결과는 계산한 값입니다. 결과는 다르지만 둘 다 기록을 읽어서 활용할 뿐이에요. 가운데 원본 기록은 여전히 4개 그대로입니다. 검색했다고 나머지 기록이 지워지는 것이 아닙니다.”

## 3. 이해 확인과 적용 — 설명을 모두 마친 뒤

| 구분 | 질문 | 기대 답 | 흔한 오답과 강사 대응 |
| --- | --- | --- | --- |
| 기본 · 원본 | 추가·조회·수정·삭제 중 원본 기록을 바꾸지 않는 동작은 무엇인가요? | 조회 | 수정이라고 답함 → F2를 다시 가리키며 “수정은 내용을 바꿨죠. 보기만 한 것은 조회입니다.” |
| 기본 · 검색과 요약 | 검색과 요약은 결과가 어떻게 다른가요? | 검색은 조건에 맞는 기록들, 요약은 계산한 하나의 결과 | “둘 다 기록을 줄인다”고 답함 → F3의 왼쪽(기록 2개)과 오른쪽(14,500원)을 번갈아 가리킴 |
| 기본 · 순서 | CRUD는 추가 → 조회 → 수정 → 삭제 순서로 실행해야 하나요? | 아니요. 네 동작의 종류일 뿐 순서가 아닙니다. | “네” → F1의 ‘순서가 아닙니다’ 표시와 단계 5(삭제만 따로 일어남)를 다시 보여 줌 |

**적용 (F4) — 이 요청은 어떤 동작일까?**

| 요청 | 기대 답 |
| --- | --- |
| 10월 7일에 산 연필 1,000원을 적어 줘. | 추가 (Create) |
| 떡볶이 금액을 3,500원으로 고쳐 줘. | 수정 (Update) |
| 교통에 쓴 기록만 보여 줘. | 검색 |
| 이번 달에 쓴 돈이 모두 얼마야? | 요약 |
| 잘못 적은 버스 기록을 지워 줘. | 삭제 (Delete) |
| 지금까지 적은 기록을 모두 보여 줘. | 조회 (Read) |

흔한 오답: ‘교통만 보여 줘’를 삭제로 답함 → “다른 기록을 지우는 게 아니라 고르기만 하는 거예요.” ‘모두 얼마야’를 조회로 답함 → “기록을 보여 주는 것이 아니라 계산한 값 하나를 원하죠.”

**한 문장 정리**

> 기록을 바꾸는 일(추가·수정·삭제), 고르는 일(검색), 계산하는 일(요약)을 구분하면 기능의 목적이 보입니다.

## 4. 강사 노트 — 정확성 경계

- **분류이지 순서가 아니다:** CRUD는 데이터 동작의 종류다. 한 프로그램이 네 동작을 모두 갖춰야 한다는 규칙도, 이 순서로 실행한다는 뜻도 아니다.
- **검색·요약과 Read:** 넓게 보면 검색·요약도 기록을 읽는 동작(Read)에 속한다. 이 장면에서는 결과의 차이를 보이기 위해 따로 이름을 붙였다.
- **Read와 Repository의 읽기:** CRUD의 ‘조회’는 사용자가 요청하는 동작이고, Scene 02의 Repository가 ‘파일에서 읽어 오는’ 일은 그 동작을 위해 저장소에서 기록을 가져오는 일이다. 같은 단어 ‘읽기’라서 섞이기 쉽다.
- **원본이 바뀐다는 뜻:** 이 장면은 프로그램이 다루는 기록이 바뀌는 것을 보여 준다. 바뀐 기록이 파일에 남는지는 Scene 04에서 다룬다.
- **변화 비교는 누적이 아니다:** 추가·수정·삭제의 예는 각각 처음 기록 4개에서 따로 비교한 것이다.
- **가상 데이터:** 모든 기록과 합계는 학습용이다. 실제 ledger에는 `add`·`list`·`search`·`summary`·`update`·`delete` 명령이 있지만, 이 화면의 숫자는 ledger를 실행한 결과가 아니다.

## 5. 선택형 심화

1. **기록을 구별하는 번호(ID)** — 수정·삭제할 기록을 정확히 가리키려면 번호가 필요하다. 실제 ledger는 `--id`로 지정한다.
2. **여러 조건 검색** — 날짜 범위·분류·메모 글자 등 조건을 함께 쓰면 모두 맞는 기록만 남는다(실제 ledger 검색은 조건을 AND로 결합).
3. **요약의 종류** — 합계 말고도 개수·평균·가장 많이 쓴 분류 등
4. **안전한 수정·삭제** — 잘못 지우지 않도록 확인하기, 없는 번호를 지정했을 때 알려 주기
