# Scene 01 v3.2 — 명령 한 줄로 일을 부탁하기

**핵심 질문: 명령 한 줄로 프로그램에 어떻게 일을 부탁할까?**

## 0. 장면 범위

| 항목 | 내용 |
| --- | --- |
| 학습 목표 | ① GUI와 CLI가 같은 부탁을 하는 두 가지 방법임을 말한다. ② 명령 한 줄을 네 부분으로 나누어 읽는다. ③ 앞부분은 Python이, 뒷부분은 프로그램이 읽는다는 것을 구분한다. ④ argparse는 받은 글자를 규칙대로 알아듣게 돕는 도구이며 실제 일을 처리하지 않는다는 것을 말한다. |
| 예시 | **가상 todo 프로그램**의 `python -m todo list --limit 5`. 실제 실행 화면·결과 목록은 보여 주지 않는다. |
| 선수 조건 | 터미널에 명령을 입력해 본 경험. 이전 미션에서 함수·클래스를 학습했다는 전제가 있지만 이 장면을 이해하는 데 필요하지 않으며, 숙련 여부를 가정하지 않는다. |
| 기본 화면에 새로 나오는 용어 | GUI, CLI, 옵션, argparse — **4개만**. 나머지 기술 용어는 선택형 심화로 둔다. |
| 다루지 않는 것 | argparse 코드, 함수 호출, `sys.argv` 같은 내부 API, 줄 번호, 교육생 코드 리뷰 |
| 예상 시간 | 설명 약 7~9분 + 학습자 질문·확인 약 3~5분 = **약 10~14분**. 시범 수업 전 **추정치**다. |

## 1. 강의용 그림 4개

한 그림에는 한 가지 개념만 담는다. 각 그림이 **흐름·구조·비교·관계** 중 무엇인지 표시한다.

### 그림 F1 — 같은 부탁, 두 가지 방법 (비교)

| 위치 | 표시 문구 |
| --- | --- |
| 그림 제목 | 같은 부탁, 두 가지 방법 |
| 가운데 위 (공통) | 부탁: **할 일 목록을 최대 5개 보여 줘** |
| 왼쪽 | 창 모양 화면에 `[목록 보기]` 버튼, `최대 개수 [5]` 선택칸 · 아래 라벨 **GUI — 화면을 눌러서 부탁** |
| 오른쪽 | 터미널 한 줄 `python -m todo list --limit 5` · 아래 라벨 **CLI — 글자로 입력해서 부탁** |
| 상단 작은 라벨 | 가상 todo 예시 |

- 좌우를 같은 크기로 나란히 둔다. 둘 사이에 화살표를 넣지 않는다(순서가 아니라 비교다).
- 넣지 않을 것: 실행 결과 목록, 가짜 할 일 데이터, 메뉴 구조 세부.

### 그림 F2 — 명령 한 줄의 네 부분 (구조) · **핵심 구조도**

명령을 화면 폭 대부분을 쓰는 크기로 한 줄에 쓰고 네 칸으로 나눈다.

| `python` | `-m todo` | `list` | `--limit 5` |
| --- | --- | --- | --- |
| **실행 도구** | **실행할 대상** | **할 일** | **조건** |
| Python 프로그램을 실행해 주는 도구 | todo 프로그램을 실행해 줘 | 목록을 보여 줘 | 최대 5개까지만 |

- 첫째 줄(명령)과 둘째 줄(일상 이름)은 처음부터 보인다. 셋째 줄(짧은 뜻)은 **지금 설명하는 칸의 것만** 보인다.
- `--limit 5` 칸에만 설명 단계에서 작은 보조 라벨 **옵션**을 추가한다. 다른 기술 용어(인터프리터·하위 명령·값)는 그림에 넣지 않는다.
- 칸 사이에 번호·화살표를 넣지 않는다. 왼쪽부터 가리키는 것은 읽는 순서일 뿐이다.
- 이 그림은 마지막 적용 질문에서 `--limit 3`으로 바뀐 형태로 한 번 더 쓴다.

### 그림 F3 — 누가 어느 부분을 읽을까 (흐름: 한 번 넘겨줌)

F2와 같은 명령 줄을 같은 위치에 두고, 위에 괄호 두 개와 아래에 화살표 하나를 더한다.

| 위치 | 표시 문구 |
| --- | --- |
| `python -m todo` 위 괄호 | **Python이 읽는 부분** — 어떤 프로그램을 실행할까? |
| `list --limit 5` 위 괄호 | **todo 프로그램이 받는 부분** — 무엇을, 어떻게 할까? |
| 아래 화살표 (Python → todo) | todo를 시작하고, 나머지 글자를 넘겨줌 |

- 화살표는 실제로 일어나는 '넘겨줌' 한 번만 표시한다. 다른 화살표는 없다.
- F2와 명령의 위치·크기를 같게 유지해 같은 명령을 다른 관점으로 본다는 것이 보이게 한다.

### 그림 F4 — argparse가 하는 일 (흐름)

왼쪽에서 오른쪽으로 세 상자, 그리고 점선으로 다음 장면 예고 상자 하나.

| 상자 | 표시 문구 |
| --- | --- |
| ① 받은 글자 | `list --limit 5` |
| ② argparse + 미리 정한 규칙 | **argparse** · 규칙 예: 할 일 자리에는 정해 둔 이름(list 등) / `--limit` 뒤에는 숫자 하나 |
| ③ 알아들은 내용 | 할 일 = 목록 보기 · 최대 개수 = 5 |
| (점선) 다음 장면 | 실제로 목록을 찾아 보여 주는 일 → 프로그램의 다른 부분 (Scene 02) |

- ①→②→③ 화살표는 실제 처리 흐름이므로 사용한다. ③과 점선 상자 사이에는 점선만 쓰고, '여기부터는 argparse의 일이 아님'이라는 경계를 굵게 표시한다.
- 넣지 않을 것: 코드, 함수 이름, 오류 메시지 예시.

## 2. 단계별 강의 진행

화면에는 **핵심 질문 + 그림 + 아래의 '화면 한 문장'**만 보인다. '강사 대본'은 강사가 말로 하는 내용이며 화면에 띄우지 않는다. 단계 번호는 강의 진행 순서이고 프로그램의 실행 순서가 아니다.

| 단계 | 그림 · 가리킬 곳 | 화면 한 문장 |
| --- | --- | --- |
| 1 | F1 · 공통 부탁 → 왼쪽 GUI | GUI는 화면의 버튼과 메뉴를 눌러 프로그램에 일을 부탁하는 방법입니다. |
| 2 | F1 · 오른쪽 CLI | CLI는 같은 부탁을 글자로 입력해 전하는 방법입니다. |
| 3 | F2 · 명령 전체 | 명령 한 줄은 네 부분으로 나누어 읽을 수 있습니다. |
| 4 | F2 · `python` | python은 Python으로 만든 프로그램을 실행해 주는 도구입니다. |
| 5 | F2 · `-m todo` | -m todo는 Python에게 “todo라는 프로그램을 찾아 실행해 줘”라고 알려 줍니다. |
| 6 | F2 · `list` | list는 todo 프로그램에게 맡길 일, 곧 ‘목록 보기’입니다. |

| 8 | F3 · 왼쪽 괄호 → 오른쪽 괄호 → 화살표 | 앞부분은 Python이 읽고, 뒷부분은 todo 프로그램이 넘겨받아 읽습니다. |
| 9 | F4 · ① → ② → ③ | argparse는 프로그램이 받은 글자를 미리 정한 규칙에 맞춰 알아듣도록 돕는 Python 도구입니다. |
| 10 | F4 · ③과 점선 상자 사이 경계 | argparse는 부탁을 알아듣는 데까지 돕고, 실제로 목록을 찾아 보여 주는 일은 프로그램의 다른 부분이 합니다. |
| 마무리 | 이해 확인 → F2(`--limit 3`) 적용 → 한 문장 정리 | (아래 3절) |

### 강사 설명 대본

**단계 1 — F1 공통 부탁, GUI**
> “할 일 목록을 다섯 개만 보고 싶다고 해 봅시다. 화면이 있는 프로그램이라면 무엇을 누를까요?” (답을 들은 뒤) “맞아요. ‘목록 보기’ 버튼을 누르고 개수를 5로 고르겠죠. 이렇게 화면을 눌러서 부탁하는 방법을 GUI라고 합니다.”

**단계 2 — F1 CLI**
> “같은 부탁을 글자로 할 수도 있습니다. 오른쪽처럼 터미널에 명령 한 줄을 입력하는 방법이에요. 이것을 CLI라고 합니다. 부탁하는 내용은 왼쪽과 똑같고, 전하는 방법만 다릅니다.”

**단계 3 — F2 전체**
> “이 한 줄이 처음엔 암호처럼 보이지만, 네 부분으로 나누면 읽을 수 있습니다. 실행 도구, 실행할 대상, 할 일, 조건이에요. 왼쪽부터 하나씩 보겠습니다.”

**단계 4 — `python`**
> “맨 앞의 python은 ‘Python으로 만든 프로그램을 실행해 줄 도구를 쓰겠다’는 뜻입니다. 우리가 부탁할 todo 프로그램이 Python으로 만들어졌기 때문에, 먼저 이 도구를 부르는 거예요.”

**단계 5 — `-m todo`**
> “다음은 무엇을 실행할지입니다. -m todo는 Python에게 ‘todo라는 이름의 프로그램을 찾아서 실행해 줘’라고 알려 주는 부분이에요. 여기까지는 Python에게 하는 말입니다.”

**단계 6 — `list`**
> “이제부터는 todo 프로그램에게 하는 말입니다. list는 ‘목록을 보여 줘’라는 할 일이에요. 화면 프로그램의 ‘목록 보기’ 버튼에 해당합니다.”

**단계 7 — `--limit 5`**
> “마지막 --limit 5는 조건입니다. ‘최대 다섯 개까지만’이라는 뜻이죠. 화면 프로그램에서 개수를 5로 고른 것과 같습니다. 이렇게 하이픈 두 개로 시작해서 할 일에 조건을 붙이는 부분을 **옵션**이라고 부릅니다.”

**단계 8 — F3**
> “그런데 이 한 줄을 한 사람이 다 읽는 건 아닙니다. 앞의 python -m todo는 Python이 읽고 ‘아, todo를 실행하면 되는구나’ 하고 todo를 시작합니다. 그리고 남은 list --limit 5는 그대로 todo 프로그램에게 넘겨줘요. 그러니까 할 일과 조건을 알아듣는 것은 todo 프로그램의 몫입니다.”

**단계 9 — F4 ①→②→③**
> “todo 프로그램이 받은 것은 그냥 ‘list’, ‘--limit’, ‘5’라는 글자입니다. 이 글자를 알아들으려면 규칙이 필요하죠. ‘할 일 자리에는 정해 둔 이름이 온다’, ‘--limit 뒤에는 숫자 하나가 온다’ 같은 규칙이요. 프로그램을 만든 사람이 이 규칙을 미리 정해 두면, **argparse**라는 Python 도구가 받은 글자를 규칙에 맞춰 ‘할 일은 목록 보기, 최대 개수는 5’로 정리해 줍니다.”
> (비유가 필요하면) “식당의 주문 접수 창구를 떠올려 보세요. 손님의 말을 정해진 주문서 양식에 맞춰 정리해 주방에 넘기는 역할입니다.”

**단계 10 — F4 경계**
> “중요한 점이 하나 있습니다. argparse는 부탁을 알아듣는 데까지만 돕습니다. 저장된 할 일을 실제로 찾아오고 다섯 개를 골라 화면에 보여 주는 일은 프로그램의 다른 부분이 해요. 접수 창구가 요리를 하지 않는 것과 같습니다. 그 ‘다른 부분’이 누구인지는 다음 장면에서 봅니다.”

## 3. 이해 확인과 정리 — 설명을 모두 마친 뒤

확인 질문과 정리는 단계 10까지 설명한 **뒤에만** 제시한다. 답은 학습자가 먼저 말해 본 뒤 공개한다.

| 기본 (누가 읽나) | `--limit 5`는 Python과 todo 프로그램 중 누가 읽나요? | todo 프로그램 (argparse의 도움을 받아) | Python이라고 답함 → F3을 다시 가리키며 “Python은 -m todo까지 읽고 나머지를 넘겨줬습니다.” |
| 적용 (새 조건) | 목록을 최대 3개만 보고 싶다면 명령의 무엇을 바꾸면 될까요? | 조건의 5를 3으로: `python -m todo list --limit 3`. 나머지 세 부분은 그대로 | 할 일이나 실행 대상을 바꾸려 함 → “바뀐 것은 ‘몇 개까지’라는 조건뿐이죠.” |
| 역할 구분 (선택) | argparse가 저장된 할 일을 꺼내 오나요? | 아니요. 부탁을 알아듣는 데까지 돕고, 실제 일은 프로그램의 다른 부분이 합니다. | “네”라고 답함 → F4의 경계선과 접수 창구 비유로 다시 설명 |

## 4. 강사 노트 — 정확성 경계

학습자 화면에는 띄우지 않는다. 질문이 나오거나 오해가 보일 때 사용한다.

- **가상 예시:** todo는 설명용 가상 프로그램이다. 실행 결과를 만들어 보여 주지 않는다. 적용 질문은 이미 있는 조건의 값만 바꾼다. 없는 할 일(예: 새 명령)을 추가로 예시할 때는 ‘가상 확장 예시’라고 밝힌다.
- **`python`을 찾는 주체:** 엄밀히는 터미널(셸)이 `python`이라는 이름의 프로그램을 찾아 실행한다. 환경에 따라 `python3`, `py`로 입력하기도 한다.
- **해석 주체의 경계:** Python 자신의 옵션은 `-m 대상` 앞에 쓴다. `-m todo` 뒤에 오는 글자는 모두 todo 프로그램의 몫으로 넘어간다.
- **`-m`의 뜻:** ‘이름으로 모듈을 찾아 실행’이다. 대상은 파일 하나(모듈)일 수도, 여러 파일의 묶음(패키지)일 수도 있다. 모듈·패키지는 Scene 02에서 다룬다.
- **argparse의 위치:** 모든 CLI 프로그램이 argparse를 써야 하는 것은 아니다. 다른 방법이나 다른 도구도 있다. argparse는 해석을 돕고 데이터를 처리하지 않는다.
- **GUI와 CLI:** 서로 반드시 다른 프로그램이라는 뜻이 아니다. 한 프로그램이 두 방식을 모두 제공할 수도 있다.
- **비유의 한계:** argparse는 사람처럼 짐작하지 않는다. 프로그램이 정해 둔 규칙을 그대로 적용하며, 규칙에 맞지 않으면 알아듣지 못한다.

## 5. 선택형 심화 목록

기본 강의에서는 다루지 않는다. 질문이 나오거나 복습할 때 연결한다. 실행·코드는 기존 학습가이드, 정확한 정의는 용어사전으로 보낸다.

1. **기술 용어 대응** — 실행 도구 = Python 인터프리터, 할 일 = 하위 명령(subcommand), 조건 = 옵션(`--limit`)과 그 값(`5`), 명령 전체에서 프로그램 이름 뒤의 글자들 = 명령줄 인자
2. **짧은 옵션과 긴 옵션** — `-h`와 `--help`처럼 같은 뜻을 두 형태로 두기도 한다.
3. **값이 없는 옵션** — `--help`처럼 켜기만 하는 옵션도 있다.
4. **규칙에 맞지 않는 입력** — 예를 들어 `--limit` 뒤에 숫자가 아닌 글자를 쓰면 argparse가 사용법과 오류 메시지를 보여 주고 멈춘다.
5. **글자 ‘5’와 숫자 5** — 프로그램이 받은 것은 글자다. 규칙에 ‘숫자로 바꾸기’를 정해 두면 argparse가 바꿔 준다. → Scene 07의 Type Hint·검증과 비교
6. **도움말 자동 생성** — 규칙을 정해 두면 `--help` 안내문을 argparse가 만들어 준다.
7. **내부 동작** — 프로그램이 받은 글자 목록(`sys.argv`)과 argparse 사용 코드. 학습가이드에서 실행과 함께 다룬다.
8. **기존 v2 자료** — [기존 Scene 01 원고](../../scene-01/script.md)
