# Scene 01 — 명령 한 줄 읽기

**공통 질문:** 명령 한 줄은 누구에게 어떤 일을 부탁하는 말일까?

**목표:** 네 블록의 역할과 Python/프로그램의 해석 경계를 설명한다.

**사례:** 가상 할 일 프로그램 todo. 이 HTML은 todo를 실행하지 않는다. 전체 4~5분 계획.

## 화면 A — 명령 네 블록 (약 2~3분)

**메시지:** 한 줄을 실행 도구·대상·할 일·조건으로 나누면 읽을 수 있다.

**그림:** `python` / `-m todo` / `list` / `--limit 5`. PC에서는 가로 네 블록, 모바일에서는 읽는 순서를 유지한 2×2 카드. 각 블록을 눌러 해당 이름·담당 주체·역할을 크게 표시한다. 네 블록을 잇는 실행 화살표는 사용하지 않는다.

**처음 던질 질문:** “할 일 목록을 최대 다섯 개 보여 달라고 버튼 대신 말로 요청한다면 어떻게 표현할까요?”

**가리킬 순서:**

1. `python`: 터미널·운영체제가 찾아 실행하는 Python 인터프리터. CLI는 문자, GUI는 버튼·메뉴라는 조작 방식 비교.
2. `-m todo`: Python 옵션 `-m`과 실행할 이름 `todo`. 이 예시는 실행 가능한 패키지다. 파일명 `todo.py`를 입력한 것이 아니다.
3. `list`: todo가 제공하는 하위 명령, ‘목록을 본다’는 할 일 선택.
4. `--limit 5`: `--limit`는 옵션, `5`는 그 값. 이 가상 프로그램은 최대 표시 개수로 정의했다. 정확히 다섯 기록이 존재한다고 보장하지 않는다.

**꼭 설명할 세 문장:**

- “CLI는 버튼 대신 문자를 입력해 프로그램에 요청하는 방식이고, GUI는 버튼과 메뉴 같은 화면 요소를 사용합니다.”
- “Python 인터프리터는 `-m todo`를 보고 이름으로 실행 대상을 찾습니다.”
- “`list`와 `--limit 5`는 todo가 이해해야 할 기능과 조건입니다.”

**혼동:** `-m`은 Python 옵션이며 todo의 argparse 몫이 아니다. 모든 옵션이 값을 가지는 것은 아니다. `python` 명령의 이름·사용 가능 여부는 환경에 따라 다르다.

**확인 질문:** `--limit 5`에서 옵션과 값은 각각 무엇인가? / `-m`은 누구의 옵션인가?

**기대 답:** `--limit` / `5`, Python 인터프리터.

**한 문장 정리:** 명령은 실행 도구·실행 대상·할 일·조건으로 나누어 읽을 수 있다.

**다음 화면 연결:** “프로그램에 전달된 문자에서 할 일과 조건을 어떻게 구분할까요?”

## 화면 B — argparse의 역할 (약 1~2분)

**메시지:** 프로그램이 규칙을 정하면 argparse가 문자 입력을 요청으로 해석한다.

**그림:** `list --limit 5` (프로그램에 전달된 문자) → `argparse` (프로그램이 정한 규칙) → ‘목록 보기 / 최대 5개’ (해석한 요청). 실제 실행 로그나 Namespace repr를 보여 주지 않는다. Python이 프로그램을 시작한 뒤 그 안에서 해석한다는 범위를 설명한다.

**처음 던질 질문:** “같은 문자라도 프로그램마다 뜻이 다를 수 있는데, 어떤 약속으로 구분할까요?”

**가리킬 순서:** 입력 → argparse → 해석한 요청. 이전/다음 단계로 각 영역을 강조한다.

**꼭 설명할 세 문장:**

- “프로그램에는 `list --limit 5`처럼 문자가 전달됩니다.”
- “argparse는 프로그램이 미리 정한 하위 명령과 옵션 규칙을 참고해 입력을 해석합니다.”
- “해석한 요청으로 어떤 일을 수행할지는 프로그램의 다른 부분이 맡습니다.”

**혼동:** argparse가 Python을 시작하거나 자동으로 CRUD를 처리하는 것이 아니다. argparse는 표준 라이브러리의 선택지이고 모든 CLI가 반드시 사용하는 것은 아니다. 숫자 변환도 정해 둔 규칙이 있어야 한다.

**확인 질문:** argparse가 목록을 저장하는 역할도 맡을까? / 다른 CLI도 항상 argparse를 쓸까?

**기대 답:** 아니다. 요청 해석과 데이터 처리는 구분한다. 다른 방법도 있다.

**한 문장 정리:** argparse는 문자 입력과 프로그램이 이해할 요청 사이를 이어 준다.

**다음 장면 연결:** “명령 해석 다음에 할 일 처리·저장·결과 표시는 어디에 나누어 둘까요?”

## 선택형 심화와 강의 후 활동

HTML 펼침: 값 없는 도움말 옵션, Python/앱 도움말의 위치, argparse 선택 여부. 기존 [Scene 01 원고](../../scene-01/script.md)에 API·입력 오류·실행 데모가 있다. 기본 강의의 필수 코드 리뷰로 사용하지 않는다.

자기 실행 명령을 종이나 말로 네 역할로 나누어 본다. 가상 todo 명령을 교육생 프로그램에서 그대로 실행시키지 않는다. ledger는 필요할 때만 별도 사례이며 이번 기본 시안에 추가하지 않았다.
