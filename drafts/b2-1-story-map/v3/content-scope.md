## 정확성 경계와 근거

- 실제 사례는 m03-pocket-money-ledger의 d14e812ca1e1caaa88fd23fae7029d95d560c2d9를 정적 대조했다. models.py는 기록 구조, repository.py는 파일 읽기/저장, services.py는 요청 처리, cli.py는 argparse·표현·입출력 코드를 가진다. 코드 줄이나 함수 내부는 학습자 화면에 넣지 않는다.
- 네 파일은 이 사례의 선택이다. 역할과 파일은 항상 일대일이 아니며 저장 변경이 저장소에만 영향을 준다고 보장하지 않는다. 강사 노트에서 '먼저 살펴본다'의 범위를 설명한다.
- Scene 01은 가상 todo, Scene 02는 실제 ledger의 파일 예시다. 패키지 마지막 단계의 todo는 '앞 장면의 가상 todo'라고 명시해 섞지 않는다.
- argparse의 해석과 Python의 -m 처리를 구분한다. Generator/JSONL의 메모리 효과, Type Hint의 런타임 비강제, Decorator의 처리 범위를 단순화로 왜곡하지 않는다.
- 공식 목표 대응은 기존 v2에서 추적한 상태를 유지한다. 공식 원문·평가 기준의 새 독립 대조는 하지 않았다.
