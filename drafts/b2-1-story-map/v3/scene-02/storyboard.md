# Scene 02 v3.1 — 네 책임과 파일·패키지

2026-10-24 · 질문: **프로그램을 여러 파일로 나누는 이유는 무엇일까?**

목표는 모델·저장소·서비스·CLI의 책임을 구분하고, 모듈·패키지·import로 함께 쓰는 의미를 설명하는 것이다. 실제 용돈 기입장 ledger의 d14e812 사례를 정적 대조했다. 전체 4~5분 계획, **A6 + B4 = 10단계**.

## A — 네 책임과 변경 상황 (1~6/10, 약 2~3분)

큰 2×2 책임 그림. **그림 안 번호·호출 화살표는 없다.** 모바일은 같은 책임을 세로로 배치한다. 아래 표의 번호는 강의 설명 순서일 뿐 실제 실행 흐름이 아니다.

| 강의 단계 | 책임·파일 | 현재 한 문장 |
| --- | --- | --- |
| 1/10 | 모델 Model · models.py | 모델은 날짜·금액·메모처럼 기록이 어떤 항목을 갖는지 정합니다. |
| 2/10 | 저장소 Repository · repository.py | 저장소는 기록을 읽고 저장하는 일을 맡습니다. |
| 3/10 | 서비스 Service · services.py | 서비스는 추가·조회·요약처럼 요청받은 일을 처리합니다. |
| 4/10 | CLI · cli.py | CLI는 명령 입력을 받고 처리 결과를 사람이 읽을 수 있게 보여 줍니다. |
| 5/10 | 상황: 저장 방식 변경 · 저장소 강조 | 파일 저장 형식을 바꾸려면 기록 읽기·저장을 맡은 저장소부터 살펴봅니다. |
| 6/10 | 상황: 출력 방식 변경 · CLI 강조 | 금액을 1,000원처럼 보여 주려면 결과 표시를 맡은 CLI부터 살펴봅니다. |

상황 버튼과 책임 블록은 모두 실제 선택 가능하다. 상황 버튼을 누르면 해당 문장과 책임 테두리가 바뀐다. UI가 파일을 수정하거나 가짜 실행 결과를 만들지는 않는다.

강사 첫 질문: “저장 형식만 바꾸고 싶을 때 어느 부분부터 찾으면 좋을까요?”

꼭 설명할 세 문장: 모델은 모양, 저장소는 읽기/저장이다. 서비스는 요청 처리, CLI는 입력/표시다. 바꿀 내용에 따라 먼저 살펴볼 책임이 달라진다.

강사 노트: 역할과 파일은 필수 일대일 관계가 아니다. 여기의 파일명은 실제 한 사례다. 저장 변경은 다른 책임에도 영향을 줄 수 있어 저장소만 수정하면 된다고 단정하지 않는다. 선택 순서는 호출/import 순서가 아니다. 클래스·객체·self·__init__() 문법은 가르치지 않는다. 공식 클래스 구조화 요구는 실제 구현과 검증을 별도로 확인한다.

연결: “이 책임을 담은 파일들은 어떻게 묶고 함께 사용할까요?” A 마지막에도 확인·정리는 띄우지 않는다.

## B — 파일·묶음·함께 사용·시작 파일 (7~10/10, 약 2분)

ledger/ 경계 안의 models.py·repository.py·services.py·cli.py로 같은 사례를 이어 본다. 기존 역할 이름 외 새로운 용어는 선택된 단계에서 하나씩 설명한다. __init__.py는 그림이나 기본 선택 항목에 없다.

| 강의 단계 | 가리킬 요소 | 현재 한 문장 |
| --- | --- | --- |
| 7/10 | 코드 파일 한 개 | 이 예시에서는 Python 코드가 들어 있는 파일 하나를 모듈이라고 봅니다. |
| 8/10 | ledger/ 경계 | 패키지는 함께 쓰는 관련 모듈을 묶은 구조입니다. |
| 9/10 | import 표식 | import로 다른 모듈의 이름이나 기능을 가져와 사용합니다. |
| 10/10 | 앞 장면의 가상 todo 시작 파일 | 앞 장면의 python -m todo는 todo 패키지의 __main__.py를 시작점으로 실행합니다. |

10/10에서는 ledger 파일 예시와 '앞 장면의 가상 todo' 표식을 분명히 나눈다. import 설명 띠와 시작 파일 띠는 한 번에 하나만 표시한다. 일반 패키지 초기화 파일은 선택 보충에만 설명한다.

강사 첫 질문: “관련 파일들을 묶고 다른 파일의 기능을 사용하려면 어떻게 할까요?”

꼭 설명할 세 문장: 이 예시의 코드 파일은 모듈이고 묶음은 패키지다. import로 다른 모듈을 함께 쓴다. 앞 장면의 python -m todo는 todo의 __main__.py를 시작점으로 실행한다.

강사 노트: .py 파일은 입문 모델이며 내장/확장 모듈도 있다. 일반 패키지 초기화 파일은 __init__.py지만 namespace package에는 없을 수 있다. 모든 패키지가 실행 가능하거나 __main__.py를 갖는 것은 아니다. import가 곧 함수 호출은 아니다. 내부 실행·import 의존도를 추적하지 않는다.

## 마지막 이해 확인과 정리 — 10/10에서만

- **기본:** 기록의 모양과 읽기·저장은 각각 누구의 책임인가요? → 모델 / 저장소
- **새 상황 적용:** 날짜 표시만 10월 24일로 바꾸려면 누구부터 볼까요? → CLI
- **정리:** 모델·저장소·서비스·CLI의 책임을 나누고, 모듈을 패키지로 묶어 import로 함께 사용합니다.
