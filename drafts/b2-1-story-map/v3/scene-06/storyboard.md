# Scene 06 v3.7 — 함수를 감싸 꾸미기: Decorator

**핵심 질문: 함수를 그대로 사용하면서 앞뒤에 새로운 일을 붙일 수 있을까?**

v3.5~v3.6 원고는 ‘공통 처리의 반복’에서 시작해 Decorator와 실제 구현으로 갔다. v3.7은 Owner의 실제 교육 방식에 따라 **변수 재대입 → 함수도 넘기고 돌려받는 값 → 함수 감싸기 → 전·후 처리 → Decorator → 활용 → 실제 사례** 순서로 일반 개념부터 쌓는다. 기존의 감싸기 구조도(바깥 테두리·안쪽 원래 기능, 정상·오류)와 활용 그림은 그대로 쓴다.

## 2. 강의용 그림 6개

### F1 — 같은 이름에 새 결과 연결 (구조)

왼쪽 큰 코드 두 줄 `a = 1` / `a = a + 1`. 오른쪽 그림: 이름표 **a**가 값 **1**을 가리키다가, `a + 1`로 새 값 **2**를 만들고 이름표 **a**가 **2**로 옮겨 감. 작은 글씨 ‘값 1이 2로 바뀌는 것이 아니라, a라는 이름이 새 값 2를 가리킴’. 이 그림은 Decorator가 아니라 뒤의 ‘같은 이름에 새 결과 연결’을 위한 준비다.

### F2 — 함수를 넘기고 돌려받기 (흐름: 실제로 일어나는 전달과 반환)

`원래 함수 work (기록 추가)` → `꾸미는 함수 decorate` → `새 함수`. 화살표 두 개는 실제 전달·반환이다.

| 단계 | 강조 |
| --- | --- |
| pass | 첫 화살표 ‘함수를 값처럼 넘김’ |
| ret | 둘째 화살표 ‘새 함수를 돌려줌’ |
| rebind | 위에 `work = decorate(work)`, 이름표 **work**가 새 함수로 옮겨 감. 원래 함수 칸에 ‘원래 함수는 그대로 · 새 함수 안에서 쓰임’. 옆에 ‘a = a + 1과 같은 모양 — 결과에 같은 이름을 다시 연결’ |

### F3 — 함수 감싸기와 실행 전·후 (구조 → 흐름)

**wrapfn:** 큰 상자 ‘새 함수’ 안에 ‘원래 함수 실행’ 블록. 화살표 없음.
**prepost:** 같은 상자 안에 `실행 전: ‘시작합니다’ 알림` → `원래 함수 실행 (기록 추가)` → `실행 후: ‘끝났습니다’ 알림`(실제 실행 흐름이라 화살표 2개). 아래 작은 글씨 ‘정상적으로 끝난 경우의 예’.

### F4 — Decorator 기본 구조 · 기존 그림 그대로

바깥 띠 ‘Decorator · 바깥: 덧붙인 공통 처리’와 안쪽 ‘원래 기능’. deco → inner → outer → ok(✓) → err(✕) 다섯 상태. 화살표 없음.

### F5 — 언제 사용하면 좋을까 · 기존 그림 그대로

rep(기능마다 같은 처리 반복 · 개념 그림) → gather(전·후) → uses(오류 처리 · 로그 기록 · 실행 시간 측정, 뒤의 둘은 ‘일반 개념 예시 · 용돈 기입장에는 없음’).

### F6 — 실제 용돈 기입장 사례 (흐름, 실제 사례) · 한 단계 요약

CLI 명령 → `handle_errors`가 감싼 `_dispatch` → 결과 세 가지를 한 화면에: ✓ 정상 → 종료 코드 0 / `LedgerError` 계열 → [오류]·[힌트], 종료 코드 1 / ✕ 그 밖의 오류 → 잡지 않음.

### 강사 설명 대본

**1 — a = a + 1**
> “a = 1이라고 적으면 a라는 이름이 1을 가리킵니다. 그다음 a = a + 1을 보세요. 오른쪽부터 읽습니다. 지금 a가 가리키는 1에 1을 더해 2라는 새 값을 만들고, 그 결과에 다시 a라는 이름을 붙여요. 이미 있는 값을 써서 새 결과를 만들고, 같은 이름에 다시 연결한 겁니다. 1이라는 값 자체가 2로 바뀐 게 아니라, a라는 이름이 새 값을 가리키게 된 거예요. 이 모양을 기억해 두세요. 곧 함수에서 똑같이 씁니다.”

**2 — 함수도 넘길 수 있다**
> “Python에서는 함수도 숫자나 글자처럼 다룰 수 있습니다. 기록을 추가하는 함수 work가 있다고 합시다. 이 work를 다른 함수, 예를 들어 decorate라는 꾸미는 함수에 넘겨줄 수 있어요. 함수를 실행하는 게 아니라 함수 자체를 값처럼 건네는 겁니다.”

**3 — 함수를 돌려줄 수 있다**
> “그리고 함수는 결과로 새 함수를 돌려줄 수도 있습니다. decorate는 work를 받아서, 새 함수를 만들어 돌려줘요.”

**4 — work = decorate(work)**
> “이제 a = a + 1과 같은 모양이 나옵니다. work = decorate(work). 오른쪽부터 읽어요. work를 decorate에 넘기고, 돌려받은 새 함수에 다시 work라는 이름을 붙입니다. 원래 함수가 고쳐지거나 사라진 게 아니에요. 원래 함수는 그대로 있고, 새 함수 안에서 쓰입니다. 바뀐 건 work라는 이름이 가리키는 대상이에요.”

**5 — 감싸기**
> “그 새 함수는 어떻게 생겼을까요? 안에서 원래 함수를 실행하도록 만들 수 있습니다. 원래 함수를 바깥에서 감싼 모양이죠. 이걸 함수를 감싼다고 말합니다.”

**6 — 전·후 처리**
> “감쌌으니 원래 함수를 실행하기 전과 후에 일을 덧붙일 수 있어요. 실행 전에 ‘시작합니다’라고 알리고, 원래 함수로 기록을 추가하고, 끝난 뒤 ‘끝났습니다’라고 알립니다. 원래 함수는 한 글자도 고치지 않았어요. 이렇게 앞뒤를 꾸며 준다고 해서 Decorator, ‘꾸미는 것’이라는 이름이 붙었습니다. 이 그림은 정상적으로 끝난 경우예요.”

**7~11 — Decorator 구조 (v3.6 그림)**
> “지금까지 본 걸 한 그림으로 보면 이렇습니다. 바깥 테두리가 Decorator가 덧붙인 공통 처리, 안쪽이 원래 기능이에요. 원래 일은 원래 기능이 하고, 바깥은 정해 둔 처리만 합니다. 정상으로 끝나면 정상 결과를 돌려주고, 정해 둔 종류의 오류가 나면 바깥이 받아서 알려 줍니다. 오류가 ‘해결’되는 건 아니에요.”

**12~14 — 언제 쓰면 좋을까**
> “그럼 언제 쓰면 좋을까요? 기록 추가·수정·삭제·검색처럼 여러 기능에 같은 처리, 예를 들어 오류 알림이 되풀이될 때입니다. 한곳에 모아 감싸면 고칠 곳도 한 곳이 돼요. 오류 처리 말고도 로그 기록, 실행 시간 측정 같은 공통 처리에 많이 씁니다. 다만 모든 기능을 꼭 꾸며야 하는 건 아니에요. 그리고 용돈 기입장에는 오류 처리 Decorator만 있습니다.”

**15 — 실제 사례 (간단히)**
> “실제 용돈 기입장은 모든 명령이 지나가는 한 지점을 handle_errors라는 Decorator로 감쌌습니다. 정상으로 끝나면 종료 코드 0, 정해 둔 LedgerError 계열 오류가 나면 [오류]와 [힌트]를 보여 주고 종료 코드 1이에요. 그 밖의 오류, 예를 들어 코드를 잘못 짠 실수는 일부러 잡지 않고 그대로 드러나게 했습니다.”

## 5. 강사 노트 — 정확성 경계

- **재대입은 객체를 바꾸지 않는다:** `a = a + 1`은 1이라는 값을 바꾸지 않고, 새 값 2를 만들어 이름 a에 연결한다. 마찬가지로 `work = decorate(work)`는 원래 함수 객체를 고치지 않고, 이름 work를 돌려받은 함수에 다시 연결한다. 원래 함수는 새 함수가 내부에서 참조하므로 계속 존재한다.
- **비유의 한계:** `a = a + 1`은 ‘같은 이름에 새 결과 연결’을 보여 주는 비유다. 숫자 덧셈과 함수 감싸기는 다른 동작이다.
- **함수가 자기 자신을 반환하는 것:** 가능하지만 Decorator의 필수 원리가 아니다. 이 장면에서는 다루지 않는다.
- **흔한 구현이지 유일한 구현이 아님:** 일반적인 Decorator는 원래 함수를 감싼 새 함수를 돌려준다. 그러나 원래 함수를 그대로 돌려주면서 어딘가에 등록만 하는 등 다른 방식의 Decorator도 있다. 클래스에 붙는 Decorator도 있다.
- **전·후 처리 예시의 범위:** ‘시작합니다·끝났습니다’는 정상 실행의 입문 예시다. 원래 함수에서 오류가 나면, 실행 후 처리는 그 오류를 어떻게 다루도록 만들었는지에 따라 실행되지 않을 수도 있다. Decorator가 할 수 있는 일을 앞뒤 알림으로 제한하지 않는다.
- **해결이 아니라 처리:** 오류 처리 Decorator는 정해 둔 오류를 받아 정해 둔 방식으로 다룬다. 원인을 고치지 않는다.
- **실제 `handle_errors` (`d14e812`):** `decorators.py`. 감싼 `_dispatch`가 정상으로 끝나면 0, `LedgerError`(와 하위 오류)가 나면 `[오류]`·`[힌트]`를 표준 오류 출력에 쓰고 1을 돌려준다. 그 밖의 예외는 잡지 않는다. `cli.py`의 `_dispatch` 한 곳에만 붙어 있고, argparse 사용법 오류(종료 코드 2)는 그보다 먼저 처리된다.
- **F5 rep는 가상 상황:** 실제 ledger에 ‘기능마다 따로 처리’한 코드가 있었던 것은 아니다.
- **일반 개념 예시:** 로그 기록·실행 시간 측정 Decorator는 용돈 기입장에 없다.

## 6. 선택형 심화

1. **`@` 표기** — `@decorate`를 함수 위에 적는 것은 `work = decorate(work)`를 짧게 쓴 표기다
2. **wrapper** — Decorator가 만들어 돌려주는 ‘감싼 함수’를 흔히 부르는 이름
3. **`*args`·`**kwargs`** — 감싼 함수가 원래 함수의 인자를 그대로 넘겨받는 방법
4. **`functools.wraps`** — 감싼 뒤에도 원래 함수의 이름·설명을 유지하기
5. **적용 시점** — Decorator는 함수를 정의할 때 한 번 적용된다
6. **예외 전파와 `try`/`except`·`finally`** — 오류가 나도 실행 후 처리를 하려면
7. **여러 Decorator 겹치기**, **함수를 반환하는 다른 방식**
