## 1. 핵심 시각화 네 가지

| 그림 | 질문 | 구성 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** Iterable과 Iterator | 하나의 리스트에서 만든 두 Iterator는 왜 다른 값을 낼까? | **A-1** 리스트(Iterable, 칸 3개)와 `iter()`로 만든 Iterator `a`·`b`(각 칸 3개: 꺼낸 칸·다음 칸), 실제 호출 다섯 번(번호 ①~⑤)과 결과 줄 · **A-2** Iterable ⊃ Iterator ⊃ Generator 겹친 상자와 구성원 | A-1: '만들어 냄'(보라 점선, 번호 없음) + 실행 순서(번호) / A-2: **포함**(선·번호 없음) |
| **B** Generator 실행 상태 | `count_up(3)`을 호출하고 `next()`를 네 번 부르면 본문은 어디까지 실행되고 어디서 멈출까? | 왼쪽 `count_up` 코드(줄 번호, `yield` 줄 강조, `print` 인자는 줄임) · 오른쪽 표: 호출(번호 ①~⑤) × **실행한 줄** × **밖으로 나온 값** × **그 뒤 상태·보관된 n** | 실행 순서(번호). 값·실행 구간·상태를 **세 칸으로 분리** |
| **C** JSONL 스트리밍 흐름 | 파일 한 줄이 어떻게 dict가 되어 소비하는 코드에 건네질까? | 파일(1행 강조) → Generator 상자(line · str → 청록 `json.loads()` → dict, `yield` 표시) → 소비하는 코드(받은 값 3개·합계·'보관: 합계 하나') · 실행 순서 ①~⑤ 설명 줄 | **변환**(청록 선, 번호 없음)과 **실행 순서**(번호·검은 실선) 분리 |
| **D** 다섯 가지 소비 방식 | 같은 파일을 어떻게 소비하느냐에 따라 꺼낸 줄과 남긴 거래가 어떻게 달라질까? | 방식 1~5 × (코드 · 꺼낸 줄 3칸 · 남긴 거래 칸 · 보관량 표기 · 끝까지 읽음?) 표 · 핵심 주의 4줄 | 비교 표. **번호 원 없음**(방식 번호는 이름표) |

그림의 모든 값·진행 위치·실행된 줄·상태·꺼낸 줄 수·남긴 거래는 `_tools/demo/`를 실제로 실행하고 `sys.settrace`·`sys.setprofile`로 추적해 얻었다. `verify_demo.py`가 매번 다시 대조한다.

**예제 선택.** 지시서대로 리스트 `[10, 20, 30]`(그림 A), 1·2·3을 내는 `count_up(3)`(그림 B), Scene 04와 같은 거래 3건(id 1 식비 8000, id 2 교통 2000, id 3 문구 3000, 그림 C·D)을 썼다. 데모는 함께 둔 `transactions.jsonl`·`broken.jsonl`을 **읽기만** 하므로 실습 중 파일이 생기거나 바뀌지 않는다. `five_ways.py`의 방식 이름은 원 숫자(①~⑤) 대신 '방식 1~5'로 바꿨다. 원 숫자는 이 스토리에서 **실행 순서**에만 쓰기 때문이다.

## 2. 시각 약속 (Scene 01~04 약속 유지 + 이번 추가)

| 표현 | 뜻 | 출처 |
| --- | --- | --- |
| 진한 실선 + 채운 검은 화살촉 + 검은 번호 원 | **실제 실행 순서**(A의 `next()` 호출, B의 호출, C의 소비자 ↔ Generator) | Scene 01~04와 같음 |
| 청록 실선 + 채운 청록 화살촉 + 함수 이름, 번호 없음 | 데이터 **모양 바꾸기**(str → dict) | Scene 04와 같음 |
| 보라 점선, 화살촉·번호 없음 + '`iter()` 새로 만듦' | **만들어 냄** 관계(리스트 → Iterator) | Scene 01의 보라 점선(규칙을 **참고**)과 같은 모양. 둘 다 '순서가 아닌 관계'지만 뜻이 다르므로 선 옆 글자로 구분(검토 요청 §7-7) |
| 겹친 상자(바깥 → 안: 회색·파랑·갈색 테두리) + 이름·설명 글자 | **포함** 관계(Iterable ⊃ Iterator ⊃ Generator) | **이번에 추가** |
| 회색 칸 + '꺼냄' + 호출 번호 원 / 굵은 검은 테두리 + '다음' | Iterator가 **이미 꺼낸 값** / **현재 위치** | **이번에 추가** |
| 생성됨(가는 회색 + '생성됨') · 멈춤(갈색 **파선** + '멈춤') · 종료(회색 굵은 실선 + '종료') | Generator **상태** | **이번에 추가** |
| 파란 굵은 칸 '→ 값' | `yield`로 **밖으로 나온 값** | **이번에 추가** |
| 회색 **점선** 칸 + 'n행' / 파란 **굵은 실선** 칸 + 'id n' | 그림 D의 **꺼낸 줄**(처리한 양) / **남긴 거래**(보관한 양) | **이번에 추가** |
| 연한 주황 띠 + '← 멈추는 곳' | 코드의 `yield` 줄 | **이번에 추가** |

- 색만으로 구분하지 않는다: 꺼냄/다음은 글자 + 테두리 굵기, 상태는 글자 + 테두리 모양(가는/파선/굵은), 꺼낸 줄/남긴 거래는 글자('n행'/'id n') + 테두리 모양(점선/굵은 실선). 검사기가 모두 확인한다.
- **번호를 붙이지 않은 곳:** A-2(포함), 만들어 냄 선, 변환 선과 변환 상자, 그림 D 전체, 값·상태 칸. 검사기가 이 영역 안·선 16px 안에 번호 원이 없는지 확인한다.
- 그림 B의 번호 원은 호출 순서이고 행 사이를 잇는 선은 두지 않았다(행의 위→아래가 시간). C의 ③(json.loads)과 ⑤(소비)는 한 상자 안에서 일어나므로 선 없이 번호 원만 둔다.

## 3. 이전 장면·기존 체험과 다른 점

- Scene 04의 C-1(변환)·C-2(처리 순서)는 파일 쓰기였다. 05의 그림 C는 같은 두 약속으로 **읽기 + 소비자와 Generator 사이의 주고받기**를 보인다.
- 그림 D는 Scene 04 그림 A의 '저장 위치 칸'과 달리 **처리한 양(꺼낸 줄)과 보관한 양(남긴 거래)을 다른 모양**으로 한 줄에 나란히 둔다.
- **기존 학습 체험 `src/B21LearningStoryView.tsx`의 Iterator 체험(변경하지 않음):** 두 Iterator의 `next()` 진행을 버튼으로 비교하는 구조는 그림 A의 상호작용(I2)에 재사용할 수 있다. 다만 ① 데이터는 '거래' 목록인데 상태 이름은 `yield 일시정지`(Generator 상태)를 써서 **리스트에서 얻은 Iterator와 Generator를 섞어 보일 수 있고**, ② `_iter_jsonl()`·`iter_all()` 구현 설명이 일반 개념보다 먼저 나온다. 재사용한다면 Iterable(리스트)·Iterator·Generator 세 층을 나누고(그림 A·B), `ledger` 코드는 구현 사례(원고 9절)로 옮기는 수정이 필요하다(시나리오 v2 §7.2와 같은 판단, Codex 단계).

## 4. 노트북용과 휴대전화용

| 항목 | 노트북용 `1280×3142` | 휴대전화용 `360×5622` |
| --- | --- | --- |
| 그림 A | 리스트(왼쪽) → Iterator a·b(오른쪽), 호출 5개 가로 | 리스트 → a → b 세로, 호출 5개 세로, '만들어 냄' 점선은 왼쪽(a)·오른쪽 가장자리(b) |
| 그림 B | 코드(왼쪽) + 표(오른쪽 4열) | 코드 위, 호출마다 카드(호출·실행한 줄·나온 값·상태) |
| 그림 C | 파일 · Generator · 소비자 가로 3열, 실행 순서 화살표는 상자 사이 | 파일 → Generator → 소비자 세로, ①④는 위·아래 화살표, ②는 파일 → Generator |
| 그림 D | 표 4열(방식·꺼낸 줄·남긴 거래·보관량/끝까지) | 방식마다 카드(코드 · 꺼낸 줄 · 남긴 거래 · 보관량) |

| 길이 | 1280px 화면(높이 약 900px)에서 약 3.5화면(A 1.0 · B 0.6 · C 0.8 · D 0.9 + 각주) | 390px 화면(칸 358px, 높이 약 800px)에서 약 7.0화면(A 1.7 · B 1.3 · C 1.6 · D 2.2 + 각주) |

**휴대전화를 한 장으로 길게 두지 않는 방안(웹 통합 후보).** 그림 A~D를 **탭 4개(I1)**로 나누면 한 탭이 약 1.3~2.2화면이 된다. 그림 B는 카드 다섯 장을 **한 장씩 넘기는 단계 탐색(I3)**으로 바꾸면 한 화면에 들어간다. 그림 D는 방식 다섯 개를 **전환(I5)**하면 카드 한 장 + 주의 4줄이 된다.

### 5.2 상호작용 후보

| # | 상호작용 | 교육적 필요성 | 동작 |
| --- | --- | --- | --- |
| I1 | 그림 A/B/C/D 탭(휴대전화) | **필요.** 약 7화면을 탭당 1.3~2.2화면으로 | 장면 안 탭, 선택 상태 유지 |
| I2 | **두 Iterator의 `next()`** | **필요(핵심).** 같은 리스트에서 진행 위치가 따로 움직이는 것을 직접 눌러 확인 | `next(a)`·`next(b)` 버튼, '꺼냄'·'다음' 칸 갱신, 다 꺼내면 'StopIteration' 표시. **값과 순서는 `two_iterators.py` 출력 순서를 기본 시연으로** 제공하고, 자유 순서는 같은 규칙(리스트 3칸)으로만 계산. 상태 이름에 `yield`를 쓰지 않는다(리스트 Iterator는 Generator가 아님) |
| I3 | **Generator 한 단계씩** | **필요(핵심).** 호출 직후 미실행 → `next()`마다 실행 구간·멈춤 위치·`n` | '다음' 버튼이 그림 B의 행을 하나씩 열고, 왼쪽 코드에서 **실행된 줄(`data-lines`)을 순서대로 강조**, 멈춤 줄에 '멈춤' 표시. 자동 재생 없음 |
| I4 | **한 줄씩 읽기(그림 C)** | **필요.** 소비자 요청 → 재개 → 한 줄 → `json.loads()` → `yield` → 소비의 반복 | '다음 거래' 버튼: 1행→2행→3행 강조(`data-line`), ①~⑤ 순서 강조, 받은 값(`data-got`) 하나씩, 마지막에 합계 13000 |
| I5 | **소비 방식 비교(그림 D)** | **필요.** 꺼낸 줄과 남긴 거래가 방식마다 어떻게 다른지 | 방식 1~5 전환. 고른 방식의 '꺼낸 줄' 칸이 차례로 채워지고 '남긴 거래'가 쌓이거나(1·4) 밀려나거나(5) 남지 않음(2). 값은 `five_ways.py` 결과만 사용 |
| I6 | 파일 수명 표시 | **유용.** 일부만 소비한 Generator가 파일을 연 채 멈춘 상태 | 원고 8절 실행 결과(`False` → `close()` 뒤 `True`)만 단계 표시. 실제 파일을 열지 않음 |
| I7 | 학습자 코드 입력·임의 데이터 크기 실험 | **보류.** 측정하지 않은 성능 수치를 보여 줄 위험, 원고의 직접 실행으로 충분 | 구현하지 않음 |

공통: 키보드 탐색, `aria-pressed`/`aria-live`, `prefers-reduced-motion` 존중, 강조는 색과 함께 굵은 테두리·글자로. **성능·메모리의 바이트·초 단위 수치는 화면에 쓰지 않는다**(측정하지 않음).
