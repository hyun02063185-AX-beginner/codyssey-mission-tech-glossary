## 1. 교육 목표

**Python 입문자가 프로그램 제작 과정에서 접한 기본 문법과 프로그래밍 개념을 이해하고, 자신의 소스코드에서 해당 개념의 적용 위치를 찾아 설명하도록 돕는다.**

- 이 스토리는 특정 용돈 기입장 구현을 해설하지 않는다. 통용되는 Python 문법·개념을 먼저 설명하고, `m03-pocket-money-ledger`는 필요할 때만 **검증된 구현 사례**로 쓴다.
- 완료 신호(정책 §1): 자료를 봤다는 것이 아니라 **자기 코드에서 개념이 쓰인 곳을 찾아 자기 말로 설명**할 수 있는 것. 점수화하지 않는다.

**제안과 반영 상태**

1. **Scene 03을 03-A·03-B로 나눔 — 반영(2026-10-22 Owner 지시).** 함수·클래스 문법, 계층 책임, CRUD·검색·요약이 한 장면에 모이면 입문자에게 새 문법과 설계 개념, 데이터 처리 흐름이 한꺼번에 들어온다. **03-A는 구조와 문법**(함수·클래스·객체, 책임을 나누는 이유, 호출 흐름과 import 의존의 구분), **03-B는 그 구조 위에서 한 기능이 작동하는 과정**(CRUD·검색·요약)을 맡는다. 학습 목표와 8개 장면의 순서는 그대로이며, 03 한 장면이 두 단위가 되었을 뿐이다. 03-A에서 CRUD는 장면 연결을 위한 목록 조회 사례 하나만 쓴다. 그림 레이아웃은 B3-1 03-A/03-B를 복제하지 않았다. **03-B(2026-10-23 시안)**는 일반 개념과 독립 학습용 예제(`crud_basics.py`·`search_summary.py`, 거래용 가상 패키지 `cashbook`)로 먼저 설명하고 `ledger`는 마지막 구현 사례 절에만 둔다. 거래 데이터에 맞추려고 03-B부터 가상 예시를 `todo`에서 `cashbook`으로 바꿨다(Owner 확인 요청).
2. **Scene 02는 Scene 01과 08 사이의 코드 읽기 기반이다.** 모듈 의존 관계와 함수 실행 흐름의 구별을 여기서 처음 가르치고, 03·05·06 장면의 '내 코드에서 찾아보기'가 이를 반복해 쓴다.
3. v1.1의 '안전한 수정·삭제(임시 파일·`os.replace`)'와 '조회·예산'은 독립 장면 대신 04(파일 재작성)·03(검색·요약)의 구현 사례로 둔다. 공식 목표 대응(§4)에서 빠지는 항목은 없다.
4. **Scene 04(2026-10-23 시안).** 지시서에 따라 질문을 '프로그램을 종료해도 데이터가 남는 이유는 무엇일까?'로 바꿨다. 일반 문법과 형식(1~7절, 학습용 예제 7개) → Scene 03-B의 메모리 CRUD 함수에 파일 읽기·쓰기를 붙인 `file_crud.py`(8절) → 운영상 안전 주의(9절) → `ledger` 구현 사례(10절) 순서다. 예시 데이터는 지시서의 3건(`id`·`category`·`amount`)으로 세 형식을 비교한다. 마지막 질문 '거래가 10만 건이라면?'으로 05에 넘기며, `for line in f`의 원리와 Generator는 04에서 설명하지 않는다.
5. **Scene 05(2026-10-23 시안).** 리스트 `[10, 20, 30]`으로 Iterable·Iterator(두 Iterator의 독립 진행)·`for`의 정체를 먼저 보이고, `count_up(3)`으로 Generator의 호출·멈춤·재개를 줄 단위로 추적한 뒤, Scene 04와 같은 거래 3건의 JSONL을 Generator로 읽는다. 결과 소비 다섯 가지(전부 리스트·한 줄씩 처리·일부 `next()`·`list(Generator)`·`deque(maxlen)`)로 **꺼낸 양과 남긴 양**을 나누고, Generator의 파일 수명, `ledger` 사례 순서로 끝난다. 장면 구성과 학습 목표는 바꾸지 않았다.
6. **Scene 06(2026-10-23 시안).** 반복되는 로그(원래 기능과 부가 기능) → 함수도 값(`greet` ↔ `greet()`) → wrapper → `@` = `func = deco(func)`와 적용 시점(정의·import 때 한 번)·호출 시점(부를 때마다) → `*args`·`**kwargs`·`return` 전달 → `functools.wraps` → 로그·예외 처리·시간 측정 세 Decorator(일반 예제) → `@dataclass` vs `@handle_errors` → `ledger`의 `handle_errors`(예외 처리만, 반환 약속을 종료 코드로 바꿈) → 자기 코드 탐색. 'Decorator만 정답은 아님'을 명시했다. 장면 구성과 학습 목표는 바꾸지 않았다.
7. **Scene 07(2026-10-23 시안).** `echo_amount("1000")`(문자열이 그대로 돌아옴)으로 질문을 연 뒤 Parameter·Argument(위치·키워드·기본값) → Type Hint 문법(힌트 유무의 실행 결과가 같음) → 표시만 vs 검증 코드(`-5`·`True`는 선언과 맞지만 규칙에서 거부) → `list[str]`·`int | str`·`-> None`의 실제 동작 → 읽는 사람·IDE·런타임 → argparse `type=int`(변환)·`limit: int`(표시)·`if limit <= 0`(검증)과 `10`·`abc`·`-2`(종료 코드 0·2·1) → 기본값 vs `None` 허용 → `ledger` 사례 3개(목록 조회·금액 검증·데이터 모델) → 자기 코드 탐색 순서다. 일반 예제는 표준 라이브러리만 쓰고 `ledger` 없이 실행된다. 장면 구성과 학습 목표는 바꾸지 않았다.

## 5. 공통 교수법

### 5.1 대면 강의 운영 (필수 초기 단계)

- **미션 시작 시 강사 주도 대면 설명을 필수 초기 학습 단계로 운영한다.** 우리 교육 모델의 운영 선택이며 코디세이 공식 출석·평가 규정이 아니다(정책 §2).
- 강사는 미션의 답을 대신 구현하지 않는다. **공통 Python 개념을 가르치고, 교육생이 자기 코드를 읽는 방법을 시연한다.** 시연은 가상 예시(Scene 01의 `todo` 등) → 구현 사례(`ledger`) → 교육생 한 명의 코드(동의를 받은 경우) 순서를 권장한다.
- 강의 시간·세부 배분·수준별 운영은 시범 운영 후 확정한다(정책 §2). 이 문서는 시간을 정하지 않는다.

### 5.2 코드 읽기의 두 경로 (모든 장면 공통)

| 경로 | 질문 | 출발점 | 따라가는 단서 | 그림 표현 |
| --- | --- | --- | --- | --- |
| **모듈 의존 관계** | 이 파일은 어떤 파일(모듈)의 기능을 빌려 쓰는가? | 아무 파일이나 | 파일 맨 위의 `import` · `from … import …` | 화살촉 없는 연결 또는 '사용' 관계선. **순서 번호를 붙이지 않는다** |
| **함수 실행 흐름** | 명령을 입력하면 실제로 어떤 함수가 어떤 순서로 불리는가? | 진입점(`python -m 패키지`면 `__main__.py`, `python 파일.py`면 그 파일) | 함수 본문 안의 호출 `이름(…)` | 번호가 붙은 실선 화살표 |

- **`import` 문에 적힌 순서를 프로그램 전체의 실행 순서로 설명하지 않는다.** import는 모듈을 불러와 이름을 쓸 수 있게 하는 연결이고, 실제 기능은 진입점에서 시작하는 함수 호출이 진행한다. (모듈을 처음 import할 때 그 모듈의 최상위 코드가 실행된다는 사실은 Scene 02에서 정확히 다룬다.)
- 두 경로의 결과가 다를 수 있음을 보여 주는 것이 Scene 02의 핵심 활동이다.

### 5.3 근거 표기

| 표기 | 뜻 | 예 |
| --- | --- | --- |
| `[확정 사실]` | Python 공식 문서·표준 형식 문서로 확인되고 이번 작업에서 직접 실행해 확인한 내용 | `python -m 패키지`는 `<패키지>.__main__`을 main 모듈로 실행 |
| `[단순화]` | 학습을 위해 줄이거나 비유한 설명. 실제와 1:1이 아닐 수 있다 | "터미널이 한 줄을 낱말로 나눈다"(셸·운영체제마다 규칙이 다름) |

### 5.4 장면 하나의 공통 구성

1. 질문(학습 질문 한 문장) → 2. 핵심 그림(노트북·휴대전화) → 3. 일반 개념 설명(가상 예시) → 4. 단순화 표시 → 5. 구현 사례(`ledger`, 구분된 절) → 6. **내 코드에서 찾아보기**(5분 안팎의 짧은 활동, 구현이 다를 때의 대체 구조 안내 포함) → 7. 이해 확인 질문(점수화하지 않음) → 8. 다음 장면으로 넘긴 것.

### 5.5 시각 약속 (모든 장면 공통 후보)

| 표현 | 뜻 | 쓰지 않는 곳 |
| --- | --- | --- |
| 번호가 붙은 진한 실선 화살표 | **실제 실행·처리 순서** | 개념 관계, import 연결 |
| 보라 점선 | 규칙·정의를 **참고**함(순서 아님) | 실행 흐름 |
| 괄호·테두리 모양 + 이름표 글자 | 그 부분을 **누가 해석·담당**하는가 | — |
| 비교 카드 | 헷갈리기 쉬운 두 개념의 공통점·차이점 | 관계선으로 잇지 않는다 |
| 회색 코드 상자 | 실제 실행 결과·코드(확인한 출력) | 비유 |

색만으로 의미를 나누지 않는다. 담당 주체는 색 + 테두리 모양(점선·파선·실선) + 이름표 글자(OS·Py·앱)로 세 번 구분한다. B3-1의 네트워크 구성도 레이아웃·장면 전개는 복제하지 않는다.

| JSONL 파일 전체를 `json.load()`·`json.loads()` 하나로 읽을 수 있다 | 파일 전체는 JSON 값 하나가 아니다(`Extra data`). 줄마다 `json.loads()` | [jsonlines.org](https://jsonlines.org/), 실행 확인 | 04 |

## 6. 이번 단계에서 직접 확인한 실행 결과 (Python 3.14.6, Windows)

가상 패키지 `todo`를 두 가지로 만들어 확인했다.

- **검증용 변형:** `__init__.py`에 출력문 한 줄, `__main__.py`에 argparse와 `sys.argv` 출력. 패키지 초기화가 `__main__.py`보다 먼저 실행되는지 보려는 것으로, **Scene 02 시연 후보**다. Scene 02는 이를 확장한 학습용 변형(`scene-02/_tools/demo/`, `cli.py`·`actions.py` 분리)을 쓴다.
- **Scene 01 시연용:** `__init__.py`에 실행 코드 없음(설명 문자열 한 줄), `__main__.py`에 argparse·`show_tasks()`와 ③·④ 확인 출력. 파일별 코드와 실행 명령은 [Scene 01 원고 '강사용 안내'](scene-01/script.md#강사용-안내)에 있다. Scene 01은 초기화 순서를 다루지 않으므로 `__init__.py`에서 아무것도 출력하지 않게 했다.

| 변형 | 실행 | 결과 | 쓰는 곳 |
| --- | --- | --- | --- |
| Scene 01 시연용 | `python -m todo list --limit 5` | `③ sys.argv = ['…/todo/__main__.py', 'list', '--limit', '5']` → `④ parse_args() = Namespace(command='list', limit=5)` → `show_tasks(5)`가 할 일 5개 출력 | 01 |
| Scene 01 시연용 | `python -m todo list --limit five` | ③ 출력 뒤 `error: argument -n/--limit: invalid int value: 'five'`, 종료 코드 2. ④·⑤는 실행되지 않음 | 01 |
| Scene 01 시연용 | `python -m todo list` / `-n 5` / `--limit=5` | 기본값 `limit=10`(할 일 6개 모두) / `limit=5` / `limit=5` | 01 |
| Scene 01 시연용 | `python -m todo -h` / `python -h` | 앞은 ③ 출력 뒤 todo의 사용법(`-h, --help`)을 보이고 종료 코드 0, 뒤는 Python 인터프리터의 도움말 | 01 |
| 검증용 변형 | `python -m todo list --limit 5` | `__init__.py` 출력 → `__main__.py` 출력(`__name__ == "__main__"`) → `sys.argv` → `Namespace(command='list', limit=5)`, `limit`은 `int` | 02 |
| 검증용 변형 | `--lim 3` | `limit=3`(argparse의 기본 축약 허용) | 참고(원고에 넣지 않음) |
| 검증용 변형 | `python -c "import todo"` | `__init__.py`만 실행, `__main__.py`는 실행되지 않음 | 02 |

### 7.2 기존 학습 체험 3개 재사용 평가 (`src/B21LearningStoryView.tsx`)

| 체험 | 정확성·교육 가치 | 재사용 판단 | 고칠 점(지금은 수정하지 않음) |
| --- | --- | --- | --- |
| A. Iterator·Generator — 두 Iterator의 `next()` 진행 상태 | 같은 데이터에 독립된 진행 상태가 있다는 핵심을 잘 보여 준다 | **Scene 05의 상호작용 후보** | 화면은 "List로 단순화한 개념 모델"이라고 밝히면서 상태 이름은 `yield 일시정지`(Generator 상태)를 쓴다. List에서 얻은 Iterator와 Generator의 차이를 섞어 보일 수 있다 → Iterable(List)·Iterator·Generator 세 층을 나눠 보여 주도록 수정 필요 |
