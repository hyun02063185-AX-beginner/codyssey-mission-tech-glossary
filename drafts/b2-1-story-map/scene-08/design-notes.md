## 1. 학습 질문과 정보 밀도

"지금까지 배운 Python 개념은 서로 어떤 관계이며 내 코드에서는 어디에 있는가?"를 다룬다. 기존 장면을 다시 강의하는 요약 포스터 대신 **선택·관계·복습·근거·설명**을 반복하는 탐색 화면이다. `ledger` 명령은 도입 연결 사례로만 쓴다.

| 화면 요소 | 첫 표시 | 선택 후 |
| --- | --- | --- |
| 영역 지도 | 7개 영역의 대표 노드 7개, 관계선 0개 | 대표 노드의 위치는 고정. 선택·연결 가능한 영역을 글자로 표시 |
| 관계 보기 | 개념 선택 안내 | 선택 노드의 직접 관계만 표시. 유형 이름·방향·범위 설명. 무관한 관계는 숨김 |
| 상세 패널 | 탐색 방법 | 쉬운 뜻 / 미션에서 등장한 이유 / 연결 개념·유형 / 복습 장면 / 사전 연결 상태 / 자기 코드 단서 |
| 비교 | 카드 선택 목록 | 한 카드씩 두 칸 비교, 그래프 선 0개 |
| 내 코드 | 원고 F·G 활동 안내 | 파일·함수·줄·소스 버전·확인 상태·자기 말 기록 |

후보에는 45개 노드·24개 관계·10개 비교가 있다. **45개를 첫 화면에 모두 표시하지 않는다.** 개요의 약 90개 후보 전체를 확정한 것이 아니다. 나머지는 개요에 보존하며, 운영 스키마 변환은 승인 뒤 웹 통합 단계에서 판단한다.

## 2. PC와 모바일 시안

PC는 고정된 대표 노드 영역과 관련 관계를 왼쪽에, 선택 개념 상세를 오른쪽에 둔다. 밝은 바탕·진한 본문·청록 선택 테두리를 사용한다. 처음에는 선이 없고, 노드 선택 후 관련 관계를 **시작 노드 — 유형·화살표 — 끝 노드** 행으로 펼친다. 이것도 그래프의 부분 보기이며, 선의 양끝에 노드 버튼을 둬 다음 개념으로 이동한다. 노드를 임의로 재배치하는 힘 기반 레이아웃은 쓰지 않는다.

모바일(360·390px)은 전체 그래프를 축소하지 않는다. **영역 / 관계 / 상세 / 비교** 버튼으로 화면을 바꾼다. 대표 노드는 목록으로 고르고, 선택하면 관계 화면으로 이동한다. 한 행의 양끝 노드는 줄바꿈되며 손가락으로 누를 수 있다. 상세는 다음 버튼으로 별도 확인한다. 가로 스크롤·호버·드래그를 기본 조작으로 요구하지 않는다.

| 동작 | PC | 모바일 |
| --- | --- | --- |
| 노드 선택 | 대표 카드 또는 관계 양끝 버튼 | 영역 목록 또는 관계 양끝의 44px 이상 버튼 |
| 관계 유형 | 유형 이름 + 화살표 + 필요 시 점선 | 같은 유형 이름·방향, 실행 번호 없음 |
| 노드 설명 | 오른쪽 패널 | '상세' 화면 |
| 전체/선택 구분 | '전체 후보 24 / 선택 연결 N' 수치와 범위 문장 | 같은 수치, 선택 연결만 표시 |
| 비교 | 카드 하나, 두 칸 나란히 | 좁은 화면은 위아래 두 칸. 각 개념 이름을 반복 |
| 학습 경로 | 선택 상자 + 이전/다음 + 복습 순서 문구 | 줄바꿈된 동일 조작. 긴 진행 막대를 축소하지 않음 |

**Generator 기본 시연:** R23(Generator → Iterator / 종류), R24(`yield` → Generator / 역할)만 직접 관계로 표시한다. `list(Generator)`는 상세 패널에서 결과 보관 설명으로 읽고 'Iterator 관계에서 R44 보기'로 이동한다. R44를 Generator와 새 직접 관계로 복제하지 않는다. Iterator에서 R22·R23·R25·R41·R44가 보이므로 유형 필터로 좁힐 수 있다. R22·R41은 반대 방향이지만 의미가 다른 관계다.

색만으로 의미를 전달하지 않는다. 선택은 굵은 테두리·'선택' 표시, 관계는 유형 글자, 확장은 '확장', 미연결은 '연결 없음', 실제 페이지 동작은 '미구현'으로 표시한다. '호출'도 전체 실행 순서가 아니므로 관계 행에 번호 원·실행 애니메이션을 쓰지 않는다. import의 '사용'은 파선과 import 글자로 실행 호출과 구별한다.

## 3. 왕복·복귀 상태 계약 (실제 라우트는 미구현)

실제 웹 통합 시 주소 형식을 여기서 새로 확정하지 않는다. 내부 상태 후보는 다음과 같다. `candidate-map.json`의 `returnExample`은 샘플 값이며 운영 contract가 아니다.

| 상태 | 보관할 값 | 이유 |
| --- | --- | --- |
| 원래 장면 | sceneId, 안정된 절·문단 anchor, scroll offset, trigger focus ID | 원래 읽던 곳으로 복귀 |
| 탐색 시작 | startNodeId=`generator` | 지도 진입 때 선택한 개념을 기억 |
| 현재 지도 | selectedNodeId, nodeHistory, relationFilter, 모바일 탭, 패널 스크롤 | 사전에서 직전 선택·관계 맥락 복구 |
| 안내 경로 | mode, pathId, stepIndex, 자유 탐색 직전 상태 | 수업 진행을 잃지 않고 모드 전환 |
| 사전 | termId와 지도 복귀 스냅샷 | 한 용어를 읽고 직전 지도로 복귀 |

**복귀 시나리오:** Scene 05 4절의 특정 문단 → Generator(R23) → Iterator → 사전 `iterator` 확장 → **직전 지도 Iterator** → '이전 선택 Generator' → **Generator 관계 화면** → 원래 Scene 05 문단. 사전에서 '시작 개념으로'를 별도 제공하면 Generator로 바로 복귀할 수 있지만 기본 뒤로 가기는 직전 선택을 복원한다. 시작 노드와 현재 노드를 하나의 필드로 덮어쓰지 않는다.

실제 서비스 요구:

- 장면·지도·사전 간 이동을 browser history에 남기며 브라우저 뒤로 가기와 화면 복귀 버튼의 결과가 같아야 한다. 새 탐색을 하면 앞으로 가기 이력은 새 분기로 갱신한다.
- 이동 전 스냅샷은 탭의 `history.state` 또는 탭 수명의 저장소에 두는 후보. 소스코드·개인정보를 URL이나 이 저장소에 자동 보관하지 않는다. 새 탭·직접 URL 진입에 복귀 상태가 없으면 '이전 학습 위치 없음'과 Scene 선택을 제공한다.
- 새로고침에서 복구할 수 있는 범위와 저장소 수명은 웹 통합 때 확정한다. 오래된 ID·삭제된 절이면 장면 제목으로 복귀하고 '이전 위치를 찾지 못함'을 알린다. 코드가 바뀐 줄 번호도 자동 유효하다고 주장하지 않는다.
- 사전 termId가 없거나 콘텐츠를 불러오지 못하면 지도의 선택을 유지하고 '연결 없음/불러오기 실패'를 표시한다. 다른 용어를 대신 열지 않는다.
- 복귀 뒤 렌더링이 끝나면 안정된 anchor로 이동하고 원래 트리거에 초점을 돌린다. 픽셀 오프셋은 글꼴·화면 폭 변화 때문에 보조값이다.

**이 폴더의 모형:** 샘플 Scene/샘플 사전 패널을 메모리 안에서 전환하고 선택·모드·필터·이력·스크롤을 되돌리는 동작만 구현한다. 브라우저 주소·history·서비스 페이지·새로고침 복구는 구현하지 않는다. 샘플 패널에는 항상 '모형 / 서비스 연결 미구현'을 표시한다. 따라서 모형 왕복 검사 PASS를 서비스 왕복 완료로 보고하지 않는다.

## 4. 강사 안내와 자유 탐색

`teacherPaths`는 `relations`와 별도 배열이다. P1~P3의 단계 번호는 **복습 순서**에만 표시한다. 단계 사이 연결을 R ID로 만들지 않는다.

| 경로 | 선택 노드 순서 | 핵심 질문 |
| --- | --- | --- |
| P1 명령 | CLI, Python의 -m, __main__.py, argparse, 함수 호출, 서비스 계층 | 의존 관계와 실제 호출을 따로 읽었는가? |
| P2 저장·처리 | CRUD, 영구 저장, JSONL, Generator, for, list() | 형식·꺼내는 방식·남기는 결과를 나눴는가? |
| P3 검증 | Parameter, Type Hint, 값 검증, 예외, Wrapper | 표시·실제 검사·처리 범위를 확인했는가? |

안내 모드에서 이전/다음은 단계를 바꾼다. 노드 자유 선택은 자유 탐색으로 전환하며 진행하던 경로·단계를 별도로 유지한다. 다시 안내 모드를 선택하면 마지막 단계로 돌아온다. 자유 탐색의 선택도 보존한다. 안내 경로 변경은 해당 경로 첫 단계에서 시작한다. 자동 재생·시간 제한 없음.

## 5. 비교·노드·termId 후보의 경계

- 노드 ID는 이번 후보 내부에 처음 부여했다. R·C ID는 개요의 번호를 그대로 재사용했다. 데이터 후보는 `status=design-candidate-not-runtime`이다.
- R04는 원래 후보의 모듈·패키지 중 **패키지 분기**만 표시했다. 새 의미 관계 ID로 갈라 만들지 않았다. R15는 일반 모듈 의존 후보를 `ledger.cli` → `ledger.services` 한 쌍으로 구체화했다. 자체 연결 오류를 피하려고 두 모듈을 별도 노드로 두었다.
- R10은 일반 패키지, R12는 `__main__.py`가 있는 예시 패키지, R14·R15는 `ledger`, R17·R18·R19는 해당 설계 예시 범위다. R47은 wrapper를 돌려주는 함수 Decorator 예시에 한정한다. 적용 범위를 패널에서 생략하지 않는다.
- C06·C07·C20·C11·C12·C30·C13·C16은 필수 8카드다. C08·C21은 경로 시연을 보조한다. 비교 카드 양끝은 노드 참조지만 **relations에 비교 유형을 넣지 않는다**.
- 사전은 현재 저장소의 `content/terms/<termId>.md`와 생성 glossary의 id가 모두 있는지 검사한다. 존재 검사는 내용 적합성 판단을 대신하지 않는다. 연결 모드는 `direct / extension / none`, 서비스 연결 상태는 전부 `unimplemented`다.
- `module`, `json-lines`, `iterator`, `decorator`, `input-validation`은 개요 §6의 이유로 **확장**이다. `type-hint`는 주의 문장을 먼저 제시하고 직접 정의 후보로 둔다. `init`은 `__init__()`에만 연결한다. `__init__.py`와 `__main__.py`는 사전 연결 없음. `main-py`·`commit-subcommand`로 대체하지 않는다.
- 후보 JSON 안의 `outlineRef`는 문서 경로+행 ID를 합친 **출처 식별 표기**이며 작동하는 HTML anchor가 아니다. 실제 링크로 렌더링하지 않는다. 승인 후 안정된 anchor/라우트를 정한다.

사전·복습 실제 링크는 disabled 상태와 '미구현' 글자를 함께 표시한다. 별도 '샘플 왕복 체험'만 모형을 연다. 모든 조작은 버튼·선택 상자를 사용한다. Tab/Shift+Tab, Enter/Space로 접근하고 초점 테두리를 표시한다. 모바일 보기 전환과 노드 변경을 `aria-live=polite`로 알린다. 화면 바뀜 때 제목에 초점을 주고, 복귀는 원래 컨트롤을 복원한다. 정보가 없는 버튼은 숨기거나 설명을 붙이고, 작은 터치 영역을 만들지 않는다. 자동 애니메이션 없음. OS의 reduced motion과 관계없이 같은 내용을 읽을 수 있다.

## 7. 편집·검증·인수인계

`candidate-map.json`이 이 폴더의 후보 원본이다. `_tools/build.py`가 후보를 읽어 자체 포함 HTML을 만든다. 기존 Scene 생성기나 운영 빌드는 호출하지 않는다. 폰트는 기존 `src/assets/fonts/PretendardVariable.woff2`를 상대 경로로 참조한다. 외부 네트워크·새 의존성·AI 호출은 없다.

```bash
python3 drafts/b2-1-story-map/scene-08/_tools/build.py
python3 drafts/b2-1-story-map/scene-08/_tools/verify_candidate.py
PLAYWRIGHT=<설치된 playwright 경로> PW_CHANNEL=chrome node drafts/b2-1-story-map/scene-08/_tools/check.cjs
```

`check.cjs`가 1280·1000·390·360px 모형 화면 PNG를 만들고, 선택·필터·카드·경로·샘플 왕복과 DOM 넘침·터치 영역을 확인한다. 시각 판정은 사람이 PNG를 따로 확인한다. 기존 Scene 01~07은 고치지 않았으므로 기존 데모 전체 검사를 반복하지 않고 **새 원고가 인용한 소스·객체·호출 예시와 후보·화면**만 검증한다.

독립 검토에는 R10·R12·R47의 한정, C07의 import 중 실행, C12의 Generator 종료, R22/R41의 방향, 복귀 상태 계약, 단일 파일·미완성 코드 활동의 적용성을 요청한다. Owner 시각 승인 뒤에만 운영 데이터·실제 서비스 통합으로 넘긴다.
