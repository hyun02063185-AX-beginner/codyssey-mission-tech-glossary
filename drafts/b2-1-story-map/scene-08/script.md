## 학습자 원고

### A. 배운 개념은 어떻게 연결될까?

Scene 07에서 본 명령입니다.

```bash
python -m ledger list --limit 10
```

짧은 명령 하나에도 CLI, Python의 `-m`, 패키지, 함수 호출, 계층별 책임, Type Hint와 값 검증이 함께 등장했습니다. 이번에는 **개념 선택 → 관계 확인 → 장면에서 복습 → 실제 코드에서 근거 찾기 → 자기 말로 설명**해 봅니다.

`ledger`는 여러 구현 중 하나를 연결해서 보는 사례입니다. 여러분의 프로그램 이름·파일 구성·실행법은 달라도 됩니다. 한 파일에서 `input()`으로 메뉴를 받고 JSON에 저장하는 프로그램도 같은 활동을 할 수 있습니다.

첫 화면에서는 실행·CLI / 모듈·패키지 / 함수·계층 책임 / CRUD·파일 저장 / Iterator·Generator / Decorator / Type Hint·검증의 **대표 개념 7개만** 봅니다. 필요한 영역을 골라 주변 개념을 펼칩니다. 이 지도는 B2-1에서 배운 개념을 찾는 지도입니다.

### B. 지도는 어떻게 읽을까?

**노드**는 개념의 이름입니다. 노드를 고르면 **상세 패널**에 쉬운 뜻, 미션에서 등장한 이유, 관계 유형, 복습 장면, 용어사전 연결 상태, 내 코드에서 찾을 단서가 나옵니다. **관계선**은 두 개념 사이의 뜻을 표시하고, **비교 카드**는 헷갈리는 두 개념의 차이를 나란히 보여 줍니다.

| 유형 | 읽는 방법 | 예시 |
| --- | --- | --- |
| 포함 | A 안에 B가 있다 | 패키지 → 모듈(R09) |
| 종류 | A는 B의 한 종류다 | Generator → Iterator(R23) |
| 호출 | A가 실행 중 B를 부른다 | Wrapper → 원래 함수(R27, 이 장면의 예시) |
| 사용 | A가 B를 이용한다. 순서는 뜻하지 않는다 | `for` → Iterator(R25) |
| 역할 | A가 B를 위한 역할을 맡는다 | Type Hint → 입출력 계약 표시(R28) |
| 비교 | 두 개념을 나란히 읽는다. **선으로 잇지 않는다** | Parameter / Argument(C16) |

화살표의 색만 보지 말고 **시작 개념·유형 이름·끝 개념**을 함께 읽으세요. 종류는 구체적인 쪽에서 큰 범주 쪽으로 향합니다. Generator → Iterator를 "Iterator가 Generator를 실행한다"고 읽으면 안 됩니다. 관계선에는 실행 순서 번호를 붙이지 않습니다. 호출 관계도 **한 번의 전체 실행 추적이나 호출 횟수**를 뜻하지 않습니다.

Generator를 선택해 봅시다.

- R23 **종류:** Generator는 Iterator의 한 종류입니다.
- R24 **역할:** `yield`는 Generator가 값을 내보내고 실행을 일시정지하게 합니다.
- **결과 보관 설명:** `list(Generator)`는 Generator를 끝까지 소비하여 내보낸 값 전체를 리스트에 모을 수 있습니다. 연결 근거 R44는 `list()`가 Iterator를 **사용**한다는 관계입니다. Iterator를 선택해 확인하세요.

첫 두 관계와 결과 보관 설명을 같은 화살표 세 개로 그리지 않습니다. JSONL을 읽는 Generator라도 결과를 전부 리스트로 모으면 그 결과 전체가 메모리에 남습니다. "꺼낸 양"과 "남긴 양"은 Scene 05 7절에서 다시 확인합니다.

### C. 강사와 함께 세 경로를 탐색하기

다음은 **수업에서 개념을 살펴보는 순서**입니다. 모든 프로그램이 이 순서대로 모든 단계를 호출한다는 뜻은 아닙니다. 안내 경로의 '다음'과 그래프 관계선은 별개입니다. 강의 뒤에는 자유 탐색으로 전환해 원하는 개념을 골라도 됩니다.

#### 경로 1. 명령을 실행하면 어디로 갈까?

**CLI → Python의 `-m` → 패키지 실행 진입점 → argparse → 실제 함수 호출 → 계층별 책임**을 차례로 살펴봅니다(Scene 01·02·03-A).

1. 내 실행 명령에서 Python이 읽는 부분과 프로그램이 읽는 부분을 나눕니다.
2. 패키지 이름을 `-m`에 주었을 때 `__main__.py`가 실행 진입점이라는 역할(R13)을 봅니다. 일반 패키지는 그 전에 불러오며 `__init__.py` 초기화 코드가 실행됩니다. 모듈 이름을 `-m`에 주면 그 모듈을 실행합니다(Scene 02).
3. argparse가 명령줄 인자를 해석하는 역할(R08)을 확인합니다. 등록한 규칙과 실제 입력 해석은 다릅니다.
4. `ledger`의 `__main__.py`가 `main()`을 호출하는 사례(R14)와 CLI가 서비스를 부르는 사례(R17)를 봅니다. **내 코드에 같은 이름의 함수가 있어야 하는 것은 아닙니다.**
5. import 줄로 모듈 의존 관계(R15)를 확인한 뒤, 진입점에서 함수 호출을 따로 따라갑니다(C07·C08). 파일이 `services.py`라는 이름만으로 서비스의 책임을 맡았다고 판단하지 않습니다.

**설명해 보기:** "이 파일은 저 모듈을 불러 쓸 수 있습니다. 이 입력에서 실제로 호출된 함수는 별도로 확인했습니다."

#### 경로 2. 저장한 데이터는 어떻게 읽고 처리할까?

**CRUD → 메모리와 파일 저장의 차이 → JSONL → Iterator·Generator → 한 건씩 처리 → 결과 보관 방법**을 살펴봅니다(Scene 03-B·04·05).

1. 내 데이터의 추가·조회·수정·삭제 중 한 가지를 고릅니다. 메모리에서 바뀐 값이 파일에도 쓰이는지 봅니다(C21·R37).
2. JSONL은 줄마다 JSON 값 하나를 적는 저장 형식입니다. Generator는 값을 하나씩 내는 실행 방식입니다(C30). JSON·CSV를 쓴다면 실제 형식을 그대로 적습니다.
3. Generator → Iterator(R23), Iterator → Iterable(R41), `for`가 Iterator를 사용함(R25)을 읽습니다. Iterable → Iterator(R22)는 `iter()`로 Iterator를 내주는 **역할**이며 R41과 방향·뜻이 다릅니다.
4. 한 건씩 읽은 뒤 합계만 남기는지, `list()`로 끝까지 모으는지(R44) 확인합니다. Generator나 JSONL을 썼다는 이유만으로 메모리를 적게 쓴다고 결론 내리지 않습니다(C27).

**설명해 보기:** "이 프로그램의 저장 형식은 ___입니다. 읽는 방식은 ___이고, 처리 뒤 보관하는 결과는 ___입니다."

#### 경로 3. 함수에 잘못된 값이 들어오면 어떻게 될까?

**Parameter·Argument → Type Hint → 실제 검증 → 예외 발생 → 예외 처리 Decorator**를 살펴봅니다(Scene 06·07).

1. 함수 정의에서 받는 자리(Parameter)와 호출에서 넣는 값(Argument)을 짝지어 봅니다(C16).
2. Type Hint는 기대 형식을 표시합니다(R28). **실행 중 잘못된 값을 자동으로 막거나 변환하지 않습니다.** argparse `type=int`는 변환이고, `if`·`isinstance` 등의 검사는 실제 검증입니다(C13).
3. 실제 검증(R29)이 거부하는 값과 예외를 찾습니다. `raise`를 발견하면 어디서 받는지도 확인합니다.
4. 예외 처리 Decorator가 있다면 wrapper가 원래 함수를 부르는 곳(R27)과 `except`의 종류를 확인합니다. **작성한 처리 범위(그 예외와 하위 종류)만** 다루며 나머지는 전파됩니다. 이 경로의 '검증 뒤 Decorator'는 복습 순서입니다. 실제 호출에서는 wrapper 안에서 원래 함수가 실행되고 예외가 돌아올 수 있습니다.

Decorator나 Type Hint가 없다면 없다고 적고, 검증과 `try`·`except`가 실제로 어디 있는지 설명합니다. `ledger`의 `handle_errors`는 `LedgerError`만 다루며, 로그·시간 측정 Decorator는 그 구현에 없습니다(Scene 06 사례).

**설명해 보기:** "이 표시는 ___를 기대한다는 뜻입니다. 실제로 거부하는 줄은 ___이고, 그 예외는 ___에서 처리됩니다 / 처리하지 않아 전파됩니다."

### D. 헷갈리는 개념은 비교 카드로

기존 장면의 비교 표현을 이어 씁니다. 더 자세한 예외와 실행 결과는 원래 장면에서 확인하세요. 아래의 `/`는 두 칸 구분이며 관계선이 아닙니다.

| 카드 | 왼쪽 | 오른쪽 | 복습 |
| --- | --- | --- | --- |
| C06 | `__init__.py`: 일반 패키지 폴더 안 파일. 패키지를 처음 불러올 때 실행(비어 있어도 됨). Namespace Package에는 없는 예외 | `__init__()`: 클래스 안의 객체 초기화 메서드. 새 객체가 만들어진 뒤 자동 호출 | Scene 02 4절·03-A 3~4절 |
| C07 | import: 모듈을 찾아 필요하면 불러오고 이름을 연결. 처음 불러올 때 최상위 코드 실행 | 함수 호출: 인자를 넘겨 함수를 실행. **import 중 최상위 코드가 함수를 호출할 수도 있으므로** import를 '실행이 전혀 없음'으로 읽지 않음 | Scene 02 7~8절 |
| C20 | ID: 위치가 바뀌어도 남은 항목의 식별자는 유지. 지운 ID의 재사용은 생성 규칙에 따름 | 인덱스: 리스트의 위치. 삭제·삽입으로 같은 위치가 다른 항목을 가리킬 수 있음 | Scene 03-B 3절 |
| C11 | Iterable: 반복할 수 있는 대상. `iter()`로 Iterator를 내줌 | Iterator: 다음 값을 꺼내는 진행 상태. Iterator도 Iterable이며 `iter(it) is it` | Scene 05 2~3·5절 |
| C12 | `yield`: 값을 내보내고 일시정지. 다시 요청하면 이어서 실행 | `return`: 함수 종료. Generator의 `return`도 반복을 끝냄. Generator의 종료 값은 `for`의 다음 항목이 아님 | Scene 05 4~5절 |
| C30 | JSONL: 한 줄에 JSON 값 하나인 저장 형식 | Generator: 값을 하나씩 내는 실행 방식. 둘 다 메모리 절약을 스스로 보장하지 않음 | Scene 04 5절·05 7절 |
| C13 | Type Hint: 기대하는 입출력 형식 표시, 런타임 비강제 | 값 검증: 함수 본문의 검사로 형식·범위 등 규칙을 확인. 거부할 때 실제 오류를 냄 | Scene 07 3~4·7절 |
| C16 | Parameter: 함수 정의에 적은 받는 자리(이름) | Argument: 호출할 때 실제로 넣은 값. 위치 인자는 순서, 키워드 인자는 이름으로 연결 | Scene 07 2절 |

### E. 장면에서 지도·용어사전으로 갔다 돌아오기

Scene 05의 Generator 설명을 읽다가 "Iterator와 어떻게 다르지?"라고 궁금해졌다고 합시다.

1. **Scene 05 4절, 읽던 위치**에서 '지도에서 관계 보기'로 들어갑니다.
2. **Generator 선택** 상태에서 R23을 읽고 Iterator를 고릅니다.
3. Iterator 패널의 주의 문장("보관량은 소비·보관 코드가 정함")을 읽고 **용어사전 확장 `iterator`**로 이동합니다. 이 용어의 파일과 실제 termId는 존재하지만 설명 범위에 주의가 있어 '확장'으로 표시합니다.
4. '이전 지도 맥락으로' 돌아오면 **Iterator 선택·Generator에서 시작한 탐색 이력·관계 필터·강사/자유 모드·패널 스크롤**을 복원합니다. 탐색 이력의 Generator로 한 번 돌아오면 R23을 보던 Generator 선택 화면입니다. Iterator를 건너뛰어 Generator 화면으로 돌아가고 싶다면 '시작 개념 Generator로'를 별도로 씁니다.
5. 'Scene 05 읽던 위치로' 돌아오면 원래 절과 문단의 위치 및 키보드 초점을 복원합니다.

**실제 서비스의 장면→지도→사전→지도→장면 연결은 미구현입니다.** 이 폴더의 시안은 샘플 Scene·사전 화면으로 복귀 상태를 설명하는 모형입니다. 실제 페이지를 연 것처럼 표시하지 않습니다. 상세한 복귀 규칙과 실패 시 대안은 설계 노트에 있습니다.

### F. 내 코드로 작은 개념지도 만들기

먼저 내가 실행하는 명령과 **검토 중인 소스 버전**을 적습니다. 파일을 직접 열고 아래 표를 채워 보세요. 내 코드에서 찾은 **개념 노드 3개 이상·관계 2개 이상·비교 1개**가 기본 활동입니다. 없는 개념을 억지로 추가하지 않습니다. 근거가 부족하면 '미확인', 구현이 없으면 '없음'이라고 적고 다른 개념으로 바꿉니다. 아직 관계 2개를 확인하지 못했다면 그 사실과 다음 확인 방법을 남깁니다.

| 내 코드에서 찾은 것 | 연결할 개념 | 관계 유형·방향·한 문장 | 파일·함수·줄 번호 | 확인 근거와 상태 |
| --- | --- | --- | --- | --- |
| 명령을 해석하는 함수(있다면) | CLI·argparse 또는 직접 입력 해석 | 사용 / 역할(실제 코드에 맞게) | | 소스 확인 / 실행 확인 / 미확인 |
| 데이터를 저장하는 부분 | 저장 책임·파일 입출력 | ___ → 파일 입출력 / 역할 | | |
| 잘못된 값을 막는 부분 | 값 검증·Argument | 값 검증 → Argument / 역할 | | |
| 내가 고른 다른 개념 | | | | |

**확인 순서:** 개념의 위치를 찾기 → 관계의 양끝 근거 줄을 찾기 → 실행을 주장한다면 명령·입력·호출 추적 또는 중단점 등의 근거를 더하기 → "그래서 ___ 관계"라고 설명하기. 출력 하나만으로 모든 내부 함수가 실행됐다고 결론 내리지는 않습니다. 실제 서비스 데이터 대신 테스트 사본을 사용합니다.

| 내 구조 | 활동 방법 |
| --- | --- |
| 클래스 없는 단일 파일 | 함수·Parameter·Argument·검증·입출력·리스트 등 실제 개념을 고름. 같은 파일의 함수 호출도 근거가 됨 |
| JSON 저장, Generator 없음 | JSON·직렬화·파일 입출력을 찾음. Generator는 '없음', 비교는 JSONL/Generator를 외워 쓰는 대신 실제로 헷갈린 짝을 고름 |
| argparse 없이 `input()` 사용 | 실행 중 입력 받기와 `int()` 변환·검증을 찾음. argparse 사용 관계를 만들지 않음 |
| 저장 기능 미완성 | 메모리 자료구조·함수·검증으로 관계를 설명하고 저장은 '미구현'으로 남김 |
| 계층이 섞인 큰 함수 | 함수 안의 입력·검사·저장 줄을 각각 적음. 파일 이름만으로 분리됐다고 주장하지 않음 |

**작성 예시(내 코드 대신 기존 학습용 파일로 시연)**

Scene 05 `_tools/demo/jsonl_generator.py`의 `read_transactions`를 엽니다. 아래는 그 파일 기준이며, 교육생 파일에 그대로 붙일 줄 번호가 아닙니다.

| 개념 | 근거 |
| --- | --- |
| Generator | `read_transactions` 5~10행 정의와 `yield`, 13행에서 얻은 `rows`가 Generator 객체임을 실행으로 확인 |
| `yield` | 같은 함수 10행에서 값을 내보냄 |
| Iterator | 13행의 `rows`에서 `iter(rows) is rows`, `next(rows)`가 다음 값을 내는지 확인 |

관계 R24(`yield` → Generator / 역할), R23(Generator → Iterator / 종류)을 기록합니다. 비교 C11에서는 **Iterator도 Iterable**이라는 설명을 빼지 않습니다. "읽은 결과를 리스트로 모으지 않고 합계만 남기는 부분은 어디인가?"라고 물으면 같은 파일 18~21행을 가리켜 설명합니다. 검증 도구는 임시 사본에서 소스 줄·실제 객체·실행을 확인합니다.

**나의 기록(제출·대화용 양식)**

```text
소스 버전/작업 시각:             실행 명령과 테스트 입력:
개념 3개와 각 파일·함수·줄:
관계 1: A → B / 유형 / 근거:
관계 2: A → B / 유형 / 근거:
비교 1: ___ / ___, 공통점과 차이:
소스로 확인한 것:               실행으로 확인한 것:
아직 모르는 것·없는 것:          다음에 확인할 방법:
나의 설명:
```

### G. AI와 함께 구조를 탐색하고 고치기

AI는 읽을 곳을 찾는 데 도움을 줄 수 있습니다. 분석에는 공유해도 되는 소스만 사용하세요. **API 키·개인 정보·실제 서비스 데이터·`.env` 내용은 외부에 붙여 넣지 않습니다.** 가능한 경우 로컬에서 파일을 읽게 하고, 비밀정보가 포함될 수 있는 파일은 분석 대상에서 제외합니다.

```text
다음 프로젝트에서 B2-1에서 배운 개념 3개와 관계 2개 후보를 찾아 주세요.
각 후보에 파일, 함수, 줄 번호와 실제 코드 근거를 적어 주세요.
관계는 포함·종류·호출·사용·역할 중에서 고르고, 비교는 별도 카드로 적어 주세요.
import 의존 관계, 함수 호출, 학습 순서를 따로 설명해 주세요.
소스에서 가능한 호출과 실제 실행에서 관찰한 호출을 구분해 주세요.
실행하지 않았다면 실행했다고 말하지 말고, 추정은 미확인으로 표시해 주세요.
파일 이름만으로 계층 책임을 판정하지 말고 본문이 하는 일을 확인해 주세요.
없는 개념·미완성·특이한 구조는 그대로 알려 주세요. 구조를 임의로 채우지 마세요.
비밀정보·개인정보·운영 데이터 파일을 열거나 출력하지 마세요.
```

AI의 답을 받은 뒤 파일을 직접 열어 함수 이름·줄 번호를 확인합니다. import만 보이는 관계를 '실제 호출'이라고 했다면 **사용(import 의존)으로 수정**하거나 호출 근거를 추가합니다. 함수 안에 호출식이 있어도 조건이 충족되지 않아 실행되지 않았을 수 있습니다.

| AI가 제안한 설명 | 직접 확인한 근거 | 나의 판단·수정 | 남은 확인 |
| --- | --- | --- | --- |
| import가 있으니 그 함수가 실행됐다 | import 줄은 있음, 해당 명령의 호출은 미확인 | 사용 관계로 수정. 실행 주장 보류 | 테스트 입력에서 중단점/추적 |
| `services.py`이므로 규칙 검증 담당 | 함수 본문에 파일 쓰기와 출력이 함께 있음 | 실제 책임을 나눠 적음 | 다른 호출 경로 확인 |
| | | 유지 / 수정 / 삭제 / 미확인 | |

결과물은 정답 노드 수가 아니라 **근거를 가지고 구조를 설명하고, AI의 추정을 직접 확인·수정한 기록**입니다.

### H. 내 프로그램을 설명하며 마치기

강사의 핵심 관계 시연을 본 뒤 내 코드를 열고 설명합니다.

> **"내가 만든 프로그램에서 사용자의 입력은 어디서 시작해, 어떤 함수를 거쳐, 어떻게 검증되고 저장되나요?"**

각 설명에 실제 소스 위치나 실행 근거 하나를 덧붙여 보세요. 저장이 아직 없다면 "메모리까지만 바뀌며 저장은 미구현"이라고 설명할 수 있습니다. 설명하기 어려운 부분은 Scene 01~07의 해당 장면으로 돌아가 다시 확인합니다.

## 강사용 안내

대면 설명은 우리 교육 모델의 필수 초기 학습 단계이며 코디세이 공식 출석·평가 규정이 아닙니다. 수업 시간과 학습 효과는 시범 운영 후 확인합니다.

1. 명령 한 줄로 핵심 질문을 열고, 학습자의 실제 실행 명령이 다를 수 있음을 말합니다.
2. 7개 영역 첫 화면에서 Generator를 선택해 R23·R24를 유형 이름까지 소리 내어 읽습니다. `list()` 설명은 결과를 보관하는 쪽의 문제로 묻습니다.
3. 안내 경로 세 개를 시연하되, 매 경로 시작에 "복습 순서"임을 말합니다. 필요할 때만 기존 장면을 엽니다.
4. 경로 1에서 같은 파일의 import와 호출 근거를 따로 짚습니다. 경로 3에서는 wrapper가 원래 함수 바깥에서 호출을 감싸는 실제 구조와 복습 순서가 다름을 확인합니다.
5. C06·C07·C20·C11·C12·C30·C13·C16 중 학습자가 헷갈린 카드를 골라 말하게 합니다. 카드 전체를 강독하지 않습니다.
6. 샘플 화면으로 Scene 05→Generator→Iterator→사전 확장→지도→Generator→Scene 05 복귀를 시연합니다. **서비스 연결은 미구현**임을 밝혀야 합니다.
7. F절 시연 예제로 표를 한 번 채운 뒤, 동의한 학습자의 코드 또는 각자의 코드로 옮깁니다. 불완전한 코드도 참여합니다.
8. AI가 제안한 연결 하나를 학습자가 유지·수정·삭제하는 근거를 묻습니다. "미확인"을 인정하고 다음 확인 방법을 정합니다.
9. H의 마지막 질문에 코드를 가리키며 설명하게 합니다. 모르면 돌아갈 장면을 함께 고릅니다.
