# Scene 01 설계 노트 — 명령 한 줄을 영역별로 나눠 읽기

> 상태: **시안(Owner 시각 검토 전)** · 2026-10-22 · 원고: [script.md](script.md) · 생성기: `_tools/build.py` · 검사: `_tools/check.cjs` · 미리보기: `_tools/preview.cjs`

## 1. 핵심 시각화

**명령어 한 줄을 영역별로 나누어 읽는 경험**이 중심이다. 그림은 네 구역으로 나뉘며 위에서 아래로 읽는다.

| 구역 | 질문 | 표현 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** 명령 한 줄 분해 | 이 한 줄의 낱말은 각각 무엇이고 누가 해석하나? | 어두운 터미널 띠 안의 토큰 6개 → 토큰 이름 → 해석 주체 괄호 3개 → 주체 설명 상자 | **담당(누가 해석)** — 순서 없음 |
| **B** 처리 순서 ①~⑤ | 한 줄이 코드에서 쓰는 값이 되기까지 실제로 무슨 일이 어떤 순서로 일어나나? | 번호 원 + 진한 실선 화살표, 단계마다 확인한 실행 결과(코드 상자)와 담당 주체 이름표 | **실제 처리 순서**(흐름) |
| **C** argparse 규칙과 해석 | argparse 코드의 네 함수는 각각 무엇을 하나? | 왼쪽 '규칙 정하기'(코드에 적는 부분), 오른쪽 '입력 해석하기'(실행할 때), 사이를 보라 점선 '규칙 참고' | **참고**(순서 아님) |
| **D** 비교 카드 3장 | 헷갈리는 쌍은 무엇이 같고 다른가? | CLI↔GUI, `-h`↔`--help`, 명령줄 인자↔함수 인자 | **비교**(선 없음) |

**흐름과 관계를 섞지 않는다.** A의 괄호는 '누가 해석하는가'만 나타내고 번호를 달지 않는다. 번호와 화살표는 B에서만 쓴다. C의 규칙 등록과 입력 해석은 실행 시점이 달라 화살표로 잇지 않는다. 이 원칙은 구버전 V01이 '② 명령 해석'을 '③ 프로그램 실행'보다 앞에 둔 문제([시나리오 v2 §7.3](../scenario-v2.md))를 피하기 위해 세웠다.

## 2. 의미 구분 (색에만 의존하지 않음)

| 해석 주체 | 색 | 테두리 모양 | 이름표 글자 | 쓰인 곳 |
| --- | --- | --- | --- | --- |
| 터미널·운영체제 | 회색 `#4b5563` | **점선** | `OS` | 토큰 `python`, 괄호, 상자, B① 이름표 |
| Python 인터프리터 | 파랑 `#1d4f91` | **파선** | `Py` | 토큰 `-m`·`todo`, 괄호, 상자, B②·③ |
| 내 프로그램(argparse) | 초록 `#17663f` | **실선** | `앱` | 토큰 `list`·`--limit`·`5`, 괄호, 상자, B④·⑤ |

| 선·도형 | 뜻 |
| --- | --- |
| 진한 실선 화살표 + 검은 번호 원 | 실제 처리 순서 |
| 보라 점선 `#6b4fa0` + '규칙 참고' 글자 | 규칙을 참고함(순서 아님) |
| 괄호 | 그 범위를 해석하는 주체 |
| 회색 코드 상자 | 실제로 실행해 확인한 출력·코드 |
| 빨간 코드 글자 | 오류 출력(색과 함께 'error' 글자로 표시) |

흑백으로 인쇄해도 테두리 모양과 이름표 글자로 세 주체를 구별할 수 있다.

## 3. B3-1과 같은 것·다른 것

- **같은 품질 기준:** 노트북·휴대전화 두 판, 최소 글자 기준(노트북 960px·휴대전화 328px 칸에서 12px 이상), 색만으로 구분하지 않기, 범례, 흐름과 관계의 구분, 자동 검사기, 대체 설명(`<desc>`).
- **복제하지 않은 것:** 네트워크 구성도의 좌우 비교 레이아웃, 구역 상자 중첩, 비교선(≈), 장면 전개. Scene 01은 **가로 한 줄(명령)을 세로로 풀어 내리는** 구조를 새로 설계했다.

## 4. 노트북용과 휴대전화용

| 항목 | 노트북용 `1280×1672` | 휴대전화용 `360×3292` |
| --- | --- | --- |
| A 명령 분해 | 토큰 6개를 34단위 고정폭 글자로 한 줄에 크게. 아래 이름, 괄호, 주체 상자 3개를 가로로 | 명령줄은 한 줄(16단위)로 보여 주고, 주체별 세로 상자 3개 안에 토큰과 이름을 한 줄씩 |
| B 처리 순서 | 단계 상자 5개를 가로로, 화살표는 오른쪽 | 단계 상자 5개를 세로로, 화살표는 아래쪽. 담당 이름표는 상자 오른쪽 위 |
| C argparse | 규칙 카드(왼쪽)와 해석 카드(오른쪽), 가로 점선 | 위아래로 쌓고 세로 점선. 긴 코드 줄은 두 줄로 나눔 |
| D 비교 | 카드 3장을 가로로 | 세로로 |
| 최소 글자 | 16단위 → 1280px 16px, 1000px 12.5px, 960px 12px | 14단위 → 390px(칸 358) 13.9px, 360px(칸 328) 12.8px |
| 길이 | 1280px 화면(높이 약 900px) 기준 약 1.9화면 | 390px 화면(칸 358px, 높이 약 800px)에서 약 4.1화면 |

휴대전화용이 길어진 이유: 처리 순서 5단계에 실제 실행 결과를 남겼고, 비교 카드 3장을 줄이지 않았다. 글자를 14단위 아래로 줄이지 않았다. 웹에서는 구역 A~D 단위로 접거나 탭으로 나누는 방안을 인터랙션 명세(§6)에 남긴다.

## 5. 글꼴·색·크기

- 본문 글꼴: `var(--font-body, 'Pretendard VF', …, 'Malgun Gothic', …)` — 웹 페이지 안에서는 서비스 테마 글꼴을 따른다. 코드: `var(--font-mono, ui-monospace, 'Cascadia Mono', Consolas, …)`.
- 고정폭 글자에는 `xml:space="preserve"`를 붙여 코드 들여쓰기를 지킨다.
- SVG는 흰 배경과 고정 색을 쓴다(다크 테마에서도 그림 자체는 밝은 카드로 보인다). 다크 테마 대응 방식은 웹 통합 단계에서 B3-1 스토리 그림과 같은 방식으로 정한다.
- 확대: 벡터이므로 확대해도 글자 품질이 유지된다. 토큰·코드 글자는 글자(텍스트)로 남겨 화면 낭독·검색·복사가 가능하다.

## 6. 추후 인터랙션 명세 (Codex 구현용 · 이번에 구현하지 않음)

SVG 요소에 아래 속성을 붙여 두었다. 웹 구현은 이 이름을 그대로 쓴다.

| 속성 | 붙은 곳 | 값 |
| --- | --- | --- |
| `data-token` | 토큰 묶음 `<g>` | `python` `-m` `todo` `list` `--limit` `5` |
| `data-owner` | 토큰·주체 상자·단계 묶음 | `os` `python` `program` |
| `data-bracket` | 해석 주체 괄호(노트북용) | `os` `python` `program` |
| `data-step` / `data-flow` | 단계 묶음 / 화살표 | `1`~`5` / `1>2` … `4>5` |
| `data-rule` / `data-ref` | 규칙 줄 / 점선 | `1`~`3` / `rules>parse` |
| `data-card` | 비교 카드 | `cli-gui` `help` `args` |

| # | 상호작용 | 동작 | 강의 중 / 강의 후 |
| --- | --- | --- | --- |
| I1 | **토큰 선택** | 토큰을 누르거나 키보드로 고르면 그 토큰과 같은 `data-owner`의 괄호·상자를 강조하고 나머지는 흐리게(불투명도 0.35 안팎). 설명 패널에 토큰 이름·해석 주체·한 줄 설명을 보여 준다 | 강사가 순서대로 시연 / 학습자 자유 선택 |
| I2 | **주체 보기 전환** | 'Python이 보는 부분' / '프로그램이 보는 부분' 버튼. 프로그램 보기에서는 `sys.argv` 목록(`['…/__main__.py', 'list', '--limit', '5']`)을 함께 표시 | 핵심 문장 시연 |
| I3 | **단계 따라가기** | '다음 단계' 버튼으로 B①→⑤를 하나씩 강조. 자동 재생하지 않는다. 각 단계에서 A의 관련 토큰을 함께 강조(예: ③에서 `list --limit 5`) | 강의 중 |
| I4 | **입력 바꿔 보기** | 미리 정한 보기만 선택(자유 입력 없음): `--limit 5` / `-n 5` / `--limit=5` / `--limit five` / `-h`. 결과 패널에 `sys.argv`와 `parse_args()` 결과 또는 오류 메시지·종료 코드 2를 보여 준다. 결과는 원고 §6에서 실제로 확인한 값만 사용한다 | 강의 후 자율 탐색 |
| I5 | **위치에 따른 `-h`** | `python -h` / `python -m todo -h` 두 보기. 누가 도움말을 출력하는지 주체 강조로 보여 준다 | 비교 카드 D2 시연 |
| I6 | **규칙 ↔ 결과 연결** | C의 `add_argument(... "--limit", type=int)` 줄을 고르면 해석 결과의 `limit=5`와 B④를 강조(점선 = 참고 관계 유지, 화살표로 바꾸지 않음) | 강의 중 |
| I7 | **예시 전환** | '설명용 예시(todo)' / '구현 사례(ledger)' 탭. ledger 탭은 `python -m ledger --data-dir ./mydata list --limit 5`를 같은 방식으로 나누고 `[구현 사례]` 표시를 유지한다. 그림을 새로 만들 때는 이 생성기의 `TOKENS`를 바꿔 같은 규칙으로 만든다 | 강의 후 |
| I8 | **구역 접기(휴대전화)** | A~D 구역 머리글을 눌러 펼치고 접기. 첫 화면은 A만 펼침 | 휴대전화 |

공통: 키보드 탐색(Tab·Enter·Space·Escape), 선택 상태를 `aria-pressed`/`aria-live`로 알림, 자동 애니메이션 없음(`prefers-reduced-motion` 존중), 강조는 색과 함께 굵은 테두리·밑줄로도 표시. 개념지도·용어사전 연결은 [개념지도 개요](../concept-map-outline.md) §7의 Scene 01 탐색 후보를 쓴다(사전에 없는 용어는 미구현으로 표시).
