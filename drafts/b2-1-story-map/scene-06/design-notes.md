## 1. 핵심 시각화 네 가지

| 그림 | 질문 | 구성 | 관계의 종류 |
| --- | --- | --- | --- |
| **A** 중복 코드와 공통 기능 분리 | 같은 로그가 함수마다 반복되면 어떻게 나눌까? | 왼쪽 '반복되는 경우'(`repeated_logs.py`의 두 함수, 로그 줄 4개에 '반복' 띠) / 오른쪽 '분리한 경우'(`log_calls` wrapper 상자: 앞·원래 함수 호출·뒤, `@log_calls`가 붙은 두 함수) · 'Decorator만 정답은 아님' | 코드 비교 + **감쌈**(보라 점선, 번호 없음) |
| **B** Decorator의 두 시점 | Decorator는 언제 실행되고, wrapper는 언제 실행될까? | **왼쪽 영역 '정의 시점'**: 원래 함수 객체 → ② `trace` 호출 → `trace`가 wrapper를 return → 이름 `greet`가 wrapper를 가리킴(③) + 단계 표 / **오른쪽 영역 '호출 시점'**: ① `greet()` → wrapper, ② 앞부분, ③ 원래 함수(= `func`) 호출, return, ④ 뒷부분 + 실제 출력 · '정의 시점 출력 1번, 호출 시점 출력은 호출마다' | 실행 순서(번호) — **영역마다 번호를 따로 매김**. return(회색), 가리킴(점선) |
| **C** 예외 처리의 세 경로 | 원래 함수에서 예외가 나면 wrapper는 무엇을 할까? | 경로 3줄(정상 / 처리하는 예외 `AppError` / 처리 범위 밖 `KeyError`) × 칸 4개(호출한 쪽 · wrapper · 원래 함수 · 받는 것과 실제 출력) | 실행 순서 ①②, return(회색), **예외**: 처리되는 예외 = 빨간 **긴 파선**, 전파되는 예외 = 빨간 **점선**(wrapper를 지나 호출한 쪽으로) |
| **D** 공통 관심사 세 가지 | 로그·예외 처리·시간 측정은 무엇이 같고 무엇이 다를까? | 관심사 3열 × (wrapper: 앞 · 원래 함수 호출 · 뒤 · 예외 · 반환값) + 원래 함수의 책임 + 실제 출력. 시간 측정은 가짜 시계 결과만 | 비교 표. **번호 원 없음** |

그림의 코드 줄·실행 순서·출력·예외 경로는 `_tools/demo/`의 실제 소스와 실행·호출 추적(`sys.setprofile`) 결과이며 `verify_demo.py`가 매번 다시 대조한다.

**예제 선택.** Decorator 원리(1~6절)는 `greet`·`hello`·Scene 03-A의 `add_tax(price, rate=0.1)`로, 공통 관심사(7절)는 거래 함수(`add_transaction`·`find_transaction`)로 설명한다. 예외 예제는 `ledger`의 `LedgerError`와 겹치지 않게 학습용 `AppError`를 만들었다. 데모는 파일을 쓰지 않는다(`import_then_call.py`가 `deco_tools.py`를 import할 때 Python이 `__pycache__`를 만들 수는 있음).

**그림 A의 코드 줄임.** 노트북·휴대전화 모두 `def` 줄과 로그 줄은 **실제 소스 그대로**, 로그가 아닌 원래 기능 줄은 `… 원래 기능: …(n줄)` 한 줄로 줄였다(회색 글자). 휴대전화 폭에서 긴 줄을 끊지 않고, 주제(반복되는 로그)에 시선을 모으려는 선택이다. 줄인 줄은 `data-span`으로 실제 줄 범위를 남기고, 검증기가 그 범위에 로그 줄이 없는지, 모든 줄을 빠짐없이 다뤘는지 확인한다. 전체 코드는 원고에 있다.

## 2. 시각 약속 (Scene 01~05 약속 유지 + 이번 추가)

| 표현 | 뜻 | 출처 |
| --- | --- | --- |
| 진한 실선 + 채운 검은 화살촉 + 검은 번호 원 | **실제 실행 순서**. 그림 B는 '정의 시점'·'호출 시점' **영역마다** 번호를 따로, 그림 C는 경로마다 | Scene 01~05와 같음 |
| 회색 가는 실선 + 빈 화살촉 + 'return' 글자, 번호 없음 | return(값을 돌려줌) | Scene 03-A와 같음 |
| 빨간 **긴 파선** + 채운 빨간 화살촉 + `raise …` | **처리되는 예외**(wrapper가 받음) | **이번에 추가** |
| 빨간 **점선** + 채운 빨간 화살촉 + '받지 않음' | **전파되는 예외**(wrapper를 지나감) | **이번에 추가** |
| 보라 점선, 화살촉·번호 없음 + 글자('@log_calls로 감쌈', '가리킴') | 관계(순서 아님) | Scene 05 '만들어 냄'과 같은 모양 — 선 옆 글자로 뜻 구분 |
| 파란 테두리 상자 + 'wrapper' 글자 | wrapper(감싸는 함수) | **이번에 추가** |
| 초록 테두리 상자 + '원래 함수' 글자 | 원래 함수(감싸인 함수, 주된 책임) | **이번에 추가** |
| 갈색 파선 띠 + '반복'(휴대전화는 '반복 ↓'를 줄 위에) | 함수마다 되풀이되는 로그 줄 | **이번에 추가** |
| 회색 테두리 영역 + 머리글 | 그림 B의 두 시점 영역 | **이번에 추가** |

- 색만으로 구분하지 않는다: wrapper·원래 함수·반복은 글자, 두 예외는 선 모양(긴 파선/점선) + 글자. 검사기가 상자 글자와 '두 예외 선의 모양이 다름'을 확인한다.
- **번호를 붙이지 않은 곳:** 그림 A, 그림 D, 관계 선(감쌈·가리킴), return 선 주변 16px.
- 그림 B 정의 시점에서 '`trace`가 wrapper를 돌려줌'은 호출이 아니라 **return**(회색)으로, '이름 `greet` → wrapper'는 **가리킴**(점선)으로 그려 호출과 섞지 않았다.

## 3. 이전 장면·B3-1·기존 체험과 다른 점

- 03-A·03-B의 호출 흐름(세로 열·가로 띠)과 달리 그림 B는 **시점별 두 영역**으로 나눴다. 같은 함수(`greet`)가 왼쪽에서는 '감싸이는 대상', 오른쪽에서는 '호출되는 원래 함수'로 나오며, 둘 사이를 선으로 잇지 않는다(다른 시점이므로).
- 그림 C는 Scene 03-B의 '실패 두 경우' 카드와 달리 **경로마다 같은 네 칸을 반복**해, 차이(예외 선의 모양·도착점)만 눈에 띄게 했다.
- B3-1 그림의 배치·장면 전개는 쓰지 않았다. 그리기 도구는 Scene 05 생성기를 불러 썼고(그 안의 04·03-B·03-A·02·01 포함), 여섯 생성기 파일은 바꾸지 않았다.
- **기존 학습 체험 `src/B21LearningStoryView.tsx`의 Decorator 체험(변경하지 않음):** `handle_errors` 코드, `_dispatch = handle_errors(_dispatch)` 풀어 쓰기, '정상 실행 / LedgerError 처리' 두 경로 전환, 'LedgerError만 처리' 경계 표기가 정확하다. 원고 9절(구현 사례)의 상호작용으로 **재사용할 수 있다.** 다만 ① 제목 '호출 **전에** 함수를 감싼다'는 '정의(import)할 때 감싸고 호출할 때 wrapper가 실행된다'(그림 B)로 더 정확히 할 수 있고, ② 처리 범위 밖 예외(전파) 경로가 없으며(그림 C의 셋째 경로), ③ 일반 예제(로그·시간 측정) 없이 `ledger`만 다룬다. 재사용 시 그림 B·C·D를 앞에 두고 이 체험은 사례 절에 둔다(Codex 단계, 시나리오 v2 §7.2와 같은 판단).
